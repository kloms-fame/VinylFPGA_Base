# O5 启动图无损评估与工程清理实施计划

> **For agentic workers:** 按步骤执行；用户已要求直接在 `main` 开发。测试/候选文件与生产 RTL 分开，阶段收益不足时保留当前实现。

**Goal:** 在启动画面 RGB、呼吸、几何位置、启动守卫和外部像素时刻完全不变的条件下，评估启动资源减负并完成安全的工程源分类。

**Architecture:** 冻结当前 ROM/boot_layer 为黄金参考。先验证无额外周期的“palette index × 64 档 gain”组合逻辑查表是否能逐像素复现三路乘法，再看 RTL 综合资源；只有资源与时序有合理收益才跑独立完整 route。O5b 只分类 `.al` 项、include 依赖和最终例化层级，不物理删除文件；若要修改 `.al`，使用单独快照并独立全流程验证。

**Tech Stack:** Verilog-2005、Icarus Verilog、Python/Pillow（仅既有素材生成依赖）、Anlogic TD 6.2.168116、EG4S20BG256、seed 5 / `area_prior`。

---

## 文件与职责

- `src/boot/boot_layer.v`：帧/行坐标、同步像素 ROM、呼吸亮度和启动状态守卫。
- `src/boot/boot_logo_rom.v`：由生成器维护的索引 ROM 与调色板；任何生产改动须由生成流程稳定复现。
- `src/include/boot_logo_geom.vh`：生成器/RTL共用的几何合同。
- `tools/gen_boot_logo.py`：素材到压缩索引 ROM 的现有生成入口。本阶段不改源图片、量化参数或几何。
- `sim/tb_boot_s2.v`、`sim/tb_boot_window.v`、`sim/tb_s2_boot_guard.v`：启动图像/边界/状态守卫基线回归。
- `sim/tb_boot_logo_compact.v`：O5候选的像素地址、调色板/增益组合输出与延迟对比检查。
- `tools/verify_boot_logo_o5.py`：冻结原版输出并对候选做全 ROM 地址、64 档增益的逐拍比较；若生成像素映射不稳定则直接失败。
- `doc/实施记录_20261009/O5/`：素材合同、层级资源、候选差异和源分类记录。
- `prj/resource_opt_verified_20261005/opt_o5a_boot_r1/`：忽略的隔离 TD 构建快照；不接触工作工程报告。

## Chunk 2：无损查表候选门禁

- [ ] 先创建测试，复现原版每个 ROM 地址在 64 档 `breath_gain` 下的 RGB 输出及一拍有效对齐。
- [ ] 在父版运行测试，确认黄金模型与实物 `boot_logo_rom`/亮度表达式匹配。
- [ ] 候选只改变 palette-index 到 RGB dim 的组合映射；不能增加同步 ROM 级或改变 top 的 `de`/`vs` 时序。
- [ ] 生产默认 `BREATH_FLOOR=192` 使用 64 档表；对其他参数值以 generate-time 保留原乘法实现，不能截断/回绕 gain 的既有行为。
- [ ] 对 16 个 palette 值 × 64 档合法 gain 穷举 RGB 结果，并覆盖 ROM 全地址、无效地址/`valid_q`、盒外边界及原一拍像素对齐；状态相关用例覆盖 reset、首图 ready、用户 skip、timeout、帧边界。
- [ ] 若候选需要增加像素周期、画面出现差异、`boot_active` 守卫错位，立即拒绝候选并恢复父版 RTL。
- [ ] 运行 gate-only 综合候选；仅当至少减少 3 DSP 且估算 total slice、LUT、BRAM 均不高于父版时进入完整 route，否则记录差值并拒绝候选。
