# O5 启动图无损减负与工程清理设计

## 用户目标与边界

- 优化 O5 启动图相关逻辑，并完成工程源/资料清理评估。
- 启动画面必须保持当前外观、像素内容、位置、呼吸效果、显示时长、跳过行为和首图/超时交接时序。
- 不生成 bit。优化收益不足、视觉输出不逐拍等价或完整 route 出现违例时，保留当前实现。
- 不物理删除素材、课程参考、legacy 文件或生成 IP；清理阶段仅分类，必要时评估 TD `.al` 源条目。

## 现状证据

- 当前最终实现层级 `u_boot_layer`：109 LUT、40 ripple、61 时序单元、10 BRAM9K、3 DSP。
- 子模块 `u_boot_logo_rom`：27 LUT、8 时序单元、10 BRAM9K、0 DSP。
- 启动图由 134×149 的 4-bit 索引图构成，2 像素/字打包并分为 8+2 个 BRAM 深度块；16 色调色板组合解码为 RGB。
- `boot_layer` 保持原 `boot_active` 状态守卫，并在 RGB 上进行 192..255 的呼吸亮度缩放。三个 RGB 通道当前各有一条乘法链。
- 生产顶层 include `boot_logo_rom.v`、`boot_layer.v` 和几何宏；`.al` 还单独列出大量 Verilog 文件。层级面积只能说明已例化生产逻辑，不能作为未例化文件“可省面积”的证据。

## 方案比较

1. **保留基线**：外观与时序风险最低，但没有启动层级减负。
2. **精确缩放调色板查表（本轮候选）**：保留全部索引像素、16 色调色板和 64 档呼吸增益，将每个“调色板索引 × 增益”的原始 8-bit 通道结果离线生成，比较以查表替换三路 DSP。预计可能减少 3 DSP，但需要额外 ROM 资源并可能增加读延迟；必须通过逐像素、逐增益等价与完整 route 验证后才决定采用。
3. **减少颜色数/移除呼吸**：可能省 ROM 或 DSP，但会改变视觉效果，本阶段排除。

## 已选验证策略

- 固定 O4 已提交版本为父版本，先记录素材/ROM/几何哈希和当前最终报告。
- 生成独立的黄金像素参考，覆盖 ROM 全地址和所有 64 档增益；启动层仿真另外检查像素盒边界、同步读延迟、整屏盒外黑色、呼吸端点/周期以及帧边界状态交接。
- 若查表候选不能在不改变外部 RGB 像素时刻与 `de` 对齐的条件下实现，则在进入 RTL 阶段前停止该候选并记录原因。
- 只有等价检查通过，才建立独立 TD 快照执行相同器件、约束、seed 与映射策略的 gate/place/route/fix_hold/final 比较；记录 LUT、寄存器、BRAM、DSP、slice、setup/hold 和启动层级差分。
- O5b 以 TD 工程源条目、顶层 include 图和完整层级报告交叉分类。仅对明确未例化且不构成 include/IP/工程依赖的条目提出 `.al` 清理候选，不删除工作区源文件；每次清单变化独立综合、回归和完整 route。

## 验收条件

- 启动输出与父版逐像素/逐周期一致，动画相位、几何、位置和黑色背景不变。
- 上电守卫、用户跳过、首图 ready、无卡超时都维持现有帧边界语义。
- 候选物理实现无 setup/hold 违例，且资源差异明确优于父版；否则保留父版启动实现。
- 源分类注明生产层级、被 include 文件、IP依赖、纯参考/legacy 项；不根据文件名或未例化面积臆测收益。
- 不生成 bit，不覆盖已有 `.al` 综合/布局布线报告。
