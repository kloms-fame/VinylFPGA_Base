## 4. 实际 RTL 优化

### 4.1 共用写 FIFO 输入流水线

新增 `src/video/media_write_pipeline.v`，顶层通过 include 接入现有 AL。背景→MV→封面的原仲裁优先级保持，valid 和 32 位数据同拍寄存，随后直接送 FIFO。切断 owner 仲裁到 FIFO 写使能的组合长链；寄存之后不再用新的 owner 门控旧 valid，防止末词丢失。

新增内部 SD 时钟一拍延迟（100MHz 下 10ns），ACK、事务 owner、DRAIN/finish、缓存 ready、SD 扇区协议不改。实际 frame_fifo_write、行为双时钟 FIFO、BG/MV 客户端共同验证正常争用与短艺术文件补零，均通过。

### 4.2 FAT 与 BMP 局部计算

- 首轮曾尝试file_start捕获 `max_cluster`，但新增物理REG、面积收益未成立，第五轮已撤回该候选，streamer恢复原来直接使用max_cluster的实现。没有把已撤回代码计入最终优化成果。
- loader 接受加载时求一次尺寸乘积；既有 WAIT_WRITE 间隙内从已寄存像素数计算三倍字节，不增加 ACK 等待或文件开始延迟。
- 完整字段在 BMP 第 51 字节到齐时预计算格式/偏移检查，第 52 字节计算载荷范围，第 53 字节按原时刻判断。保留实时宽高判定、32 位溢出语义、错误报告及像素消费守卫。
- 第四轮最终offset比较路径仍负裕量，第五轮再利用第49字节拆分高低16位偏移比较，第51字节汇总offset有效，第53字节判定仍不变；原尺寸/字节协议保持。
- 优化前后 loader + streamer 逐周期差分覆盖当前四封面索引/CRC/旧格式回退场景，所有相连输出一致；64×4 小尺寸回归通过。此结论不扩大到事务中途任意改变卷参数。

### 4.3 共享光栅减法

`background_raster_address` 先选择 16/336/640 边界，再用一个减法生成 span。原 cursor、frame/epoch 冻结、突发范围和数据返回节拍保持；实际 read FIFO 的两整帧与慢消费者/停顿测试通过。

### 4.4 第二轮面积候选

- `lrc_five_osd` 六槽各自先取同列 8 位字形，再选择行，替代先选择 128 位行再选字。请求、长度、颜色、无歌词分支及坐标均保持，无新增字体延迟。新旧 639400 向量（含两整屏）组合差分通过。
- `frame_fifo_write` 的横坐标从固定 16 位改为 FRAME_WIDTH 所需位数，宽度 1 用一位保护。默认 640 宽使用 10 位；线性地址不依赖该计数器，纵向翻转的 1/8/640 宽和词数检查均通过。没有扩展原有非法或超大尺寸支持。

### 4.5 维护清理

移除顶层悬空 seg_decoder 实例/输出线及不消费的字模输出绑定，保留数码管实际驱动和兼容 ASCII 输入。诊断生成器仍保留可启用功能。厂家 IP、ROM、灯效、缩略图历史文件没有因“看起来冗余”而大规模删除。

### 4.6 歌词六槽缓存的数据通路共享

第二轮同 seed5 布线报 PHY-8023，定位到 `u_lrc_window_controller` 的宽缓存 mux 走线冲突，没有生成第二轮固件。停止该已报错的独立 TD 进程，保留所有日志；没有继续盲目改种子。

第三轮将六槽共用的 ROM有效数据/清零选择提取成一份，六槽分别控制写使能，保留滚动时从下一槽移位的二选一。状态机、ROM地址/读取延迟、行长、有效发布时刻、复位期间缓存保持及 frame_start 优先级不变，不新增缓存或字库端口。现有缓存不复位的约定继续保留：有效标志隐藏未完成窗口，全部槽写完才发布。

新增窗口全部输出逐周期差分，61204周期通过，覆盖1986次移位、750次填槽和1次尾行操作；尾行越界清零另经RTL逐支复核，不能仅凭tail=1声称所有尾行分支都已被仿真覆盖。独立复核确认fill_slot=6/7不写槽，保持原default语义。

### 4.7 INDEX 串行检查提前准备

第三轮布线完成后只剩 INDEX `chk_idx→chk_ok` 一条 −279ps Setup 路径，第四轮据此优化。每拍仍只检查一条目，在流结束拍准备第0条；检查当前条时提前准备下一条。将簇号高/低16位比较结果及封面/字节数标志寄存，再组合为原错误判定，避免选条目、32位比较和有效性累计挤在一拍。

仅增加3位提前索引和6位检查标志，未采用历史四条目并行方案；P_CHK/P_FIN顺序、busy/done/valid/error时刻均保持。实际接口约定是 `in_done` 在最后有效字节之后独立出现、`max_cluster` 事务期间稳定；当前 file_streamer 满足。对任意外部“有效字节与结束同拍、同时修改条目0字段”的输入不扩大等价承诺。

第四轮5项针对性验证通过：原INDEX六种合法/错误输入、BGR扩展、64×4加载、新旧loader逐周期差分、新旧INDEX逐周期差分。loader的旧副本同时引用优化前streamer与INDEX，避免两侧都使用新INDEX导致差分失去意义。独立规格复核通过。

## 5. 为什么分轮

首轮的最终时序通过，但物理 LUT 和 Slice 增加，作为可生成固件的时序检查点保存，继续第二轮；未把 gate 的下降写成最终面积收益。所有轮次使用同一器件、area_prior、seed5、原约束、显式 fix_hold。没有反复随机换种子、降频或添加 false_path 掩盖负裕量。

第二轮走线冲突失败后进行第三轮有针对性的缓存共享化，最终统计取成功轮；失败尝试也列入交付记录，不冒充正常通过。

第四轮虽MCP gate通过，最终物理时序失败且LUT回退，因此第五轮继续拆分BMP偏移比较并撤回max_cluster副本。第五轮7项相关FAT/INDEX/loader检查全部通过，记录在 `closure_verification_20261013_r5_final/`；实际header比较寄存器10007组随机/边界输入通过，覆盖offset=53/54、等于file_len、16位进位、最大32位值。该局部强制内部状态测试补充流式集成，不代替整个文件协议。完整软件覆盖由第三轮全量结果与第四/五轮受影响路径验证共同构成。

最终统计必须使用 `final_verbose.area` 的物理 #lut/#reg/#mslice/#lslice/#plb。gate 的 `#Total_luts` 是另一个口径；gate 的 PLB=0 也不代表最终不占 PLB。
