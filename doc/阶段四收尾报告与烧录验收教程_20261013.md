## 2. 四项修改与效果

### 2.1 完整封面缩小

播放页媒体窗口为 X=[16,336)、Y=[48,288)，即 320×240。完整 640×480 封面通过偶数列、偶数行抽取，目标局部坐标 `(x,y)` 映射到源 `(2x,2y)`，不再仅显示大图局部。

为了保持 SDRAM 连续突发读取，窗口每行仍读取 640 个源像素，只将偶数列放入读 FIFO；行尾跳过一个源行。浏览页保留完整大图，MV 保留原 320×240 紧凑帧；SD 卡中的原封面文件不需要重新缩小。

这一选择不新增缩放 BRAM/DSP，但封面播放复合帧的读命令从 307200 增至 384000（25%），最终仍输出 307200 个屏幕像素。综合/仿真已通过，实际音频连续性及显示边缘仍需上板确认。

### 2.2 第四模式 ART2

KEY11 只在播放页推进背景；循环顺序为：

| 模式 | 显示效果 | 未就绪时 |
|---|---|---|
| 0 | 原柔和灰渐变 | 直接显示 |
| 1 | 当前歌曲封面模糊背景 | 柔和灰 |
| 2 | 通用蓝紫柔和 ART1 | 柔和灰 |
| 3 | 通用暖金/青灰柔和 ART2 | 柔和灰 |

两张艺术图复用同一显存槽，未增加全屏 SDRAM 槽。切图先使旧身份失效，更新 epoch，等读端帧边界清 FIFO 并确认后才覆盖槽；完成后校验身份并整帧显示。快速按键合并为最终目标，过时任务不能发布。

模式在整次上电期间记忆；返回选歌页再进入、切歌均保持。复位/重新上电回模式0。图像加载优先让出音频；没有承诺固定200ms加载时间，应以测试卡实测为准。

INDEX 的 BGR1 扩展兼容原5帧及新6帧。旧阶段三卡能继续用，但缺ART2时模式3显示灰底。要验收新艺术图，必须写阶段四卡。

### 2.3 MV 首帧黑场

进入播放/新曲目元数据提交时，媒体窗口先黑场，随后无MV歌曲显示封面；有MV歌曲等待完整首帧准备好，再在帧边界显示视频。加载期间不闪现封面。

补充修复了MV→MV切歌的旧帧保留：换曲目使旧 display_valid 失效；同曲目的Seek/refill仍保留已显示视频帧。用户主动按KEY08选封面时仍可显示封面，不会被“有MV”条件永久遮黑。元数据提交边界上，无MV歌曲可能出现一帧短黑场，这是防止跨域切歌瞬间露出旧封面的处理。

### 2.4 背景读写可靠性

复用现有512-word写FIFO暂存一整扇区的256个RGB像素。只有512字节顺序完整且无sector_error才释放hold写SDRAM；失败先重新握手清FIFO，然后重读相同LBA/地址，最多额外重试2次。重试耗尽则cancel当前写事务、释放所有权、不写零PAD、不发布失败帧，维持灰底回退。

突发长度准备寄存器增加明确就绪信号；长度和地址稳定后才允许发新突发。隔列保留按实际 `Sdr_rd_en` 返回有效信号计数，支持回数间隙，未假设固定SDRAM返回延迟。

参考材料提出的“横线物理根因”没有被直接当成事实：原注册span已有排空等待，原PAD失败帧也已经禁止发布。本轮加强读写事务并用完整帧独立地址检查验证；偶发横线是否在实体板上消失，仍以人工验收为准。

修改完成后首次实现r1 Setup−1.362ns，r2−0.302ns，均未放行。按真实路径分三处小幅回修：反馈音事件及参数整束延迟一个50MHz周期；写FIFO信用判断打一拍，hold/cancel/read-busy仍实时仲裁；BMP字节、valid、done整束打一拍，BMP头校验和数据消费同步使用新流水，索引流不移动。最终r3通过。

PLB仅余11个，且Setup/Hold余量仍小。新增流水改善本轮实测路径，但LUT下降并不代表所有物理资源都下降；后续每次改RTL都需要重新看最终路由结果。

最终 `check_timing` 的no clock、clock definition、invalid constraint、combinational loops均为0；仍有3个dummy node、2个PLL反馈相关提示和既有IO delay提示，未为了消除提示改动PLL或板级接口。结论是当前既有约束下的内部Setup/Hold通过，不是全部板级IO时序签核。

SynthPilot已按官方llms.txt流程完成最新源码的 `elaborate → opt_rtl → opt_gate`，约64秒。MCP单运行默认映射结果为逻辑LUT12459、分配LUT18283、REG10943、BRAM47/DSP10，门级Setup估计−1.054ns。该会话映射与原AL的area_prior不同，不能将其门级面积/余量与最终物理指标混用；最终发布依据上表原AL完整实现。

### 7.1 使用当前已生成固件

## 8. 分步人工验收

建议一轮连续操作完成，约10～15分钟；记录等待时间和可复现操作。

### A. 启动和原功能

- [ ] 冷启动进入选歌页，四张封面、曲名、歌手、曲号和时长正常。
- [ ] 进入播放页后数字时长正确，标题/歌手没有末尾重复残字；进度条白色已播、浅灰未播，左侧已播和右侧负号剩余时间位于条下方。
- [ ] 歌词、波形、音量、暂停继续、Seek、重播、曲尾策略、灯条、数码管、EC2浮窗保持原行为。
- [ ] 母板和扩展按键、拨码、编码器、红外反馈音正常；新流水只有20ns，不应造成能听出的操作迟滞。

### B. 完整封面

- [ ] 对比四首的原BMP与播放窗口：画面整体缩到320×240，四角和完整构图可见，不能仍是左上/中心局部特写。
- [ ] 大图浏览不变；媒体窗口上下左右边缘、屏幕x=256/512附近没有重复条带、错行或黑线。
- [ ] 有MV的第一首按KEY08切到封面也能看到完整缩小图；切回视频正常。

### C. 四背景与缓存切换

- [ ] KEY11每次按下推进一档，顺序灰→歌曲模糊→ART1蓝紫→ART2暖金/青灰→灰；释放不多推进。
- [ ] ART1/ART2能明确区分，加载时允许灰底，准备后整帧切图，不应出现艺术图混杂或下半旧图。
- [ ] 快速连续按KEY11、尤其ART1/ART2来回切，停下后最终图与最终模式一致；不能卡死在中途模式。
- [ ] 歌曲背景模式切四首，音频立即按原逻辑播放，未就绪先灰，随后换正确曲目背景。快切数首后无过时背景覆盖。
- [ ] KEY7返回选歌，再进播放保留模式；复位回灰。选歌页按KEY11不改播放模式。
- [ ] 记录艺术图首次加载、ART1→ART2重载、新歌背景加载时间。不要把加载暂灰判成故障，但需反馈长期不出图。

### D. MV首帧与Seek

- [ ] 进入第一首含MV曲目：首帧准备前媒体窗口黑场，无封面闪现；准备后视频正常。
- [ ] 在第一首视频播放中执行Seek/重播：保持已有显示策略，不应突然切回封面；暂停继续正常。
- [ ] KEY08主动选封面后不被永久黑场遮挡，再按KEY08可返回视频。
- [ ] 从MV曲目切到无MV曲目显示完整封面；重新回到MV首帧行为正常。
- [ ] 可选：使用另备的双MV曲目卡验证MV→MV换歌黑场、新首帧及无旧视频残留。本轮成品卡只有一首MV，不把此项标成已完成板级验收。

### E. 连续播放与旧卡兼容

- [ ] 至少连续播放5分钟，穿插切背景、切歌、MV/封面切换和Seek；音频无中断/杂音，背景无固定或偶发横线、闪烁、撕裂。
