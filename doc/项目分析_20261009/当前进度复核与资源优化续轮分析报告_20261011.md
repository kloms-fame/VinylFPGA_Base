## 1. 结论与建议

目前保留的资源/时序优化基线仍是候选 E。它清除了固定 native 流程下的内部时序违例，但尚未形成宽裕的后续开发空间。本轮重新构建未改动的隔离副本，完整复现：**Slice 8588/9800、PLB 2422/2450、LUT 15683/19600、BRAM9K 47/64、DSP 10/29，final Setup/Hold WNS +0.116/+0.030ns，违例端点均为 0。**

建议先做两项不会改变协议、显示效果或处理节拍的结构候选：

1. **N1：FAT32 目录名保存为逐字节匹配标志。** 门级确实存在 88 个文件名字节触发器；所需信息可用 25 个不同匹配谓词和 2 位 PIC 序号表达。88→27 是逻辑信息量计算，**不是已经测得的最终 FF/Slice/PLB 节省**。
2. **N2：INDEX 版本字段保存为等价字节分类标志。** 本轮已确认正式最差路径真正由 `hdr_version[7]` 发起；用三个标志完整表达当前所需的“版本 1 / 版本 2 / 其他”判断，替代 16 位原始字段。保留所有非法版本的拒绝规则。

这两项之后，重新判断资源与时序，再选择 N3（歌词字形选择网络）、N4（进度除法数据通路）、N5（歌词缓存 RAM 化）、N6（INDEX 元数据 RAM 化）。**所有候选都未实施、未做候选级综合，不能承诺实现后一定节省 PLB。**

功能删减不属于默认方案。五行歌词、字体质量、亮度/对比度五档、音量、MV、Seek、暂停、按键/红外/编码器、蜂鸣与灯效均按现状保留。可讨论的兼容性简化选项见第 10 节。

## 5. 最关键的新发现：真正的最差路径起点

此前文档无法确认 `blue_adj[5]` 为什么出现在 100MHz SD 域，本轮已用同一份 final 网表闭环：

```verilog
// 物理 Slice：u_brightness_contrast_steps/blue_adj[5]_syn_48
.clk(sd_card_clk),
.q({open_n72861,
    \sd_card_bmp_m0/fat32_media_loader_m0/u_song_index_db/hdr_version [7]}));
```

这是物理打包后的实例名：同一 Slice 可以容纳来自不同 RTL 层级的组合函数和寄存器，名称及源注释不能代替引脚连接。**该路径起点实际是 INDEX 版本位，不能据名字去修改亮度/对比度像素算法。**

第一条路径的事实：+0.116ns，数据延迟 9.604ns，cell 3.059ns/31%，net 6.545ns/69%，7 级逻辑，最大扇出 50。沿路径看到 `hdr_version[7] → fin_err 相关组合网 → song_mv0_b_n1 → src_data[62] → src_data_latched[5]`。

```mermaid
flowchart LR
  A[INDEX hdr_version 位：SD 域] --> B[版本判断及 MV 输出门控]
  B --> C[选曲 MV 元数据选择]
  C --> D[CDC 源侧影子锁存：SD 域]
  D --> E[既有 req/ack 握手]
  E --> F[视频域整包接收]
```

上述是路径族解释，不宣称每个 LUT 都仅实现某一个判断。N2 针对常量版本判定的信息表达；进一步的 CDC 或宽元数据重构必须保留整包稳定、busy 合并到最新、目的域单独复位后重发的现有语义。

## 7. 保持原功能的候选详细分析

### 7.1 N1：目录名字节谓词缓存——推荐第一项

落点：`src/SD/fat32_volume_scanner.v:79` 与目录解析 `:210` 起。当前保存 11 个字节，在偏移 11 的属性字节为 `0x20` 时匹配 `PIC1..4 BMP`、`AUDIO PCM`、`INDEX BIN`；PIC 第四字节还用于生成 2 位资源序号。

在每个原字节写入点，保存“是否等于 P/A/I 等需要的常量”；PIC 数字位置保存是否在 1..4 和对应 2 位序号。不同名字在同一位置共享相同字符的谓词可共享一个标志，总计 25 个谓词加 2 位数字信息。

**等价性条件：**每个谓词只在其对应的字节位置更新；复位与原字节复位到 0 的结果一致；不能在每个条目开头擅自清空所有谓词。后者会改变原设计对不完整/异常顺序输入的保持语义。偏移 11 的判断、偏移 31 的输出提交、错误/超时/无 INDEX 回退均保持原拍。

优点：减少真实保存状态，将十一个字节的宽比较从属性判断拍移到各个字节到达时；不复制 max_cluster 比较、不新增流水、不改 FAT 格式。风险：把候选错误写成只支持严格连续字节流的累计匹配器。方案采用逐位置缓存，规避该风险。

收益：状态信息量净少 61 位；实际工具可能采用其他编码/复制/打包，**最终 LUT、FF、Slice、PLB 待候选综合和 route**。不能把 61 位等同于 61 Slice 或若干确定 PLB。

### 7.2 N2：版本字段的无损分类编码——与真实最差路径对应

落点：`src/SD/song_index_db.v:76,139,255,308,349`。版本字段为小端偏移 8/9；目前其唯一功能是识别版本 1/2、拒绝其他值，以及控制 v2 MV 描述符/flags。

分别保存低字节“等于 1”“等于 2”和高字节“等于 0”三个标志，导出 `is_v1`/`is_v2`。任何 16 位值都能得到与当前比较相同的结果；并非丢弃高位或默认相信 PC 文件。

复位及被接受的 start 对应旧值 0：low_v1=0、low_v2=0、high_zero=1。各标志在原对应字节写入拍更新。错误优先级、CRC、P_CHK/P_FIN、done/valid、song_flags 与 4 路 MV 输出全部保持。

收益：原字段 16 位→3 位信息状态，减少长版本判断的机会；实际宽网和物理打包结果待测。与 A 的区别是**替换原存储、保留固定常量语义**，不增加四组运行时簇比较或预计算寄存器。不保证因此一定改善 WNS；N1 后还要复核路径是否仍是主要目标。

### 7.3 N3：歌词字形选择/字库读地址组织

落点：`lrc_five_osd.v` 的六行选择与逐列字形选择；`playback_page.v` 的标题/歌手/时间/歌词仲裁。字库仍为 4096×16、178 个字形。

本轮 gate 网表在 `u_shared_song_font` 名下有 398 个 LUT 和 8 个 BRAM，但前几个 LUT 的输入/输出实际上是 `lyric_y_sum`、`line_y`、`song_line_count_frame` 与 `font_addr`。BRAM 已用 4096×2 的八路位平面映射，没有发现“整个字体落成 FF”的证据。

应评估的是“先选 128 位行，再选 8 位字符”的两层选择、请求门控及跨层连线。可以尝试将行/列选择组织为明确的窄字形输出或局部 one-hot 选择，**不新增五个字库读口，不改字体，不改字号/坐标/颜色/高亮/滚动**。两种 mux 分解的逻辑复杂度可能相同，只能用映射/route 判断收益。

不要据 629 LUT 的层级名字盲目改 ROM 生成方式。完整字体有 938 种不同 16 位行；做行字典需要约 10 位索引表与另一张点阵表，增加一级读取，对当前 PLB 目标未证明有益，暂不优先。

### 7.4 N4：进度共享除法器的数据通路复用

`playback_progress.v:40` 已有单个 40 拍恢复除法器，进度、秒、分钟共享；不存在需要删掉的“五套组合除法器”。但 `div_trial>=divisor` 与条件减法可评估是否合并为一次 **34 位零扩展减法+借位判断**。

数学边界：33 位 trial 减 32 位 divisor 的差处于 `[-(2^32-1), 2^33-1]`，34 位可安全表示；第 33 位表示负差，剩余值保留原 33 位 remainder。必须保持 40 拍、输出更新拍、total=0、elapsed>total、32 位极值、48000/60、BCD 和每帧 snapshot 行为。

综合器可能已经共享部分比较/减法；现有 native 495 LUT 是整个 formatter 的面积，不能全部算为可回收。此项只作为独立的低到中风险测量候选。

### 7.5 N5：六行歌词缓存 RAM 化与循环行槽

现缓存声明 6×128 位，但当前短歌词与常量数据已使 native 整模块 seq 降到 266；不能承诺回收 768 FF。本轮 MCP gate 的同模块 seq 又为 569，说明裁剪/打包具有阶段与策略依赖。

可将 6×16 个 8 位字形号存入小 RAM，通过“行槽+列”取出一个字形；滚动时旋转行基址，重写新尾行，不再并行搬动六组 128 位数据。逻辑容量 96×8 可放进一块 BRAM9K，**实际映射和读写仲裁需确认**。

代价：同步 RAM 引入 glyph 读取拍；必须让 font/RGB/DE/VS/X/Y、波形/浮窗/Logo 叠加全部对齐；行重填仅在安全窗口发布，Seek/暂停/切歌时不得读到混代内容。该项可能减少组合网络/复位负担，但不能为省资源而牺牲五行和帧同步语义。

因此 N5 是另行确认的结构项目，不与 N1/N2 混合落地。

### 7.6 N6：INDEX 元数据由 FF 表改为窄口 RAM

当前四曲 cover/audio/MV 合计名义 4×3×64=768 位原始字段，同时有宽输出选择/有效门控。可保持 INDEX 文件与 CRC 规则，用小 RAM 保存条目，预取当前需要的 cover/audio/MV 描述符，保留必要的当前曲目寄存器。

若采用字节存储，4×64=256 字节条目载荷在容量上适合一块 BRAM9K；但验证、预取、所选曲目缓存和并发访问会增加控制。现有“4 路 64 位输出即时可见”的模块接口不能无说明地替换为串行接口。

需要联动 `song_index_db`、`fat32_media_loader`、顶层 metadata_update/CDC 发布时刻；新增明确 valid/ready、取消旧请求的代次机制。封面四 bank 预载、无索引回退、快速切歌和目的域复位后重发都要重验。此项面积潜力较大，风险也最高；**不能直接宣称节省 768 FF**。

### 7.7 次级候选和不建议重复的工作

| 检查项 | 本轮结论 |
|---|---|
| sector_buffer 512×8 改小缓存 | 旧输出只剩 125 个相关 cell，读地址均为常量；不能预估省 4096 FF |
| 编码器 32 位改 16 位 | 当前已自动裁成 16 FF/路，预计主要是代码表达清理，非优先资源项 |
| IR、蜂鸣、共享去抖 | 已有宽度约束与共享 tick；蜂鸣历史候选失败，不再重复 |
| UART/缩略图/旧黑胶渲染 | 主链已停用或删除；清理文件不会自动产生器件收益 |
| 所有 32 位 FAT/LBA/size 缩窄 | 无完整范围证明；FAT 坏卡/溢出行为亦属协议，不做统一截断 |
| 给 CDC/SD 扇出加大量寄存器 | PLB 紧且 A/D 已表明可能恶化；只作为有因果证据的独立时序候选 |
| 字库/Logo 有损压缩 | 不采用；保留原像素与点阵 |
| 亮度/对比度查表 | 三路并行读口和 ROM 容量会消耗 BRAM；不能只凭 25×256 表大小推断收益 |
| 靠关小型 DSP 换面积 | DSP 不是瓶颈；常量 ×3 等可能换成更多 LUT，不作为默认目标 |

### 7.8 功能正确性提醒：D14 不应与本轮资源候选混合

现 waveform 对负样本使用 `~pcm_tap_left[15:8]+1`，忽略低 8 位。对于 −1，当前结果为 1，而整 16 位取绝对值后右移 8 应为 0；对于 −32767，当前结果为 128，而整幅值右移应为 127。故后续若目标是准确幅值，不能只特判 −32768，需验证整个负半轴的取整和满幅饱和。

本轮不修改这个行为。它属于 D14 的功能修正，先定义目标幅值合同，再与资源优化分开验证。

## 9. 验证状态、约束与开发余量

### 9.1 本轮 fresh 仿真

- 7 项定向全部 PASS：media_loader、index_loader、file_streamer、volume_scanner、song_index_db、fourbank、media_lifecycle。
- 完整 runner：53 项，40 PASS、13 FAIL，失败集合与 E 前/后档案一致。
- 13 项中 **11 项为编译/接口错误、2 项为运行期断言失败**。前者涉及旧缩略图、旧 volume/OSD/控制接口；后者为 `tb_x1x2_lights` 与 `tb_ws_vu_only`。
- 两个 WS 测试均未连接现有 D8 `brightness_level` 输入，有明确夹具过期线索；但在更新夹具并复跑前，不能将断言失败直接宣布无害。
- 当前 `sim/` 没有专门的五行窗口、滚动、播放页/进度测试；旧 `tb_lrc_font_sync` 验证的是早期 lrc_font，不能替代新的 song_font/五行链。

这些失败是已有验证债务，**“零新增失败”不等于完整功能证明**。N1/N2 必须另有逐拍差分/独立边界测试。N3/N5 开始前应先补齐显示链验证。

### 9.2 约束/物理检查

正式 final 检查为：no_clock=0、invalid_constraint=0、combinational_loop=0、no_path_constraints=0；33 输入无 input delay、38 输出无 output delay；两个 PLL local feedback 警告仍在，另有 dummy node=3、SDRAM 位置未 honored 与一条时钟网走 local routing 的既有提示。

本轮 MCP gate 检查另外报 abnormal_input_delay=32，而正式 native final 为 0。阶段差异必须保留，不能引用 gate 的异常条目宣布正式接口已错，也不能只说所有检查为 0。

不新增 false_path/multicycle，不虚构板级 IO delay，不把同源 PLL 的相位关系仅凭时钟树不同就断言为异步正确。现有 clock group 合理性仍需 CDC/板级专项审查；本轮沿用其条件，未验证全部跨域结构或外部接口时序。

### 9.3 准备后续功能的资源门槛

| 项目 | 当前 | 历史优化目标 | 差距 |
|---|---:|---:|---:|

达到这些目标也不自动批准 D13/F2/F3：每项仍需独立增量预算和完整 route。旧 D13 的“+300 Slice/+3 BRAM”只是规划数，F2 的“净 BRAM 接近 0”也不是实测。若 N5/N6 采用 BRAM，必须计入后续加载器、字库和缩放预算，防止用完其他资源的扩展空间。

## 10. 可以讨论的功能简化——均未纳入默认实施

| 选项 | 可能减负的范围 | 用户会失去什么 | 判断 |
|---|---|---|---|
| 只支持 INDEX.BIN，不再 PIC/AUDIO legacy 回退 | 部分目录匹配、旧资源表及回退控制 | 无 INDEX/坏 INDEX 的旧卡不能继续播放/浏览 | 是最值得讨论的兼容性取舍；BPB/FAT/INDEX 搜索仍必须保留，不能算删整个 scanner |
