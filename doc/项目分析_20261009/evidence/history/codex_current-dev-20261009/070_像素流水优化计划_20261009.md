# 像素流水优化与构建证据计划

基线：`6bfe956`，器件：EG4S20BG256，TD：6.2.168116。

目标：为后续开发切断缩略图、转场、对比度串联组合路径，同时保留逐位运算语义和默认模块接口时序。

方案比较：单纯调整映射策略不能消除串联逻辑；改乘法为查表可能扩大 RAM，且有取整等价风险；本轮选择在对比度模块输入处增加可选流水级。顶层启用后总延迟从一拍变为两拍，RGB/DE/亮度/对比度同拍采样。下游 VS 同步延迟两拍，X 按输出 DE 重建；原始 VS/frame_start 继续驱动读调度和帧参数提交，诊断图案保持原始节拍。没有新的时钟、CDC 或时序例外。

执行清单：

- [x] 使用 SynthPilot 对隔离源码执行综合、时序/面积/逻辑深度/扇出/约束检查和物理实现，建立新鲜基线。
- [x] 先增加流水延迟与连续像素算术记分板，确认未优化版本不能满足新增流水契约。
- [x] 实现可选输入流水及顶层显示控制对齐，保持独立模块默认一拍。
- [x] 验证随机参数、极值、正负饱和、行首行尾、消隐、异步复位及顶层显示接线；58 项完整回归通过。
- [x] 对独立优化快照执行同策略综合与物理实现，逐项比较 QoR，保留日志、输入 SHA256 和工具调用结果。
- [x] 记录真实签核状态、剩余风险和后续开发门禁，使用简体中文详细 Git 提交。

本轮不以历史报告作为通过证据。只有同轮 setup/hold、资源、未布线与 DRC 均通过才具备生成 bit 的条件，板级验收另行记录。

执行中根据新鲜 STA 增加 UIRES 首扇区地址寄存，拆开簇减法、移位、加法；独立审查发现并补上 scanner_error 判定，阻止失败扫描发布旧目录元数据。对比还发现 single-run 的实际映射为 auto，采用工程原有 area_prior 策略可明显降低物理资源，因此补充了原生 TD 的隔离快照、数据库导出和显式 hold 修复。

最终保留最终 RTL 的 area_prior、seed 7 实现：Slice 8817（89.97%）、MSlice 4404，setup/hold WNS 分别为 +0.081/+0.024 ns，违例端点均为 0。仍需解决时钟告警、I/O 约束审计和时序余量；本轮没有生成 bit 或进行硬件验收。详细数据与后续顺序见 [像素与资源优化报告_20261009.md](./像素与资源优化报告_20261009.md)。
