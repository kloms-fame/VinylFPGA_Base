## 1. 项目定位

VinylFPGA 是一个面向 **安路 EG4S20BG256 FPGA**（Tang Dynasty 6.2.1）的**黑胶唱片风格音乐播放终端**，属于 FPGA 创新设计赛道·安路赛项完赛工程。核心能力：

- 640×480 HDMI 1.4b 视频输出 + I2S/HDMI PCM 音频（48 kHz）
- SD 卡 FAT32 文件系统：WAV 流式音频、BMP 封面/背景、MP4 类 MV 帧流、LRC 歌词
- 人机交互：EC11 旋转编码器（×2 路 EC1/EC2）、红外 NEC 遥控、板载 DIP 拨码、KEY 按键、WS2812 灯环、蜂鸣器
- 播放态视觉：烘焙底图（SDRAM 乒乓）+ 封面/黑胶/MV 三模式视窗 + 歌名歌手 + 极简进度条 + 右侧五行歌词 + 底部音谱

顶层为 `src/top_tf_hdmi_audio.v`（约 137 KB，巨型顶层），全工程约 **126 个 RTL 源文件**。

## 4. 架构盘点

### 4.1 显示流水线（25 MHz video_clk 单向级联）

```
SDRAM 640×480 烘焙底图（乒乓 Bank0/1）
  → u_media_window_mux（封面直通 / 黑胶覆写 / MV 320×240 展宽）
  → u_song_meta_osd（歌名 Y:276、歌手 Y:298）
  → u_progress_bar_osd（3px 细线进度条 Y:326）
  → u_lrc_five_line_osd（右侧五行歌词，Line 0 硬件 2× 放大 + 16 帧滚动）
  → u_promax_audio_waveform（底部音谱 X:64~576, Y:376~471）
  → 消隐选通（DIP4 息屏）→ video_rgb_to_axis → HDMI 1.4b 发送核
```

### 4.2 SDRAM（8 MiB / 2M×32-bit）空间划分

| 分区 | 基地址（字） | 大小 | 用途 |
|---|---|---|---|
| Bank0/1 显示乒乓 | 0 / 307200 | 各 1.17 MiB | 当前/后台 640×480 底图 |
| Bank2/3/4 MV 环形帧 | 1228800 起 | 各 0.29 MiB | 320×240 RGB565 MV 三帧 |
| 黑胶 16 帧贴图 | 1459200 | 0.58 MiB | 160×160 唱片微缩序列 |
| 安全保留区 | 1612800+ | 1.85 MiB | 防越界溢出 |

### 4.3 关键数据通路

- **SD 扇区仲裁**（`fat32_media_loader.v`，57 KB）：优先级 音频 > 扫描/流读取 > UI > 歌词 > 背景（最低），背景只做后台预取，永不抢占播放主链路。
- **UIRES 侧车**：SD 卡上 `UIRES.BIN` 作为独立资源区，LBA 55494 起连续 19330 扇区，与 `INDEX.BIN` 通过 entries CRC32（`0x842ACEF4`）绑定。
- **MV 三段行组合（C4 目标，未实现）**：每行 `BG[0..23] + MV[0..319] + BG[344..639] = 640px`。

## 6. 核心阻塞：物理签核未通过

这是当前项目**唯一的、最高优先级的问题**。RTL 仿真 13/13 全绿，但 FPGA 物理实现失败，bit 被硬门禁拦截：

| 指标 | 门禁要求 | gate 阶段实测 | route 阶段实测 | 判定 |
|---|---|---|---|---|
| Setup WNS | ≥ 0 | **−1.382 ns**（55 端点违例） | **−2.000 ns**（533 端点，TNS −294.552 ns） | 🔴 |
| Hold WNS | ≥ 0 | +0.471 ns | −0.011 ns（8 端点） | 🔴 |
| Route slices | ≤ 90%（88% 健康） | 3163（32.28%，gate 预估） | **9560/9800 = 97.55%** | 🔴 严重拥塞 |
| Gate LUT | ≤ 16500 | 面积优先最佳 17211/19600（87.81%） | — | 🟡 超门禁 |
| Route overflow | 0 | — | 隔离复跑第 32 轮仍 505 overflow，已终止 | 🔴 |

根因定位（SynthPilot 分析）：

1. `sd_card_clk`（100 MHz）扇出极高——逻辑级数分布显示该时钟下 6664 条路径停留在 level 1，长组合路径无法收敛。
2. 逻辑热点集中在 `ui_asset_loader`（2782 cells）、`sd_card_bmp`（7528 cells）、`expansion_integration`（3091 cells）。
3. route 占用 97.55% 时，工具自动跳过 hold 修复，形成负裕量。
4. SDRAM 实例位置约束两次未被完全满足；`ext_mem_clk_sft` 使用 local routing（已知告警）。

**处置现状**：已有 bit（SHA `561B…2995`）被明确标记为 UNSIGNED，不执行 JTAG 下载；串口 CH340 COM8 在位但 OmniProbe 5 秒采样为空，无板级运行证据。这一自律（负裕量不烧录）是工程质量控制的正面信号。
