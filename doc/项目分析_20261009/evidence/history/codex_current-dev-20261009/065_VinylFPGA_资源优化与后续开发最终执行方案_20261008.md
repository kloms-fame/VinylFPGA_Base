## 3. 已锁定架构决策

以下决策已经确认，实施阶段不再反复讨论：

1. **底层存储：** PC 生成 Superblock；FPGA 从固定绝对物理 LBA 读取，彻底删除 FAT32 卷扫描、目录遍历、FAT 链解析和旧格式回退。
2. **UIRES V2：** Superblock 持有描述符；单曲静态槽固定 7,168B，即 14 个扇区；歌词记录固定 20B。
3. **字形缓存：** 默认 128 字形槽；64 槽只作为 BRAM 仍超标时的二级激进方案。
4. **外设中枢：** `expansion_integration` 采用统一事件路由，输入只消抖/译码一次，参数只有一个所有者。
5. **WS2812：** 保留 Off/Simple VU/Simple Progress；PC 预生成 16 档 192-bit 色彩帧；删除复杂彗星、充能、衰减和实时通道乘法。
6. **Logo：** 保持 268×298 可见尺寸和画质；采用无损有效行跨度/紧凑编码，不允许先行有损缩放。
7. **静态 OSD：** 采用 A-Lite，只预译码标题、歌手、进度条及公共播放使能，不扩展成全局巨型总线。
8. **C4：** 双行 RGB565 缓冲，槽带 generation、行号、complete、valid 和 consuming；`frame_read_write` 引出 `read_available`、`read_return_valid`。
9. **U4：** 完整业务页面转场，采用黑场提交屏障，单缓冲歌词更新期间禁止显示混合代次页面。
10. **U3：** 固定 `VOL → BRI → CON → ROT → WSL` 五项；`INCLUDE_ROT=1`；END/EFFECT/WS/LYRIC 继续由 KEY12/KEY09/KEY10/KEY06 独立循环。
11. **功能底线：** 默认保留蜂鸣器、波形、缩略图和五行动态歌词并做等效瘦身；只有物理门禁失败时才按 E1→E5 裁剪。

### 4.3 BRAM 专项说明

“最终 BRAM ≤54”是目标，不是当前已证明事实：

```text
当前 58
− lrc_cache 128 槽：预计 4～6
− Logo：预计 2～4
+ C4 双行缓存：预计 3～4
= 预计 52～56
```

要稳定达到 ≤54，C4 接入前应达到 BRAM ≤50。若无损 Logo 只能降至 8 块、导致 C4 后超过 54，则按顺序处理：

1. 检查两条 640×16 缓冲能否通过合并深度/原语 wrapper 压到 3 BRAM9K。
2. 继续压缩 Logo 的无损行跨度格式。
3. 仅当 UIRES 资产审计持续满足最大字形编号 ≤63 时，启用 64 槽二级方案。
4. 无论如何不得超过 BRAM9K 60 的硬门禁。

## 5. 最终数据流

### 5.1 SD 与资产流

```text
PC 资产/歌曲目录
  → vinyl_packer.py
  → Superblock + 连续资源区 + CRC + 可读 manifest
  → 固定发布镜像
  → FPGA 固定 LBA Superblock loader
  → 音频/MV/UIRES/壁纸绝对 LBA
  → 各专用流读取器
```

FPGA 不再理解目录、文件名、簇、FAT 链、长文件名或旧卡格式。

### 5.2 视频页面流

```text
C4 背景/MV基础页
  → 亮度/对比度
  → A-Lite 标题/歌手
  → 进度条
  → 五行歌词
  → U4 F0/F1/F2 完整页面转场
  → 波形
  → U3 EC2 浮窗
  → Boot 覆盖
  → Blank/严重错误覆盖
  → HDMI
```

# Chunk 3：UIRES V2 与 BRAM收敛

## Task 6：PC 生成 UIRES V2

每曲固定槽：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| `0x0000` | 16B | 标题字形编号 |
| `0x0010` | 16B | 歌手字形编号 |
| `0x0020` | 4,096B | 128×32B 字形 |
| `0x1020` | 2,560B | 128×20B 歌词行 |
| `0x1A20` | 480B | 零填充 |
| 总计 | 7,168B | 14 扇区 |

歌词记录固定为：

```text
timestamp_ms[31:0] + glyph_id[16]
```

- [ ] PC 端验证字形编号 ≤127、行数 1～128、时间戳单调、标题/歌手长度 ≤15。
- [ ] 超限资产必须让打包失败，不允许静默截断。
- [ ] CRC覆盖完整 7,168B，包括零填充。
- [ ] 当前四曲重新打包并生成 V2 manifest。

## Task 7：`lrc_cache` 改为 128 槽
