### 1.1 本方案交付的最终产品

- 保留已验收的浏览、缩略图、切曲、暂停、重播、Seek、EOF 策略、媒体恢复、LED、WS2812、数码管和开机画面。

- EC2 固定五项：`VOL → BRI → CON → ROT → WSL`，所有场景列表一致。
- 播放态左侧显示黑胶或 MV；封面底图作为媒体未就绪时的回退，不默认新增 KEY08 三态循环。

- 非 MV 播放时允许背景自动轮播；MV 显示期间保持当前背景，暂停新的背景装载。
- 多曲歌词跟随既有播放时间，暂停冻结，Seek 后重新定位，切曲不串词。
- UI 素材缺失只降级视觉，不阻塞音频主链路。
- 核心版本不依赖 Flash 持久化、自动演示或 FFT。

## 3. 三份方案的分析与最终取舍

### 3.1 原 `11111...最终执行方案`：保留架构约束，更新进度和顺序

保留：音频优先、现有主链路复用、唯一参数写入口、可靠跨域、文件格式明确、缺资源降级，以及不改加密 SDRAM/HDMI IP 的边界。

调整：

| 原安排 | 本方案处理 | 原因 |
|---|---|---|
| X0R/X1/X2 仍待做 | 标记为用户已验收的前置 | 项目已继续发展 |
| 先 X3A 视觉，再 X4 歌词，再 X5 CSR | CSR、资产、装载、组合取像先做，像素界面后做 | 避免 UI 写好后再改接口 |
| X4 三行歌词 | 数据层支持五行窗口，先静态五行，再动画 | 对齐播放态新目标 |
| EC2 含 MUTE/SEEK | 改为 VOL/BRI/CON/ROT/WSL | Seek 已有 EC1/IR；VOL=0 提供静音 |
| 1.8 s 隐藏＋3 s 状态复位 | 统一 1.8 s 回 IDLE 并发隐藏状态 | 减少隐藏期间继续编辑的歧义 |
| 保留母板旧菜单并桥接到 CSR | 不恢复已退出生产路径的旧菜单 | 避免重复功能和资源反弹 |
| 数码管错误／临时参数优先 | 保留当前固定时间与曲号 | 尊重后续优化后的产品状态 |
| 每阶段全量回归、多 seed、长稳门禁 | 不作为本轮及后续默认流水线 | 遵从本次高效推进要求 |
| X7/X8 强依赖发布 | 持久化、演示拆成独立增强 | 核心产品先完成 |

### 3.2 `播放态开发方案.md`：布局可用，数据通路必须补齐

建议采用的部分：640×480 布局、左侧 240×240 媒体焦点、320×240 MV 窗口、歌名／歌手、3 像素进度条、五行歌词、底部既有波形、PC 端烘焙背景。

需要修正的内容：

| 草案内容 | 静态分析结论 | 最终处理 |
|---|---|---|
| Bank0/1 改成播放背景 | 当前 Bank0～3 是四曲封面缓存，缩略图仍需全部保留 | 新增专用背景地址区 |
| RGB565 文件等同 SDRAM 存储 | 现有 MV 先展开为 `{RGB888,8'b0}`，一个像素占一个 32-bit 地址字 | 文件字节数与 SDRAM 字数分开计算 |
| 16 帧黑胶贴图 | 当前黑胶是程序化渲染，没有这片 SDRAM 资产 | 继续程序化黑胶，不新增动画贴图区 |
| MV 上覆写背景即可 | 当前只有择一帧读，没有两份像素同时可用 | C4 增加组合行取像，是核心依赖 |
| DIP5 控制壁纸轮播 | DIP5 当前控制红外 | 保留 DIP5；新增轮播使用 DIP2 |
| KEY06 手动切背景 | 与歌词模式冲突 | KEY06 保留歌词模式；主线不增加手动换背景键 |
| 直接把 `exp_key_n[5]` 接单拍输入 | 原始低有效电平不是消抖事件 | 所有动作经过既有事件链 |
| 在 `frame_start` 当拍做宽乘除 | 时钟使能不会自动把组合除法变成多周期计算 | 控制域串行计算，视频域只收结果 |
| total=0 时进度满格 | 未知时长与播放结束含义不同 | total=0 显示空槽／隐藏 |
| 128 B INDEX 条目 | 当前是 64 B 条目、512 B 文件、v1/v2 格式 | 保持原索引，添加可选侧车资产文件 |
| GBK 数据直接当字形号 | 双字节编码和紧凑 glyph ID 不是同一种格式 | PC 将 Unicode 文本转换为局部字形号 |
| 五行共用一份 `line_text_indices` | 只能重复同一行，不能提供前后五行 | C2 提供五份独立行描述／字符缓存 |
| 电平 `next_line_trigger` 发起动画 | 满足时间条件后持续为真，可能反复启动 | 用行号变化提交事件触发一次 |
| 5-bit `y_offset` 累计到45 | 5 bit 不能表达45；上移还涉及负坐标 | 动画用足够位宽、有符号坐标和裁剪 |
| 五行一律每帧上移3 px | 草案行基准间距不等，不能统一位移后自然对位 | U2 按每一行起终点分别插值 |
| 共享现有字库即可零资源增量 | 现有 ROM 是单口同步读，字形集合有限 | 规划字形 RAM、端口调度与一拍读取延迟 |
| 顶层示例宣称接上底部波形 | 示例末级接 `lrc5_rgb`，没有展示新链路中波形的完整连接 | U1/U4 明确所有图层的生产连接 |

### 3.3 `EC11-B 风格 EC2 浮窗调参.md`：采用交互方向，不照搬代码

采用：五项固定参数环、三态 FSM、1800 ms 超时、按键/红外音量联动浮窗、青色选择与金色编辑、进入/退出提示音、边界钳位、控制域格式化 ASCII。

必须修正：

1. **方向编码**：现有事件 `aux[0]=0` 为顺时针递增；草案 FSM 把 1 当递增。桥接统一生成 `step_inc`，FSM 不再直接解释底层方向位。
2. **外部音量唤醒**：草案同一 always 块先设置 `osd_visible=1`，后又可能被 IDLE 分支覆盖。改为唯一 next-state 决策，明确优先级。
3. **超时同拍事件**：新操作与超时同时到达时，操作优先，不能先回 IDLE 吞掉有效动作。
4. **EC2 快转**：逐源 pending 会合并事件，必须使用计数差恢复步数，不能仅看到一次事件就只走一步。
5. **跨域**：帧边界直接采异步标签、数值、状态不是原子 CDC；必须先握手快照，再由视频域在帧边界提交。
6. **静音**：VOL=0 只让 PCM 增益为零，保持样本握手和播放时间推进，不能停掉音频链路。
7. **蜂鸣器**：现有接口含 `sound_enable`、DIP/EC1/EC2/IR 分类；草案模块不是可直接替换的同接口实现。只扩展现有模块，并避免 EC2 按压双响。
8. **字模坐标**：标签从 x=237 起，不能用绝对 `pixel_x[2:0]` 当字符列；应使用相对文字区域的 x/y。
9. **满格计算**：166×255/256 只能填165像素；最大值必须显式得到完整166像素，屏幕进度条同理。
10. **默认值**：草案档位音量会把当前默认200改成192；本方案保留200，使用8-bit音量寄存器和饱和步进。
11. **画质旁路**：当前 brightness=255、contrast=128 才是中性值；不能把两者都默认设为同一档值。
12. **资源结论**：动态画质会重新启用此前常量传播裁掉的逻辑；不承诺零 DSP 或固定180 Slices。

## 4. 最终交互契约

以下是本方案提出的后续产品规则；未实现的新规则不能写成当前板上已有行为。

### 4.1 保留输入含义

| 输入 | 浏览态 | 播放／暂停态 |
|---|---|---|
| EC1 旋转 | 选图／选曲 | ±2 s Seek |
| EC1 按压、KEY02 | 确认 | 暂停／恢复 |
| KEY01 / KEY03 | 上一项／下一项 | 上一曲／下一曲 |
| KEY04 / KEY05 | 既有上下导航 | 音量＋／－ |
| KEY06 | 不修改浏览功能 | 歌词模式循环，见 U2 |
| KEY07 | 既有缩略图进入／退出 | 保持已验收的返回选曲行为，关闭 EC2 面板 |
| KEY08 | 保持现有行为 | 保留 MV／黑胶切换；无 MV 时回退黑胶 |
| KEY09 | 既有效果切换 | F0 直接、F1 黑底揭示、F2 淡入淡出 |
| KEY10 | 既有 WS 模式切换 | 关闭／VU／充能进度 |
| KEY11 | 全局回主界面 | 停播回主界面，关闭面板并取消当前 UI 装载 |
| KEY12 | 保持结束策略设置 | E0 播完暂停、E1 单曲循环、E2 自动下一曲 |
| EC2 | 五项参数选择和编辑 | 同样五项，不接 Seek |
| IR EA / F8 / F6 | 保持现有状态门控 | 前进5 s／后退5 s／重播 |

普通播放按键在 EC2 SELECT/ADJUST 时继续按原语义工作，EC2 只消费自己的事件。切曲、退出播放、KEY07、KEY11、媒体丢失时关闭编辑状态。这样不会为了编辑画质临时冻结已验收的播控。

外部音量事件只有在业务路由认定为音量操作时才唤醒 VOL；浏览态 KEY04/05 的导航不误触发音量。专用 IR 音量键在浏览态的原有门控先保留；若以后明确需要全局音量，单列行为变更。

### 4.2 拨码与母板功能

| 控件 | 最终含义 |
|---|---|
| DIP1 | 扩展板在场／动作使能，沿用现有门控 |
| DIP2 | 新增：非 MV 播放态背景自动轮播使能，上拨=1 |
| DIP3 | LED 总使能 |
| DIP4 | 既有自动消隐；消隐首事件只唤醒 |
| DIP5 | 红外总使能，禁止复用为背景开关 |
| DIP6 | WS 总使能；WSL 不得越过它点灯 |
| SW1 | 当前数码管显示使能 |
| 其余母板开关／按键 | 保留当前实现，不借 UI 改造恢复历史诊断和菜单 |

DIP2 是本方案利用预留输入的新分配，不涉及更换引脚。读取同步、消抖后的 `dip_level[1]`，不直接使用原始 `exp_dip_n[1]`。

主线不增加手动背景下一张。需要时可在后续明确分配空闲控件，不能抢占 KEY06 或 KEY12。

### 4.3 EC2 规则与参数字典

| 参数 | 表示／范围 | 默认 | 步进与输出 |
|---|---|---|---|
| VOL | 8-bit，0～255 | 200 | 每格±16，饱和钳位；0为PCM静音 |
| BRI | 档位0～4 | 4 | 输出0/64/128/192/255；255保持现有亮度 |
| CON | 档位0～4 | 2 | 输出0/64/128/192/255；128为中性对比度 |
| ROT | 档位0～5 | 2 | 10/20/30/40/50/60秒 |
| WSL | 档位0～9 | 9 | 10%～100%；100%逐通道保留当前灯效颜色 |

音量选择保留当前200和±16手感，不强行变成17个绝对值档位。因此它是“固定步长＋端点饱和”，不是草案中的 `vol_step=0..16`。UI 显示真实0～255值，不能用档位伪造数值。

- IDLE：首个 EC2 旋转或按压只唤醒 VOL，进入 SELECT，不改值、不跳到 BRI/WSL。此项是本方案为减少误操作作出的明确取舍。
- SELECT：旋转切项，按压进入 ADJUST。
- ADJUST：旋转改当前参数，按压回 SELECT。
- 无有效 EC2／音量操作1800 ms：控制域同拍回 IDLE、idx=VOL、visible=0；视频层在下一个帧边界隐藏，最多有一帧显示提交延迟。
- 外部音量命令执行后：统一切到 VOL/SELECT 并刷新计时，避免原来编辑 ROT 的状态带入音量编辑。
- 其他有效播控动作不延长 EC2 超时；切曲／退出等上下文变化直接关闭面板。
- 消隐首事件、系统确认拦截事件不能在后台修改参数，也不能稍后通过计数差重放补回来。
- VOL=0 后旋转增大直接恢复音量；不另设 MUTE 记忆开关。若需要“一键静音再恢复原值”，属于额外需求。

## 5. 核心架构与接口

### 5.1 时钟域和状态所有权

| 归属 | 保留／新增职责 |
|---|---|
| `clk` 50 MHz | 事件路由、EC2 FSM、权威参数CSR、提示音、WS执行 |
| `sd_card_clk` 100 MHz | 播放控制、Seek、文件与扇区调度、资产装载、背景事务 |
| `video_clk` 25 MHz | 已有音频消费时间、歌词定位与显示快照、像素层、帧提交 |
| `ext_mem_clk` 125 MHz | SDRAM读写、组合行取像、在途事务归属 |

复用既有 PLL、复位同步、SDRAM/HDMI IP、PHY 和音频输出接口。新功能只扩展外围客户端、状态接口和像素合成，不修改加密核。

**参数和运行状态分开管理：**

- CSR 管理 volume、bri、con、rotate_sec、ws_brightness，以及迁移后的 effect_mode、ws_mode、lyric_mode、end_mode。
- `play_ctrl` 继续拥有 play_active、paused、sel_song；`seek_controller` 继续拥有定位计算；`stream_session` 继续拥有播放会话重启。
- 不把播放位置、MV当前帧、SD忙状态复制为可写参数。
- `timebase_48k` 已由 `wav_sample_consumed` 驱动。新增歌词继续用其 `lyric_time_ms`；屏幕进度读取其样本计数或与其同一播放代次的一致快照，不新增自由运行时间计数器。
- 已验收的 SD 域 `seek_cur_sample_sd`、数码管和灯条进度保持现状，不以“统一”之名同时重写。

### 5.2 命令与快照

参数命令建议：`valid/ready + id + op + value`，其中 op 为 SET/INC/DEC/NEXT。第一版 value 用足够容纳参数的位宽即可，不把 Seek 的32-bit目标塞入参数总线。

1. 同域命令在被接受后改一次参数；外部音量、EC2、按键模式切换各有明确入口。
2. 高频旋转通过累计计数差／待执行步数保存；跨域消费者忙时不能仅靠一次脉冲表示“已经成功”。
3. 参数权威寄存器只由 CSR 写；目标域允许存在只读执行快照。
4. 源域将完整 payload 锁住，再翻转 req；目标同步 req，捕获 payload 后返回 ack；源收到 ack 后才覆盖在途数据。
5. 在途期间可以把后续“最终参数状态”合并到一个待发快照，但业务操作必须先在 CSR 中完成，不能静默丢掉用户的增减。
6. 视频目标域收到快照只更新 pending，在 frame_start 一次发布成 active。req/ack解决跨域一致性，frame_start解决半帧变化，两者缺一不可。
7. 显示资产带 `song_id + generation`；离开播放、切曲、媒体复位后不接受旧代次完成事件。第一版单在途，取消后排空旧事务再发下一笔，避免只靠ID匹配掩盖未完成事务。

### 5.3 两种优先级不能混淆

SD 卡扇区客户端：恢复／取消处理 → 音频补给 → MV帧 → UI静态资产／背景。每个扇区事务完成后才换所有者；不能打断一半的512字节返回流。

SDRAM 客户端：首先满足扫描输出的行截止时间，兼顾既有FIFO水位和刷新；写入必须遵守现有读写互斥。不能把“音频优先”直接套成SDRAM仲裁规则，因为本工程音频并不是新增背景读口的消费者。

### 5.4 新增功能失败的降级

| 故障／缺失 | 行为 |
|---|---|
| 可选UI索引／资产缺失 | 继续当前封面、黑胶／MV和播放，不显示不匹配歌词 |
| 当前曲目字库／歌词坏 | 关闭对应文字层，不影响音频 |
| 某背景未装完／失败 | 保留当前有效背景，不切到半张图 |
| 背景与当前歌曲不匹配 | 使用统一深色背景或当前曲封面，不展示上一曲封面／标题 |
| MV暂无有效帧 | 沿用现有保持／回退策略，不为等MV停止PCM |
| EC2快照暂未送达 | 保留上一帧完整面板，下一次提交最新状态 |
| 组合行缓存来不及 | 输出确定的回退颜色并记录内部状态；不暂停视频时序，不把旧代次行当新行 |

## 6. 资源文件设计：保留 INDEX，新增可选 UIRES

### 6.1 为什么不直接改成128字节索引

现有 `song_index_defs.vh`／`vinyl_packer.py` 使用64字节头、64字节曲目条目，整个 INDEX.BIN 固定512字节；标题是24字节ASCII，MV描述符位于条目偏移56。RTL 当前不消费标题。

草案把MV描述符放到0x18会覆盖现有音频CRC和LBA字段；条目扩成128字节后，四首歌加头部也超过512字节。直接覆盖会同时影响打包、CRC、扫描、解析和所有既有SD卡。

**主线采用可选 `UIRES.BIN` 侧车资源包：原 INDEX.BIN 不变。** 没有 UIRES 的卡照常播放。新文件装入当前曲目的文字、字形、歌词和背景描述符。

### 6.2 建议冻结的容量

| 项目 | 第一版上限／规则 |
|---|---|
| 曲目数 | 维持现有最多4首 |
| 每曲歌名／歌手 | 各最多15个16×16字符，超长在PC侧按完整字符截断并报告 |
| 字形号 | 8-bit局部索引；0保留空白；首版上限256个字形／曲 |
| 歌词行数 | 最多128行／曲 |
| 每行存储 | 最多16个字形号；显示区按实际宽度裁剪 |
| 时间单位 | u32毫秒，与现有歌词时基一致 |
| 背景数量 | 每曲1～4张；同曲每张均烘焙相同封面和不同底图 |
| 背景编码 | 640×480、RGB565LE、从上到下、无压缩 |
| 每张背景 | 614400字节＝1200个512字节扇区 |
| 运行时缓存 | 只缓存当前曲歌词／字库，不缓存所有歌曲文字 |

256字形和128行是产品容量上限，不承诺“2块BRAM全部装下”。若真实歌词去重后超限，PC工具明确报出曲目、数量和缺口；不能静默把大量汉字替换为空白。可先选用不超过容量的素材推进，扩容作为有明确资源代价的调整。

### 6.3 UIRES.BIN V1 数据布局

下面是待 C2 实现的新格式，不是现有工程已支持格式。PC定义与RTL头文件共同维护，所有整数小端。

文件首部固定1024字节：64字节公共头＋4×128字节曲目描述符＋零填充。1024字节后为4个固定16384字节的静态资产槽，再后面排列背景裸流；空槽置零，所有背景偏移512字节对齐。

公共头：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 8 | magic=`VINYLUI1` |
| 8 | 2 | version=1 |
| 10 | 2 | header_bytes=1024 |
| 12 | 2 | descriptor_bytes=128 |
| 14 | 2 | song_count，1～4 |
| 16 | 4 | file_bytes，实际文件总长度 |
| 20 | 4 | 绑定的 INDEX entries_crc32 |
| 24 | 4 | flags，bit0表示PC确认整个文件连续分配 |
| 28 | 4 | header_crc32，覆盖1024字节，计算时本字段置零 |
| 32 | 32 | 保留为0 |

每曲128字节描述符：

- 0～15：`song_id:u16, flags:u16, static_offset:u32, static_bytes:u32, static_crc32:u32`。
- 16～31：`glyph_count:u16, line_count:u16, title_len:u8, artist_len:u8, wallpaper_count:u8, reserved:u8, audio_bytes:u32, audio_crc32:u32`。
- 32～95：4个背景描述符，每个16字节，分别为 `offset:u32, bytes:u32, crc32:u32, format:u16, reserved:u16`；format=1表示上述RGB565LE格式。
- 96～127：保留为0。

每曲静态槽内部：64字节小头，包含magic、song_id、glyph_count、line_count、标题/歌手长度、各段偏移；随后歌名16字节、歌手16字节、字形行数据、歌词行记录。具体小头偏移在 `ui_asset_defs.vh` 与 Python 格式表中定稿，禁止两端各自猜测。

字形为每个16×16、每行u16，共32字节；每条歌词记录24字节：时间u32、长度u8、flags u8、reserved u16、16个u8字形号。128条共3072字节，256字形共8192字节，连同文字和头部可容纳在16384字节槽内。

### 6.4 连续文件约束与装载策略

为避免给已验收的 `fat32_file_streamer` 增加随机偏移Seek，本版要求 **UIRES.BIN 在卡镜像中连续分配**，采用与现有 MV 类似的物理扇区读取方式。

- PC工具在最终镜像中遍历实际FAT链，确认全文件连续、尺寸一致，再填写连续标记和索引绑定。
- RTL发现UIRES目录项后，用现有卷参数计算起始LBA；每次读取前检查 offset+length 不越界、LBA加法不溢出。
- 歌词/字库按静态槽读取，背景直接按描述符的扇区偏移读取，不从文件开头扫描几MB数据来找背景。
- 普通文件复制可能重新分配簇，因此交付步骤必须针对最终卡镜像重新打包／检查；不能把旧镜像的物理连续结论移用于另一张卡。
- 装载静态槽时做CRC；背景边收边算CRC，只有长度、CRC和SDRAM写完成都满足才置ready。
- 新CRC计算复用或采用逐字节分拍实现，不在100MHz路径拼接宽组合CRC树。
- 老卡、侧车文件缺失、绑定不匹配，均回退原显示；不会被解释为音频媒体整体失效。

### 6.5 歌词时间处理

PC侧：解析UTF-8 LRC、多时间标签、offset；排序；同时间戳按明确规则合并为一条，超长报告截断；负时间钳位0并报告；输出单语行级歌词，不生成虚假的逐字时间。

FPGA侧：从已有 `lyric_time_ms` 定位最后一个 `timestamp <= time` 的行。未到首行时 current_valid=0；到末行后保留末行；EOF暂停保持最后的时间定位。

窗口为 `i-2, i-1, i, i+1, i+2`，越界位置填空白。Seek／重播直接重新查找目标行并取消旧滚动；正常播放跨行才启动一次动画。128行可用顺序扫描，首版不必实现复杂二分搜索。

## 7. 显存、背景与 MV：先解决数据从哪里来

### 7.1 保留现有四封面＋三MV帧

当前顶层明确使用四个307200字的封面区和三个76800字的MV区。SDRAM地址单位为32-bit字；MV文件虽然是RGB565，写入前会展开成RGB888加填充字节。

基于现有21-bit地址范围，新背景规划如下。区间统一采用左闭右开 `[base,end)`，避免最后地址与长度混写。

| 区域 | 起始字地址 | 结束字地址（不含） | 长度／字 | 状态 |
|---|---:|---:|---:|---|
| COVER0 | 0 | 307200 | 307200 | 保留 |
| COVER1 | 307200 | 614400 | 307200 | 保留 |
| COVER2 | 614400 | 921600 | 307200 | 保留 |
| COVER3 | 921600 | 1228800 | 307200 | 保留 |
| MV0 | 1228800 | 1305600 | 76800 | 保留 |
| MV1 | 1305600 | 1382400 | 76800 | 保留 |
| MV2 | 1382400 | 1459200 | 76800 | 保留 |
| PLAY_BG_A | 1459200 | 1766400 | 307200 | C3新增 |
| PLAY_BG_B | 1766400 | 2073600 | 307200 | C3新增 |
| 保留区 | 2073600 | 2097152 | 23552 | 不分配业务资产 |

两张背景在SD卡上各614400字节，在当前SDRAM格式中各占1228800字节。全部规划后只余94208字节，不能再称“尚有1.85MiB安全区”。

不存储黑胶动画贴图，不覆盖封面bank，不为每首歌保留两张播放背景。播放背景只保留当前显示和下一张候选。

### 7.2 背景装载与帧提交

推荐状态：`IDLE → WAIT_RESOURCE → ISSUE → RECEIVE → WAIT_WRITE_DONE → READY → WAIT_COMMIT_ACK → IDLE`。

- 先选择非活动背景区，并锁存 `song_id/generation/bg_id/base`。
- 写端口事务被接受后再请求SD数据，保证数据有接收者。
- BG使用top-down RGB565流，转换为当前32-bit像素格式，走线性写入；不能继承BMP的垂直翻转路径。
- SD最后一个字节结束不等于SDRAM写完；等待写FIFO排空和对应写完成事件。
- 校验通过才发布ready；视频域在帧边界提交背景地址，返回提交确认后才允许复用旧显示区。
- 请求发出时不修改当前bg_id；仅在成功提交时更新“正在显示的背景编号”。
- 更换曲目／媒体恢复时，旧在途事务先排空，其结果作废；不立即复用仍可能收到写数据的buffer。
- 禁止显示帧中途改读基地址，禁止将未写完的背景设为active。

第一张背景准备期间，音频可继续起播；显示现有封面／确定的深色底，不强制等完整614400字节读完才出声。

### 7.3 轮播规则

有效条件：PLAY、当前曲目背景数≥2、DIP2=1、未暂停、未显示MV、没有更高优先级会话事务。

- ROT默认30秒，以已有可复用毫秒tick累计，避免用大常量乘时钟频率做超长计数器。
- 每张背景成功提交后重新计时。
- 暂停时冻结剩余时间；恢复继续。
- 进入MV时不发新的背景请求；已进入SDRAM写事务的请求安全收尾，但不在MV期间提交新的轮播画面。退出MV后重新计满一个ROT周期。
- DIP2关闭时取消尚未启动的轮播请求，在途请求安全收尾但不强制切屏；再次开启后重新计时。
- ROT被编辑后从新值重新计时，避免刚减小周期就立即连跳。
- 切曲重置bg_id并请求新曲第一张；缺资源时不复用上一曲烘焙封面。
- KEY06不参与轮播。

### 7.4 为什么需要 C4 组合行取像

现有顶层在 `mv_read_active` 时切换帧读地址、长度和窗口外颜色，因此单纯增加一个 `media_window_mux` 没有足够的数据输入。

最终选择：**新增播放态组合行取像器，逐行决定当前像素来自背景还是MV，再送入小型乒乓行缓存。** 不同时拉取两张完整画面，也不增添整屏BRAM。

```text
帧边界锁存：背景base、MV帧base、MV有效、窗口几何、generation
    ↓
逐行生成读段
    非MV行：背景640像素
    MV窗口内行：背景左段 + MV 320像素 + 背景右段
    ↓
SDRAM单读口，按段读取并将返回数据送对应行缓存
    ↓
双行缓存：显示行／预取行
    ↓
640×480完整基础画面
    ↓
后续黑胶、歌词、进度条、波形、浮窗像素层
```

该路径理论上每帧仍取307200个像素字，不需要“完整背景＋整帧MV”两遍读取。按60Hz预算，基础读有效载荷约73.728 MB/s；这是32-bit地址字计算的需求量，不是现有硬件的实测吞吐结论。

推荐双行缓存每行640×32-bit，逻辑容量5120字节；物理BRAM映射按器件端口宽深比计算，暂按约6块BRAM9K规划，不能仅按总bit数向下取整。

实现边界：

1. 新增reader在 PLAY 使用；浏览／缩略图继续沿用原reader。
2. 修改 `sdram_rd_arbiter` 的客户端归属，而非修改加密核。模式切换必须先停止旧请求、排空返回、清理旧FIFO，再授予新reader。
3. 暂不叠加复杂逐周期多主仲裁；播放组合reader取得播放显示读口，按现有读写互斥和刷新规则取数。当前顶层 `mv_thumb_read_busy` 只覆盖缩略图读请求及返回排空；必须把新reader的“正在发读请求＋返回尚未排空”合并进 `frame_read_write.external_read_busy`，否则写端看不到新reader的占用。新reader起批次前检查 `frw_write_busy`、初始化和刷新状态；读批次全部返回后释放占用，批次之间允许MV／背景写入，不能整帧一直置busy饿死写端。
4. 缓存槽带行号、generation和完整标志；显示端只使用与当前扫描行一致且完整的槽。
5. 消费槽通过握手释放，mem域不得覆盖video域正在显示的行。
6. 首行提前准备；正常扫描行中预取下一行。不能假设只在每行水平消隐区就能完成全部640字读取。
7. 不为等数据拉长HS/VS/DE；未就绪使用确定回退色，调度器丢弃已经错过的行任务，避免错一行后持续错位。
8. MV帧base和背景base整帧保持。改显示模式时同步处理现有 `mv_read_active`、FIFO读使能和scheduler保留帧状态。
9. MV显示bank必须与新reader建立取得／释放关系：reader仍有旧bank的在途读或行预取时，scheduler不能把该bank交还写端。不能只在同一个frame_start各自更新寄存器，导致reader锁到旧bank、写端却已认为它空闲。背景区复用也遵守同一条在途读排空规则。
10. 暂停与Seek继续复用既有MV生命周期；新reader只改变读取来源与buffer交接，不另造MV时间调度器。

C4属于实现“壁纸背景＋MV”的必要工作。如果暂时停在C3，只能称背景轮播阶段版，不能声称已经完成播放态草案全部视觉目标。

```text
    → 现有底部音频波形／峰值指示
    → EC2浮窗
    → BOOT覆盖
    → 最终消隐黑屏
    → RGB/DE转AXIS → HDMI
```

- BRI/CON调节媒体底图与媒体窗口，文字／进度／浮窗保持可读。C1沿用当前路径，U4再将执行位置收口到完整媒体层，避免C1同时大改显示。
- 页面转场只使用现有单画面效果，不读两张全屏图做混合。
- BOOT期间不显示旋钮浮窗；最终消隐优先级最高。
- 不恢复已经删除的常驻诊断字符／诊断数码管页。未来如需视觉错误提示，另定义小型状态提示，不作为本轮前置。
- 背景烘焙只负责暗化和封面，歌名歌手仍由运行时字形层绘制，避免两套元数据不一致。

### 9.3 字形读端口与延迟

现有 `lrc_font_rom` 是同步读，不能按草案当组合ROM使用。新字形RAM同样按明确的一拍读取契约设计。

同一像素处，元数据区域与歌词区域不重叠，可由一个文字渲染请求选择器合并地址访问。若多个模块各自发地址，顶层必须仲裁；不能把两个地址线直接连接到同一端口。

当前像素命中、字形列号、前景色和基础RGB与字形读取延迟对齐后再合成。OSD ASCII可单独用小ROM；若它增加流水级，也同步延迟DE/x/y等关联信号。目标是确定延迟，不是强行要求所有级“零延迟”。

## 10. 资源控制：依据真实增量，不采用草案保证值

### 10.1 Slices

仅以O8历史7735为规划参照，距离旧88%目标8624还有889 Slices；但当前HEAD不同，实际余量应在以后正常构建时更新。本次不因此重开资源优化轮次。

新增功能有四项主要成本：动态画质恢复、歌词/字库管理、SD背景事务、组合行读取。它们不能遗漏在“面板只需180 Slices”的估计之外。

执行原则：

- 不为每个参数各造一个计时器、除法器、CDC邮箱或独立大队列；有明确同域关系的功能共享tick和运算单元。
- 不为预定比例结果在像素路径使用宽除法。
- 不承诺所有功能一定低于88%；88%继续作为规划预警线，越线时针对本阶段真实新增部分减负，避免回头删已验收功能。
- 动态BRI/CON先保持五档；若通用乘法重新展开代价过高，可按档位用移位/加法实现等价计算，默认旁路与饱和语义不变。
- 图层、字体和加载器的真实资源以以后阶段正常构建为准，不预先声称零BRAM／零DSP。

### 10.2 BRAM

| 新功能 | 逻辑容量／规划影响 |
|---|---|
| 256×16×16当前曲字库 | 8192字节，按16-bit行输出约8块BRAM9K级别规划 |
| 128×24字节歌词记录 | 3072字节，具体行表／字符表拆分决定约3～4块及端口成本 |
| 五／六行显示窗口 | 80～96字节字形号＋少量行属性，可用小寄存器缓存 |
| 元数据、快照与头部缓存 | 只保留用到的字段，不常驻整个UIRES文件头副本 |
| 双行32-bit像素缓存 | 5120字节，暂按约6块BRAM9K规划 |
| EC2 ASCII字库 | 独立小ROM；按实际映射决定LUT或BRAM |

O8历史剩余22块BRAM，上表已经占用其中较大部分。替换旧单曲ROM后可能释放资源，但只有实际移除生产实例才可记收益；不能同时保留新旧整套词库又扣除旧成本。

### 10.3 资源紧张时的处理顺序

1. 不做FFT、中文参数标签、复杂透明混合、额外动画贴图。
2. 将歌词滚动暂时退为静态五行；保留当前曲歌词与时间定位。
3. 根据实际素材减少字形上限或最长歌词行数，并在打包清单中明确限制，不静默丢字。
4. 对新参数/加载器/行缓存的实现做局部压缩，优先共享运算和缓存，避免无关系统重构。
5. 若C4无法在可用资源内闭合，交付C3阶段版并明确“MV窗口外仍为原背景策略，完整组合显示待实现”。这属于功能未完成，不能改写成最终目标已经满足。

Flash持久化、自动演示、FFT均不占当前核心版的预留承诺。

## 11. 独立增强，不阻塞核心版本

### E1：参数持久化

核心版完成后再确认用户SPI Flash的实际连接与配置Flash区别。未确认前不分配写地址，也不按历史草案假设“前1MiB存bit，后面任意存参数”。

需要时保存CSR里的音量、画质、ROT、WSL、效果／灯效／歌词／结束策略，不保存瞬时Seek位置和缓存状态。采用不同擦除扇区的A/B记录、版本、序号、CRC和最后提交标记；参数实际改变后延迟保存，不因单纯唤醒面板写Flash。

本轮不开发、不烧写该功能。

### E2：自动演示

后续通过统一命令入口驱动，人工操作立即退出；先确认母板SW4是否要赋予新产品功能。演示不能直接写CSR内部寄存器，也不能绕过播放会话管理。

### E3：高级视觉

FFT、歌词逐字卡拉OK、跑马灯、中文浮窗标签、更多曲目、更多背景、背景跨淡入和立体声扩展均单列需求。现有波形/VU不是FFT；行级LRC不是逐字时间。
