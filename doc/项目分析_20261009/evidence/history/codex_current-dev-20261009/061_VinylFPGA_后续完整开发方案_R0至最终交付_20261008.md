# VinylFPGA R0 至最终交付完整实施计划

> **执行者要求：** 实施本计划时，若环境允许子任务代理，使用 `subagent-driven-development`；否则使用 `executing-plans`。所有任务使用复选框跟踪，每个阶段都必须经过“测试 -> 综合 -> 资源/时序门禁 -> 人工验收”后才能进入下一阶段。

**目标：** 在不破坏既有音频、浏览、SD 卡与播放控制链路的前提下，先解决 EG4S20BG256 上当前资源拥塞和时序违例，再完成 C4 背景与 MV 组合取像、U4 全页转场、U3 EC2 浮窗，最终交付通过时序、可烧录并具备板级运行证据的固件。

**架构：** 采用单主线、硬门禁推进。R0 先把当前 C1-C3、U1-U2 基线恢复到可签核状态；C4 按“帧级视图快照、逐行读段、两槽行缓存、代次校验”实现基础画面；U4 在完整页面边界统一转场；U3 最后以轻量字符面板接入现有参数核心。每个阶段均可独立回退，不允许多个高风险改动同时进入综合。

**技术栈：** Verilog-2001、Anlogic EG4S20BG256、TD 6.2.1 Engineer 6.2.168.116、SynthPilot MCP、Icarus Verilog、PowerShell、Python 3、FAT32/UIRES 离线工具、EK-OmniProbe 串口桥。

### 3.3 统一硬门禁

以下条件必须同时满足：

1. 默认 RTL 回归全部 PASS，日志中不能同时出现 `PASS` 和 `FAIL`。
2. Gate LUT 不高于 16500，BRAM 不高于 60；C4/U3 每阶段必须记录相对上一签核点的增量。
3. Route slices 不高于 90%；若 88% 以下可视为健康区，88%~90% 为黄色预警区。
4. Setup WNS >= 0、Hold WNS >= 0、TNS = 0、违例端点 = 0。
5. Route overflow = 0，bitgen 无错误。
6. 不新增未解释的时钟、锁存器、CDC 或多驱动告警。
7. SDRAM 位置与 `ext_mem_clk_sft` local routing 既有告警必须单独跟踪，不能淹没在告警总数中。

若 R0 两轮结构优化后仍不能达到 LUT <=16500 或 slices <=90%，必须触发架构决策：删除非核心常驻诊断/显示逻辑，或迁移到更大器件；不得继续开发 C4。

## 7. 阶段 R0-B：结构性资源优化

**目标：** 在功能零变化前提下，把 LUT 降至不高于 16500，并让 route slices 降至不高于 90%。

### 7.1 优化原则

1. 先用 SynthPilot hierarchy、logic-level、fanout 和 QoR 报告定位真实增量。
2. 一次只改一个逻辑锥；每次先补等价测试，再改实现，再比较 gate。
3. LUT 没下降、时序恶化或测试变慢到不可接受时立即回退该试验。
4. 不通过删功能、降低 CRC 校验、改变音视频语义换面积。
5. 不以寄存器下降代替等价 LUT 和 slices 的真实下降。

### 7.2 候选顺序

| 优先级 | 候选 | 允许动作 | 禁止动作 |
|---|---|---|---|
| 1 | `src/SD/ui_asset_loader.v` | 合并重复解析比较、收窄计数器、复用互斥状态中的组合逻辑 | 删除 CRC/长度/绑定检查 |
| 2 | `src/io/expansion_integration.v` | 拆除重复解码、常量传播、共享只在互斥模式使用的格式逻辑 | 改变 C1 参数 owner |
| 3 | `src/display/lrc_five_line_osd.v` | 共享行级边界计算、缩短不必要位宽、将常量表推入 ROM | 合并五行内容状态导致串行错行 |
| 4 | `src/SD/sd_card_bmp.v` 周边 | 删除已被常量关闭且无验收用途的遗留诊断支路 | 修改已验收 SD 协议状态机时序 |

## 15. 失败处理与回退策略

| 失败 | 立即动作 | 禁止动作 |
|---|---|---|
| 定向仿真失败 | 停止综合，缩小到首个失败测试 | 带错进入 gate |
| Gate LUT 超限 | 回退最近功能增量，比较 hierarchy delta | 用 seed 解决面积 |
| BRAM >60 | 检查行缓存/字库推断，改实现或缩小非核心缓存 | 占满 64 块继续 route |
| Route slices >90% | 继续结构优化或触发器件决策 | 继续增加 U3 |
| Setup/Hold 失败 | 按起终点修 RTL/约束，重新完整构建 | 仍生成“发布”bit |
| C4 missed_line | 检查预取窗口、请求空洞、owner 饥饿；保留确定回退 | 拉长视频时序 |
| MV bank 串写 | 立即禁用 C4 MV 模式，修 acquire/release | 只靠 frame_start 猜测安全 |
| 串口无数据 | 检查 COM、波特率、桥接接收状态 | 解释为空闲/通过 |
| 板上音频异常 | 回退到上一签核 bit，对比 C4 owner 对写端/PCM 的影响 | 继续 UI 调试 |

## 18. 执行优先级总结

1. **立即执行 R0。** 当前最大风险是 97.55% slices 和负时序，不是缺少更多 UI 功能。
2. **R0 通过后只做 C4。** 先背景整行，再 MV 三段行，再 owner 集成；三步分别签核。
3. **C4 后做 U4。** 先把现有页面代次和转场顺序修正确。
4. **U3 最后做。** 面板必须消费 C1 CSR 快照，不另建参数副本。
5. **每阶段重新收敛。** 新功能不能借用上一阶段的旧 QoR 或旧 bit 证明自己通过。
6. **最终只发布一个签核 bit。** 其 commit、输入哈希、资源、时序、告警、烧录和板验记录必须完整对应。
