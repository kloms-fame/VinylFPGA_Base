## 2. 代码级机理分析

### 2.1 S2 现象解析

**2.1.1 为什么"看不到"开机 Logo（主因：与显示器热检测/同步锁定竞态）**
`boot_layer.v` 离开 STATE_BOOT 有三个条件（帧边界提交）：用户事件（500ms 保护窗后）、**首图就绪且满 1500ms（HOLD_MS）**、兜底 8000ms 超时。插卡冷开机时，SD 扫描+首图加载很快完成，boot 在约 1.5~2s 就正常退出；而电视/显示器在冷开机场景需要经历 HPD 热插拔检测、分辨率与色彩空间协商，通常 2~4s 才真正出画面——**Logo 窗口恰好在显示器就绪之前关闭**。这解释了全部三个"矛盾"现象：
- 冷开机看不到：显示器还没就绪（你的"开机太快、HDMI 显示慢"猜测成立）；
- 某次软复位能看到：显示器已处于就绪状态，不再重新协商；之后再复位看不到：可能那次首图就绪+1.5s 窗口又被其它事件提前打断（任何一次按键/编码器抖动都会触发 skip，见 2.1.4）；
- **不插卡能看到且"一直显示"：正是超时路径**——无卡时 `first_image_ready` 永远不成立，Logo 显示满 8000ms 才退出，100% 符合设计。8 秒后黑屏是"无卡无图可显"的正常表现，不是加载失败。
验证方法（不改代码）：冷开机时**先让电视开到该 HDMI 通道并保持唤醒**再给板子上电；或在 boot 期间完全不要碰按键，看 Logo 是否能停留满 1.5s。**建议修复**：把 `HOLD_MS`/`TIMEOUT_MS` 加大（如 HOLD 4000ms），或在 `main` 顶层将两者参数化后用 boot_v5 快照重构建一次；这不是 bug，是 1500ms 最短窗口对显示器热检测时间过于乐观。
另：首图灰色后闪一下恢复彩色，是 HDMI 发送端与显示器色彩空间（RGB/YCbCr）锁定过程的常见现象，与 S2 无关，可在后续 HDMI 稳定性专项里观察。

**2.1.2 `BOOT LOGO` → `BOOT DONE` 串口序列证明固件无问题**
`exp_echo_reporter.v` 的 `BOOT LOGO` 行只在 `state==ST_BANNER` 时 `boot_active=1` 才补打（第 320 行），`BOOT DONE` 在 `boot_active` 由 1→0 的边沿打（第 336 行）。三种场景都有这两行，说明：Flash 固化成功、S2 逻辑在跑、boot 有进有出。问题只在**人眼观察窗口与 Logo 窗口错时**。

**2.1.3 `DIP 1 0` 与拨码编号的规律（全部正常，是上电瞬态）**
`key_dip_monitor` 的消抖器上电初值全 1；拓展板 `exp_dip_n` 低有效+内部上拉，**拨到 OFF 的引脚真实电平为 0**，消抖时间到后报"1→0 变化"，即 `DIP (index+1) 0`。你的四组观察完全吻合：
- 全 OFF：最低位先收敛 → `DIP 1 0`；
- 只开 DIP1（1 号线保持高）：最先落 0 的是 2 号 → `DIP 2 0`；
- 开 DIP2、关 DIP1：理论上 1、3 号线都会报 0，具体先报哪个由消抖收敛先后决定（多路同拍变化时按 index 仲裁），你看到 `DIP 3 0` 属竞态窗口内的正常变体；
- 后续任何一次真实拨动拨码，都会即时打印对应 `DIP n 1/0`（可自测验证）。
该上电首次 `DIP n 0` 已被 boot 跳过逻辑明确排除（`EV_DIP_CHANGE` 过滤，S2 v4 修复点），不会再引发"秒退 Logo"。

**2.1.4 软复位"有时看到有时看不到"的补充解释**
复位后 boot 重新开始；1.5s 窗口内任何一次按键抖动/编码器触碰（500ms 保护窗之后）都会立即 skip。显示器若已就绪+你复位时手碰了 EC1，就会出现"这次显示、下次不显示"的随机感。

**2.1.5 "无法判断拓展板是否正常插入"是真实的设计空白**
横幅打印无条件执行；J2 引脚在无板时靠上拉保持静止，不产生任何事件，因此现有机制**确实无法区分"插了没动"和"没插"**。可选方案（低成本）：上电后主动探测——把某一路线（如 `exp_ext_o[0]` 回环到 `exp_ext_in`，若板上存在物理回环）打脉冲读回；或利用拨码某位作为"板在位"约定开关（拨码 6 置 ON = 在位声明），串口打印 `EXPHUB PRESENT`。建议归入 S1 补丁而非新功能。

### 2.2 S3 缩略图"同序号跳转黑屏死锁"——真 bug，代码路径已定位
黑屏链条（`sd_card_bmp.v` 优先级 0 分支，第 447~457 行）：
1. 确认跳转 → 顶层置 `thumb_select_pending_sd`，转场控制器起淡出；淡出完成 `fade_next_event` 后置 `thumb_select_hold_sd` 向 `sd_card_bmp` 发 `select_req`；
2. `sd_card_bmp` 收到请求且目标 bank 已就绪：直接切 `img_idx` 并回 `select_ack`；**当 `select_index == img_idx`（选的就是当前这张）时，state_code 不变化，`index_commit` 不会产生**，代码用 `switch_abort_toggle` 反转来"释放转场状态机"（注释自证知道这个坑）；
3. 实测该 abort 释放路径没有真正解活转场/淡入状态机：`fade_active` 停在 alpha=0（淡出已完成、淡入未启动）→ **整屏黑**；同时转场 busy 门控后续所有按键切换与确认 → **按键无响应**，与"卡死、只能断电"现象完全一致。
你描述的"正在显示第 2 张时跳第 2 张黑屏"精确命中 `select_index == img_idx` 分支。
**修复建议**：与其依赖 abort 旁路，不如在 `thumbnail_controller` 层过滤——`thumb_confirm` 时若 `focus_index == active_index`，只退出缩略图视图、根本不发起 `select_pending`/转场（一行门控，改动最小，回归风险最低）；同时用 `sim/` 等价 bench 补一个"同 bank 快速选择"用例锁住行为。此 bug 应立为 S3.1 补丁阶段（走独立快照+bit 复现门禁）。

### 2.3 S3 转场方向区分——可行的体验增强
`video_fade_transition` 已有 `wipe_active/wipe_ramp` 斜擦通道，且 `brw_thumb_right/left` 方向信息在 sd 域可得。给转场控制器加一根 `direction` 输入、让 `wipe_ramp` 正计数/倒计数（或镜像 alpha 时序），即可实现"逆时针=从左往右、顺时针=从右往左"。建议与 2.2 一并列入 S3.1。

### 2.4 S4 现象解析
**2.4.1 开机 0.5~1s 琵琶音**：`audio_source_mux` 在 `wav_stream_active` 之前默认输出 `pcm_media_tone`（按 media_id 出琶音，S0 保留设计），直到 WAV 流启动才抢切。插卡时 0.5s 是"首图显示完成→（按 EC1 或自动）启动 WAV→流就绪"的正常空窗；不插卡则永远停在琶音。**体验优化建议**：boot 期间强制静音（或极低音），进浏览态才放开——避免用户误认为"故障"。

**2.4.2 broken 卡的降级全部符合设计**：card_A_broken（音频数据坏）→ 封面链路独立正常、WAV 流报错→mux 停在琶音；card_B_broken（文件系统结构坏）→ 扫描失败→黑屏+OSD 错误码+琶音。这正是"索引体系坏一张救一张"的降级验证，**S4 验收判为通过**。
关于错误码 `1E00`：OSD 通道本身携带的是 8 位 `osd_error_code`（`sd_card_bmp.v:559` 装入 `{4'b0, bmp_error}`，另有扫描器 8 位 `fs_error`）。我在本地代码中未能找到字面量 `16'h1E00`，它应是 OSD 显示格式把两路错误字节拼成 4 位十六进制（具体映射需对照 `fat32_volume_scanner.v` 的错误表核对，不臆断）。**建议**：把完整错误码表（0x10 扇区读失败 / 0x20 引导签名 / 0x21 BPB 不支持 / 0x22 资源缺失 / 0x23~0x26 流式各错）写进验收文档附录，并在 OSD 说明中标明高低字节来源——1E 这种不在表内的值本身就说明表与显示存在缺口。

### 2.5 S5 KEY07 循环琵琶音——半设计半体验问题
`top_tf_hdmi_audio.v:1508`：`audio_force_arp = S5_PLAY_ENABLE & paused_v2`，注释说明目的是"暂停时保持 48k 样本流，避免 HDMI 音频饿死"。因此**任何进入 paused 态的操作都会强制回到琶音源**：KEY07 第一次按下使歌曲暂停 → 琶音循环；第二次进入缩略图（仍暂停）→ 琶音继续；选中开播 → 恢复。这解释了你的全部现象。
与"EC1 按压暂停声音停"存在行为不一致，疑两条暂停路径分别落在 `paused_v2` 与 `play_enable` 门控上（前者触发 force_arp、后者直接停发样本）。**修复建议**：把 force_arp 换成"静音样本流"（结构不变、幅值置 0），暂停即真安静，HDMI 也不饿死；顺带统一两条暂停路径。这是 S5.1 小补丁级别。

## 3. 结论与阶段门禁判定

| 阶段 | 判定 | 遗留项 |
|---|---|---|
| S0 | ✅ 通过 | — |
| S1 | ✅ 通过 | 板在位检测为设计空白（低优先） |
| S2 | ⚠️ 有条件通过 | 与显示器就绪竞态；建议 HOLD_MS 加大出 boot_v5 复验，或接受"无卡 8s 超时可见"作为验收证据 |
| S3 | ❌ 不闭环 | **同 bank 跳转黑屏死锁是真 bug**，需 S3.1 补丁+快照+bit 复现+仿真用例 |
| S4 | ✅ 通过 | 错误码 1E00 映射需补文档 |
| S5 | ⚠️ 通过带瑕疵 | 暂停态琶音（force_arp）体验问题，S5.1 静音流补丁 |

按项目纪律"上一阶段未通过不得引入下一阶段"：**S3 黑屏死锁修复应排在 S6 黑胶层二次尝试之前**。S2 的 HOLD_MS 调整与 S5.1 静音流可与其并行，各自走独立快照与 QoR 门禁。三个修复都是小改动、低回归风险，预计不会重演 S6 的时序危机；但 S3 修完需重测一遍缩略图全路径（进入/移动/确认/同序号/跨序号/快速旋转），S5 修完需回归 EC1 暂停/续播与歌词定格。
