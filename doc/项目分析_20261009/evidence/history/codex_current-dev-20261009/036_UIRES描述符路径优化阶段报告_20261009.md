# UIRES 描述符路径优化阶段报告（2026-10-09）

## 阶段目标

针对 `u_uires_static_loader/desc_static_bytes_r_reg[3] → state_reg[3]` 的
100 MHz `sd_card_clk` 关键路径，保持 UIRES 接口、资源格式、错误码和装载时序不变，
降低描述符几何校验直接参与状态跳转造成的组合路径压力。

## 实施内容

修改文件：`src/SD/uires_static_loader.v`

- 新增 `desc_geometry_ok_r` 描述符几何合法性寄存器。
- 在 header 读取完成时一次性锁存以下检查结果：歌曲索引、描述符 ID、资源标志、静态槽偏移/长度、文件边界、保留字段、壁纸数、标题/歌手长度、字形数和歌词行数。
- `S_HEADER_CHECK` 仅使用锁存的单比特结果决定是否进入 `S_SLOT`，不再让多个 32 位比较器和加法器直接驱动状态寄存器。
- 复位和新一轮 `load_start` 均清除该结果，避免旧一轮合法性状态泄漏。
- 未修改 SDC、ADC、CDC、接口端口、UIRES 数据格式和第三方 HDMI IP。

## 阶段判定

本阶段 RTL 优化**保留**：功能回归和物理实现均通过，且 setup 时序余量由 +0.081 ns
提升到 +0.126 ns。

但本阶段不是 bit 交付版本，原因是：

1. Slice 使用率达到 90.15%，资源余量较小；
2. setup/hold 余量仍低于建议的 +0.2/+0.05 ns；
3. PLL 局部反馈告警和 I/O delay 约束审计仍需单独处理；
4. 本阶段没有执行 bitgen、烧录或串口人工验收。

## 后续门禁

后续优先审计时钟/接口约束和 PLL 反馈告警，再考虑 UIRES 或 SD 路径的下一项单结构优化。
在没有重新取得 route 通过证据之前，不叠加大规模功能，不生成 bit。
