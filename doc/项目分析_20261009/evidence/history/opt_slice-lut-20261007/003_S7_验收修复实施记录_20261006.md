## 2. 证据和对两份根因报告的修正

| 现象/说法 | 源码及日志核对 | 处理 |
|---|---|---|
| 1E34，换好卡不恢复 | `song_index_defs.vh` 明确 0x34 为 SIDX_ERR_CRC。日志 3726–3727 行出现 IDX=34/ERR=34；3732 行软复位后仍错误；3839 行好卡 IDX=00 | 校验失败不再视为挂载成功，保留具体错误直至重新验证成功；周期重试 |
| 监督器没有复位加载器 | 该说法不准确：原 supervisor 已经复位 sd_card_bmp 及内部 loader。实际问题为 `scan_done` 同时表示成功/失败终态，不能代表可用；外部 WAV/MV 不在完整恢复生命周期内 | 顶层成功条件加入元数据校验、封面预载、可用 bank 和 OSD 无错；分发媒体复位到外部客户端和视频域 |
| 重插后歌曲信息回来但仍 ERR05 | 日志 967–969、1937–1939 等位置出现元数据恢复而旧错误保持；STAT 中 ERR00=1368、05=402、34=83、04=8 | supervisor 是当前错误唯一来源，正常恢复显式输出 ERR00；health_monitor 接受清错，累计计数不清 |
| KEY7 双击后唱片/音频/音谱卡死 | browse_fsm 与实际 play_ctrl 实例均在 SD 域，不能归因于报告所述的异域。问题包含同一 KEY7 多处分派、视图与播放状态不一致、切曲数据代际未等待完成 | browse_fsm 单一决定停止/打开缩略图；统一返回；音视频切换等待事务退出及读端空闲 |
| 拔卡变成琵琶音 | audio_source_mux 在 WAV 不活跃后使用既有琶音音源；WAV 欠载本身输出零 | 启动、浏览、暂停、故障、预取期间均输出静音采样，保持 HDMI 音频节拍 |
| 主界面拔卡不立即报错，仍能切图 | 封面已缓存到 SDRAM，切图不访问 SD；板上无独立 card-detect 输入 | 已挂载且空闲约 1 秒后发低优先级 LBA0 只读探测；读故障使用物理 adapter 超时路径 |
| 切曲慢/漏步 | 忙时脉冲和单槽 pending 不能保存用户累计目标，encoder 总线还可能合并步骤 | 重建 encoder 累计差值，忙时更新目标 bank，单笔选择保持到 ACK 后再发下一笔 |
| 播完后不从头播放/再次切曲卡住 | 正常 EOF、故障退出、FIFO 指针跨域复位和旧扇区完成混杂；原环形指针差在回绕时宽度不正确 | 正常完成单独跨域；旧事务退出后开启新播放代际；源域寄存 Gray；修正模指针减法；从真实消费样本推进歌词时间 |
| DIP5 打开后遥控可用 | 用户已实测可用，保持 DIP5 门控与反码校验 | 增加真实 router→bridge 混合测试；IR 上/下曲作为单步 KEY01/KEY03，不能伪造累计 encoder count |

`1E00` 表示第一首、手动、错误 00，本身不是故障码。日志时间及基线版本仅用于定位用户此次测试，不能据此推断新固件已经上板。

## 3. 最终实现

### 3.1 媒体生命周期

- `media_supervisor.v` 接收具体 mount_error；坏索引完成不清错误。只有校验和预载成功才清为 00。
- `fat32_media_loader.v` / `sd_card_bmp.v` 导出物理 adapter 的完成/错误，所有客户包括空闲探测均可触发恢复。
- `media_probe.v` 独占完整探测扇区，屏蔽探测数据/完成对音视频客户端的影响。busy 仅由寄存所有权及下游 busy 产生，避免与 mux 的请求门控形成组合环。
- 顶层挂载总期限设为 15 秒，包含最多四张封面预载；每次单扇区读超时仍为 250 毫秒；连续挂载失败按既有重试次数进入 3 秒冷却，再次重挂。坏索引换好卡不会要求全局软复位，可能需等待下一次挂载窗口。
- 媒体复位覆盖 WAV 写端、同步后的读端、MV 客户端、mux、播放 session、视频调度及时间基准。故障停播并退出缩略图；恢复后返回主界面，确认后重新播放，不自动沿用拔卡前地址。

### 3.2 操作与显示

| 操作 | 最终行为 |
|---|---|
| 主界面 ENC1 SW / KEY02 | 播放当前已显示曲目；媒体未就绪或封面正在切换时不接受启动 |
| PLAY 中 ENC1 SW / KEY02 | 暂停/恢复；正常 EOF 后再次确认从头重播 |
| KEY7 | PLAY→停止并回主界面；主界面→缩略图；缩略图→主界面。单次事件不会同时停止并打开缩略图 |
| KEY11 | 返回主界面，清理缩略图未完成操作并停播 |
| KEY9 | F0 无效果 → F1 方向翻页 → F2 淡出/淡入 → F0 |
| KEY12 | E0 播完暂停 → E1 单曲循环 → E2 自动下一曲 → E0 |
| 左/右、ENC1 旋转 | 主界面选封面、播放态切歌、缩略图移动焦点；快速操作最终到达累计目标 |
| KEY04/05 | 主界面上一/下一张；PLAY 音量加/减 |
| 音谱 | 在帧边界按 PLAY 和视图状态锁存显示使能；回主界面/缩略图完全透明，包括缓存柱条和底线 |

F1 每帧推进 40 像素，共 16 帧；方向跟随上一/下一操作，缩略图选择按目标相对显示位置决定。F1 是单幅缓存的方向揭示，不是两张图片同时滑动的物理卷页。F2 保持独立淡出/淡入。无效果切换也等待帧边界及 bank 握手。

OSD 保留既有曲号/错误行，并增加 E/F 模式提示。固件串口版本设置为 `VER=07030002`。

### 3.3 流式播放与 CDC

- 新 `stream_session.v` 在切曲、重播、停播后等待 SD 事务、MV 写入退出以及读端 idle 同步，再等待 32 个 SD 时钟让元数据稳定。
- WAV 写/读指针分别在源域产生并寄存 Gray，再由对端同步；流重启先禁用两端并确认空闲，不允许复位后的指针跳变被当成在播样本。
- 环形 FIFO 指针差使用地址宽度的模减法，覆盖 4096 样本边界回绕。
- WAV 扇区完成先更新计数，再在 WS_DONE 单独判断 EOF/高水位，消除 32 位加法、比较及状态选择同拍形成的长路径；成功结束仅增加一个 SD 时钟判断，不改变样本内容/顺序。
- 成功完成与 SD error 分离；读侧在尾样本排空后才报告正常 EOF。完成状态单比特跨域，不再同步多位写 FSM 状态。
- MV abort 结束当前不可抢占扇区，完成失败邮箱/清理握手后再允许新代际。
- 歌词/进度时间基准由 WAV 实际消费脉冲推进；音频欠载不会只让歌词空跑。

## 4. 独立审查与验证

独立只读审查发现并修复：探卡组合环、红外与累计 encoder 混用、PLAY 翻页方向继承旧值。对应增加 mux/probe、IR/encoder、顶层双向翻页测试。v1/v2 中间构建不得作为交付固件；其中组合环告警不是继承 IP 告警。v3 已确认组合环为 0，但 WAV 扇区计数→状态机 Setup WNS=-0.403 ns、TNS=-1.321 ns（6 个端点），未生成固件。v4 在完成前被 v5 的上述时序修复替代并停止，保留 ABORTED.txt。发布脚本新增结构检查：无时钟、无效约束、组合环必须为 0，且 Setup/Hold WNS/TNS 均通过才允许 bitgen。

回归入口：
```powershell
python -X utf8 tools/verify_s7_acceptance.py
python -X utf8 tools/verify_s0_s5_fixes.py
```

针对性覆盖：
- 真实 FAT32/SIDX fixture：CRC 坏卡改好、读取封面中途拔卡、超时后重扫/重载，无全局复位。
- 10 次在途 WAV 切曲，首样本按 LBA 计分，正常 EOF 与故障分离；48 扇区 12,288 个样本、三次 FIFO 完整回绕。
- 三种 EOF 策略、零曲目拒绝、四首循环、KEY7/KEY11、缩略图选择同/异 bank、顶部控制联调。
- 303 次快速导航覆盖三种动效，16 帧时长、无叠加渐暗、选择保持 ACK、双向 PLAY 翻页。
- 主界面和缩略图音谱隐藏；强制缓存有效且像素位于底线时，RGB 仍原样透传。
- 真实 mux/probe 阈值同拍竞争、低优先级/数据隔离；SD/MV/读端退出等待。

## 5. 上板复验顺序与判定

1. 烧录交付 bit 后保存新串口日志，确认 `VER=07030002`，使用 card_S6.img，DIP5=1。此次实现未自动烧录硬件。
2. 主界面 ENC1 SW、KEY02 分别直接播放；KEY11 返回后下方音谱消失。KEY7 连续操作至少 20 轮，核对 PLAY→主界面→缩略图→选歌，不出现黑屏卡死/焦点锁死。
3. KEY9 遍历 F0/F1/F2，F1 左右方向正确且约 0.27 秒，无渐暗；F0 保持快速切换，F2 才有淡入淡出。快速正转/反转旋钮后，封面与实际歌曲一致，不掉回旧 bank。
4. KEY12 遍历 E0/E1/E2，分别播放至音乐 EOF；E0 停在播放界面并可确认从头播，E1 重播本曲，E2 循环到下一曲（含最后→第一）。MV 比音频先结束时不提前改变音频结束策略。
5. PLAY 中拔卡，检查停止/静音、错误显示及退出旧事务；插回好卡，等待重扫/预载后 ERR00，再确认播放。重复 10 轮，同时观察歌词、音谱、MV 均能重新启动。
6. 主界面和缩略图中拔卡，考虑约 1 秒空闲探测及 250 毫秒读超时后应报错；缓存图片短暂存在不是失败。恢复后应可正常进入 PLAY，歌词不能单独空跑。
7. 空卡启动后插入好卡，等待下一次 15 秒挂载/3 秒冷却窗口和预载完成，再确认播放；不用全局复位。
8. card_B_broken.img 显示 34；在不重启 FPGA 情况下换 card_S6.img，等待自动重挂，确认清为 00 并能连续切歌/播放。若测试方式是在 PC 改写卡，安全卸载 PC 后再插回，不能让 FPGA 与 PC 同时写读卡。
9. 遥控上/下一曲各连续按 10 次，再与旋钮正反转交替；检查 DIP5=0 不响应、DIP5=1 恢复，音量/暂停仍正确。
10. 用目标卡及较慢卡验证四张全尺寸封面预载；播放/循环至少 30 分钟，记录 UR/BL/VF/OV 增量和可闻/可见异常。HDMI 实际显示、声音、插拔电气行为与长期稳定性须以此新固件板测为最终证据。
