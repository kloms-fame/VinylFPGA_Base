## 3. 关键路径族逐项核对（用户要求"核实而非预设"）

用户要点：核实"当前关键路径是否由 4 路 64-bit INDEX 音频元数据选择、size/cluster 有效性、cluster−2 与条件锁存共同构成"，并逐项指出门级证据。**结论：该判断只在 SynthPilot 诊断口径下成立；在正式 native 口径下，音频/封面族不在最差清单前列，最差是 BMP 像素族与 `max_cluster` 同源族。** 逐项证据如下。

### 3.1 4 路 64-bit INDEX 音频元数据选择 —— 有 RTL 证据，但门级证据分级

RTL 证据（`src/SD/fat32_media_loader.v:185-197`）：

```verilog
185: reg  [63:0] idx_audio_sel;
186: always @* begin
187:     case (song_sel)
188:         2'd0:    idx_audio_sel = idx_audio0;
...
192: endcase
194: wire [31:0] idx_aud_cluster = idx_audio_sel[31:0];
195: wire [31:0] idx_aud_bytes   = idx_audio_sel[63:32];
```

门级证据：

- **SynthPilot final（诊断口径）** 最差 Setup 为 `u_song_index_db/e_aud_by_reg[85] → audio_cluster_m2_d_reg[13]`，9.499ns，cell 28% / net 72%，7 级 LUT，最大扇出 33 —— 这是"4 路 64-bit 选择 + 后续 32 位比较"叠加后的宽网。
- **native final（签核口径）** 没有 `e_aud_by` 族进入前 6 违例；native 6 条违例是：`e_cov_by[13]→chk_ok`（−541ps）、BMP 像素族 `pixel_byte_cnt[0]→bmp_data[19].ce`（−377ps）、`max_cluster[26]→file_streamer` 4 条（−214/−214/−43/−19ps）。
- **隔离 area_prior + seed5（before，本阶段基线）** 最差是 **BMP 像素族** `pixel_byte_cnt_reg[12] → pixel_count_reg[24].ce`（−0.127ns，9.847ns，cell 27% / net 73%，7 级，fanout 36）；音频/封面族**不在前 20**。

**判定**：4 路 64-bit 选择确实在 RTL 中构成宽组合网（RTL + SynthPilot 路径直接证据），但**它不是 area_prior 映射下的绑定约束**；两套口径下"谁最差"不同，必须分别评价。

### 3.2 size/cluster 有效性（`idx_aud_valid`）—— RTL 直接证据

```verilog
196: wire        idx_aud_valid   = (idx_aud_bytes != 32'd0) &&
197:                               (idx_aud_cluster >= 32'd2);
```

扫描路径对应（`fat32_media_loader.v:315-317`）`audio_cluster_valid = scanner_audio_valid && (scanner_audio_cluster>=2) && (scanner_spc!=0)`。这两段有效性判断是候选 A 想搬走的对象；候选 A 把 `idx_aud_valid` 改为读取预计算窄标志 `idx_aud_valid = idx_aud_ok_sel`（1 位）。

### 3.3 cluster−2 与条件锁存 —— RTL + STA 直接证据

```verilog
365: audio_cluster_m2_d    <= idx_aud_valid ? (idx_aud_cluster - 32'd2) : 32'd0;
...
381: end else if (audio_meta_pending) begin
382:     audio_file_valid_reg    <= audio_file_valid_calc;
```

RTL 注释（`:322-327`）已记录该链的一次历史修正："32bit 减法 → 桶形移位 → 32bit 加法 → 选择，TD final 报 8 级逻辑 / 10.244ns，setup WNS −0.524ns"，随后拆成两级寄存器（`scanner_done` 当拍锁存 `cluster-2`、移位量、基址、长度，下一拍做移位+加法）。

**判定**：`cluster−2` 与条件锁存确实存在且已做过一次流水拆分；是否是绑定约束取决于映射口径。

### 3.4 结论

- "关键路径由 4 路 64-bit 选择 + size/cluster 有效性 + cluster−2 与条件锁存共同构成" —— **在 SynthPilot 诊断口径下有直接 STA 证据；在 native area_prior 口径下不成立**（音频族不在前 20）。
- 这条分歧本身是候选 A 失败的根因之一：候选 A 针对的正是"诊断口径的最差族"，而正式口径的绑定约束在别处。

## 4. `u_volume_scanner.sector_buffer` 复核（512×8 vs 125 cell）

RTL 声明（`src/SD/fat32_volume_scanner.v:70`）：

```verilog
70: reg [7:0]  sector_buffer [0:511];
```

TD 综合后只返回 **125 个 `sector_buffer_reg*` cell**。**这不是"只剩 125 bit"，也不是"省下 4096 FF"。** 正确解读：

- `sector_buffer` 主要作为**扇区字节的临时解析缓冲**，逐字节/逐字段被消费（FAT 表项、目录项、boot 布局）。
- 综合器对未同时活跃/未形成可复用存储阵列的部分做了**裁剪**，并把大量字节级解复用/比较吸收进组合逻辑（对应 `u_volume_scanner` 的 `le=1354 / lut=1119 / seq=1084`，SynthPilot 层级表）。
- 因此**不能把声明位数当作实际资源**；真正影响面积的是"被综合保留的 `seq`（ff）+ 相关组合"。

> 该结论同时纠正旧报告的可能误读：任何"省 512×8=4K FF"的描述都是**方向性错误**。

## 5. 层级 cell count 复核（区分 cell count 与 LUT/Slice/PLB 面积）

用户要求重点复核 `sd_card_bmp_m0(2590)`、`u_expansion_integration(1120)`、HDMI wrapper(997)、`u_playback_page(594)`、`u_song_index_db(563)`。**关键结论：这些是"cell count"口径，不等于 LUT/Slice/PLB 面积，两者不能互换。** 同模块在不同报告口径下差异巨大：

| `u_expansion_integration` | 1120 | 2206 | 1673 | 2526 | 2605 |
| `u_hdmi_1_4b_transmitter_core_wrapper` | 997 | 1876 | 1530 | 2704 | 2829 |
| `u_playback_page` | 594 | 1164 | 986 | — | — |

要点：

- `cell count` 只统计**实例个数**（含大量 1-bit cell），与 `LUT/Slice/PLB`（片区级物理资源）是**两种口径**。

## 7. SDC 与 PLL local feedback 边界检查

- **无 IO delay**：`constraints/timing.sdc` 未对 SD MISO / HDMI 前向时钟与数据等 IO 设置 `set_input_delay`/`set_output_delay`。这会让这些路径**默认按最悲观（或未约束）处理**，但**不得因此臆造板级延迟**：补齐 IO delay 需要真实的板级走线与收发时序数据（见第 13 章缺失清单）。
- **PLL local feedback critical warning**：`check_timing` 对两个 PLL 的检查项均为 0；真正的 CRITICAL-WARNING 是 native `PHY-5079`：1 条时钟网 `ext_mem_clk_sft → U3/u2_ram/SDRAM_CLK`（fanout=1）使用 local routing（硬 IP 侧预期行为，需硬 IP 确认）。
- **禁止做法**：不得用宽泛 `false_path`/`multicycle` 把真实路径藏起来以"改善指标"；本轮未新增任何例外（候选 A 改动只动 RTL，未动 SDC）。

### 8.5 失败机制分析（关键）

1. **after 最差路径是候选 A 自己新增的链**：
   - 起点：`sd_card_bmp_m0/fat32_media_loader_m0/u_volume_scanner/max_cluster_reg[7]`
   - 终点：`sd_card_bmp_m0/fat32_media_loader_m0/u_song_index_db/cov_ok_reg[1].a[1]`
   - Slack −0.519ns，Data Path 10.239ns（**cell 3.260ns / 31%，net 6.979ns / 69%**），7 级（LUT5×5 / LUT4×1 / LUT3×1），Max Fanout 11。
   - 含义：候选 A 把每曲 32 位比较从"宽选择之后"搬到了"条目解析末尾"，但 `max_cluster` 是**同步更新、高扇出的 32 位寄存器**，比较器被追加在其后，反而形成新长链。
2. **面积方向与旧判断相反**：新增 8 个 FF（4×`aud_ok` + 4×`cov_ok`）与 8 组 32 位比较搬运 → gate LUT +224、final LUT +234、Slice +139。
3. **gate 表面变好具有误导性**：`area_prior` 映射下 gate WNS −34ps→+74ps，但 route final 从 −127ps 崩到 −519ps。这正是"不得用 gate/place 数字替代 route 签核"的直接反例。
4. **after 的 18 个违例端点**绝大多数落在 `sd_card_clk` 域，且多为候选 A 相关族（`cov_ok`）+ 原有 BMP 像素族（`pixel_end_reg[9]`/`bmp_error`/`pixel_byte_cnt`）+ `max_cluster` 同源族（`add3_syn_194 → file_streamer`）。
5. **before 与 after 的 before 基线与正式 native 也非同一网表**：隔离 before（area_prior）最差是 BMP 族，工作区 native（无 seed5）最差含 `e_cov_by→chk_ok`。三者口径需分别标注。

## 10. 唯一推荐的第一项实现（本轮重选）

**推荐：候选 D（`u_file_streamer` / `max_cluster` 相关比较预计算或分拍）。** 理由：

1. **它是唯一能同时覆盖 native 最重一类违例的单项**：native 6 条 Setup 违例中 4 条同源于 `max_cluster[26] → file_streamer`（−214/−214/−43/−19ps），一次改动可同时改善。
2. **它正面命中候选 A 失败暴露的高扇出根因**：`max_cluster` 是同步更新、高扇出的 32 位寄存器，候选 A 与 native 违例都围绕它；把比较预计算/分拍是"搬到更宽松的位置"而非"在它后面再串比较器"。
3. **风险与回退性可控**：改动局限在 `fat32_file_streamer`（必要时配合 `fat32_volume_scanner` 的 `max_cluster` 提交时机），语义面小、纯增量、无接口变化。
4. **诚实的前提**：本轮实测已证明"单项远不足以让 native Setup≥0"。要达成 **route Setup/Hold WNS≥0**，现实路径是 **D + E（BMP 像素族）组合**，且**必须逐项独立综合 + route 对照**（不合并综合）。

**为什么不是 B/C（对比）**：

- B/C 都针对**音频选择族**，而该族在正式 native 口径下**不在前 6 违例**（候选 A 已实测该方向无物理收益）；B 的 FF 增量最大且语义窗口最多，C 的寄存器成本最高且只是搬运组合逻辑。**先做 D，再看 E，B/C 暂缓。**

**若数据不足的判断**：候选 D/E 都**缺"候选独立综合 + route"证据**（第 13 章），因此本报告只给方向与排序，不给精确节省数。
