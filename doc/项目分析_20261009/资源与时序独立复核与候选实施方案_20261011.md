### 2.4 cell count 与 LUT/Slice/PLB 面积是两种口径

现有报告使用的 `sd_card_bmp_m0(2590)`、`u_expansion_integration(1120)`、HDMI wrapper(997)、`u_playback_page(594)`、`u_song_index_db(563)` 等数字来自 `get_cells` 按实例名筛选的**单元计数**。它有三个陷阱：

1. 父实例筛选包含其下级单元，父子项不能相加；
2. 单元数不含每个单元的面积权重（LUT 与 FF、RAM、DSP 不同）；
3. 综合会重排/合并/裁剪单元，同一 RTL 在不同流程下计数不同。

例如 `u_song_index_db` 的 cell 计数为 563，而面积口径为 le 1031 / lut 872 / seq 877；`sd_card_bmp_m0` 的 cell 计数为 2590，而面积口径为 le 4818（含 fat32 子系统）。**优化排序应以面积口径为主、单元计数为辅。**

### 2.5 拥塞与逻辑级数

- SynthPilot place：Top 1% tile util 60 / 平均 62.03%，超 100% tile 数 0；native place：59 / 60.93%，超 100% tile 数 0。两者都不存在硬拥塞溢出。
- native route 日志显示最拥塞 1% tile 平均布线利用率 61.66%。
- SynthPilot gate 逻辑级数分布（关键行）：`sd_card_clk`（100MHz/10ns）在 6 级有 525 个、7 级 849 个、8 级 122 个端点；`video_clk`（25MHz/40ns）长尾可到 20+ 级但周期宽松；`ext_mem_clk`（125MHz/8ns）最深层级为 6 级（10 个端点）。这解释了为什么 100MHz 的 `sd_card_clk` 是最容易出负裕量的域。

第 1 条路径的门级序列显示：`e_cov_by[3][13]` 单 net 就占 **2.981ns**，随后经过 `chk_ok_reg_syn_133/135/147/167/211/223` 六级 LUT 组合，路径末段甚至借用 `u_volume_scanner/resource2_size_reg[14]` 的输入引脚与 `e_cov_cl_reg[30]`、`mux117_syn_607`、`mux4_syn_29` 完成最终判决，最终写 `song_index_db.v(71)` 的 `chk_ok`。这说明封面校验链并非"干净的两级比较"，而是与扫描器资源字段、多路 mux 交织的长组合链，属于 native 下最值得优先处理的路径。

第 2 条路径的门级序列是 `pixel_byte_cnt[0] → file_len/pixel_end/bmp_error → expected_pixel_count_q → bmp_data_wr_en → bmp_data[19].ce`，两处 net 分别达到 **0.830ns/fo=36** 与 **1.424ns/fo=34**，属于 BMP 像素写入使能的组合链。

第 3–6 条路径的 4 个终点共享同一起点 `max_cluster[26]` 与同一段组合逻辑（`mux68_syn_2475/2479/2482/2508/3[30]`，fanout 34，net 1.678ns），是**单一起点、多终点**的扇出型违例：只要该段被缩短一拍，4 条违例会同时改善。

### 3.4 Hold 分析

| 口径 | WNS | TNS | 违例端点 | 说明 |
|---|---|---|---|---|
| SynthPilot route 阶段 QoR（`prj/route.qor`） | −4ps | −8ps | 2 | 位于 HDMI 音频 packet FIFO 的嵌入式 RAM 地址端（`addra[11]`/`addrb[6]`），路径极短（约 0.341ns），属物理/布线层面的极短路径 |
| SynthPilot final（`prj/final_timing.rpt`） | **+0.127ns** | 0 | 0 | `update_timing -mode final` 之后 |
| native route QoR（`phy_1/route.qor`） | +11ps | 0 | 0 | fix_hold 之后 |
| native final（`phy_1/final_timing.rpt`） | **+11ps**（clock summary 最差 +0.103ns） | 0 | 0 | 签核口径 |

**结论**：现有报告"Hold 未过硬门槛"的表述只对 SynthPilot **route 阶段**成立，对两套 final 均不成立。但不能据此删除 Hold 风险记录，因为 route 阶段曾出现 −4ps/2 端点，说明该结构对物理实现敏感；后续任何实现变更都必须复核这两个端点是否再次转负。

### 3.5 native 流程日志里的其他风险

1. `PHY-5079 CRITICAL-WARNING`：**1 条时钟网络使用 local routing 资源** —— `ClockName=ext_mem_clk_sft`、`Driver=AL_PHY_PLL`、`Clock/Fanout=0/1`、`NetName=U3/u2_ram/SDRAM_CLK`、`Marked=true`。这是 SDRAM 硬 IP 的采样移位时钟，fanout=1，属硬 IP 内部窗口；`timing.sdc` 已用 `set_false_path` 处理 `ext_mem_clk` 与 `ext_mem_clk_sft` 的互跨。风险点是时钟树补偿不可预测，需由硬 IP/板级验证覆盖。
2. `PHY-7002 CRITICAL-WARNING`（出现两次）：`Instance U3/sdram location (12,12)` 与 `(164,288) is not honored`，ECO placement 起点位置不合法，将被移动。当前 `constraints/pin.adc` 未见 SDRAM 位置约束，说明该位置来自 IP/器件内部约束；需要与硬 IP 提供方确认允许位置范围，并在后续 native 签核中复查该告警是否消失。
3. 时钟树合并：日志显示 `sd_card_clk` 与 `sys_pll_m0/clk0_buf` 合并、`u_sync_fade_gain/pix_clk` 与 `video_pll_m0/clk0_buf` 合并，与 SDC 的 `rename_clock` 命名一致。
4. native 日志的 Utilization Statistics **不输出 `#plb`/`#mslice`/`#lslice`**，因此 native 侧的 PLB 数值当前缺失（见第 8 章取证清单）。

## 4. 关键结构专项复核

### 4.1 `u_volume_scanner` 的 `sector_buffer`

声明（`src/SD/fat32_volume_scanner.v:70`）：`reg [7:0] sector_buffer [0:511]`，字面 512×8 = 4096 bit。

声明之外的证据：

- 读取方式：`src/SD/fat32_volume_scanner.v:100-112` 的 `le16/le32` 从 buffer 动态取字节（引导扇区字段按小端拼装），因此 buffer 的读侧是组合、按索引解复用；
- 使用位置：`src/SD/fat32_volume_scanner.v:320-366` 校验启动扇区签名、分区类型、BPB 字段并解析 FAT 布局；`:377-381` 计算 `max_cluster` 与根簇 LBA；
- 综合结果：11:41 副本 review 会话执行 `get_cells -verbose *sector_buffer_reg*`，返回 **125 个 cell**（名字保留原 4096 位位号，最大到 `sector_buffer_reg[4095]_syn_4`）；
- 时序角色：SynthPilot 第 2/5 条路径起点均为 `sector_buffer_reg[3793]`，扇出 89，终点为 `root_cluster_reg[3].ce` / `fat_start_lba_reg[0].ce`。

分析结论：

1. 125 是 `get_cells` 的单元匹配数，**不是**"sector_buffer 只剩 125 个 bit"的完整描述。综合会对未被观察的位做常量化/裁剪，也会把组合读解复用吸收进 LUT，因此实际资源远小于声明的 4096 bit，但剩余结构不能用 125 线性换算。
2. 该结构仍值得优化，但优化对象不是"删数组"，而是**引导扇区字段的装载使能与解复用网络**（高扇出 89 的位被多个字段比较复用）。
3. 任何"把 512×8 改成字段寄存器可省 4096 个 FF"的估算都是错的，必须用综合前后实测差值评估。

### 4.2 `u_song_index_db` 的元数据组织

- 存储：`song_index_db.v:84-91` 保留 4 组数组 —— `e_cov_cl[4]`、`e_cov_by[4]`、`e_aud_cl[4]`、`e_aud_by[4]`（每组 32 位 × 4 首 = 128 FF，合计约 512 FF），另有 `e_has_cover[3:0]`、`e_has_audio[3:0]`。
- 输出：`song_index_db.v:147-154` 每首输出 `valid ? {bytes, cluster} : 0`，即"有效性门控 + 64 位拼接"，4 首共 8 条 64 位输出（封面 4 + 音频 4），全部扇出到 `fat32_media_loader` 的选择树。
- 校验：`song_index_db.v:157-161` 的 `cover_entry_bad` 每拍比较一首：`!e_has_cover[chk_idx] || cluster<2 || cluster>max_cluster || bytes==0`。
- 头部/CRC：`song_index_db.v:61-62,95-105`、`:164-175` 为 64 字节头 + 64 字节/条目 + CRC-32 逐字节状态机。

资源含义：4 组 32 位数组是必要状态，真正的组合代价在"输出选择树（4×64）"与"逐曲校验比较"。候选 A 的落点就在这两处。

### 4.3 `u_file_streamer` 的簇范围判定

`src/SD/fat32_file_streamer.v:178-197` 使用 `first_cluster > max_cluster` 等范围判断参与 `cluster_delta`/`current_cluster` 的使能；native 侧 4 条违例同源于 `u_volume_scanner/max_cluster_reg[26]`，说明该判定与扫描器的 `max_cluster` 寄存器形成跨模块长组合链（net 75%）。

### 4.4 字库、开机 Logo、D13、F2 的真实资源利弊

| 对象 | 实测/事实 | 判断 |

| 歌词字库 | `song_font_rom` 为 `row_mem [0:4095]` 16-bit ≈ 64 Kibit；`u_shared_song_font` 实测 8 BRAM；`lrc_font_rom` 1024×16 ≈ 16 Kibit | 已是 BRAM 形态；BRAM 有余量（47/64）但 PLB/Slice 无余量 |

### 4.5 SDC 与约束健康度

`prj/top_route.check_timing` 关键结果：

- `1. checking no clock` = 0；`2. checking clock definition` = 0；`3. 0 leaf clock pins driven by multiple clocks`；`4. 0 clocks created on internal clock network`；`0 local clocks`；`0 generated clocks not connected to masters`；
- `5. checking PLL/buffer clock constraints` = 2（即两个 PLL 各一项检查），逐项均为 0：`sys_pll_m0/pll_inst` 与 `video_pll_m0/pll_inst` 都是"0 个无时钟约束引脚、0 个频率失配"；

`constraints/timing.sdc` 的现状与边界：

- 主时钟 `create_clock -name clk -period 20`，PLL 输出经 `derive_clocks` + 5 条 `rename_clock` 命名（`sd_card_clk`/`ext_mem_clk`/`ext_mem_clk_sft`/`video_clk`/`hdmi_5x_clk`）；

- 第 7 节明确写明：SD MISO 与 HDMI 前向时钟/数据缺少卡/屏建立保持与板级走线数据，**因此没有输入/输出延迟，且不臆造 0 或标称值**；机械 UI 输入为异步并已在 RTL 同步；

## 5. 候选优化方案

### 5.1 共同设计原则

1. 只改一类逻辑，保留 INDEX v1/v2、CRC 拒绝、缺字段、`size==0`、`cluster<2`、`cluster>max_cluster`、无索引回退等语义；
2. 不新增裸跨时钟域信号，沿用现有帧/脉冲提交方式；
3. 不以加 `false_path`/`multicycle` 或降低约束的方式"改善"指标；
4. 每项独立综合 + route 对照，记录 ΔLUT/ΔSlice/ΔPLB/ΔBRAM/ΔDSP 与 WNS/TNS/违例端点；
5. 无综合结果前不给精确节省数，只给方向。

### 5.2 候选 A：逐曲预计算窄有效/范围标志（同时覆盖音频与封面）

设计意图（不是已实施代码）：

- 在 `song_index_db` 的条目解析/输出阶段，为每首曲子形成窄标志：
  - `aud_ok[k] = (e_aud_by[k]!=0) && (e_aud_cl[k]>=2)`；
  - `cov_ok[k] = e_has_cover[k] && (e_cov_cl[k]>=2) && (e_cov_cl[k]<=max_cluster) && (e_cov_by[k]!=0)`；
  其中 `k=0..3`，共 8 个位（或按现有编码压缩为更少位）。
- `fat32_media_loader` 侧改用"选择 64 位数据 + 选择 1 位有效标志"的两棵窄树，而不是在 64 位选择结果之后再串 32 位非零/范围比较；
- `song_index_db` 侧把 `chk_ok` 的逐曲校验改为读取 `cov_ok[chk_idx]`（或把 `cov_ok` 与 `chk_ok` 合并成一次窄写），缩短 `e_cov_by → chk_ok` 的 8 级组合链。

预期收益方向：两条最差路径（SynthPilot 音频选择、native 封面校验）的组合深度可能各减少 1–2 级；LUT 方向中性偏减（比较器没有消失，但可与窄树合并/提前），FF 增量为个位数位，Slice/PLB 方向需实测。

寄存器成本：约 8 个 FF（若只做位标志），或按每曲 2 位≈8 位；启动延迟不变；边界语义可完全保持（标志与字段同拍更新）。

风险：低。唯一需要注意的是标志必须与 4 组字段同拍更新（含 CRC 通过后的 `valid` 置位拍），否则会出现"字段有效但标志未更新"的一拍窗口。

### 5.3 候选 B：所选 cluster/size 分拍锁存

设计意图：在 4 路宽 mux 与 `cluster-2`/有效性判断之间再插一级寄存器（在现有两级流水之上再加一拍）。

预期收益方向：对 net 占比 72% 的路径有打断潜力，可能比 A 更直接。

寄存器成本：约 32 位（cluster）+ 32 位（size）+ 控制位 ≈ 70 FF 量级，Slice/PLB 方向可能上升；启动延迟 +1 拍（配合现有 `audio_meta_pending` 需要再扩展一级握手）。

风险：中。必须处理"切歌后旧曲元数据仍在新一级寄存器中"的窗口，快速连续切歌、播放启动首帧都可能受影响。

### 5.4 候选 C：INDEX 解析期预计算有效性与归一化 cluster

设计意图：在 `song_index_db` 逐字节解析条目时就计算并保存每曲的 `cluster-2` 与有效位，使播放端只做窄选择。

预期收益方向：解析期状态机速率低（每字节多拍），时序余量大，理论上可以把减法/比较彻底搬离 100MHz 高负载路径，收益上限最高。

寄存器成本：4 曲 × 32 位归一化 cluster + 标志 ≈ 140 FF 量级，是三候选中最高；且只是把 LUT 从负载路径搬到解析逻辑，是否净减需实测。

风险：中高。解析期必须正确处理 CRC 未通过、条目缺失、v1/v2 差异与回退，语义面最大。

### 5.5 候选 D：`u_file_streamer` 簇范围判定预计算/分拍（native 必需）

设计意图：把 `max_cluster` 与 `first_cluster/current_cluster` 的比较结果在扫描完成时预计算/寄存，或在 `fat32_file_streamer` 内部插入一级流水，打断 `max_cluster[26] → cluster_delta[*].ce/current_cluster[*].ce` 的 4 条同源违例。

预期收益方向：一次改动可同时改善 native 4 条违例（−0.214/−0.214/−0.043/−0.019），是达到 native Setup≥0 的必要项之一。

寄存器成本：与实现方式相关（预计算标志约 4–8 FF；分拍则约 30+ FF）。

风险：中。涉及 FAT 链推进正确性，需要碎片链、跨簇边界、末簇收敛的定向仿真。

### 5.6 候选排序表

| 排序 | 候选 | 资源方向 | 时序路径 | 风险 | 需要的仿真/人工验收 | 可回退性 | 现有综合/route 证据 |
|---|---|---|---|---|---|---|---|
| 1 | A 窄有效/范围标志（音频+封面） | LUT 中性偏减、FF +个位数、Slice/PLB 中性（待实测） | SynthPilot 音频选择族 + native 封面校验链 | 低 | INDEX v1/v2 仿真；切歌/进出播放/自动轮播/封面回退人工验收 | 高（纯增量、无接口变化） | 无候选级综合；基于两套基线 |
| 2 | D 簇范围判定预计算/分拍 | 中性到略增 | native 4 条同源违例 | 中 | 碎片 FAT 链、跨簇边界、末簇收敛仿真 | 中 | native final 违例清单 |
| 3 | B 所选 cluster/size 分拍锁存 | FF +，Slice/PLB 可能上升 | SynthPilot 音频路径（net 72%） | 中 | 快速连续切歌、播放启动首帧 | 中 | 无 |
| 4 | C 解析期预计算归一化 cluster | FF 最高 | 收益上限最高 | 中高 | v1/v2、CRC、缺字段、回退语义 | 中低 | 无 |

### 5.7 为什么第一项选 A 而不是 B/C

1. A 同时命中两套 flow 的最差路径族，而 B/C 只针对音频选择；native 的第 1 条违例（−0.541ns）必须靠"封面窄标志"才能覆盖。
2. A 不增加流水拍，不引入新的握手与旧数据窗口，风险与回退成本最低。
3. B 的资源增量最大且语义窗口最多；C 的寄存器成本最高且只是搬运组合逻辑。
4. A 不能承诺"净减 LUT"——这是必须实测的结论，本文不写具体节省数。

**重要限定**：A 单独不足以让 native final Setup≥0。native 6 条违例中 4 条属于候选 D 的路径族，1 条属 BMP 像素使能族（`pixel_byte_cnt → bmp_data.ce`）。因此推荐路径是"第一项 A，第二项 D"，两者分别独立对照，不合并综合。

## 6. 推荐实施方案（候选 A 落地）

### 6.1 目标与范围

- 目标：缩短 `e_aud_by → audio_cluster_m2_d` 与 `e_cov_by → chk_ok` 两条路径，同时保持全部功能语义；
- 范围：`src/SD/song_index_db.v`、`src/SD/fat32_media_loader.v`（必要时 `src/SD/song_index_defs.vh` / `src/include/*`），不触碰 HDMI IP、SDRAM 硬 IP、SDC/ADC；
- 不做：D13、F2、F3、宽泛例外、有损图像压缩。

### 6.2 实施步骤（含定位点）

1. 固化输入哈希：记录 HEAD、`git status --porcelain`、`prj/VinylFPGA.al`、`constraints/timing.sdc`、`constraints/pin.adc`、涉及 RTL 的 SHA-256。

## 9. 参考报告纠错清单

1. 《资源与时序现状及后续优化分析_20261011.md》第 17 行称 `prj/VinylFPGA_Runs/phy_1` 是 2026-10-10 22:10 的"旧 run" —— **已过期**：当前 native run 为 10-11 11:13:40–11:18:00，含比特流。
