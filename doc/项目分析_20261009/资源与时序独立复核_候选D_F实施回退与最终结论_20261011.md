### 0.2 关键结论（十二条）

1. **本轮没有新提交。** HEAD 仍是 `263425f`，本轮对 `src/SD/fat32_file_streamer.v`、`src/SD/fat32_media_loader.v` 的试验性修改已 100% 回退（SHA256 与试验前基线逐字节一致）。
2. **候选 D 功能等价但资源方向恶化，按规则回退。** native route final：Setup +0.132ns（E 为 +0.116ns，看似略好），但 Hold 从 +0.030ns 退到 **+0.024ns**，Slice 8588 → **8615（+27）**、LUT 15683 → **15934（+251）**、PLB 2422 → **2423（+1）**、MSlice/LSlice 各 +8/+19、布线 +34k。用户要求"尽可能腾出 PLB/Slice"且"资源或时序变差立即回退"，D 与目标方向相反。
3. **候选 D 的时序收益不成立为"净收益"。** 它把最差路径从 `u_brightness_contrast_steps/... → u_mv_metadata_cdc/...`（E 的族 A）换成了 `u_song_index_db/byte_idx_reg[3] → e_aud_by_reg[5].ce`（同域内另一条，5 级、net 84%），本质是"路径搬家"，没有减少该域的总违例压力。
4. **候选 F native route 直接失败。** `PHY-8023 ERROR: Location (x5y31_w2beg4), nets: .../u_song_index_db/mux129_syn_2[0] .../I_rst_dup_19_holdbuf` 之后 `RUN-8102 ERROR: Incremental route failed.`，route 未收敛，没有 `final.qor`。
5. **候选 F 在 place 阶段曾"看起来最好"，这是重要的口径警示。** F 的 place QoR 是三项里最漂亮的（Setup +2856ps、FMAX 194.4MHz、Slice 8461 最低），但 route 失败。**place/gate 数字不能替代 route**，用户第 4 条的纪律在本轮被实测证明是必要的。
6. **候选 F 的 gate 阶段就已经显著变差。** Setup WNS −492ps / TNS −3156 / **41 个违例端点**（E 为 −369ps / −1121 / 9 个，D 为 −689ps / −981 / 14 个）。说明 F 改动把 `pixel_count` 之外的组合深度加大了。
7. **用户给出的最差路径是"诊断口径、E 之前"的。** `u_song_index_db/e_aud_by_reg[85] → audio_cluster_m2_d_reg[13]`，9.499ns、cell 28% / net 72%、7 级、扇出 33，逐字命中 `vinylfpga_sp_diag_before_v3` 的 `final_timing.rpt`（Slack +0.221ns）。它在 **native before 里不存在**（native before 的两条违例同源于 `pixel_byte_cnt_reg[12]`）。引用时必须标口径。
8. **E 之后的 native 最差路径是族 A（元数据 → CDC 影子），不是 audio_cluster_m2_d 族。** `u_brightness_contrast_steps/blue_adj[5] → u_mv_metadata_cdc/src_data_latched_reg[4].b[0]`，+0.116ns、Data Path 9.604ns、7 级、扇出 50；其 net 链可定位到 `u_song_index_db`（`song_mv0_b_n1`）、`cdc_bundle_latest.v(12/18)`。起点实例名 `blue_adj[5]` 与 RTL 时钟不符，属工具重命名产物，**不能据此认定 RTL 功能起点**。
9. **高扇出复核（SynthPilot MCP，route 阶段库）显示：sd_card 域最宽的网已被工具复制。** 全区最大的网是复位族（`u_exp_reset/s2` 753、`u_video_reset/s2` 668、`u_media_video_reset/s2` 460…）；sd_card 域内最大的是 `u_song_index_db/chk_ok_reg_syn_dup_130`(239)、`media_status[22]_dup_1`(225)、`u_volume_scanner/sectors_per_cluster_shift_b[1]_syn_dup_7`(153)。**关键路径上那个"扇出 50"并不是全设计最宽的网**，说明该域的瓶颈是"长互连 + 中高扇出"的组合，而不是单一宽网。
10. **`sector_buffer` 的 512×8 声明不能当资源算。** 声明 = 4096 bit；但读侧**只出现常量偏移**（字面量 0/13/16/450/510/511，加上 `le16/le32` 的固定偏移 11/14/17/22/32/36/44/454），没有变量索引读。TD 只保留 **125 个位级 cell**。按声明位数估资源会严重高估。
11. **cell count 与面积是两种口径。** 用户引用的 `sd_card_bmp_m0(2590)`、`u_expansion_integration(1120)`、HDMI(997)、`u_playback_page(594)`、`u_song_index_db(563)` 是**实例个数**；决定"放不放得下"的是 Slice/MSlice/LSlice/PLB 与 LUT/reg。
12. **可签核基线保持不变：候选 E 的 native route final。** Setup WNS +0.116ns / 0 违例端点，Hold WNS +0.030ns / 0 违例端点，资源不超限。在拿到"更小面积 + 不低于 E 的时序"证据之前，不应再叠加新的 RTL 候选。

| 口径 | 工具与流程 | 用途 | 代表数字（现基线） |

## 3. 关键路径族：逐项门级证据复核

用户要求核实"当前关键路径是否由 4 路 64-bit INDEX 音频元数据选择、size/cluster 有效性、cluster−2 与条件锁存共同构成"，并逐项给出 STA 上的门级证据。结论分三段：

### 3.1 用户给出的路径（诊断口径、E 之前，已逐字核实）

来源：`vinylfpga_sp_diag_before_v3\prj\final_timing.rpt`（SynthPilot 默认诊断口径，E 之前）。

```
Slack            : 0.221ns
Begin Point      : sd_card_bmp_m0/fat32_media_loader_m0/u_song_index_db/e_aud_by_reg[85]_syn_4.clk
End Point        : sd_card_bmp_m0/fat32_media_loader_m0/audio_cluster_m2_d_reg[13]_syn_4.d[0]
Check Type       : setup（slow，10.000ns）
Data Path Delay  : 9.499ns (cell 2.683ns (28%), net 6.816ns (72%))
Logic Level      : 7 ( LUT5=3  LUT4=2  LUT3=2 )
Max Fanout       : 33
```

用户给出的"9.499ns / cell 28% / net 72% / 7 级 LUT / 最大扇出 33"**逐项命中**。但请注意：**这条路径在 native before 里不存在**。native before（E 之前）的两条 sd_card_clk setup 违例是：

```
#1  -0.127ns  pixel_byte_cnt_reg[12] → pixel_count_reg[24].ce      9.847ns (27%/73%)，7 级，扇出 36
#2  -0.027ns  pixel_byte_cnt_reg[12] → bmp_data_reg[18].ce         9.747ns (28%/72%)，7 级
```

两条**同源**（都出自 `pixel_byte_cnt_reg[12]`）。这正是候选 E 的靶点，也是 E 能让 native 违例 2 → 0 的原因。

### 3.2 "4 路 64-bit INDEX 音频元数据选择" —— 有 RTL 直接证据

`src/SD/song_index_db.v`（当前文件，属用户改动，按现状分析）：

```verilog
// 每首歌 {bytes[63:32], first_cluster[31:0]}
output wire [63:0] song_audio0, song_audio1, song_audio2, song_audio3,
output wire [63:0] song_mv0, song_mv1, song_mv2, song_mv3

assign song_mv0=(valid && hdr_version==2 && e_has_mv[0]) ? e_mv[0] : 64'd0;
assign song_mv1=(valid && hdr_version==2 && e_has_mv[1]) ? e_mv[1] : 64'd0;
assign song_mv2=(valid && hdr_version==2 && e_has_mv[2]) ? e_mv[2] : 64'd0;
assign song_mv3=(valid && hdr_version==2 && e_has_mv[3]) ? e_mv[3] : 64'd0;

assign song_audio0 = valid ? {e_aud_by[0], e_aud_cl[0]} : 64'd0;   // 同理 1/2/3
```

**证据等级：直接（RTL）。** 4 路 × 64-bit 的元数据（音频 cluster/bytes、封面、MV）确实存在，且每路都带 `valid` / `hdr_version` / `e_has_*` 条件门控。这就构成"广选择 + 条件化"的组合结构，是族结构的来源。

对应到 STA net 名：E native final 最差路径里出现 `...u_song_index_db/song_mv0_b_n1`（扇出 14）、并汇入 `cdc_bundle_latest.v(12)`、落在 `src_data_latched_reg[4]`。**net 名与 RTL 的对应关系成立**。

### 3.3 "size/cluster 有效性" —— 有 RTL 直接证据

同一文件的校验段（P_CHK 每拍比一首）：

```verilog
wire cover_entry_bad =
    !e_has_cover[chk_idx] ||
    (e_cov_cl[chk_idx] < 32'd2) ||
    (e_cov_cl[chk_idx] > max_cluster) ||
    (e_cov_by[chk_idx] == 32'd0);
```

`fat32_media_loader.v` 里音频的等价判定：

```verilog
wire audio_file_valid_calc = audio_cluster_valid_d && (audio_size_d != 32'd0);
```

**证据等级：直接（RTL）。** "cluster 落在 [2, max_cluster]、size 非 0"这类有效性/范围比较确实存在，并且它是宽比较（32-bit vs `max_cluster`）。

对应 STA：E native final 第 4 名路径的终点就是 `u_volume_scanner/resource1_cluster_reg[18]_syn_4.ce`，中间 net 为 `resource_valid_reg[3]_syn_6`（`fat32_volume_scanner.v(148)`），cell 15% / net 85%、扇出 8 —— 这是"资源有效性 → 条件写使能"的另一种体现（volume_scanner 侧）。

另有一条独立佐证：高扇出复核里 `u_song_index_db/chk_ok_reg_syn_dup_130` 扇出 **239**，正是 `e_cov_cl/chk_ok` 校验树的下游宽网（工具已复制 130 次）。**"校验结果宽网"是本域真实的扇出热点。**

### 3.4 "cluster−2 与条件锁存" —— 有 RTL 直接证据

`src/SD/fat32_media_loader.v`（当前文件，含第十二讲时序修正注释）：

```verilog
// 第十二讲时序修正：audio_start_lba = data_start + ((cluster-2)<<shift)
// 原本是一条组合链（32bit 减法 → 桶形移位 → 32bit 加法 → 选择，TD final
// 报 8 级逻辑 / 10.244ns，在 sd_card_clk 100MHz 下 setup WNS -0.524ns）。
// 这里拆成两级寄存器：scanner_done 当拍只锁存 cluster-2、移位量、基址和长度，
// 下一拍再做移位+加法并写入结果寄存器。
reg  [31:0] audio_cluster_m2_d;
reg  [31:0] audio_size_d;
reg         audio_cluster_valid_d;

audio_cluster_m2_d    <= idx_aud_valid ? (idx_aud_cluster - 32'd2) : 32'd0;   // 条件锁存
audio_cluster_valid_d <= idx_aud_valid;
```

**证据等级：直接（RTL）。** "条件锁存 + 下一拍做移位/加法 + 用 `audio_cluster_valid_d` 统一把关"的结构确实存在，`cluster−2` 也确实在这一级被算出来。

对应 STA：用户给出的那条诊断路径的终点正是 `audio_cluster_m2_d_reg[13]`，与 RTL 一一对应。

### 3.5 该族的门级解释（把三段串起来）

把 3.1～3.4 合起来看，用户给出的这条路径的门级构成可以这样读（诊断口径 net 逐级）：

```
e_aud_by_reg[85]（某一路 64-bit 元数据的字节数字段，路由到选择树）
   → 多级 LUT（LUT5/LUT4/LUT3 共 2 级在起点侧）
   → 4 路选择 + valid 条件门控（组合）
   → 扇出 33 的中间网
   → audio_cluster_m2_d 的 D 端（条件锁存）
```

- **cell 只占 28%、net 占 72%**：说明这条 9.499ns 里 **6.8ns 是互连**，逻辑只有 2.7ns。这是判断"该不该动 RTL"的最关键数字 —— 组合逻辑有真实可减空间，但空间上限受互连压制。
- **7 级、扇出 33**：属于"中高深度 + 中高扇出"，不是极端宽网（对比全区最大网 753 是复位）。

## 8. `u_volume_scanner.sector_buffer` 复核（512×8 vs 125 cell）

声明（`src/SD/fat32_volume_scanner.v:70`）：

```verilog
reg [7:0] sector_buffer [0:511];    // 512 × 8 = 4096 bit
```

写侧：`sector_buffer[sector_byte_index] <= sector_byte;`（变量索引，0..511）。

读侧（本轮逐行核对，**全部是常量偏移**）：

```
字面量索引      : 0, 13, 16, 450, 510, 511
le16/le32 常量  : le16(11)=11,12 ; le16(14)=14,15 ; le16(17)=17,18 ;
                  le16(22)=22,23 ; le32(32)=32..35 ; le32(36)=36..39 ;
                  le32(44)=44..47 ; le32(454)=454..457
```

即：**没有任何变量索引的读**。综合器据此可以判定"绝大多数写入位置永不参与任何读取"，从而大幅裁剪。

TD 实测（SynthPilot MCP，`get_cells "*sector_buffer*"`）：`num[125]`，例如 `sector_buffer_reg[1]_syn_4` … `sector_buffer_reg[4095]_syn_4`。

结论：

1. **不能按声明 4096 bit 计资源。** 实际只保下 **125 个位级 cell**。
2. 该数组**没有**被推断成 BRAM/DRAM：`#bram` 前后均为 47、`#DRAMHARDCON = 0`、层级表里 `u_volume_scanner` 的 bram 列为 0。
3. 125 是"该 netlist 该流程下"的可复现实测值，随流程/优化强度会漂移；不能由它反推"精确省了多少 LUT"。前一版交接里出现的 118 与本次不一致，**以本次 125 为准**。
4. 该 MCP 会话 netlist 是**E 之前**的（同会话还能查到 `pixel_byte_cnt` cell）。E 之后的结构证据只认 native 的 `final.area` / `final.timing`。

### 11.2 边界判定

1. **无 IO delay 是"已知缺口"，不是"已满足"。** 33 输入 / 38 输出没有 input/output delay，意味着这些端口的板级建立/保持没有进入 STA。**本轮不虚构板级延迟**（不补 0、不补名义值）。要闭环必须先拿到板级参数（SD 侧 setup/hold、HDMI 前向时钟/数据走线预算、显示端/接收端）。
2. **PLL local feedback 是真实的补偿不确定性**，影响 PLL 输出相对参考的相位精度，不是 fabric 内部路径。当前用 `set_clock_groups -asynchronous` 分组、同源 `video_clk`/`hdmi_5x_clk` 保留同步分析，是**保守且可接受**的。**不为了指标好看加宽泛 `false_path`/`multicycle`。**
3. **本轮未新增任何 `false_path`/`multicycle`/IO delay。** 候选 D、F 都只改 RTL，且都已回退。
4. **SDRAM 位置未 honored + PHY-5079 时钟局部走线是既有提示**，与本轮改动无关；若后续出现 SDRAM 读写异常，优先复查这两条。
5. **不要为了让 WNS 变好看而动 SDC。** 本域 slack 由互连决定（cell 31% / net 69%），放宽约束只会掩盖问题。

## 13. 唯一推荐的第一项实现（本轮结论）

### 13.1 本轮不产生新的"第一项"

用户在只读复核之后要求"自行选择最优方案并实施第一项"。实际执行序列是：

```
候选 A  → 实施 → native 恶化（−0.519ns / 18 EP，LUT +234）→ 回退
候选 E  → 实施 → native 门槛通过（+0.116 / +0.030，资源不超限）→ 提交 263425f   ← 当前签核基线
候选 D  → 实施 → 功能等价但资源方向恶化（Slice +27 / LUT +251 / PLB +1 / Hold −6ps）→ 回退
候选 F  → 实施 → native route 失败（RUN-8102 / PHY-8023）→ 回退
```

因此本轮（继续轮）**没有任何候选通过"资源方向 + native route"的综合门槛**，**不提交新 RTL**。当前可签核基线仍是**候选 E**。

### 13.2 为什么 E 仍然是"唯一推荐的第一项"

按权重排序的理由（均为实测）：

1. **失败机制被锁定**：native 的 2 条（乃至 9 条）sd_card_clk setup 违例全部来自同一扇出源 `pixel_byte_cnt`（扇出 36、net 73%），是典型"单点宽网"，改 RTL 结构即可解决，不需要动约束、不需要新增流水。
2. **等价性可证明、可仿真**：守位替换逐拍恒等，不引入新寄存器、不改变启动/Seek/暂停延迟；7 定向 + 2 边界 + 53 回归失败集合零变化。
3. **资源方向可接受**：native 口径 LUT −97、reg −58、PLB −3、布线 −45k（唯一变差的是 Slice +70 / LE +120，<1%）。
4. **硬门槛通过**：native 正式签核 Setup +0.116ns / 0 EP、Hold +0.030ns / 0 EP、资源不超限。
5. **风险可闭环**：单文件、单提交、`git revert` 即可；与用户未提交的 D11/D12 改动零重叠。

### 13.3 为什么 D / F 不能取代 E

| 维度 | E | D | F |
| --- | --- | --- | --- |
| 功能等价 | 逐拍恒等 | 等价（启动 +1 拍） | 等价（未达 route） |
| Slice / LUT / PLB | 8588 / 15683 / 2422 | 8615 / 15934 / 2423 | route 失败 |
| Setup / Hold | +116ps / +30ps | +132ps / **+24ps** | 失败 |
| 能否签核 | **能** | 能但得不偿失 | **不能** |

### 13.4 如果数据不足，缺什么（下一项方向）

1. post-E netlist 上**族 A（元数据 → CDC 影子）的信号级交叉探针**，用来确认族 A 的真正 RTL 起点，以及是否值得作为下一项（对应候选 G）。
2. 候选 **G** 的候选级综合（gate/place/route + area）。
3. `report_analysis -mode basic`（关键路径）与 `report_hfn -mode gate|place|route` 的**完整输出**（本轮已拿到 route 阶段 fanout 直方图与 Top-50，gate/place 阶段尚未全量产出）。
4. 板级 IO 参数（SD / HDMI 前向 / 显示端）—— 33 输入 / 38 输出无延迟是真实缺口。

**在拿到上述证据之前，不建议再叠加新的 RTL 候选。** 当前设计没有任何资源或时序门槛压力。
