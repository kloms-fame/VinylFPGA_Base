# MV 卡顿修复（fixF）产品版人工验收清单

- 版本对象：`doc/资源/sd卡/release_20261028_mv_fixF/VinylFPGA_MV_fixF_20261028.bit`
- 基线：`e65bec439587970ff39e8cec6f37387db6069f78`（e65bec4，main）
- 本版包含：切歌冻结修复、seek 归零修复（fixF.1）、SD 单所有权仲裁 + 250 ms 看门狗修正、CMD18 流式读、WAV 尾包误报 underrun 修复
- bit 基本信息：`680840` B（以出片实际为准），SHA-256 见 §0
- 适用板卡：EG4S20BG256（顶层 `top`），**产品版固件，不输出 @M2 串口诊断行**，因此本清单所有判据均为**肉眼/耳朵/数码管**可判，不依赖串口

## 1. 验收环境与准备

| 项 | 要求 |
| --- | --- |
| SD 卡 | ≥3 首曲目，其中至少 1 首时长 ≥3 分钟且带 MV；至少 1 首为纯音频（无 MV） |
| 显示 | HDMI 显示器/电视，可看清歌词与数码管 |
| 音频 | HDMI 或模拟输出接音响，音量可闻 |
| 输入 | 红外遥控（F8 = +5 s、EA = −5 s、F6 = 重播）、EC1（暂停/继续）、EC2 旋钮（±2 s seek）、母板 KEY3（保存参数）、KEY4（静音）、SW1（数码管开关） |
| 记录 | 手机（录像 + 秒表），用于卡顿量化 |

### 1.1 判据定义（全篇统一）

| 术语 | 定义 |
| --- | --- |
| **卡顿** | 画面停顿 >0.5 s，或音频断续/爆音/静音 >0.2 s |
| **长卡顿** | 画面或音频中断 ≥1.0 s（fixE 之前实板 2000 s 内出现 20 次） |
| **三者一致** | 数码管时间、歌词当前行、MV 画面内容指向同一播放位置（误差 <1 s） |
| **回 0** | MV 回到第一帧 / 歌词回到第一行 / 数码管归零。**本次修复的核心禁止项** |
| **P0** | 必须通过，否则不可发布 |
| **P1** | 应当通过，失败需记录并评估 |

## 2. A 组：冒烟（约 3 分钟，P0）

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| A1 | 上电，插入已写好曲目的 SD 卡，等待首屏 | 启动画面正常，无花屏/黑屏 |
| A2 | 选第一首播放 | ≤3 s 出声，MV 与歌词出现 |
| A3 | 观察 30 s | 画面连续、音频连续、数码管时间递增 |
| A4 | 按 EC1 暂停，再按恢复 | 暂停时声音停、画面定格、数码管停；恢复后从原位置继续，不重启 |
| A5 | 关闭 SW1，再打开 | 数码管熄灭/恢复，播放不中断 |

---

## 3. B 组：连续播放 10 分钟（P0）

| 编号 | 操作 | 期望 | 失败特征 |
| --- | --- | --- | --- |
| B1 | 单曲连续播放 ≥10 min（选 ≥3 min 且带 MV 的曲目，可循环） | 无卡顿、无长卡顿；音频无爆音 | 出现 ≥0.5 s 停顿、画面撕裂/花帧、声音断续 |
| B2 | 播放中观察数码管与画面 | 数码管秒数匀速递增，与画面/歌词同步 | 数码管跳变、停滞、回退 |
| B3 | 播放中观察 MV 帧率（目测） | 10 fps 观感稳定，无规律性掉帧 | 周期性顿一下（每几秒一次） |

> 参考：fixC/fixD 版本在 2000 s 内出现 20 次 ≥1 s 卡顿；fixE 诊断版 300 s 零卡顿。本组 10 min 若能保持零长卡顿，即达到 fixE 的实板水平。

## 4. C 组：切歌（P0）

| 编号 | 操作 | 期望 | 失败特征 |
| --- | --- | --- | --- |
| C1 | 扩展 KEY3 切下一首，正常速度切 3 次 | 每次 ≤1 s 出新歌音频与画面 | 停顿 >2 s（旧固件 2.4–2.6 s 冻结即为已修复的缺陷） |
| C2 | 快速连切 5 次（间隔 <1 s） | 最终停在最后一首并正常播放，不卡死、不静音 | 卡死、花屏、无声、需要断电 |
| C3 | 切到新歌后立即观察画面 | **新歌从第一帧开始**，不是上一首残留帧 | 新歌开头闪上一首画面 |
| C4 | 切到纯音频曲目（无 MV） | 显示封面/占位，不花屏、不卡顿；音频正常 | 黑屏、卡住 |
| C5 | 切歌时观察数码管 | 归零并重新计时 | 保留上一首时间 |

## 5. D 组：进度 seek（**本次修复重点**，P0）

> 触发方式：EC2 旋钮（±2 s）、红外 F8（+5 s）、红外 EA（−5 s）、红外 F6（重播）。
> 三个位置必须同时正确：**数码管时间 / 歌词当前行 / MV 画面内容**。

| 编号 | 操作 | 期望 | 失败特征（出现即判 FAIL） |
| --- | --- | --- | --- |
| D1 | 播放 30 s 后，EC2 顺时针转 1 格（+2 s） | 声音从新位置继续；数码管 +2 s；歌词推进；**MV 停在原位置附近，不回第 0 帧** | MV 回到第一帧、歌词回到第一行、数码管归零 |
| D2 | 同上再逆时针 1 格（−2 s） | 位置回退 2 s，三者一致 | 同上 |
| D3 | 红外 F8 连续按 3 次（+15 s） | 每次步进 5 s，累积 +15 s；画面/歌词跟随 | 数码管对但画面/歌词不动；或画面回 0 |
| D4 | 红外 EA 连续按 2 次（−10 s） | 回退 10 s，三者一致 | 回退到开头 |
| D5 | 从 90 s 位置 seek 到 0（连按 EA 到底或重播键 F6） | 回到开头并从头播放（此时回 0 是**正确**行为） | — |
| D6 | 播放到距结尾 5 s 内，按 F8 | 位置钳在结尾附近不越界；播完进入下一首/循环 | 越界后黑屏、卡死 |
| D7 | 切歌后 1 s 内立刻 seek | 新歌按 seek 目标播放，三者一致 | 卡死、回 0、声音停 |
| D8 | 连续快速 seek 5 次（间隔 0.3 s） | 最终停在最后一次目标位置，播放连续 | 位置错乱、回到开头、无声 |
| D9 | 暂停中 seek，再恢复 | 恢复后从 seek 目标位置播放，图像与音频同步 | 恢复后回 0、音画不同步 |
| D10 | seek 后观察 10 s | 位置**不自增漂移**（不会自己往前跑或跳帧） | 画面自动快进/跳帧 |

> 判据补充：seek 后允许 ≤0.6 s 的画面重新定位延迟（帧定位器最坏 576 µs + 帧提交）；超过 1 s 仍停在旧帧判 P1 失败。

## 11. 失败处置

1. **先留证**：手机录 10 s 视频（含数码管与画面同框），记录曲目名、时间点、操作序列。
2. **分级定位**：
   - 只有画面/歌词回 0、数码管正确 → seek 归零类缺陷（fixF.1 已修，若复现说明另有路径）。
   - 切歌冻结 2–3 s → 时基/调度类（本版应已修复）。
   - 播放中 1 s 以上停顿且伴随音频断 → SD 仲裁/看门狗类（本版应已修复）。
   - 曲尾断音 → WAV 尾包类。
3. **回滚**：烧回 `VinylFPGA_MV_fixF_20261028_pre_seekfix.bit`（对照）或基线 bit（保住可用性）。
4. **回报**：把 §10 表格 + 视频 + 曲目样本（SD 卡镜像或曲目文件）一起回传，便于在 `sim/mv_owner_20261028`、`sim/fixF_20261028` 仿真环境复现。
