## 4. 真正需要改的路径与优先级

### P0-A：SD 媒体通路的长连线与宽比较

本次最终最差路径已不同于旧报告的索引写使能，必须以新报告定位：

| 路径 | slack | 数据延迟与连线占比 | 首要检查 |
|---|---|---|---|
| `fat32_media_loader.data_offset → header_offset_parts` | −2.218 ns | 11.966 ns，连线 81% | BMP 头偏移/文件长度分段比较和寄存器邻近性 |
| `audio_prefetch_sdram.producer_remaining → sd_sector_adapter.sector_lba` | −2.197 ns | 11.917 ns，连线 77% | 请求控制与 LBA 选择长组合通路，检查握手边界 |
| `song_index_db.hdr_version → u_mv_metadata_cdc.src_data_latched` | −2.130 ns | 11.778 ns，连线 78% | 索引有效性/元数据选择及更新使能的扇出 |
| `fat32_media_loader.stream_file_size_q → file_streamer.current_cluster` | −2.119 ns | 11.839 ns，连线 84% | 文件边界、簇选择及控制使能的跨模块共享 |

`fat32_media_loader.v` 已有提前到头部尾字节执行的 `header_offset_parts`、`header_payload_parts`，不能把它误判为还保留原始 32×32 组合乘法器。建议先减少比较/选择范围、局部化相关控制，必要时利用头部未使用字节时隙进一步分段；所有 valid、错误判定和字节偏移必须保持一致。

这些连线占比说明物理资源拥挤、共享长网和数据控制耦合很重要。继续给全模块随意加流水会消耗本已紧张的 Slice，而且不一定缩短关键线。

### P0-B：SDRAM 写入控制的加法/比较

本次最差路径为 `frame_fifo_write.write_cnt → fifo_ready`，slack **−1.641 ns**，数据延迟 9.389 ns，其中连线 69%。后续 `linear_latch → App_wr_addr_r` 多条路径也有违例。

源码 `src/SD/frame_fifo_write.v` 的 `fifo_ready` 判定包含 `write_len_latch <= rdusedw_r + write_cnt`；应评估拆分剩余字数/就绪条件的计算与寄存，保持突发长度、FIFO 可读数据量、线性写入和翻转写入协议。只改一组路径后重新测量，不同时重写整个 SDRAM 仲裁/官方 FIFO。

旧报告中的 `write_buf` 读地址路径仍作为备查：实际 `wfifo_32_32_512` 定义在 `src/IP/afifo_16_32_256.v`，文件名与模块名不同；它不再是本轮最差路径，不能继续按旧排序作为第一改动。

### P0-C：高扇出复位与控制的局部化

本次综合库 HFN：`sd_media_rst_n` 扇出 3884，`sdcard_rst_n` 740；最终路由库分别仍有 **2292**、**453** 个负载，最差 slack −1.010 ns。`sd_media_rst_n` 的最差 net delay 达 8.813 ns。

这些测量支持评估局部复位分发、工具支持的复制/物理聚集，以及减少复位信号在数据 mux 中的使用。不能简单增加彼此独立的复位同步器，造成模块不同拍释放；不能直接删除必须的状态/valid 复位，也不能对整条复位来源随意加 false path 掩盖数据路径。

歌词窗口 `tail_pending` 扇出 673，但最终最差 slack 为正的 +26.063 ns。它说明分布宽、可作为资源优化候选，不是应抢先修复的时序瓶颈。

## 5. 资源优化：按收益与改动风险分层

| 项目 | 预计意义 | 风险/限制 | 建议顺序 |
|---|---|---|---|
| J2 WS2812 复用已有 1 ms tick | 去掉一组本地分频，改动局部 | 保持 20 ms 刷新和攻击/衰减行为；实际节省需测量 | 第一轮小改 |
| 500 ms 启动保护窗改用已有 ms tick | 源码当前是 27 位周期计数；500 档 ms 计数只需 9 位 | 要精确核对完成拍、KEY2/KEY3 接受窗及 SW2 锁存时刻；不能承诺净省 18 FF，工具可能已裁剪原高位 | 同轮独立小项 |
| LED 复用 ms tick | 可移除另一组本地分频 | 原分频在 DIP3 禁用时清零，共享后首个周期相位不同；需确认允许误差 | 后于 WS |
| 歌词六行缓存的存储/译码结构 | 六个 128 位 glyph 缓存，共 768 位，模块综合约 986 LUT/885 FF，潜在收益较大 | 不是加 `ram_style` 即可：下游现为 768 位并行接口；改 RAM 要重做按行/字寻址和读延迟对齐 | 小优化不足时单独设计 |
| 字库或缓存的 BRAM32K 映射 | BRAM32K 尚有 15 块空闲，可换取 BRAM9K/逻辑余量 | 端口、布局、初始化、延迟均要核验；增加 BRAM32K 属资源重平衡，不是“完全不增加 RAM” | 中期备选 |
| Flash FSM/命令译码共享 | 约 550 LUT/256 FF，无新增 RAM | 掉电安全、CRC、WEL/WIP、保护和回读已实现，不能为面积删除；风险高于普通计数器 | 较低优先 |
| HDMI/SDRAM 加密或官方 IP 重写 | 理论上涉及较大区域 | 验证代价高、影响音画基本链路 | 收尾阶段优先保留 |

本工程已有 `audio_prefetch_stage.v` 使用 `EG_PHY_BRAM32K` 的实例，可作为 primitive 接口参考；不能仅凭余量数字推断任意并行缓存都能无代价迁移。

**纠正两项旧分析：**

1. `ui_command_router` 已以 `USE_EXTERNAL_MS_TICK=1` 实例化，本地计数器是备用参数分支，不应重复计算收益。
2. `debounce_tick` 默认 5000 个 50 MHz 周期，即 **0.1 ms**；`ui_ms_tick` 是 1 ms。直接合并会改变按键/编码器消抖，不纳入本轮低风险共享。

前两项小优化主要用于先释放少量余量并验证流程，不应宣称必然解决 PLB/时序。若只省少量 LUT 而 PLB 不动，应停止在小计数器上反复投入，转向有实测收益的大区域。

- **结构检查**：当前 no-clock=0、invalid constraint=0、combinational loop=0。PLL/buffer 小节列出两个实例，但细项均为 0，不能将标题计数直接当作两个 PLL 故障。
- **I/O 模型**：check_timing 报 no input delay=37、no output delay=49、abnormal input delay=32。机械异步输入/常量输出与 SD/SDRAM/HDMI/Flash 的同步接口需分开审查；后者应依据板卡和器件参数补充，不填虚构 0 ns。内部 STA 覆盖 99.96% 不等于板外全部接口已完成时序签核。
- **Local clock 告警**：本次标记的是 `ext_mem_clk_sft → U3/u2_ram/SDRAM_CLK`，Clock/Fanout=0/1。不是 SD 或视频主时钟未走全局网；结合已有移位输出时钟约束，按 SDRAM 输出接口核验，不盲目再加 BUFG 或更改 PLL 相位。
- **SDRAM 初始位置告警**：`U3/sdram` 的初始 location 未被保留，place 已移动实例并完成；需追溯初始/IP/回标约束来源。不能把它当作用户 GPIO 约束冲突，也不能未经确认修改板级引脚。
- **Dummy node**：包含常量 GPIO、WP/HOLD、UART 及波形 RAM 映射等分组。需要逐项审阅，不能把标题的 3 个分组直接等同于三个功能失效。

|---|---|---|
| PLB 使用量不高于 | 2376 | 2327 |
| Slice 使用量不高于 | 9506 | 9310 |
