## 2. 问题根因（为什么切换会"卡"）

* SDRAM 只有 2,097,152 个 32bit 字（8MB）。固定占用：4 个屏缓存（0 / 307200 / 614400 / 921600）、3 个 MV bank（1228800 / 1305600 / 1382400）、专辑封面 SONG_ADDRESS=1,459,200、艺术图 ART_ADDRESS=1,766,400（各 307,200 字）。
* 艺术图之后**只剩 23,552 字**（约 92KB），装不下第二张 307,200 字的图 → `ART_ADDRESS` 是**唯一槽位**。
* 原实现中，艺术一占用该槽；请求艺术二时`job_obsolete` 失效，必须重新读整图：640×480×2 Byte = 614,400 B = 1,200 个 512 字节扇区，且与音频预取、MV 写回抢同一个 SD 扇区仲裁器 → 用户体感就是"切背景要等一下"。

## 3. 修复方案：一张图一槽 → 一张槽装两张图

同一 307,200 字里，把两张图的 RGB565 分别放进**高半字**和**低半字**：

* 艺术一 → bits[31:16]，艺术二 → bits[15:0]（`write_mask`：1=屏蔽该字节）
* 写入仍按 2 源字/像素的节奏，读节拍、地址、屏窗口全部不变（不影响 125MHz/25MHz 两边 FIFO 的速率匹配）
* 读出时按"本次突发属于哪张图"选半字，再做 565→888 位扩展，视频域看到的仍是 `[31:8]` 的 RGB888 → **下游 `video_delay` 及所有显示逻辑零改动**

### 3.1 关键代码

`src/video/background_cache_loader.v`
```verilog
assign write_mask = job_art ? (job_art2 ? 4'b1100 : 4'b0011) : 4'b0001;
assign pixel_data = job_art ? {rgb565,rgb565}
                            : {rgb565[15:11],rgb565[15:13],rgb565[10:5],rgb565[10:9],rgb565[4:0],rgb565[4:2],8'd0};
```

`src/SD/frame_read_write.v:100-102`
```verilog
wire [15:0] art565 = read_data_art2 ? Sdr_rd_dout[15:0] : Sdr_rd_dout[31:16];
wire [31:0] graphics_read_data = read_data_art ?
    {art565[15:11],art565[15:13],art565[10:5],art565[10:9],art565[4:0],art565[4:2],8'd0} : Sdr_rd_dout;
```

`src/SD/frame_fifo_read.v:122-123`：按突发打标签（源边界切突发并排空后才换标签，避免半字选错）
```verilog
assign read_data_art  = burst_art;   // burst_art <= raster_background && frame_art (S_CHECK_FIFO)
assign read_data_art2 = frame_art2;  // frame_art2 <= background_art2 (S_ACK)
```

`src/audio/audio_sdram_arbiter.v`：`graphics_wr_mask` 取代常量 `4'b0001`（held_mask 同步），写入掩码打通到 `App_wr_dm`。
`src/top_tf_hdmi_audio.v`：`background_write_mask` → `background_mask_m0/m1`（`ext_mem_clk` 域两级寄存）→ 仲裁器；`background_art2` 送 `frame_read_write`。

### 3.2 就绪与切换（不再互相作废）

`src/video/background_cache_loader.v:60-77`
```verilog
wire job_obsolete = !source_valid || (!job_art && (job_song != song_id || song_changed)); // 艺术图不再随专辑 epoch 失效
wire need_art1 = !art_ready && !art_failed;                    // 开机预热艺术一
wire need_art2 = source_art2_supported && !art2_ready && !art2_failed;  // 开机预热艺术二
assign ready_info = {epoch,art2_ready,art_ready,song_ready,cached_song};
```
* 两张图各自有 ready/failed 位，先到先得；显式请求艺术二可插队（`requested_art2`）
* `frame_finished && job_art && !job_art2` → `art_ready`；`job_art2` → `art2_ready`（第 214/222 行）
* `src/video/background_frame_select.v:26-28`：`mode==2'd2 && ready_info[3]` / `mode==2'd3 && ready_info[4]`，艺术类**不再看专辑 epoch**
* `src/video/background_raster_address.v`：新增 `background_words` 输出供突发标签使用

切换动作退化成：帧边界换一次 `base`/半字选择 → 零 SD 事务、零 SDRAM 重写。

**代价**：开机预热多读一张图（1,200 扇区 ≈ 600KB），启动阶段比原来多读一张静态图的时间；换来运行期切换零等待。

## 5. 时序收敛：为什么第一次构建是 -424ps，最后怎么过

### 5.1 第一次构建（背景功能已完成）不合格

`phy_1/seed_7`：`Setup WNS -424ps / TNS -424ps / 1 条违规`，Hold +27ps，slices 9,355，wire 2,979,624。

违规路径（`VinylFPGA_pr.timing` 85-155 行）：

* 起点 `u_volume_scanner/mux132_syn_26`（网络 `sec510[5]`，`src/SD/fat32_volume_scanner.v(81)`）
* 终点 `u_volume_scanner/fs_error_reg[0]`（`fs_error[0]`，只有 `ERR_UNSUPPORTED_BPB=0x21` 才为 1）
* 数据延迟 10.144ns = cell 2.504ns + **net 7.640ns（76%）**；逻辑 6 级；关键网络单扇出却 2.356ns

即：违规是 **FAT32 卷扫描器里既有的同一条路径**（本次完全没有恢复 `fat32_volume_scanner.v`），我们只是把布局扰动 +33K 线长，把它从 +148 挤到了 -424。归档补丁里用 `ST_SIG0/ST_SIG_BOOT` 打断该路径的实验版本同样停在 -424，说明"把签名比较挪一拍"并不能解决。

### 5.2 处置：先做物理实现种子扫描（零功能风险、可复现）

按复盘"试验隔离"要求，不动 FAT32 RTL，改 `prj/VinylFPGA.al` 的 MultiSeed 配置一次跑 3 个布局种子（`Num=3, Init=7, Step=1, Seeds 7 8 9`），复用同一 syn_1 网表只重跑 place/route：

| 种子 | Setup WNS | 线长 | 结论 |
| --- | --- | --- | --- |
| 7 | -424ps | 2,979,624 | 违规 |
| 8 | -1987ps | 3,028,880 | 违规 |
| **9** | **+117ps** | **2,733,672** | **达标**，TNS 0、0 条违规 |

线长与 WNS 强相关（2.73M vs 2.98M），说明这是布局拥挤问题而非逻辑级数问题。TD 自动把达标种子 9 记为 best（`<Seeds select="9">`）。

> 注意：同一"种子 9"在 `Num=1` 单种子模式下重跑得到 -71ps（线长 2,751,144），说明**必须在 MultiSeed 三段式配置下运行才能复现 +117ps**。因此 `.al` 保留 `Num=3 / Seeds 7 8 9 / select=9`，不要改回单种子。
