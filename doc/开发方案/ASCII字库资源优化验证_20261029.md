# ASCII 字库存储资源优化验证（2026-10-29）

## 改动

在完整 UI 配置中，将共享 1024×8 ASCII 字库从一个 9K BRAM 移至一个 32K BRAM；地址、字节内容和单拍读延迟保持不变。生产版使用 `EG_PHY_BRAM32K` 的 INIT 参数，仿真兼容分支保留原始字库；`tools/check_ascii_font_init.py` 检查两份数据全部 1024 个地址一致，避免后续维护时产生偏差。原语输出在首个时钟之前为 X，因此增加初始化输出门控以保持原模块初值为 0。没有裁剪 UI 或改动外部接口。

- `python tools/verify_stage4.py`：显示与媒体 21/21 通过。
- `python tools/verify_lyric_focus.py --output <新目录>`：8/8 通过。该回归的顶层 Icarus 编译启用 `VINYL_MV_BURST_BEHAV`，修复此前缺少原语模型导致的编译失败。
- `python tools/verify_seek_integration.py`：seek 时间、帧位置和 PCM 正反转落点通过。
- `python tools/verify_mv_owner.py --out <新目录>`：11/11 通过。
