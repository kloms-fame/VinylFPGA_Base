## 结论与本轮边界

本轮首先按用户要求提交双灯带统一亮度：`0ed19c3`，其父提交 `1e973d7` 为 SPI Flash 参数持久化。随后实现播放模式图标，等待用户生成固件、人工验收后再提交。没有修改原播放控制、上下左右/确认、红外键位、音频握手或持久化格式。

目前最需要推进的是**物理资源余量和 setup 时序收敛**。功能可在板上运行、综合完成、BitGen 产出与时序零违例是不同结论。不要把一次上板通过当作时序收敛，也不要把旧版布线面积作为新源码的资源结论。

本文件是对当前实现和报告的分析；不自动授权批量重构，也不重新启用旧方案中已被用户撤销的按键/OSD 方向键改动。

## 3. 优先级 P0：先解决可测量的时序问题

本轮图标 r2 的**综合估算**最差路径已变为 `u_sdcard_reset/s2_reg → u_mv_sector_mux/owner_valid_reg` 及 MV 状态寄存器，SD 域 WNS −1.093 ns，数据延迟 10.977 ns，连线占 72%；SDRAM 域综合 WNS −0.953 ns。后续需同时检查同步复位释放信号在数据/状态逻辑中的高扇出和局部化机会。该结果与下文的旧版布线路径分属不同阶段，既不能互相替代，也不能据此断言新的布线最差点一定仍在旧位置。

### 3.1 SD 100 MHz 域：索引记录写入的长连线

Flash r3 布线报告最差路径位于 `song_index_db` 内，从记录相关寄存器到音频簇地址寄存器写使能：

- setup slack：−2.522 ns；数据路径延迟 12.242 ns。
- 其中单元延迟 0.843 ns（6%），连线延迟 11.399 ns（94%），逻辑层级仅 2。
- 源文件：`src/SD/song_index_db.v`；相关生成块是 `entry_bank/byte_lane`，已有输入字节、字段和 lane 的寄存器译码，不能将其误判为完全未流水的宽动态数组写入。

建议先检查物理共享后的 bank/lane 写使能网络和记录字段扇出，尝试局部化使能、限制不合适的跨 bank 共享、收拢相关寄存器布局。每次只做一项可对比的修改。这个证据更支持先减少长网和拥挤，而不是继续给已只有两级的路径盲目加寄存器。

SD 域其它已报告路径还涉及 `seek_cur_sample_sd`、目录匹配与音频预取状态机。先解决最差一组后再重新排序，不应一次改动整个读取/播放链路。

### 3.2 SDRAM 125 MHz 域：写 FIFO 的读地址路径

同一布线报告的该域最差路径为：

`frame_read_write_m0/write_buf/rd_addr_reg[0] → write_buf/ram_inst/ramread0.addrb[6]`

setup slack −1.706 ns；数据延迟 9.292 ns，其中连线 7.142 ns（77%），单元 2.150 ns（23%）。实际 `wfifo_32_32_512` 模块定义位于 `src/IP/afifo_16_32_256.v`，由 `src/SD/frame_read_write.v` 的 `write_buf` 实例调用；文件名与模块名不一致。应检查其地址/空判断/读使能关系和物理邻近性。不能随意修改官方 FIFO 时序协议或省掉地址寄存器；若要增加一拍，必须同时确认读请求和有效数据延迟的对齐。

### 3.3 约束与放行原则

当前 `constraints/timing.sdc` 已分组异步域，并保留 video/HDMI 同 PLL 域的同步分析。上述两个问题都是域内 setup 违例，不应新增 false path、随意多周期或降低约束频率来隐藏。

板外 SD MISO、SDRAM、HDMI 等接口的板级时序参数仍不完整，SDC 已记录部分缺口。后续应依据真实器件、工作模式、板级延迟和官方 IP 时序模型补充；不能用虚构的 0 ns I/O delay 填满覆盖率。新增 Flash 接口也应在此审查范围内；当前低速 Mode 0、半周期采样不能替代完整板级接口模型。

### 优先尝试的低风险项目

1. **本轮源码复核纠正**：`ui_command_router` 已由 `expansion_integration` 以 `USE_EXTERNAL_MS_TICK=1` 实例化，本地计数器是参数化备用逻辑，不能将其作为仍占资源的重复分频器。可评估的是 `led_business_driver` 和 `ws2812_effects`；LED 本地分频受使能清零，共享 tick 会改变使能后首个 tick 的相位，必须单独确认。另一个 `debounce_tick` 默认为 5000 个周期，即 0.1 ms，并非重复的 1 ms，不可直接替换。
2. 字库、UI 面板和歌词模块内的重复范围比较或字符选择，先使用综合层次报告定位，再做局部共享。不要把“RTL 代码行更短”当作 LUT 一定更少。
3. BRAM9K 64/64，而 BRAM32K 1/16。若需要为后续功能腾出小 RAM，可评估部分只读字库在 BRAM32K 上的合并/重映射，但必须核对端口带宽、位宽、读延迟和安路 primitive 支持；这只是候选方向，尚无节省结果。

不预先承诺 LUT、Slice 或 WNS 的改善数值。特别是本器件 MSlice/LSlice/PLB 的分布压力，不能仅凭综合 LUT 降低就判定一定可布局。
