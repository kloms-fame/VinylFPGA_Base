## 2. 已核实的 RTL 事实与方案冲突

1. `ui_param_csr.v` 当前默认值为 `VOL=200、BRI=3、CON=2、ROT=2、WSL=4`。`ROT=2` 是 3 秒，`slideshow_controller.v` 的复位默认也为 level 2，与用户确认的 3 秒一致，无需改动。
2. `play_ctrl.v` 当前复位 `end_mode=0`，需改为列表自动下一首对应的模式；`ws2812_effects.v` 当前复位 `mode=0`，需改为上电默认 VU 开启。实现时查清模式编码及歌曲结束状态转移，以 RTL 定义和人工验收闭环。
3. 主板顶层当前接入 `key3` 和 `sw1..sw4`；`key3`（B1）经消抖后参与用户操作/Boot 跳过事件及反馈音，`disp_mode_tgl` 已绑为 0。用户已指定 KEY3 改为手动保存、SW2 承担开机跳过 Boot；前期先从 KEY3 的通用用户事件/Boot 跳过路径中移除，保存功能及其成功反馈全部留到阶段 4，再由 SW2 在复位启动时选择是否跳过动画。
4. 用户已明确主板 LED 高电平点亮。旧《产品交互.md》中的低电平说明按本轮指示更新；主板 LED 仍须在 `pin.adc` 中新增用户指定引脚约束，并检查与工程已有管脚无冲突。
5. 当前 `ui_command_router.v` 与《产品交互.md》的红外映射不同。用户已指定以产品交互文档为功能验收基准，允许调整存在冲突的键位；阶段 3 应更新 RTL 映射以符合该文档，完整核对 21 项功能，不能只交换 F8/EA 两个码。若为解决实体按键冲突而调整遥控键位，应同步更新《产品交互.md》映射表后再实现。
6. `KEY2/KEY3/KEY4`、CSR、播放结束模式、背景/转场模式分属不同模块及时钟域。旧方案关于“扩一个 bundle 位就零成本跨域”及“3 个或门即可同步复位多个模式”的说法未由当前 RTL 证明。新增跨域控制要使用符合信号类型的同步/握手方案；多位参数不能直接逐位双触发器同步。
7. `spi_master.v` 提供单字节传输与外部片选控制，不能仅凭例化就视为完整 Flash 驱动。旧方案的 `clk_div=6` 与宣称的 3.125 MHz 不匹配：按本模块 50 MHz 输入、每半周期 7 个时钟计算，SCLK 约为 3.57 MHz。W25Q64 的板载引脚、WP/HOLD 接法、擦除时间与上电行为也需以实际板卡资料确认。
8. KEY2 参数复位、KEY3 手动保存、SW3 自动保存、SW4 告警沿用产品交互文档定义；用户已明确 LED 高有效、KEY3 手动保存和 SW2 启动跳过。KEY3 保存、SW3 自动保存、KEY2 清除 Flash 及其成功提示等全部 NVM 功能统一留到可选的最后阶段，不阻塞前面的稳定收尾。

## 3. 收尾目标与实施规则

目标是让当前 `main` 上的 `VinylFPGA.al` 对应源码可重复完成综合、布局布线及 BitGen，并提供可由用户烧录的阶段候选。用户负责烧录和硬件验收；每阶段的交付应包含候选 bit、SHA-256、构建报告摘要和简体中文验收清单。用户确认该阶段硬件验收通过后，再创建该阶段 Git 提交。

- 按依赖由浅入深推进：先锁定可追溯基线，再做已确认默认值，再做主板控件及 KEY3/SW2 职责迁移，再按产品交互表校准红外，最后评估 Flash。
- 一次只开发一个可独立验收的小阶段。每次只编译当前已完成阶段；失败则定位该阶段改动，不并入下一阶段。
- 以 TD 实际综合/布线结果计量增量：记录 LUT、寄存器、Slice、BRAM、DSP、setup/hold WNS/TNS 与违例数。每阶段必须无新增 BRAM、无 setup/hold 违例且 BitGen 成功；若 Slice 或时序变差到无法留出可接受余量，先缩减功能再进入下一阶段。
- 不预先承诺每项功能的 LUT/Slice 数。现有 Slice 余量虽为 357，但 STA 余量仅 33/37 ps，新增逻辑可能改变布局布线和关键路径，最终以当前 seed 5 的可追溯报告为准。
- 使用新建、唯一命名的构建快照和日志；保留现有 `VinylFPGA_Runs` 结果用于回溯。构建失败或被中断时不交付 bit，不以“文件存在”或进程退出码单独判成功。
- 不在本阶段做板上烧录，也不要求长时间等待用户的硬件验证。构建到 BitGen 完成并收集终态报告后即可交付。

## 4. 分阶段执行计划

### 阶段 0：HEAD 基线复现与候选交付（不改功能 RTL）

**目的**：确认当前 `main` 与工具链可从 `VinylFPGA.al` 生成对应 bit，替代旧方案中错误的“回退到干净基线”。

**工作项**：

1. 记录 HEAD、工作区状态及 `.al`、ADC、SDC、所有实际参与编译源文件的 SHA-256。
2. 保存当前工程/Runs 证据，使用唯一快照运行综合、布局布线、时序分析、BitGen；确认 seed、器件、顶层与约束与 `.al` 一致。
3. 归档新 bit、完整哈希、route/QoR、时序与构建日志；确认本次构建输入哈希与当前 HEAD 一致。
4. 人工烧录验收当前音频预取修复候选，包括长播、暂停/继续、Seek、切歌、EOF、MV/背景并行和 TF 卡异常恢复。验收重点记录欠载/断音与恢复情况。
5. 额外收集遥控器实际 32 位帧码；本阶段只采集，不改红外译码。

**编译放行**：综合、route、setup/hold 均完成且零违例，BitGen 完成，产物与快照可追溯。**人工验收**：用户确认现有播放基线可接受后进入阶段 1。若硬件验收发现音频问题，先单独修复，不叠加新功能。

### 阶段 1：默认状态对齐（改动小，不新增模块）

已确认的目标默认值：`VOL=200、BRI=3、CON=2、ROT=2（3 秒）、WSL=4`；播放结束为列表自动下一首；WS2812 上电默认 VU 开启。

**工作项**：

1. 保留 `ui_param_csr.DEFAULT_ROTATION=2` 与 `slideshow_controller.DEFAULT_PERIOD_LEVEL=2`，验证两者仍共同对应 3 秒。
2. 将 `play_ctrl.v` 的复位 `end_mode` 设为列表自动下一首对应的编码；检查所有结束模式编码、末曲回绕和只有一首歌时的处理。
3. 将 `ws2812_effects.v` 的复位模式设为 VU。验收时 DIP6 拨上，确认灯带立即显示音频电平；DIP6 拨下仍按既有设计清屏。

**阶段验收**：OSD 参数值符合上列默认值；轮播实测 3 秒；单曲自然结束后启动下一首且列表末尾行为符合列表循环定义；上电 VU 生效。生成独立 bit，记录与阶段 0 的 LUT/Slice/时序差值。

### 阶段 2：主板按键、静音及基础状态指示

按已确认的硬件功能和极性逐项实现；先完成一项低风险功能并构建、人工验收，再加入下一项。

1. 将主板 `KEY2(B2)`、`KEY4(C1)`、`LED[3:0](A4/A3/C10/B12)` 接入顶层并增加 `pin.adc` 约束；LED 高电平点亮。保留 KEY1(A2) 全局复位及 `SW1..SW4` 现有引脚。
2. 将 KEY3(B1) 从通用 Boot 跳过/用户操作事件中移除，避免按键误跳过启动动画；前期不实现保存请求、保存成功提示或其他 NVM 行为。KEY3 的手动保存完整功能仅在阶段 4 接入。将已存在并已消抖的 SW2(C7) 电平经安全跨域后接到 `boot_layer`，只在复位启动时决定是否略过 Boot 动画。SW2 打开后开机直达主界面，不能要求另外按 KEY1 或依赖普通 UI 输入。
3. 按已确认定义实现 KEY2 参数恢复默认；前期仅恢复当前运行参数。擦除 Flash、阻止旧配置在下次启动恢复等持久化行为全部留到阶段 4，不预埋未实现的 NVM 行为。
4. 一键静音优先采用音频输出的单点门控，保持音量参数值不变；确认静音对 WS2812 和 OSD 的显示行为后再联动。跨域控制按实际时钟域设计，不把跨域同步开销写成零。
5. 实现 SW4 故障告警总控及 LED 状态语义，按产品交互规定覆盖系统心跳、TF 就绪、播放活动、故障告警。告警源和周期应复用现有健康/媒体状态信号，先查明现有蜂鸣器事件通道，避免新增分频器或重复状态机。
6. 对顶层与子模块做一次死代码/失效功能清理：优先删去已被 KEY3/SW2 新职责取代的旧路由、恒定绑值、未使用端口和重复逻辑。只移除证实无消费者且不影响媒体、音频、视频、歌词或扩展板业务的代码；清理单独审阅并计量资源变化。

**验收**：按键短按/长按无重复误触发；静音与恢复不改变音量值；LED 的实际亮灭极性和状态符合板级接线；Boot 跳过不造成音画状态错位；蜂鸣门控只影响约定告警。每项验收均由单独阶段 bit 承载。

### 阶段 3：NEC 红外映射与 OSD 方向键

以《产品交互.md》所列 21 项功能映射作为短按功能和验收的基准；当前 RTL 与该表不一致时调整 RTL。先整理唯一的功能到码值表，再按“短按映射 → Repeat → OSD 方向键分流”分步实现。长按只对产品交互表明确标注支持连发的功能启用 Repeat；若表内说明与实测遥控器协议存在差异，记录冲突并更新交互表后再合入。

将《产品交互.md》的表作为验收源，维护一张唯一映射表，列出功能、完整 32 位帧、地址/命令校验、短按行为、长按行为和对应业务事件。该表中的 `F3/A1/BD/B5/E6/F2` 按文档实现；如果为了消除实体按键冲突而调整码值，先同步修订交互文档再实现。

**验收**：逐键确认实际功能；Repeat 仅对允许名单生效且节流/超时符合约定；OSD 打开时方向键不触发切歌或 Seek，关闭后原交互恢复。

### 阶段 4：SPI Flash 参数持久化（高风险，最后评估）

本阶段集中实现所有 NVM 功能：KEY3 手动保存、SW3 参数停变 5 秒自动保存、KEY2 恢复默认并清除旧 Flash 配置、上电读取并恢复有效参数，以及保存/加载状态提示。前面阶段不实现这些功能的部分逻辑或提示。

开始前先确认板卡手册/原理图中的 Flash 型号、引脚、WP/HOLD 连接、可用管脚约束及擦写寿命需求。确定保存字段、版本兼容、掉电中断恢复、默认值清除行为后再实现。

方案需要覆盖：SPI 字节事务与 CS 时序、读 ID/读参数、擦除与 WIP 轮询、写使能、页边界、数据校验、无 Flash/坏数据回退、上电加载与用户写入的仲裁。不得把“复用 `spi_master.v`”当作已验证驱动，也不把 5 字节帧/异或校验/单扇区地址当作既定设计。

Flash 不纳入基础收尾的必需范围。若加入后无法在不增加 BRAM 且保持时序零违例、Slice 余量充足的条件下完成，则先交付不含 Flash 的稳定收尾固件，再将 NVM 留作后续版本。

**2026-10-17 阶段 4 执行记录**：已在 `093efe7` 基线上实现五项参数保存、启动恢复、KEY2 默认配置持久化及 KEY3/SW3 调度，仿真通过，seed 5 完成布线与候选 BitGen。最终 Slice 9766/9800、无新增 BRAM/DSP，但 setup WNS −2.522 ns，尚未满足本方案零违例的正式放行条件。当前阶段标记为“功能候选已实现，时序未放行，待人工验收”，不标记最终稳定版。详见《阶段4_SPI_Flash参数持久化_交付与验收.md》。

## 5. 每阶段交付与验收格式

每阶段交付报告固定包含：

1. 本阶段改动文件与功能边界。
2. 当前分支/HEAD、输入快照标识和候选 `.bit` 绝对路径及 SHA-256。
3. 综合与 route 终态、器件和 seed、LUT/寄存器/Slice/BRAM/DSP、setup/hold WNS/TNS/违例数。
4. 与上一阶段的资源差值、发现的限制及未完成项。
5. 逐条简体中文上板验收步骤和预期现象。

用户完成并确认该阶段人工验收通过后，再以简体中文提交该阶段变更并进入下一阶段。硬件未验收的 bit 只能标为“待验收候选”，不得标作最终稳定版。

### NVM 阶段边界

阶段 0 至阶段 3 不实现 Flash SPI 驱动、参数持久化、自动保存计时器、擦除、上电恢复及保存成功提示。若最终跳过阶段 4，KEY3/SW3/KEY2 的持久化相关行为一并留待后续版本；前期已完成的 KEY2 运行时恢复默认不受影响。

## 7. 当前建议的下一步

按阶段 0 → 1 → 2 → 3 执行，所有 Flash/NVM 功能集中到最后的阶段 4；该阶段可按资源与硬件条件选择实施。先检查并安全释放任何占用工程的 TD 锁，再从 `cee91f719e11eb08ad1d19ae4e79972432ef8585` 建立输入哈希快照、完成一次可追溯 BitGen，并与现有 `VinylFPGA_Runs` 报告比对；随后交付音频基线候选和人工验收清单。阶段 1 实施已确认默认值，阶段 2 完成主板按键、LED、SW2 开机跳过和音频控制（KEY3 仅移除旧 Boot 跳过路径，持久化保存推迟），阶段 3 按《产品交互.md》修正遥控器译码。
