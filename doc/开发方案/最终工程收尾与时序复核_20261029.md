## 原问题与修复

本轮开始时的真实 Runs 为：seed 7 SWNS -0.424 ns，seed 8 -1.987 ns，选中的 seed 9 -0.071 ns；seed 9 HWNS +0.031 ns，有 1 个 setup 违例端点。`best_result` 也指向该失败结果。旧文档/归档中的 +0.117 ns 属于历史构建，不能证明当前结果通过。

seed 9 关键路径为音频总长度到 seek 影子计数器使能，7 级逻辑，数据延迟 9.791 ns，其中网络 6.930 ns。历史与当前源码一致，布局指标一致而布线发生差异。高密度下应以当前生成的报告判定，不能把种子编号本身作为验收证据。

### 本轮实际变更

1. `.al` 从 7/8/9 三种子改为原生 MultiSeed 的单 seed 10，`Enable=true`、`GenBit=true`、`EndStep=bitgen` 保留。减少后续重复运行无效种子的时间。生产 RTL、引脚、PLL 频率、SDC 异步组和时序例外均未修改，源文件与约束哈希与本轮输入快照一致。
2. `configure_optimized_project.tcl` 不再用 `-num 1` 偷改工程的种子列表，并核对保存前后 MultiSeed 配置一致。
3. `run_closeout_project.tcl` 检查阶段 marker、综合/布局/布线数据库、非空 bit、最终四项时序和违例端点；校验 `best_result` 与所选产物一致。只在全部通过后输出 `CLOSEOUT_BUILD_TIMING_PASSED`；保留实际通过的 GUI 选择。旧 `run_optimized_project.tcl` 统一调用此入口。
4. `verify_gui_runs.py` 按 Num/Init/Step/选中项校验配置，并以新产物和真实时序判定；不再把 seed 9 写死。拒绝空固件、非零 TNS、过期或不一致结果，隔离副本校验使用该副本源码根目录。
5. 修复过时的顶层回归：MV 已迁到 CMD18，测试改为核对 CMD17 音频优先及 CMD18 缓存准入；SD 所有权事务另有 11 项真实控制器仿真覆盖。补齐 MV RAM 行为仿真开关和 ModelSim 的安路 32K RAM/glbl 依赖。
6. 新增 `tools/audit_final_timing.tcl`，从选中的新布线数据库独立重算时序并保存详细 `check_timing`，不重新布局布线或生成固件。
7. 新增 `tools/build_closeout.ps1`，使用 GUI 同款引擎、隐藏窗口、同步等待和 stdout/stderr 重定向，核对进程退出码、完成标志和最终产物。一次主工程构建虽已得到正确固件和正时序，但 TD 在没有 stdout 句柄时打印结果返回 1；用最小脚本复现后修复启动方式，并完成最终主工程全量重建验证。另一次重建被图形界面并发运行覆盖配置和产物，已停止并排除其结果；启动器增加同工程 TD 进程检查；GUI 关闭时再次保存旧配置的尝试也被停止，在窗口关闭后重新写入 seed 10。

## 未消除的告警与检查边界

物理日志仍有 `PHY-7002`（SDRAM primitive 初始位置被 placer 调整）及 `PHY-5079`（SDRAM 移位时钟使用一条本地布线）。本轮 route 报告 `No multi-drive` 与 `No abnormal timing path`；这些结论不等于所有告警已消除。综合还有厂商 IP 未接端口、位宽裁剪、ROM/未驱动网络等告警，未通过删功能或修改加密 IP 来清零。

独立 `check_timing` 摘要如下，完整节点在原报告中：

```text
Table of Contents
-----------------
1. checking no clock(0) (HIGH)
2. checking clock definition(0) (HIGH)
3. checking dummy node(3) (HIGH)
4. checking invalid constraint(0) (HIGH)
5. checking pll/clock buffer clock constraints(2) (HIGH)
6. checking combinational loops(0) (HIGH)
7. checking soft fifo timing exception constraints(0) (HIGH)
8. checking no path constraints(0) (MEDIUM)
9. checking shadowed/ignored timing exception constraints(0) (MEDIUM)
10. checking no input delay(37) (MEDIUM)
11. checking no output delay(49) (MEDIUM)
12. checking partial input delay(0) (MEDIUM)
13. checking partial output delay(0) (MEDIUM)
14. checking abnormal input delay(32) (MEDIUM)
```

32 项 abnormal input delay 对应 TD 为硬核 SDRAM `U3/sdram.dq[31:0]` 自动生成的约束，参考 `ext_mem_clk_sft` / `U3/sdram.clk`，fast/slow 最大 5 ns、最小 1 ns；完整命令见审计原报告。这些检查项没有通过删除自动约束来隐藏，也不能仅凭正 WNS 判定其板级模型正确。

PLL feedback 检查项、primitive dummy node 和外部 I/O delay 缺项仍需按器件/板级模型解释与确认。37 个输入、49 个输出的 delay 检查集合包含异步按键等非同步接口，也包含需要板卡与外设参数的接口；不能用虚构的零延迟或扩大 false path 来消除报告。当前 positive WNS 仅代表现有约束覆盖范围通过。Slice 和 9K BRAM 余量仍小，不承诺后续添加功能无需重新实现。

## 使用方式

如果 TD GUI 在本轮开始前已经打开该工程，请关闭后重新打开 `prj/VinylFPGA.al`，确认 MultiSeed 仅包含并选中 10，再使用 Run All。GUI 的 `bitgen Success` 必须配合以下检查：

```powershell
python tools/verify_gui_runs.py
```

批处理执行 `pwsh -File tools/build_closeout.ps1`。它调用 `tools/run_closeout_project.tcl`，使用 TD 的 `td.exe -nogui -b`，同步等待、保留标准输出并检查 `CLOSEOUT_BUILD_TIMING_PASSED`，最终打印 `CLOSEOUT_NATIVE_BUILD_VERIFIED`。独立时序审计入口为 `tools/audit_final_timing.tcl`。构建过程会重置当前综合和物理 Runs，修改源码前应保留已验证固件和证据。

本轮源码未改变功能，但新的布局固件仍建议完成冷启动、至少三首歌连续播放、多次切歌、双向 seek、背景切换、歌词与 OSD、Flash 参数恢复及断电重启确认。历史版本的人工验收不能替代这次新固件的实板验收。
