# 播放模式图标：设计与验收

## 目标与位置

基线：`main` / `0ed19c3`。在播放界面显示当前的播完处理模式，不改变模式切换、自然结束、暂停或选曲行为。

图标位于进度条下方时间行的中央：左上角 `(168,350)`，尺寸 `16×16`；进度条范围为 x=16..335、y=342..345。左侧已播放时间 x=16..55，右侧剩余时间 x=288..335，图标不占用原有文字、进度条、歌词或波形区域。

| 控制器编码 | 模式 | 图标 |
|---|---|---|
| 0 | 播完暂停 | 暂停双竖线 |
| 1 | 单曲循环 | 循环箭头中带数字 1 |
| 2 | 列表循环 | 循环箭头 |

图标显示的是**播完处理策略**，不是当前正在播放/暂停的瞬时状态。手动暂停不应把循环图标变成暂停图标。复位默认列表循环。浏览、Boot、测试图案界面不显示此图标。播放暂停时保留当前策略图标。

## 方案选择

比较三种方案：

1. **复用现有 ASCII 字库及文字流水线（采用）**：在原 1024×8 ROM 的空闲控制码 4..15 放置三幅原生 16×16 图形，每幅拆成四个 8×8 小块。复用已有字体请求、同步读取、文字分类和着色，无新 ROM 实例或 RGB 流水级。原生字形使单曲循环的数字 1 更清楚。
2. 新建 16×16 位图模块：分辨率更细，但引入独立译码、覆盖使能和对齐寄存器，不适合当前物理资源余量。
3. 图标加模式文字：可读性高，但占用更宽的显示区域及字符选择逻辑，当前先保留紧凑图标。

图标使用时间文字同款浅灰色，不加背景框、动画或闪烁，沿用当前背景和显示层级。字形透明处保留原背景。

## 实施步骤

1. `src/top_tf_hdmi_audio.v`：将 `play_end_mode` 附加到已有 SD→video 歌曲元数据握手总线的高两位。原低三位含义和所有消费者保持原索引；扩展总线宽度与源端变化检测，避免逐位同步二进制模式。
2. `src/display/playback_page.v`：新增视频域模式输入，在已有帧开始信号处锁存。加入图标区域和文字分类，复用字体请求/读数据寄存器。图标以横纵坐标高位选择小块、低位选择像素，普通文字仍使用原来的采样方式。
3. `src/display/ascii_font_rom.v`：在未使用的控制码区域补充三种字形，不改变原字库深度、宽度或任何可打印字符。
4. `src/include/playback_layout.vh`：集中定义图标坐标与尺寸。
5. 编译相关模块，使用 SynthPilot 查看字库资源并在相同 `area_prior` 配置下完成工程综合；保留独立源码快照。按现有开发约定，用户自行布局布线、生成固件并上板验收；本轮不另增仿真测试或等待完整物理实现。

## 设计边界

- 运行在原有 video_clk；模式只在帧边界变化，不增加像素时钟或除法器。
- 新增帧模式寄存器显式初始化且与复位一致，独立 always 块控制。
- 复用既有 `cdc_bundle_latest` 握手，增加数据位而不新建握手控制器；模式来自真实 `play_ctrl.end_mode`，不在显示侧重新计算或计数按键。
- 字库容量保持不变；实际 BRAM/LUT 结果以综合报告确认，不能仅凭 RTL 大小承诺 Slice 不变。
- 不修改 `play_ctrl`、按键/红外事件映射、音频通路或 Flash 保存字段。模式仍按原设计复位为列表循环，不新增模式持久化。

## 上板验收

1. 复位进入播放页后，时间行中央显示列表循环图标，时间、进度条、歌词和波形位置正常。
2. 短按拓展板 KEY12，循环切换“列表循环 → 播完暂停 → 单曲循环 → 列表循环”，图标在下一帧更新。红外对应播放模式键应得到相同反馈。
3. 三种模式分别自然播完一次：暂停双竖线对应播完暂停；带 1 箭头对应当前曲目从头重播；普通箭头对应下一首，列表末尾回到第一首。
4. 手动暂停/恢复、静音/取消静音、Seek、切歌时，图标保持所选策略；不闪烁、不出现半幅旧图或错误的中间模式。
5. 切换四种播放背景和 MV/封面状态，确认图标对比清晰；调参浮窗正常，原时间字符未被图标字形污染。
6. 停止回浏览、进入 Boot 或测试图案时图标不残留；重启后的模式和图标都回到列表循环。

## 实现与综合结果

最终源码快照：`prj/resource_opt_verified_20261005/mode_icon_20261018_r2/`。前一版 r1 为 8×8 放大字形，已因数字 1 可读性不足而废弃，不作为最终交付。r2 的布局预览为 `mode_icon_layout_preview.png`，按 RTL 中的字库数据和坐标绘制，非仿真输出或上板截图。

SynthPilot 单独对比修改前后的 `ascii_font_rom`：均为 1 个 BRAM9K，未增加字体存储实例。整机依原工程配置，在独立快照内完成综合、物理实例合法化和综合时序报告；日志含 `MODE_ICON_GATE_COMPLETE`，已生成有效 `gate.db`。综合结果与已提交的亮度版比较：

| 指标 | 亮度版基线 | 最终图标 r2 | 差值 |
|---|---|---|---|
| LUT 利用量 | 17,884 | 17,841 | −43 |
| 寄存器 | 11,853 | 11,861 | +8 |
| BRAM9K / BRAM32K | 64 / 1 | 64 / 1 | 0 / 0 |
| DSP | 10 | 10 | 0 |
| setup WNS（综合估算） | −1.837 ns | −1.093 ns | 仍未收敛 |
| hold WNS（综合估算） | +0.471 ns | +0.471 ns | 0 |

本轮页面模块本身的层次逻辑 LUT 从 853 增到 875；整个工程 LUT 降低是全局重新映射的结果，不能声称图标本身为负开销。新增寄存器用于扩展既有握手数据/变化检测和帧模式快照，不新增控制器。视频域综合 setup WNS 保持 +15.240 ns。全局综合 TNS −89.995 ns、124 个 setup 违例端点，仍需后续资源/时序优化和真实物理实现验证。

按 Verilog-2005 模式编译 `playback_page` 及 `ascii_font_rom` 通过。最初使用 `-g2005-sv` 时，既有函数参数名 `packed` 被 SystemVerilog 当作关键字；采用工程对应的 Verilog-2005 模式后通过，没有为此改动原函数。未新增或运行本轮仿真测试，硬件验收按上节执行。

交付状态：

- `current_stage`：图标 RTL 与综合完成，待人工验收。
- `goal`：以原生 16×16 图标反馈真实播完策略，保持既有控制行为。
- `confirmed_constraints`：原 video_clk、原共享字库与像素延迟；无新增 BRAM/DSP/时钟/物理引脚或 NVM 字段。
- `artifacts`：四个 RTL/布局文件、产品交互说明、本设计、r2 源码哈希/综合报告和布局预览。
- `decision`：可交付用户生成固件并进行功能验收；尚未满足正式时序放行条件。
- `blocking_reason`：无源码实现阻塞；综合 setup 仍有违例，本轮未执行布局布线或 BitGen，不能承诺最终 Slice 和布线时序。
- `next_action`：用户生成当前固件并按六项清单上板验收，通过后提交本功能。
