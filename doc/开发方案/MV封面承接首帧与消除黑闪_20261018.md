# 封面承接 MV 首帧（阶段二，2026-10-18）

MV 加载期间顶层曾在 320×240 视频窗口内强制输出黑色；播放启动和切歌时，MV 帧需要读取完整 300 个扇区并写入 SDRAM，因此黑块会持续到首帧完成。现在 MV 尚未在帧边界提交时继续输出当前已选封面/帧缓存像素，只有有效 MV 缓冲区提交后才切换视频。MV 窗口以外仍沿用原有背景遮罩策略，帧边界提交机制不变。

本阶段不改变视频读取/写入时序，也不改动封面 SD 载入流程。未运行综合、仿真或板上验收；对现有仿真失败提示的文字同步做了语义更新。

## 2026-10-19 交叉验收补修

移除首帧黑色遮罩后，浏览切换的淡入淡出/擦除仍能在进入 PLAY 时压黑整个像素链。新增 `preserve_media`，由帧锁存的播放页面状态驱动：PLAY 跳过浏览 alpha/wipe，保留亮度控制；浏览页继续执行原过渡。

`tb_closure_no_blackflash` 穷举 256 个 alpha、擦除边界并检查亮度控制和浏览行为；`tb_closure_top_handoff` 编译真实 top，仅在硬 IP 边界使用仿真 stub，验证封面/MV 像素均不会被 PLAY 过渡压黑。两项均在 Icarus 与 ModelSim 通过。顶层共享信号声明提前至首次表达式使用之前，解决两种仿真器的 Verilog-2005 编译兼容问题；该整理不增加硬件逻辑。实际 SDRAM、HDMI 与实体卡的联合板测仍待完成。
