# 阶段二：选歌浏览与播放时间显示人工验收

## 本轮变更

- 播放页将歌曲名、歌手放在进度条上方；进度条采用白色已播放段和浅灰色未播放底轨，条下左侧显示已播放时间，右侧显示带负号的剩余时间。
- 播放时间格式为 `0:34` / `-2:10`；歌曲名、歌手和时间使用现有同步字库通路，数字、冒号、负号使用与 EC2 OSD 共用的 ASCII 字库 ROM。
- 选歌浏览页从同一组格式化时间数据读取总时长，避免时长字符走中文字库编码路径。未知时长以 `--:--` 显示。
- 时长计算沿用现有串行除法和 BCD 转换资源，在视频消隐期间逐帧更新；没有新增除法器或独立 ASCII ROM。
- 播放总采样数从 SD/音频时钟域通过稳定数据 CDC 快照传入视频时钟域，避免跨域采样到不一致的高低位。
- 标题和歌手字形各自只有 16 个 16 像素字格；文本窗口现限制为 256 像素，修复原 264 像素窗口在末尾 8 像素将 4 位字格索引回卷到首字形、造成尾部残字的问题。
- 播放页布局调整为媒体画面 y=48..287、歌曲名 y=298、歌手 y=318、进度条 y=342、时间 y=350。浏览页封面、底栏、切歌标记和视频边缘消隐继续沿用原验收项。

## 当前分析结论

旧代码中的分钟/秒 ASCII 转换已经加了 `8'd48`，所以“完全遗漏数字 ASCII 偏移”不是本次乱码的直接原因。浏览时长和播放时间已改为直接读取共用 ASCII 字库；总采样数增加稳定 CDC。后续排查到标题/歌手窗口比 16 个字形槽多 8 像素，低 4 位列索引在末尾回卷；现将窗口收至字库容量。Icarus 回归检查在修改前复现尾部回卷，修改后标题与歌手两行通过；最终显示仍需按下方步骤在板上确认。

## 构建与固件

- SynthPilot 已从当前 `VinylFPGA.al` 完成至 `opt_gate`，并显式加载 `constraints/pin.adc` 与 `constraints/timing.sdc`。
- 本地 TD 原生布局布线及 bitgen 使用隔离快照：`prj/resource_opt_verified_20261005/stage2_playback_time_ui_20261013_r2`。首个快照因补做标题/歌手尾部残影修正而作废，不用于板上验收。
- 快照内 `native_build.log`、`final.qor`、`final.area`、`final.constraints` 是物理实现与时序验收依据；`release_driver.log` 记录后续 bitgen 进度。
- bitgen 通过后固件为 `prj/resource_opt_verified_20261005/stage2_playback_time_ui_20261013_r2/VinylFPGA_optimized.bit`，旁边的 `bitstream.sha256` 记录本轮哈希。
- 仅使用本轮新生成且 bitgen 闭环的 `.bit`。不要拿同目录旧构建、`top_gate.*` 中间文件或其他阶段固件替代。固件写入方式为 JTAG/SRAM，不写 Flash。
- 本轮 SynthPilot opt_gate 资源报告：16,912 LUT（86.29%）、10,553 REG（53.84%）、47/64 BRAM、10/29 DSP。gate 阶段 Setup WNS 为 -305 ps、TNS 为 -983 ps，有 4 个违例端点；最差路径位于 `sd_card_clk` 下 FAT32 卷扫描器。最终固件是否放行以本轮 route 后的 `final.qor` 为准，自动发布脚本会在最终 setup/hold 时序不通过时停止 bitgen。

## 烧录前检查

1. 等待本轮 `release_driver.log` 明确记录 `BITGEN_COMPLETE`，并确认快照目录内存在非空 `VinylFPGA_optimized.bit`、`bitstream.sha256` 和 `.bitgen_param.f`。若布局布线尚未完成，不要烧录。
2. 查看 `native_build.log` 有 `VERIFIED_ROUND_COMPLETE`，且没有 `BUILD_FAILED`、`ERROR` 或 `FATAL`。核对 `final.qor` 中 Setup/Hold WNS 均大于等于 0、Setup/Hold TNS 均为 0；`final.constraints` 中 no-clock、invalid-constraint、combinational-loop 计数均为 0。
3. 核对 `final.area`：BRAM9K 预期 47 块，LUT 与当前快照报告为准。本轮为播放显示增加逻辑，不将阶段二旧版本的 LUT 增量阈值当作新的通过条件。
4. 对照 `bitstream.sha256` 记录固件哈希，验收记录中填写此哈希；若日志出现 `BUILD_FAILED`、`BITGEN_FAILED`、`ERROR` 或 `FATAL`，停止使用该固件。

## 开发板与测试卡准备

1. 使用项目现有 S6 验收卡。需要重写测试卡时，运行 `doc/资源/sd卡/write_card.bat` 并在菜单中选择 **6**（`doc/资源/sd卡/card_S6.img`）；先确认目标盘符是 TF 卡，写入结束后安全弹出。
2. `card_S6.img` 的四首曲目共用同一个 `AUDIO.PCM`，时长约 4 分 05 秒，因此四首歌显示相同的总时长属于预期现象。使用曲号、封面、标题与歌手对应关系检查切歌同步。
3. 连接开发板电源、HDMI、J2 扩展板和 TF 卡，沿用当前稳定版本的拨码设置。
4. 在 Tang Dynasty 下载工具中选择 EG4S20BG256，加载上述本轮 `VinylFPGA_optimized.bit`，执行 JTAG/SRAM 下载，然后复位开发板。

## 人工验收步骤

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 冷启动浏览页 | 下载后复位，等待启动 Logo 结束 | HDMI 显示封面；第一首歌底栏显示 `TRACK 01/04`、`Never Gonna`、`Rick Astley`、`04:05`，数字清晰，无乱码、黑屏或花屏 |
| 浏览总时长 | 依次浏览四首歌，观察右侧时长 | 均能稳定读出 `04:05`；快速切歌时不出现乱码、残字或上一首时长 |
| 浏览信息栏 | 观察底栏及其边缘 | 栏目覆盖封面底部，封面暗化后仍可辨认；边线和分隔线连续，无漏像素 |
| 四曲切换 | 用 EC1 旋转/方向键依次选择第 2、3、4 首，再回到第 1 首 | 曲号依次为 `02/04`、`03/04`、`04/04`；标题/歌手依次为“山湖之间/山野唱片”“森林漫步/绿野唱片”“玫瑰心语/花语唱片”；封面、文字同步更新 |
| 焦点标记 | 每次切歌后观察屏幕下方四个标记 | 当前曲目对应金色标记，其余为灰色标记；顺序与曲号一致 |
| 播放页层次 | 在任一曲目按 EC1 确认进入播放页 | 歌曲名在上、歌手在下，均位于进度条上方；白色已播放段覆盖浅灰色轨道；左下方为已播放时间，右下方为带负号的剩余时间 |
| 标题尾部清洁 | 观察标题和歌手各自最后一个字之后、进度条右端上方 | 最后一个字后是干净背景，不重复出现歌名/歌手的首字残片，也没有错位或残留笔画 |
| 时间格式与更新 | 播放至少 35 秒，在开始和约 34 秒时记录时间 | 开始约为 `0:00` / `-4:05`；约 34 秒时应接近 `0:34` / `-3:31`。秒数始终为两位，冒号、数字清晰，不显示旧式斜杠或乱码 |
| 进度变化 | 连续播放约一分钟，观察进度条 | 白色已播放部分随播放增长，浅灰部分缩短；更新平稳，不闪烁、不反向跳动 |
| 暂停与继续 | 播放时按暂停键，等待 5 秒后继续 | 暂停期间已播放/剩余时间和进度条保持不变；继续后再同步前进 |
| 切歌与返回 | 播放中切歌；按 KEY7 或 KEY11 返回浏览页 | 新歌的标题、歌手、总时长及时间重新对应；返回后封面、文字和焦点一致，无黑帧或残留字符 |
| 结束边界（可选） | 允许一首歌播放到末尾 | 时间不下溢、不出现负值溢出；进度条到达最右端，显示归零状态 |
| HDMI 消隐 | 观察有效画面四周及页面切换 | 有效画面外保持黑色，画面稳定，无彩色杂点 |
