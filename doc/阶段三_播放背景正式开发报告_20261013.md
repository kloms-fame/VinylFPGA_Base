**Goal / 目标：** 在现有稳定播放页中加入四种背景选择与 KEY11 帧边界切换；3A 先交付柔和灰、近黑、模式记忆和图片未就绪回退。

**Architecture / 架构：** 灰底用共享的低位宽坐标运算生成，近黑用常量；图片由电脑离线生成，3B 缓存在 SDRAM 并复用显示 FIFO 分区域读取。3A 将跨域事件与背景控制封装为独立模块，通过播放页已有的一拍 RGB/DE/VS/x 级保持文字、媒体与背景对齐。

**Tech Stack / 技术环境：** Verilog-2001、EG4S20BG256、TD 6.2.168116、SynthPilot MCP、Icarus Verilog、640×480 视频、48 kHz 音频。

## 3. 完整阶段三的背景图片路线

电脑根据四张封面自动生成四张静态彩色背景，并生成一张通用蓝紫光晕图；生成新测试卡镜像，供用户自行写卡。灰/黑模式无需新素材。图片生成与缓存加载属于 3B。

现有 SDRAM 为 2,097,152 个 32 位 Word（8 MB）。

| 区域 | 地址范围（半开区间，Word） |
|---|---|
| 四张封面 | [0, 1,228,800) |
| 三帧 MV | [1,228,800, 1,459,200) |
| 拟定当前歌曲彩色背景槽 | [1,459,200, 1,766,400) |
| 拟定通用艺术图槽 | [1,766,400, 2,073,600) |
| 剩余 | [2,073,600, 2,097,152) |

两背景槽共 2,457,600 Bytes，可放入尾部空闲区域。当前歌曲彩色槽携带曲号/代次/就绪状态，避免切歌期间显示旧图。背景加载采用低优先级扇区调度，音频优先、MV 次之，背景在剩余带宽下推进。

现有显示接口只能顺序读取一幅封面或 MV。3B 需要按区域取媒体和背景，再送入同一显示 FIFO；地址生成以取数进度为准，处理突发边界、刷新和写入竞争。其目标是保留清晰封面/MV，同时不增加片上帧缓存。

## 4. 对参考文件的工程修正

- 640×480 是每帧 307,200 Words；按 60 帧计算显示消费约 73.728 MB/s，必须计入帧率。
- 两个显存槽能容纳背景，不代表仅换基地址就能同时显示清晰媒体与背景。
- KEY11 单拍事件不能直接与 frame_start 相与；先记住请求再整帧提交，防止漏按键。
- 灰度运算使用保证不下溢的有界幅度，避免原参考公式在阈值处突然变亮。
- LUT 数量、最终时序与加载延迟均以测量为准；“18 LUT”“零延迟”不作为承诺。

| 文件 | 责任 |
|---|---|
| 新增 src/display/playback_background.v | KEY11 toggle 同步、待提交/当前模式、灰度和近黑背景生成 |

| 新增 sim/tb_playback_background.v | 验证异步事件、帧边界提交、循环与持久化、渐变范围和回退 |
| 集成验证 | 检查 KEY11 不返回、KEY7 返回、媒体/文字与消隐对齐 |

背景模块运行于 video_clk（25 MHz），低有效 video_rst_n。输入 cycle_toggle_async 来自现有 50 MHz 消抖事件解码；frame_start 来自播放页 VS 边沿，enable 表示播放页。像素坐标和背景输出均属于视频域。

灰底预设为中性灰，每通道约 105～128，随离媒体中心的距离轻微降低亮度。原非当前歌词 606068 在灰底上对比不足，灰底/图片未就绪模式下适配为 B0B4BC；歌手/时间适配为 D0D4D8，沿用原有 text_color_q 寄存级。近黑模式使用原文字配色，当前行金色高亮语义和排版保持。

每个新寄存器显式复位/初始化为 0，独立 always 块控制；组合运算只用比较、移位和加减。顶层负责连接，背景业务封装在子模块。现有 RTL 风格与字库函数沿用。
