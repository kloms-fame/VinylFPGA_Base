## 三、教程链路与本工程的对应关系

教程的数据流：

```text
reader 输出 pixel_rgb
  -> brightness_contrast_adjust
  -> OSD
  -> HDMI
```

完赛工程的实际做法与教程 2.1 一致：亮度不再单独占 3 个乘法器，而是折进
第十讲已有的转场 alpha：

```text
eff_alpha = alpha * (brightness + 1) / 256
fade_rgb = rgb_in * eff_alpha / 256
```

因此：

```text
brightness = 255 时，eff_alpha = alpha，默认画面逐位不变；
稳定显示 alpha = 255 时，亮度退化为 rgb * (brightness + 1) / 256；
转场时亮度和淡入淡出共用同一组 RGB 乘法器。
```

对比度按教程 3.2.2 参考答案独立实现：

```text
out = saturate((bright - 128) * contrast / 128 + 128)
```

其中 `/128` 使用有符号算术右移 `>>>7`，负值按二进制补码正确右移；
三个通道分别做饱和截断，结果限制在 `0..255`。

本工程的实际映射：

| 教程模块 | 本工程实现 | 说明 |
|---|---|---|
| `media_video_pipeline` 中的亮度折入 alpha | `video_transition_apply.v` | 只增加一次 `alpha * (brightness+1)` 乘法 |
| `brightness_contrast_adjust` 练习骨架 | `src/display/brightness_contrast_adjust.v` | 教程 3.2.2 参考答案，保留独立亮度通路，顶层固定接 `255` |
| `param_menu_controller` | `src/io/param_menu_controller.v` | 教程参数菜单思路；本工程只有 KEY1/KEY2，使用双键组合键 |
| `status_osd_overlay` 扩展 | `src/display/status_osd_overlay.v` | 保留第九讲第一行状态，新增第二行 `BxxCyy` |
| OSD 24 位包装 | `src/display/osd_overlay_24.v` | 增加亮度、对比度、菜单三根输入 |

## 五、关键设计决策

### 5.1 亮度折进转场 alpha

完赛工程没有单独的亮度模块，而是让亮度与第十讲淡入淡出共用乘法器。
本工程按这个做法修改 `video_transition_apply`：

```text
brightness_eff = brightness + 1
alpha_mul      = alpha * brightness_eff
effective_alpha = alpha_mul[16:8]
```

默认 `brightness = 255` 时：

```text
effective_alpha = alpha
```

所以默认状态下，第十讲的淡入淡出和自动轮播擦除行为逐位不变。

### 5.2 对比度模块

对比度继续使用教程给出的独立模块，顶层把亮度固定为 `255`，只让对比度
参与这一级：

```text
ctr = signed(bright) - 128
scaled = (ctr * signed(contrast)) >>> 7
sum = scaled + 128
out = (sum < 0) ? 0 : (sum > 255) ? 255 : sum[7:0]
```

`contrast = 128` 时，三个通道都严格回到输入值，默认状态不改变画面。

### 5.3 KEY1/KEY2 组合键参数菜单

教程完赛工程使用 KEY4，但本工程物理上只有 KEY1/KEY2。第 2.4 节明确允许
组合键方案，因此本讲采用：

```text
KEY1 + KEY2 同时长按 1 秒后松开：进入 / 退出参数菜单
菜单内 KEY1 短按：亮度 +1 档
菜单内 KEY1 长按 1 秒：亮度 -1 档
菜单内 KEY2 短按：对比度 +1 档
菜单内 KEY2 长按 1 秒：对比度 -1 档
菜单内 10 秒无操作：自动退出
```

档位表与教程一致：

```text
亮度/对比度档位：0、64、128、192、255
默认值：brightness = 255，contrast = 128
亮度 +1 从 255 绕回 0；亮度 -1 从 0 绕回 255
对比度同理
```

菜单外两路按键完全直通原有逻辑；组合键按住期间和菜单打开期间，原有
KEY1/KEY2 输出强制为松开态，避免误触发“下一张 / 上一张 / 轮播”行为。

### 5.4 跨时钟域与帧边界锁存

参数菜单运行在 `sd_card_clk`（100 MHz）域，像素处理运行在 `video_clk`
（25 MHz）域。亮度、对比度和菜单状态先经过两级同步，再在 `frame_start`
锁存：

```text
sd_card_clk 域：cfg_brightness / cfg_contrast / menu_active
        -> 两级 2FF 同步
        -> video_clk 域 frame_start 锁存
        -> 整帧使用同一组参数
```

这样调参时不会出现上半帧旧参数、下半帧新参数的撕裂。

### 5.5 对比度流水线与像素对齐

`brightness_contrast_adjust` 内部有一拍输出寄存器。本工程在顶层同步移动
像素坐标：

```text
in_de      -> adjusted_de
pixel_x    -> adjusted_pixel_x
rgb        -> adjusted_rgb
```

OSD 和音频波形都使用 `adjusted_de` / `adjusted_pixel_x`，因此 OSD 仍然
位于最上层，波形仍然位于 OSD 之后。

### 5.6 菜单 OSD 显示

`status_osd_overlay` 保留第九讲原有的第一行状态字符：

```text
图片序号 + 自动/手动 + 错误码高/低半字节
```

菜单打开时，在第二行显示：

```text
BxxCyy
```

其中 `xx` 是亮度的十六进制值，`yy` 是对比度的十六进制值。例如
默认状态显示 `BFFC80`。OSD 字符在对比度模块之后叠加，所以菜单文字
不会被亮度/对比度再次处理。

## 八、已知边界与风险

1. 本工程只有 KEY1/KEY2，组合键长按是最小侵入方案；组合键按住期间
   原有两键功能会被暂时屏蔽，这是为避免误触发而做的设计取舍。
2. 参数菜单当前只在运行时生效，未接入 Flash 持久化；复位后恢复
   `brightness=255`、`contrast=128`。
3. OSD 参数显示采用十六进制 `BxxCyy`，与第九讲 4 字符 OSD 的半字节
   字体保持一致，没有新增完整十进制字库。
4. 亮度折入转场 alpha 是教程 2.1 的完赛工程做法；稳定显示和默认参数
   下逐位旁路，但调亮/调暗时亮度与淡入淡出会共用同一组乘法器。
5. 本讲没有改动 SD 卡、SDRAM、HDMI IP、PLL、FIFO、视频时序和约束文件；
   最终时序收敛通过物理种子实现，没有为时序去改 SD 卡功能语义。
