## 一、 现状物理穿透核查与设计冲突终局裁决

### 1. 代码已有资产与四大致命断点

1. **输入链断点（高危）**：`expansion_io_hub` 与 `ui_event_bus` 已打通 EC2 正交解码与按压事件，但在 `src/io/ui_event_bridge.v:55, 59` 中仅处理了 `ev_aux[1]==1'b0`（EC1），完全缺失对 `ev_aux[1]==1'b1`（EC2）的分流。EC2 物理动作在进入桥接层后被**全数静默丢弃**，这是 X5 必须首先修复的断点。

## 二、 交互核心：EC11-B 风格无菜单浮窗 OSD 架构

本设计彻底摒弃破坏视听沉浸感的传统二级树状菜单，将右旋钮 EC2 升格为全局最高优先级的“即拧即调、盲操感知”参数浮窗。   

```
                        ┌────────────────────────────────────────────────────────┐
                        │      EC2 调参浮窗 190×64 @ 屏幕顶部 (225, 58)           │
                        │ ┌────────────────────────────────────────────────────┐ │
                        │ │ ▓ 音量·调节中 (金)                         200     │ │ ← 行1: 标签(12px) / 数值(16px粗)
                        │ │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░             │ │ ← 行2: 进度槽(8px高), 填充宽∝Ratio
                        │ │       调节中 · 按下返回选择 (10px 暗灰)             │ │ ← 行3: 操作提示串
                        │ └────────────────────────────────────────────────────┘ │
                        └────────────────────────────────────────────────────────┘
```

### 1. 三态 FSM 与状态双计时器（绝对时刻法）

- **三态逻辑真值表**：   
  - `IDLE`：面板不渲染。旋转 EC2 任意方向 $\to$ **直接弹出浮窗并顺势切换一格参数项**（不卡顿在初始项），进入 `SELECT`；按下 EC2 $\to$ 弹出浮窗，停留在当前参数项，进入 `SELECT`。   
  - `SELECT`（青色边框 `#00CED1`）：旋转 EC2 $\to$ 在有效参数表中循环滚选（`idx = (idx ± 1 + N) % N`）；按下 EC2 $\to$ 蜂鸣器发 **1320 Hz / 50 ms 高音**，边框变金 `#FFD700`，进入 `ADJUST`。   
  - `ADJUST`（金色边框 `#FFD700`）：旋转 EC2 $\to$ 实时修改当前参数数值并立即硬件生效（音量无延迟变音、亮度当场缩放）；按下 EC2 $\to$ 蜂鸣器发 **990 Hz / 50 ms 低音**，边框退回青色，回到 `SELECT`。   
- **双计时器解耦架构（严禁合并）**：   
  - **OSD 视觉窗口（1800 ms）**：控制面板图形的显示与淡出。最后一次物理操作后维持 1.8 秒，超时后面板淡出隐藏。   
  - **FSM 逻辑空闲窗口（3000 ms）**：控制状态机上下文生命周期。最后一次物理操作后维持 3.0 秒，超时后状态机静默复位至 `IDLE`（下次操作从音量重新起步）。   
  - **1.2 秒上下文记忆盲区**：在 1.8s ~ 3.0s 之间，虽然面板已隐藏，但用户若再次拧动旋钮，状态机**直接继承上次的调节上下文并瞬间重现浮窗**，保证操作手感高度跟手。   
  - **实现方式**：基于 50 MHz 提出的 1 ms 时基，维护自由递增 `ms_cnt[31:0]`，采用 `ms_cnt < osd_deadline` 的绝对比较法，彻底根除递减计数器的装载抖动与周期偏移。   

### 2. 参数项动态过滤与边界保护

系统参数表内置 4 项核心物理参数（静音作为布尔项并入）：   

| **索引 idx** | **参数标识**     | **类型** | **取值范围与步长**                           | **状态过滤条件**     | **硬件受控落点**                   |
| ------------ | ---------------- | -------- | -------------------------------------------- | -------------------- | ---------------------------------- |
| `0`          | **音量 (VOL)**   | 连续值   | `32 ~ 255`，步长 `16`（默认 200）            | 全局可见             | `pcm_volume_fade.v` 增益乘法器     |
| `1`          | **亮度 (BRI)**   | 离散档   | 5 档 LUT（0, 64, 128, 192, 255）             | 全局可见             | `brightness_contrast_adjust.v`     |
| `2`          | **对比度 (CON)** | 离散档   | 5 档 LUT（0, 64, 128, 192, 255）             | 全局可见             | `brightness_contrast_adjust.v`     |
| `3`          | **进度 (SEEK)**  | 时间戳   | `[0, total_samples)`，步进 ±2s（96000 样本） | **仅在 PLAY 态可见** | `wav_stream_player` 目标扇区重定位 |

- **动态列表长度与钳位保护**：播放中有效项数 $N=4$；浏览态或开机态进度项隐藏，有效项数 $N=3$。当用户在播放态将光标停留在进度项（`idx=3`）并退出播放时，进入浏览态的瞬时必须执行 `idx <= (idx >= N_eff) ? (N_eff - 1) : idx` 强制钳位，杜绝读出未定义地址导致的 OSD 乱码。   

### 3. OSD 像素级流式合成与 CDC 同步

- **插入层级锚定**：

  $$\text{SDRAM 原始流} \to \text{转场应用} \to \text{亮度/对比度} \to \text{波形图} \to \text{MV/黑胶} \to \text{三行歌词} \to \mathbf{knob\_osd\_panel} \to \text{消隐与 Boot 选通} \to \text{HDMI}$$

  面板插在歌词层之上、屏幕消隐（`blank_active`）之下，保证调参绝不被任何多媒体图层覆盖，且在消隐关屏时同步隐匿。   

- **首版无 BRAM 纯组合渲染**：为规避同步 BRAM 带来的一拍流水线延迟和行缓冲状态机开销，首版字符采用 ASCII 短标签（`VOL`, `BRI`, `CON`, `SEEK`），复用 `lrc_font_rom` 的 16×16 点阵资源。面板背景采用 4 档硬件 Alpha 混色（25%、50%、75%、100%），以纯移位加法器实现，零 DSP 消耗。   

- **跨时钟域快照（50 MHz $\to$ 25 MHz）**：50 MHz 域维护 `knob_frame_data[31:0]` 与单比特翻转 `knob_frame_tog`。视频像素域在场消隐期（`frame_start`）对数据实施锁存快照，像素扫描期全程只读稳定副本，彻底隔绝撕裂。

### 各阶段详细实施规程与完成定义（DoD）

#### 阶段 X0：基线物理板验与交互欠账清算（不改写业务 RTL）

- **核心目标**：解除主干代码与物理板卡状态脱节的风险，为后续拓展建立可信的测量学基线。   
- **具体工作**：
  1. 烧录最新快照 `S7_03b_key07_key11_20261006_s7` 比特流（SHA256: `23fd3bb1...`）。   
  2. 执行人工板验：验证 KEY07 直达缩略图、KEY11 全局返回主界面，使用测试卡录制 10 分钟连续播放视频，量化音画同步误差（确认 $\le 100\text{ ms}$）。   
  3. **UR=0005 欠载归因排查**：通过抓取串口 `STAT` 帧，排查连续切歌时产生 5 次 underrun 的物理诱因（判定系真实 SD 读取抖动还是 `health_monitor` 上电初始误报）。   
  4. **J2 端口 IO 约束审计**：对 IDC40 排线上的高频数据建立时序裕量记录表，重点针对 WS2812 800 kHz 数据线的波形完整性进行评估。   
- **交付门禁（DoD）**：输出 `X0_board_verification_report.md`，S6 与 S7-03b 板级验收项全数归档确认。   

#### 阶段 X1：状态反馈与外设执行器落地（R1 日用交互版）

- **子阶段 X1A（LED 语义化与数码管自愈多路复用）**：
  - *模块新建*：`src/io/led_status.v` 与 `src/display/seg_content.v`。   
  - *逻辑改动*：在 `expansion_integration.v` 中解开 `exp_led_n` 直通逻辑，将 LED1 分配为有效 IR 脉冲（单次展宽 80 ms）、LED2 为业务操作确认（80 ms）、LED3 为系统心跳（1 Hz）、LED4 为 `health_monitor` 故障常亮。引入 DIP3（`led_enable`）作为总开关。   
  - *数码管状态树*：构建严格的硬件仲裁器：错误状态 `Err-01..09`（最高）$>$ 调参临时覆盖态（维持 2 s）$>$ 播放态 `xx-MM:SS`（连字符常亮，秒点闪烁，封顶 99:59）$>$ 浏览态 `Song xx`。   
- **子阶段 X1B（WS2812 驱动移植与双模控制器）**：
  - *驱动迁入*：引入 `ws2812_driver.v`，运行于 50 MHz 晶振时钟，精准生成 800 kHz NRZ 码（位周期 63 拍，0 码高电平 18 拍，1 码高电平 35 拍，Reset 锁定 3000 拍）。   
  - *控制器构建*：新建 `ws2812_effects.v` 与 `pcm_tap.v`。提取有效 PCM 采样点绝对值（特别处理 `-32768` 边界），以 60 Hz 场同步为衰减步进，实现 8 级阈值映射（灯 15 绿，67 橙，8 红）；从 `song_index_db` 导出条目偏移 20 的 `audio_bytes`，以 `audio_bytes / 2` 为总样本分母驱动进度条填充模式。   
  - *KEY10 与 DIP6 闭环*：KEY10 在“全灭 $\to$ 律动 $\to$ 进度”之间循环切换；DIP6 关闭时，控制器先行强制下发一帧 8 灯全黑数据并完成硬件锁存，随后保持总线为低，禁止硬切产生半帧偏色。   
- **交付门禁（DoD）**：示波器实测 WS2812 波形满足时序容限；连续播放 1 小时音频欠载计数不增加；DIP3/DIP6 关断 100 ms 内物理器件彻底熄灭。   

#### 阶段 X2：歌曲结束策略、重播与 Seek（传输层大闭环）

- **核心目标**：将红外进度控制键转为真实功能，消除播放异常中断导致的死锁。   
- **具体工作**：
  1. **结束策略（KEY12）收口**：在 `play_ctrl.v` 中修正 `end_mode` 状态机语义，明确第 0 态为“播完返回浏览态（`go_home`）”，第 1 态为“单曲循环重播”，第 2 态为“顺序下一曲（最后一首自动回绕第一首）”。   
  2. **两级 EOF 安全防线**：保持 `wav_stream_player` 写侧 `finished` 与读侧 FIFO 排空双重校验，杜绝因存储卡突发延迟将卡顿误判为歌曲播完。   
  3. **±5 秒连续 Seek 引擎**：

## 四、 资源红线与极限时序防御机制

### 1. 资源红线阶梯式防御预案

当前 Slices 占用率为 **85.84%（8412 / 9800）**，距离 88% 的安全阈值仅剩 **212 个 Slices**！后续开发必须严格遵守以下资源法则：   

1. **全局编译门禁**：所有发布快照必须严格执行带有 `--map-mode area_prior` 的构建脚本，严禁使用 TD GUI 默认流程（后者会导致 Ripple-LUT 激增 1100+ 导致溢出）。   
2. **阶梯式减负响应机制**：
   - *Slices $\le 88.0\%$*：正常推进下一阶段。   
   - *88.0\% < \text{Slices} \le 90.0\%*：**触发减负评估**，必须首先执行无损逻辑优化（如缩减 `key_dip_monitor` 消抖计数器位宽、删除各状态机中位宽不对齐的冗余比较器、精简 `expansion_integration` 树形结构），使 Slices 回落至 84% 以下后方可继续编码。   
   - *Slices $> 90.0\%$*：**绝对红线**！立即挂起当前阶段，无条件砍掉或降级候选功能（例如放弃 X3B 真实 FFT、将 OSD 界面进一步静态压缩）。   

### 2. 贴线时序（Hold +3 ps）保护规范

1. **100 MHz 域运算全流水化**：`sd_card_clk` 域严禁出现“长链条比较/大位宽乘除后直接作为使能端”的组合逻辑，所有地址偏移运算必须拆分为两拍流水，复用 `fat32_media_loader` 中已成功验证的 `pixel_end` 加法外提模式。   
2. **多 Seed 扫描规则**：单次构建时序收敛不能证明结构余量充裕，每次提交必须执行 Seed 扫描（推荐 Seed: 7, 5, 1, 2, 3），只有在多数 Seed 下 Setup/Hold 均非负、TNS=0、违例端点为 0 时才可准入放行。严禁使用伪造 `false_path` 或放宽时钟周期的手段欺骗工具。
