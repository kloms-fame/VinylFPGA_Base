## 1. S3 做了什么（一句话）

把"选哪张封面"的**业务入口**从"母板 KEY1/KEY2"迁到 `ui_event_bus`：
J2 **EC1 旋转 + 方向键**驱动当前封面选择，**EC1 按压/KEY02** 确认；
母板 KEY1/KEY2 仍并联为兜底通路；**不触碰** 2×2 缩略图布局、四 bank 预加载、
选图握手与转场行为。

## 2. 修改后的 RTL 文件清单与关键差异

### 2.3 为什么这么切（边界与理由）

```text
J2 EC1/方向键 ──► expansion_io_hub ──► ui_event_bus ──┬─► exp_echo_reporter（串口回显，不变）
                                                      └─► ui_event_bridge（clk 域选曲解码）
                                                              │ 4×toggle（单比特电平）
                                                              ▼ 3FF 同步 + 边沿
母板 KEY1/KEY2 ──► key_press_hold ────────────────────► browse_fsm（sd 域按 view_mode 路由）
                                                              │
                    ┌─────────────────────────────────────────┴───────────────────────────┐
                    ▼                                                                     ▼
          全屏：fs_next→既有转场                                 缩略图：focus/confirm/mode
          （整帧边界切换）→ sd_card_bmp                            → thumbnail_controller（原封不动）
          全屏：fs_prev→sd_card_bmp.prev_event
```

- **不新写浏览/取数逻辑**：`thumbnail_controller.v`、`thumbnail_layout.v`、
  `thumbnail_view_reader.v`、四 bank 预加载与 `select_req/select_ack` 握手**一行未改**。
- **CDC 复用 S2 已验证手法**：单比特电平翻转 + 目标域同步 + 边沿检测，
  1 次事件只产出 1 拍；事件间隔（编码器 ~ms 级）远大于同步延迟（~30 ns）。
- **状态跳转仍在 `frame_start` 边界提交**（沿用 `thumbnail_controller` 的 `trans_pend/transition_req`）。
- **全屏"下一张"复用既有转场路径**（`fade_start_event_sd → fade_next_event → sd_card_bmp.next_event`）；
  全屏"上一张"复用既有 `prev_req_pending` 分支，因此"已实现的浏览与取数行为"不变。

## 3. 事件编码格式（沿用 S1，`src/include/exp_event_defs.vh`）

总线本体**未改动**：单拍有效、同一拍只分发一个，
优先级 `KEY_DOWN > KEY_UP > DIP > EC 步进 > EC 按压 > IR`。

| `ev_code` | 名称 | `ev_arg[15:0]` | `ev_aux[15:0]` |
|---:|---|---|---|
| 0 | `EV_NONE` | - | - |
| 1 | `EV_KEY_DOWN` | `key_index` (0..11) | 0 |
| 2 | `EV_KEY_UP` | `key_index` (0..11) | 0 |
| 3 | `EV_DIP_CHANGE` | `{12'b0, dip_level, dip_index[2:0]}` | 0 |
| 4 | `EV_ENC_STEP` | `enc_count[15:0]` | `{14'b0, enc_id, direction}` |
| 5 | `EV_ENC_SW` | `{15'b0, pressed}` | `{15'b0, enc_id}` |
| 6 | `EV_IR_FRAME` | `ir_code[15:0]` | `ir_code[31:16]` |
| 7 | `EV_IR_REPEAT` | `ir_code[15:0]` | `ir_code[31:16]` |

约定：`enc_id` 0=EC1 / 1=EC2；`direction` 0=递增(+) / 1=递减(-)；
`EV_ENC_SW` 的 `ev_arg[0]`：**0=按下(DOWN) / 1=释放(UP)**。

### 3.1 S3 新增的"事件 → 选曲动作"映射（`ui_event_bridge.v`）

| 选曲事件 | 触发条件 | 全屏态动作 | 缩略图态动作 |
|---|---|---|---|
| `prev` | `EV_ENC_STEP` 且 EC1 且 `direction=1`；或 `EV_KEY_DOWN` idx=0(KEY01左)/3(KEY04上) | `fs_prev`：显示上一张 | `thumb_left`：焦点 3→2→1→0→3 |
| `next` | `EV_ENC_STEP` 且 EC1 且 `direction=0`；或 `EV_KEY_DOWN` idx=2(KEY03右)/4(KEY05下) | `fs_next`：显示下一张（转场） | `thumb_right`：焦点 0→1→2→3→0 |
| `confirm` | `EV_ENC_SW` 且 EC1 且 DOWN；或 `EV_KEY_DOWN` idx=1(KEY02中) | 进入 2×2 缩略图 | 确认焦点并返回全屏 |
| `mode` | `EV_KEY_DOWN` idx=6(KEY07切歌模式) | 进入/退出缩略图 | 进入/退出缩略图 |

> EC2 不参与 S3 选曲（预留给后续播放控制）；红外事件不参与 S3（留待 S7 完整映射）。

### 3.2 母板兜底通路（与事件侧并联，不覆盖）

| 母板按键 | 全屏态 | 缩略图态 |
|---|---|---|
| KEY1 短按 | 下一张 | 焦点 +1 |
| KEY1 长按 1 s | 进出缩略图 | 进出缩略图 |
| KEY2 短按 | 自动轮播开/关（既有） | 焦点 −1 |
| KEY2 长按 1 s | 上一张（既有） | 确认（既有） |

`S3_J2_BROWSE_ENABLE=1'b0` 时事件侧整体旁路，上表母板行为与 S2 完全一致。

## 4. 串口输出格式（**无变化**）

115200 8N1，`uart_tx = D12`，由 `ECHO_TEST_ENABLE` 开关；事件驱动、静止无输出。
S3 **不新增任何串口行**：`exp_echo_reporter` 仍独立旁听同一 `ui_event_bus`，因此
选曲事件的串口表现与 S1/S2 一致，可直接用它做上板对照：

```text
VINYL EXPHUB S1          上电横幅（1 条）
BOOT LOGO / BOOT DONE    S2 启动窗口
KEY nn DOWN / KEY nn UP  nn=01..12
DIP n v                  n=1..6，v=消抖电平（上拨=1）
ENCx +/- hhhh            EC1 旋转；S3 下每一拍同时切换封面
ENCx SW DOWN / ENCx SW UP
IR hhhhhhhh CMD hh / IR REPEAT
```

即：看到 `ENC1 + 0001` 时应同步看到封面切到下一张；`ENC1 - 0002` 切上一张；
`ENC1 SW DOWN` 进入/确认缩略图；`KEY 07 DOWN` 进出缩略图。

### 6.3 时序收敛说明（为什么改用 seed 1）

seed 7 下路由失败：Setup WNS `-850 ps`、2 个违例端点。逐条定位后**全部落在既有
`sd_card_bmp_m0/fat32_media_loader_m0`（100 MHz）内部**（`data_offset_reg → pixel_byte_cnt_reg`
的组合路径，逻辑级数 9、最大扇出 33），**不在任何 S3 新增逻辑上**（S3 逻辑本身深度 < 5）。
这与 S1 记录的现象一致（该既有 100 MHz 路径对布局种子敏感，S1 即由 seed 5 改 seed 7 收敛）。
做法：保留同一份 `gate.db`，扫描种子重做 place/route，**seed 1** 收敛为
Setup `+106 ps` / Hold `+4 ps`、0 违例。**未使用任何假路径或放宽约束**。

> 过程快照：`S3_browse/`（seed 7，失败证据 + 供种子扫描用的 `gate.db`）、
> `S3_browse_s1/`（用 `--gate` 复用 gate.db 的种子扫描产物）、
> `S3_browse_v1/`（**正式产物**，全流程从 RTL 重跑）。
