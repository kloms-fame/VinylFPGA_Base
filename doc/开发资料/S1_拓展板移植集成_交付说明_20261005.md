### 1.4 black box 的成因与加固（收尾修复）

现象：直接用 `VinylFPGA.al` 编译时报
`ERROR: expansion_integration(...) is a black box in ../../../src/top_tf_hdmi_audio.v(1536)`。

成因：该报错的含义是"`top` 例化的模块没有被综合分析到"。S1 的 12 个源文件记录在 `.al` 的 Verilog 文件列表里，一旦 TD 侧工程文件列表不完整（条目丢失、相对路径基准变化、GUI 保存后重写）就会漏掉 `expansion_integration.v`，于是 `top` 里的例化变成黑盒。本机用同一份 `.al` 走 `open_project`/`elaborate` 时 76 个源文件全部通过，说明问题出在"文件列表是否被带进综合"，不是 RTL 语法。

加固（双层，互不冲突）：

1. `src/top_tf_hdmi_audio.v` 顶部用 include 把 12 个 S1 源文件拉进同一编译单元（`io/sync_bit.v` … `io/expansion_integration.v`）。只要 `top` 在工程里，S1 一定被分析到。
2. 12 个源文件各自加模块级包含保护（`` `ifndef <MACRO> / `define <MACRO> / ... / `endif `` 包住整个文件）。于是即使 `.al` 仍单独列出这些文件，TD 第二次分析会被保护跳过，不会重复定义。

注意：`exp_event_defs.vh` 里是 module 作用域的 `localparam`，不能加包含保护——TD 预处理器是全局的，加保护会让第二个包含它的模块拿不到常量并报 `HDL-8007 ... is not declared`。

独立源文件仍然保留，供 lint 与 iverilog 单模块仿真使用。

## 2. 事件编码格式（`ui_event_bus` 输出）

单一事实来源：`src/include/exp_event_defs.vh`。事件为单拍有效，同一拍只分发一个，优先级：`KEY_DOWN > KEY_UP > DIP > EC 步进 > EC 按压 > IR`。

| `ev_code` | 名称 | `ev_arg[15:0]` | `ev_aux[15:0]` |
|---:|---|---|---|
| 0 | `EV_NONE` | - | - |
| 1 | `EV_KEY_DOWN` | `key_index` (0..11) | 0 |
| 2 | `EV_KEY_UP` | `key_index` (0..11) | 0 |
| 3 | `EV_DIP_CHANGE` | `{12'b0, dip_level, dip_index[2:0]}` | 0 |
| 4 | `EV_ENC_STEP` | `enc_count[15:0]` | `{14'b0, enc_id, direction}` |
| 5 | `EV_ENC_SW` | `{15'b0, pressed}` | `{15'b0, enc_id}` |
| 6 | `EV_IR_FRAME` | `ir_code[15:0]` | `ir_code[31:16]` |
| 7 | `EV_IR_REPEAT` | `ir_code[15:0]` | `ir_code[31:16]` |

约定：`enc_id` 0=EC1 / 1=EC2；`direction` 0=递增(+) / 1=递减(-)；`pressed` 1=按下。
NEC 帧布局 `{Addr[31:24], ~Addr[23:16], Cmd[15:8], ~Cmd[7:0]}`：命令字节取 `code[15:8]`，判键用高 8 位地址 `code[31:24]`。
DIP 电平直接沿用标定实测语义（上拨=1），不做二次取反。

## 3. 串口输出格式（v2：事件驱动，无周期刷屏）

串口沿用 J2 标定工程配置：115200 8N1，板载 USB 转 UART，`uart_tx = D12`（顶层参数 `ECHO_TEST_ENABLE` 开关；=0 时保持空闲高电平、完全静默）。上电打印一次横幅 `VINYL EXPHUB S1`，之后只在动作发生时输出，静止时无任何输出。

### 3.1 KEY 事件行（最简格式）

```text
KEY nn DOWN
KEY nn UP
```

| 字段 | 含义 |
|---|---|
| `nn` | 01..12，= `exp_key_n` 数组位 + 1 |
| `DOWN/UP` | 本次事件是按下还是释放 |

实测样例（本机仿真）：

```text
KEY 04 DOWN
KEY 07 UP
```

### 3.2 其余事件行

```text
DIP n v              n=1..6，v=当前消抖电平（上拨=1）
ENCx +/- hhhh        x=1/2，+递增 / -递减，hhhh=16 位计数
ENCx SW DOWN / ENCx SW UP
IR hhhhhhhh CMD hh   hhhhhhhh=32 位 NEC 码，hh=命令字节 code[15:8]
IR REPEAT
```

行尾统一 CRLF。事件队列深度 8；持续高速旋转时若队列满只翻 `q_overflow` 标志，不覆盖已有事件。

变更说明：v1 曾每 250 ms 打印一行 `EXP KEY ...` 状态快照，静止时也会持续刷屏。v2 已删除该周期行，其"按下/释放状态 + 事件计数"信息合并进 KEY 事件行。

## 8. 操作反馈音（蜂鸣器）

### 8.1 硬件事实（先确认再实现）

| 结论 | 依据 |
|---|---|
| 母板**有**蜂鸣器，`BUZZER` = **H11**，PNP 驱动，**低电平鸣叫**，硬件 **SW5** 串联通断 | 原理图 `2_FPGA.pdf`（`IO_BE3N_0H11` + `NLBUZZER`）；`资源/开发方案/开发方案.md`、`产品交互.md`；J2 工程 `constraints/interaction_showcase.adc` |
| **拓展板没有蜂鸣器器件** | `4_GPIO.pdf`（J2/GPIO 页）搜不到任何 BUZ/BEEP/蜂鸣；`产品交互.md` 原文"扩展板无蜂鸣器，为母板独有" |
| 拓展板可用的音频落点只有 J2 的 `exp_ext_o`（U11 EXT1‑6 预留排母，可外接蜂鸣器/蜂鸣器模块） | `产品交互.md` / `开发方案.md` 的 U11 说明 |

因此实现为：**母板 H11 直接发声**；同时把**同一蜂鸣波形**送到 **EXT1（`exp_ext_o[0]`）**，
供拓展板外接蜂鸣器使用。EXT2‑EXT6 仍固定 0。

### 8.2 母板按键 / 拨码引脚（原理图 U7 网络表）

| 功能 | FPGA 引脚 | 状态 |
|---|---|---|
| KEY01 | A2 | 已被现有 `rst_n` 占用，不重复接入 |
| KEY02 | B2 | 现有 `key1`（主链路切图键），本轮接入反馈音 |
| KEY03 | B1 | **本轮新增** `key3`，接入反馈音 |
| KEY04 | C1 | 现有 `key2`（主链路轮播键），本轮接入反馈音 |
| SW1 | C8 | **本轮新增** `sw1` |
| SW2 | C7 | **本轮新增** `sw2` |
| SW3 | C6 | **本轮新增** `sw3` |
| SW4 | C5 | **本轮新增** `sw4` |
| 蜂鸣器 | H11 | **本轮新增** `board_buzzer_n` |

> 注意：主工程既有的 `key1`/`key2` 端口命名沿用不改（改动会波及已验证的主链路）。
> 按原理图网络表，它们实际落在 B2/C1（即丝印 KEY02/KEY04），`rst_n` 落在 A2（KEY01）。

### 8.3 事件源与音调

`buzzer_feedback` 逐字移植自 J2 标定工程，运行在 50 MHz `clk` 域（与标定工程同频，
默认音调参数无需换算）。并入的触发源：

| 来源 | 事件 |
|---|---|
| 母板 | `key1`/`key2`/`key3` 按下；`sw1`~`sw4` 改变 |
| 拓展板 | KEY01‑12 按下；DIP1‑6 改变；EC1/EC2 旋转步进；EC1/EC2 按压；红外新帧（不含 REPEAT） |

音色沿用标定固件（KEY / DIP / EC 正向 / EC 反向 / 编码器按压 / 红外，各有不同音高；
DIP 为低‑高双音；优先级 按压 > 红外 > 拨码 > 按键 > 旋转）。

### 8.4 使能与验证

- 软件总开关：顶层参数 `BUZZER_FEEDBACK_ENABLE`（默认 `1'b1`；置 0 立即静音）。
- 母板蜂鸣器还需硬件 **SW5 拨到接通档**才会发声（纯硬件通路，FPGA 无法绕过）。
- 仿真：`sim/tb_expansion_s1.v` 增加两项断言并通过 —— `PASS board SW feedback tone`
  （母板拨码改变 → 蜂鸣器进入鸣叫）、`PASS buzzer feedback on key press`（按键 → 鸣叫，且 EXT1 同步）。
- 移植保真：J2 原版 `tb_buzzer_feedback.v` 对移植后的模块 `TEST_PASS buzzer_feedback_sequences_priority_and_gate`。

### 8.5 新增约束片段

```tcl
# 母板蜂鸣器：H11，PNP 驱动，低电平鸣叫；硬件 SW5 必须拨到接通档
set_pin_assignment	{ board_buzzer_n }	{ LOCATION = H11; IOSTANDARD = LVCMOS33; DRIVESTRENGTH = 8; PULLTYPE = NONE; }

# 母板按键 / 拨码（原理图 U7 网络表：KEY_3=B1，SWKEY_1..4=C8/C7/C6/C5）
set_pin_assignment	{ key3 }	{ LOCATION = B1; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment	{ sw1 }	{ LOCATION = C8; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment	{ sw2 }	{ LOCATION = C7; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment	{ sw3 }	{ LOCATION = C6; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment	{ sw4 }	{ LOCATION = C5; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
```

> 拨码电平按"上拉 + 上拨=1"处理（与 J2 DIP 语义一致）。即使实际拨码极性相反，
> 也只影响双音的高低顺序，不影响"改变即发声"的结论。
