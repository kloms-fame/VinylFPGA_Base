## 1. 反馈"开机不显示 Logo"的根因与修复

### 1.1 根因一：只下 SRAM，上电跑的是 Flash 里的旧镜像（主因）

本板是**配置 Flash 上电自启**结构：

- 用户数据 SPI Flash：`W25Q64`（用户 SPI 实验用，**不是**配置芯片）；
- **配置 Flash：`W25Q16`（MSPI，JEDEC `EF 40 15`）**，掉电保存 FPGA 配置镜像。

此前 S2 只做了 `download -mode jtag`（易失 SRAM 下载），**没有写配置 Flash**。
因此断电重上电后，FPGA 从 Flash 里配置的是 S1 老镜像——该镜像里根本没有 Logo 图层，
所以"开机不显示 Logo"；而"开机到出图约 4 秒"正是 SD/FAT32 扫描加载首图的时间。

**修复**：用 BitWizard 把 S2 位流写入配置 Flash（第 6.4 节）。

### 1.2 根因二：图源已换成透明背景 PNG

`doc/资源/VinylFPGA_640x480.jpg` 已删除，改为 `doc/资源/开机logo透明背景.png`。
生成器与 ROM 已按新图源重新生成（用 alpha 通道求内容包围盒）。

### 1.3 顺带确认：片内 ROM 的初值确实被 TD 采用

为排除"TD 不支持 `initial` 推断 ROM 初值"，做了对照实验：同一工程、同一 seed，
只把 `boot_logo_rom.v` 的初值全部换成同一常量 → RAM 数从 **46 降到 34**。
只有综合真的读取并传播了初值才会出现这种化简，**结论：初值有效，ROM 正常**。

### 1.4 根因三（真正的功能 bug）：场同步低有效，行计数被压死在 0

用户把 Flash 固化后复测，仍然"上电黑屏 → 直接出图"。定位到这是**硬件时序极性**问题：

- `src/SD/color_bar.v` 在 640×480 配置下是 `VS_POL = 1'b0`，即 **vs 低有效**：
  vs 只在场同步脉冲那 2 行拉低，其余 523 行**保持高电平**；
- 而 `boot_layer` 最初写的是 `if (vs) pixel_y <= 10'd0;`（"vs 为高就清零行计数"）。
  结果行计数几乎一直为 0，**永远进不了 Logo 的 Y 范围 `[88,385]`**，整屏全黑；
- 之前的 `sim/tb_boot_s2.v` 把 vs 建模成"高有效单拍脉冲"，因此仿真通过、上板失败。

**修复**（`src/boot/boot_layer.v`）：行计数清零改用与主链路同一个帧边界判据
`frame_start`（`vs_q & ~vs`），不再依赖 vs 电平极性：

```verilog
if (frame_start)            pixel_y <= 10'd0;   // 帧边界清零（与极性无关）
else if (!de && de_q)       pixel_y <= pixel_y + 10'd1;
```

**回归证据**：把测试台的 vs 改成真实低有效后，修复前 `FAIL logo too sparse, nonblack=0`
（与板上现象完全一致），修复后 `PASS boot logo rendered: nonblack=43236 ...`。

> 教训：新增像素层必须按 `color_bar.v` 的真实极性建模（HS_POL=0 / VS_POL=0），
> 不能用"高有效脉冲"的惯例假设。

### 1.5 根因四（上板仍黑屏的真正原因）：上电消抖收敛被误当成"用户跳过"

修好 vs 极性后上板仍然黑屏，最终定位到**上电瞬间的假事件把 Boot 跳过**：

`src/io/sync_bit.v` 与 `src/io/debounce_filter.v` 的上电初值都是 `1`，而
`debounce_filter` 在消抖时间（8 ms）到点后发现"真实电平 ≠ 初值"就报一次**变化**：

| 输入 | 上电时的真实电平 | 后果 |
|---|---|---|
| J2 拨码 `exp_dip_n[k]` | 拨在 "0" 位时读 0 | `dip_change_pulse` → `EV_DIP_CHANGE` |
| 编码器 `exp_enc*_a/b` | 静止相位常有一相为低 | `EV_ENC_STEP` |
| 按键 `exp_key_n` / 母板 `key1/key2` | 被按住或读低（key1/key2 内部 `PULLTYPE=NONE`） | `EV_KEY_DOWN` |

S2 的 `ui_ev_valid` 原本把这些**全部**接成"跳过请求"，于是上电约 8 ms 后就产生一次
skip，`boot_layer` 在第一个帧边界把 `boot_active` 清 0 → **Logo 从未被显示，整屏黑**，
随后照常显示 SD 图片。这与板上现象完全一致。

**修复**（`src/io/expansion_integration.v`）：

```verilog
wire ev_is_dip = (ev_code == EV_DIP_CHANGE);
// ① 拨码是静态配置、不是操作，且上电必然报一次，明确排除；
// ② 再加 500 ms 上电保护窗，屏蔽所有输入通道的消抖收敛瞬态。
assign ui_ev_valid = ((ev_valid & ~ev_is_dip) | (|board_key_fall_pulse))
                     & skip_guard_done;
```

**回归证据**：新增 `sim/tb_s2_boot_guard.v`（把 J2 拨码设成停在 0 位、编码器静止相位为低）。
修复前：`FAIL power-on settling produced 1 skip event(s) inside guard window`（精确复现板上黑屏）；
修复后：`PASS no power-on skip event inside guard window` +
`PASS real key press after guard still reported`（保护窗后真实按键仍能正常跳过）。

> 教训：任何"上电即消费事件"的 FSM 都要考虑输入消抖器的初值收敛，
> 不能把"状态变化"直接等同于"用户操作"。

### 2.3 插入点为什么选在末级

```text
SDRAM 读回 -> video_delay -> 转场 -> 亮度/对比度 -> OSD -> 音频波形 -> [S2 Logo 图层] -> RGB->AXIS -> HDMI
```

`osd_overlay_24` 与 `promax_audio_waveform` 的 `rgb_out` 都是纯组合替换，RGB 与
`adjusted_de/adjusted_pixel_x` 严格对齐，因此：

- 只看像素，不改 `de/vs/hs` 节拍，不动 HDMI 核与音频数据岛调度；
- `STATE_BOOT` 期间整屏由 Logo 接管（盒外纯黑），不会叠加 OSD/波形；
- `boot_active=0` 时 `final_rgb` 完全等于 S1 的 `waveform_rgb_out`，可视为零影响。

### 2.4 Logo 数据是怎么塞进 BRAM 的

原图 640×480 有 84% 是全透明背景，整帧直接存片内放不下。因此：

1. 用 alpha 求内容包围盒 → `x[194,445] y[96,376]`，外扩 8 像素得裁剪盒 `x[186,453] y[88,385]`（268×298）；
2. 裁剪盒按 2 倍欠采样存 `134×149`（19966 像素），显示时按 2 倍还原到 268×298，盒外保持纯黑；
3. 自适应调色板量化到 **16 色**，4bit 索引 **2 像素/字**打包 → ROM 约 9.7 KB；
4. TD 实际把它推断成 `16384×8` 块 RAM，占 **16 个 BRAM9K**。

画质取舍（整屏还原 PSNR）：8 色 23.24 dB / **16 色 24.77 dB** / 32 色 25.38 dB / 64 色 25.61 dB。
32 色起需要 32 块 BRAM 才多 0.6 dB，性价比低，故选 16 色。

## 3. 事件编码格式（沿用 S1，`src/include/exp_event_defs.vh`）

单拍有效，同一拍只分发一个，优先级 `KEY_DOWN > KEY_UP > DIP > EC 步进 > EC 按压 > IR`。

| `ev_code` | 名称 | `ev_arg[15:0]` | `ev_aux[15:0]` |
|---:|---|---|---|
| 0 | `EV_NONE` | - | - |
| 1 | `EV_KEY_DOWN` | `key_index` (0..11) | 0 |
| 2 | `EV_KEY_UP` | `key_index` (0..11) | 0 |
| 3 | `EV_DIP_CHANGE` | `{12'b0, dip_level, dip_index[2:0]}` | 0 |
| 4 | `EV_ENC_STEP` | `enc_count[15:0]` | `{14'b0, enc_id, direction}` |
| 5 | `EV_ENC_SW` | `{15'b0, pressed}` | `{15'b0, enc_id}` |
| 6 | `EV_IR_FRAME` | `ir_code[15:0]` | `ir_code[31:16]` |
| 7 | `EV_IR_REPEAT` | `ir_code[15:0]` | `ir_code[31:16]` |

**S2 对事件的使用**：不新增事件类型。`expansion_integration` 输出
`ui_ev_valid = ev_valid | (|board_key_fall_pulse)`：

- `clk`(50 MHz) 域：任一事件 → `boot_skip_toggle_clk` 翻转；
- `video`(25 MHz) 域：`boot_layer` 内两级同步 + 边沿检测 → 一次事件只消费一次；
- 状态跳转只在 `frame_start`（`vs` 下降沿）提交，避免半帧撕裂。

## 4. 串口输出格式（沿用 S1，新增两条 Boot 行）

115200 8N1，`uart_tx = D12`，由顶层参数 `ECHO_TEST_ENABLE` 开关。行尾统一 CRLF。

```text
VINYL EXPHUB S1          上电横幅（1 条）
BOOT LOGO                进入 STATE_BOOT（1 条）
KEY nn DOWN / KEY nn UP  按键事件（动作时才有）
DIP n v                  拨码变化
ENCx +/- hhhh            编码器步进
ENCx SW DOWN / ENCx SW UP
IR hhhhhhhh CMD hh / IR REPEAT
BOOT DONE                离开 STATE_BOOT（首图就绪 / 用户事件 / 兜底超时）
```

S2 新增语义：`BOOT LOGO` 与 `BOOT DONE` 之间就是 Logo 显示窗口（本板约 4 s，等于 SD 首图加载时间）。

```powershell
python tools/gen_boot_logo.py --colors 16 --verify   # 写 ROM + 几何宏 + 还原预览 PNG
```

BRAM 紧张时的降级办法：`--scale 4`（存储减到约 1/4）或 `--margin 0`（收紧裁剪盒）。

## 8. 上板人工验收清单（请断电重启后逐项确认）

1. 拔掉下载器，**彻底断电再上电**。
2. 上电后屏幕**先出现金色黑胶唱盘 + 底部 VinylFPGA 字样的开机画面**（不再是黑屏等待）。
3. 不操作时 Logo 亮度按固定周期平滑呼吸，HDMI 同步稳定、无花屏撕裂。
4. 约 4 秒（首图加载完成）后自动切到第一张图片，转场与原有行为一致。
5. 重新上电并在 Logo 期间按任一 J2 按键/旋钮/红外，应在下一帧边界立刻跳到浏览态（只跳一次）。
6. 拔掉 J2 排线或 TF 卡再上电，仍能显示 Logo 且不自锁（8 s 兜底离开 Boot）。
7. 串口（115200 8N1）应看到：`VINYL EXPHUB S1` → `BOOT LOGO` → … → `BOOT DONE`。
8. 回归确认：切图、缩略图、参数菜单、音频、数码管显示与 S1 一致。

## 9. 回滚

| 场景 | 操作 |
|---|---|
| 只想临时关掉 Logo | 把 `top` 的 `S2_BOOT_ENABLE` 置 `0`，重新综合布线 |
| 想退回 S1 上电镜像 | 用 S1 位流重烧配置 Flash：`bw_commands_prompt.exe` + `program_spi`（流程同上，换成 `S1_j2_io_v5/VinylFPGA_optimized.bit`） |
