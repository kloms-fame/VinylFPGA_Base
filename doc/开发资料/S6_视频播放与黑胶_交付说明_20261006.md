# S6 视频播放与黑胶交付说明

日期：2026-10-06。工程：`VinylFPGA`；器件：`EG4S20BG256`；顶层：`top`。

## 1. 基线与交付边界

已完整阅读《VinylFPGA_主链路开发报告_代码与规划交叉核对_20261005.md》。按用户本次确认，基于“FPGA 创新设计赛道·安路赛项（完赛系列）”的主链路及 S0–S5 已开发、修复并通过人工验收，作为本次已通过基线；不把历史报告中的“待验收”重新设为前置阻塞。开始时实际源码对应 `S0_S5_fix_20261006_v4`，其路由 Setup/Hold WNS 为 +114/+3 ps。

本次实现 S6 RTL、资源工具及验证。S6 板上播放、实卡持续带宽和长时间视听同步尚需人工验收；仿真与时序结果不替代这些项目。本次未向板卡下载、未改写配置 Flash 或 TF 卡。

S2 浏览态的 J2 事件迁移已经由 S3 及 2026-10-06 修复版完成，本次沿用该通路：EC1、方向键驱动选择，母板 key1/key2 保留并联兜底；2×2 布局、四 bank 封面预加载、封面地址与浏览选择握手不变。

## 2. 用户可见行为

- 带有效 MV 描述的曲目：播放 320×240 RGB565 视频，固定 10 fps，显示窗口 `x=16..335, y=64..303`。保持 640×480 HDMI 时序。
- 无 MV、旧版索引或不支持的视频描述：显示黑胶。黑胶中心 `(176,184)`、半径 112，转动相位使用现有音频毫秒时基。
- 播放态 KEY08 按下，在下一帧边界切换 MV/黑胶；释放不重复触发。无 MV 时仍显示黑胶。显示偏好保留到下一次按键或复位；选择黑胶期间 MV 调度仍保持与音频时间轴同步。
- 暂停冻结视频发布、后续取帧及黑胶相位；已经发出的 SD 请求允许排空。恢复后继续使用音频时间轴。
- 视频供数不足时保持最后完整帧，供数恢复后跳过过时帧并追赶音频；最后一帧播完保持末帧，不自动循环。首帧未就绪时使用黑胶。
- 歌词继续叠加在 S6 图层之上，Boot Logo 保持最高优先级。

### 3.1 SDRAM 地址与仲裁

下表单位为 **32 位字地址**，不是字节地址：

| 用途 | 半开地址范围 | 字数 |
|---|---|---:|
| 原有四个 640×480 封面 bank | `[0,1228800)` | 1228800 |
| MV bank 0 | `[1228800,1305600)` | 76800 |
| MV bank 1 | `[1305600,1382400)` | 76800 |
| MV bank 2 | `[1382400,1459200)` | 76800 |

终点小于现有 21 位字地址范围。三帧区不覆盖封面；显示中的 bank 不写入。MV 仍使用现有 SDRAM 写 FIFO 与帧读取 FIFO，不增加 BRAM。

扇区一旦发出便不可抢占；音频优先发生在扇区边界。`wav_buffer_low` 两级同步后硬门控视频。退出播放时允许在途 MV 写排空，缩略图读/返回后保留 64 拍窗口，和原写忙信号一起避免共用 SDRAM 总线冲突。浏览请求、布局、像素源逻辑本身保持原实现。

### 3.2 CDC 与提交规则

- `clk` 50 MHz 的 KEY08 先转独立 toggle，video 域同步后识别一次事件，只在 `frame_start` 改变模式。
- video → SD 的取帧 mailbox 只允许一笔在途；LBA/bank 从请求发出一直保持到完成，接收端使用三拍 toggle 同步后锁存。
- SD → video 的完成 toggle 经过三拍同步；失败状态保持到下一请求，配合两拍同步，在完成被消费前稳定。
- 完成含义为 SDRAM `write_finish`，不是最后一个 SD 字节。显示 bank、帧号和有效位只在场消隐边界提交。
- 当前曲目元数据采用保持数据两级采样，调度使能/重启后留 15 拍稳定窗，再发起请求；切曲时旧请求只排空、不发布。
- 继续使用 S5 的唯一 `timebase_48k`，视频按每 100 ms 一个目标帧、黑胶相位取 `time_ms[10:3]`，无第二套音频时钟。

## 4. 资源和索引格式

MV 为无头文件：320×240、RGB565 小端、从上到下逐行、每帧 153600 字节，即 300 个 512 字节扇区，固定 10 fps。帧数 1..65535；实际容量还受 FAT32 单文件大小限制。当前版本要求 MV 文件物理连续，不支持压缩视频、动态分辨率或 12 fps。

INDEX 保持 512 字节总长、64 字节条目。无 MV 的打包结果保持版本 1；含 MV 时生成版本 2。旧 v1 可直接继续使用。

| 条目相对偏移 | 长度 | v2 含义 |
|---|---:|---|
| 原 flags 字段 bit3 | 1 bit | has_mv |
| 56 | 4 字节 LE | MV 首物理 LBA |
| 60 | 2 字节 LE | 帧数 |
| 62 | 1 字节 | fps，必须为 10 |
| 63 | 1 字节 | codec，1 = RGB565LE 320×240 |

扩展描述受原条目区 CRC32 保护。PC 工具拒绝碎片、非整帧大小、不支持的 fps、零帧及 LBA 越界；RTL 对不支持的描述回退黑胶。`verify` 校验根目录文件与 LBA/大小/连续性，并输出 MV 内容 SHA256；索引未存 MV 载荷 CRC，验证文件身份需对照打包时 `INDEX.json` 中的 SHA256，不能把索引 CRC 当成视频内容 CRC。

在工程根目录运行以下命令。`frames` 中应为事先准备好的 320×240、10 fps 图片序列，文件名补零并按时间字典序排列；工具不静默缩放或重采样。

```powershell
python tools/mv_pack.py --frames frames --output TRACK1.MV
```

把 MV 和原有封面、PCM 文件加入待处理 FAT32 镜像后，使用清单（PCM 沿用现有 48 kHz、16 位单声道格式）：

```json
{"songs":[{"title":"Track 1","cover":"PIC1.BMP","audio":"AUDIO.PCM","mv":"TRACK1.MV"}]}
```

```powershell

python tools/vinyl_packer.py info --image card.img
python tools/vinyl_packer.py verify --image card.img
```

`pack` 在已有 FAT32 镜像中查找文件并写入 INDEX，不负责把本机文件复制进镜像；文件移动或重排后必须重新打包索引。无 MV 曲目省略 `mv` 字段。原有四曲目上限、根目录搜索范围、封面规格和音频约束仍生效。

## 5. 事件编码与业务映射

事件总线保持 50 MHz 域的 `valid` 单拍，以及 `code[3:0] + arg[15:0] + aux[15:0]`。以下以 `ui_event_bus.v` 的实际打包和消费逻辑为准；早期 `exp_event_defs.vh` 对 ENC_SW 的注释有旧语义，不能按该注释改线。

| code | 事件 | arg | aux |
|---:|---|---|---|
| 0 | NONE | 0 | 0 |
| 1 | KEY_DOWN | 按键索引 0..11 | 0 |
| 2 | KEY_UP | 按键索引 0..11 | 0 |
| 3 | DIP_CHANGE | `{12'b0,level,index[2:0]}` | 0 |
| 4 | ENC_STEP | 编码器累计计数 | `{14'b0,enc_id,direction}` |
| 5 | ENC_SW | bit0：0 按下，1 释放 | bit1：enc_id |
| 6 | IR_FRAME | NEC 低 16 位 | NEC 高 16 位 |
| 7 | IR_REPEAT | NEC 低 16 位 | NEC 高 16 位 |

`enc_id=0` 为 EC1，1 为 EC2；direction=0 顺时针/递增，1 逆时针/递减。KEY08 即 `valid=1, code=1, arg=7, aux=0`，本次没有增加编码种类。

| 操作 | 浏览/缩略图 | 播放 |
|---|---|---|
| EC1 顺/逆 | 下一/上一封面或焦点 | 切曲 |
| KEY01/KEY03 左/右 | 上一/下一选择 | 保持原 S5 行为 |
| KEY04/KEY05 上/下 | 上一/下一选择 | 音量± |
| EC1 按下 / KEY02 | 原有确认/进入行为 | 暂停/恢复 |
| KEY07 | 原有视图切换 | 退出播放 |
| KEY08 | 不改变选择 | MV/黑胶切换 |
