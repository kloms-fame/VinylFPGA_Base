## 1. 两张图片说明的问题

第一张图片明确指出：`phy_1 → Optimize Placement → seed` 当前值为 5，默认值为 0。这是 **TD 私有参数非默认警告**。点击 Revert 会恢复该参数，工程重新保存后固定种子 5 就丢失了。之前仅把 seed=5 写入 PlaceProperty 的处理不适合你的打开方式。

## 2. 采用的工程配置

保留 syn_1 的 `map_mode=area_prior`，在原 AL 保存 **TD 官方 Multi-Seed 配置，仅运行固定种子 5**：

| 设置 | 值 |
|---|---|
| Enable | true |
| Number of Seeds / Num | 1 |
| Minimum Seed / Init | 5 |
| Seed Step | 1 |
| Run Jobs | 1 |
| Save Number | 1 |
| Random | false |
| End Step | bitgen |
| Generate Bitstream | true |
| Filter | false |
| Selected Seed | 5 |

普通 PlaceProperty 的 seed 保持默认值 0，不再持久化私有 seed=5。真正的实现种子由 Multi-Seed 在运行时设置为 5；两者不是同一处配置。

TD 6.2.168116 自带 `doc/scripts/MultiSeed.tcl` 在 `drHoldFix=on` 时执行：

1. 关闭 route 内部 Hold 修复。
2. 执行 route。
3. 独立执行 fix_hold。
4. 更新 final 时序、导出真实路由数据库并生成 bit。

这解决了原流程 Slice 占用超过 90% 时跳过内建 Hold 修复的问题。无需修改 TD 安装文件，无需放宽时钟或添加掩盖违例的时序例外。
