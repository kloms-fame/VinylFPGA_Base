# 交互、参数、Flash 与实体硬件详解

## 1. 交互系统不是把引脚直接接到功能

实际链路为：异步物理输入→同步→消抖或协议解码→统一事件→业务命令→对应状态机。分层以后，同一个业务动作可以来自旋钮、按键或遥控，而无需复制三套播放逻辑。

输入层负责“发生了什么”，业务层负责“在当前状态下它意味着什么”。例如确认键在浏览态开始播放，在播放态暂停/恢复；EC1旋转在浏览态换焦点，在播放态定位进度。

## 2. 同步与消抖分别处理什么

两级同步降低异步采样亚稳态传播概率。消抖要求输入保持稳定若干采样周期后才接受变化，处理的是机械触点来回抖动。二者不能互相替代。

按下电平与按下事件也不同。若每个时钟周期都把低电平当“再按一次”，一次真实按键会触发成千上万次。应在稳定状态变化时生成一次事件；长按和连发需要另外定义节流策略。

## 3. 编码器为什么能分辨方向

A/B两相按相邻Gray状态变化，例如00→01→11→10→00，与反向序列相反。通过前后状态可以判断方向，并对非法跳变作处理。

工程还要考虑每个机械卡点对应几次电平变化、抖动、事件合并、计数回绕和业务门控。当前事件桥用“最新绝对计数与已交付计数之差”重放EC1步进，源域事件之间留出间隔供toggle跨域消费。

答辩不应说“有toggle就永远不丢脉冲”。正确说法是：在设计约束的事件速率、重放间隔与目标采样条件下传递，并有对应边界测试。

## 4. 当前操作语义速查

以下以当前`ui_event_bridge`、`play_ctrl`等连接为准，某些丝印与功能命名的旧文档有差异，最终上场前应按实际板子逐项核对。

| 操作 | 当前业务用途 |
|---|---|
| EC1旋转 | 浏览态选曲，播放态±2秒Seek |
| EC1按压/扩展KEY2 | 浏览确认，播放暂停/恢复 |
| 扩展KEY1/KEY3 | 浏览前后切换；播放态上一曲/下一曲 |
| 扩展KEY4/KEY5 | 浏览导航；播放态音量增/减 |
| 扩展KEY6 | 五行歌词/当前句专注 |
| 扩展KEY7 | 返回浏览 |
| 扩展KEY8 | 封面/MV偏好切换，是否显示还取决于能力和就绪 |
| 扩展KEY9 | 转场模式循环 |
| 扩展KEY10 | J2灯效模式 |
| 扩展KEY11 | 四种播放背景循环 |
| 扩展KEY12 | 播完暂停、单曲循环、自动下一首 |
| EC2旋转/按压 | 参数调节与参数菜单项切换 |
| 主板KEY2/KEY3/KEY4 | 默认参数、保存参数、静音 |

主板与扩展板都出现KEY2/KEY3等名字。现场说话加“主板”或“扩展板”，避免操作员按错。主板SW1当前用于数码管总控，不能照顶层残留注释说成反馈音总开关。

## 5. 红外路径的特殊性

当前解码后的32-bit表示为四个字节，并按两组反码检验；本遥控的低两个字节固定FF/00，识别功能主要使用高字节白名单。不要把这里的字段展示顺序硬套成所有NEC设备的通用判键方式。

合法帧还要通过红外使能、业务门控和消隐唤醒策略。repeat只能在已有合法前导键、未超时且符合节流条件时执行，当前重点允许进度键连发；不能将任意repeat当重复执行上一条危险操作。

旧交互表对F8/EA音量方向与当前路由常量有冲突，Seek模块头部也保留了旧红外标签。比赛前依据`ui_command_router`与真实遥控逐键核对，不能只背字面名称。

## 6. 唯一参数所有者为什么重要

五个参数统一由50MHz域`ui_param_csr`维护：

| 参数 | 含义 | 当前默认 | 范围或档位 |
|---|---|---:|---|
| VOL | 数字音量增益 | 200 | 0—255，步进16、两端饱和 |
| BRI | 亮度档 | 3 | 0—4，对应1/4、1/2、3/4、1、5/4 |
| CON | 对比度档 | 2 | 0—4，对应1/2、3/4、1、5/4、3/2 |
| ROT | 轮播周期档 | 2 | OFF、2、3、5、10、20秒 |
| WSL | 两路灯带亮度比例档 | 4 | 0、25、50、75、100% |

播放域产生音量修改意图，经桥接送回唯一CSR，而不是50MHz与100MHz各保留一份可写“真实音量”。这样菜单、音频和持久化都围绕同一事实值。

`ui_param_csr`默认值、合法恢复范围和写优先级都是可以指给评委看的实现。满量程是数值增益上界，数字档位不是经过声压校准的分贝数。

## 7. 参数跨域与帧边界提交

一组参数先在源域锁存，握手期间保持稳定，再由目标域捕获完整快照。画面参数与相关控制在帧边界一起提交，使同一帧使用一致值。

如果BRI逐位独立同步，二进制011到100可能被目标看到为中间错误组合。若参数在画面中途生效，上下半帧又会出现亮度差异。因此“数据一致性”和“何时可见”是两个步骤。

## 8. 配置Flash与参数Flash必须分开

| 对象 | 用途 | 谁负责装载/访问 |
|---|---|---|
| FPGA配置Flash | 保存bitstream，掉电后上电配置FPGA | 配置机制/下载流程 |
| 独立U33 W25Q64 | 保存五项用户参数 | FPGA内SPI事务与参数存储状态机 |
| TF卡 | 音频、封面、MV、背景及索引等媒体 | FPGA媒体管理链路 |

W25Q64是64Mbit，即8MiB。用户手册中配置Flash容量描述和型号存在疑似单位/排版错误，赛题资料也有MB/Mbit混写。答辩说清用途和实际芯片型号；若被问具体容量，以实物料号、JEDEC ID和对应数据手册确认，不背矛盾数字。

## 9. Flash保存的完整事务

当前只写W25Q64末端两个4KiB扇区，起点为`0x7FE000`和`0x7FF000`。一条有效记录16字节，含魔数、版本、标志、序号、五参数、CRC16与提交标记。

```text
读取当前参数快照
 → 选择另一槽
 → 写使能与擦除，轮询忙状态
 → 写入载荷与CRC
 → 回读比对
 → 单独写A5/5A提交标记
 → 再确认有效记录
 → 保存成功
```

CRC16/CCITT-FALSE覆盖记录前12字节，提交字节在其后单独编程。顺序的目的：新记录没有完整提交前，旧有效记录仍可使用。双槽加CRC提高恢复判断能力，但不能替代所有断电时刻、电压条件与Flash寿命实测。

序号有回绕规则，不能简单用数值更大的8-bit序号永远代表更新。参数范围也要校验，CRC正确而参数非法仍不能盲目恢复。

## 10. 自动保存、快照与dirty

主板SW3使能自动保存后，参数停止变化5秒才触发保存，减少每次旋钮动作都擦Flash的频率。手动保存通过主板KEY3等合法入口请求。

若保存的是快照A，保存期间用户调成B，完成后只能说A保存成功；当前值B依然是dirty。当前LED2需要已存快照与当前值一致，才表示当前参数已持久化。恢复默认则先改运行值，再按默认保存事务处理，不是简单清一个屏幕变量。

练习：VOL由200改为216并保存，写入期间又调成232。最后应该恢复哪个值、当前已保存指示应该怎样？回答要区分提交快照与后续待保存值。

## 11. 唱针、电机和灯效的真实因果

`vinyl_playback_effects`的电机运行条件可以概括为：

```text
motor_enable = 复位已释放 AND 播放有效 AND 未暂停 AND 唱针闭合
```

唱针不采集唱片音沟，也不负责开始音频播放。它控制播放期间的转盘和唱片灯效。数字音频仍来自TF卡，通过HDMI输出。

FPGA输出控制电机驱动器件的使能/栅极信号，不能把电机负载电流理解为由普通GPIO直接提供。硬件说明应指向实际扩展原理图，说明公共地、驱动级、电源和引脚方向，避免只展示外观。

WS2812用不同高电平时长表达0/1，串行发送GRB等约定数据并给复位锁存间隔。`WSL=0`关闭灯的亮度，不改变电机条件；DIP6是灯带总使能，不能说成整台设备电源管理。

## 12. 息屏听音与低功耗的区别

当前息屏主要是输出像素消隐，音频继续；显示时序和HDMI链路可以保持工作。它改善使用体验，但如果没有整机电流/功率实测，就不能给“待机降低XX%功耗”的数字。

消隐期间第一个有效操作可只用于唤醒，避免刚亮屏就同时执行选曲或Seek。演示前要熟悉这一语义，防止误以为按键无响应。

## 13. 串口目前不是主要运行证据

顶层端口注释仍残留115200回显描述，但当前`expansion_integration`直接把`uart_tx`置高，生产UART静默。历史课程里的串口事件打印不应当作当前必有功能。

如果比赛时需要说明状态，可用实际LED、数码管、OSD及已归档仿真；不要现场期待不存在的串口日志。

## 14. 两张扩展原理图应该怎样读

### 交互扩展板

从40Pin接口开始，先按网络名追EC1/EC2、KEY、DIP、IR_RX、LED和WS2812_DATA，再把网络与ADC中的FPGA管脚对应。原理图中的GPIO序号、连接器物理脚号、FPGA封装脚号和RTL数组下标是四套编号，不能直接互换。

图中编码器A/B各有4.7k上拉，按压开关有10k上拉；独立按键用10k上拉，按下连接地，所以“低有效”的逻辑有电路来源。四个指示LED从3.3V经限流电阻连接到控制网络，拉低点亮，与扩展LED低有效代码相符。

红外接收器由3.3V供电，附近有供电电阻与电容，IR_RX再进FPGA解码。LED供电部分、串联WS2812数据链和去耦要分别看，不能把电源灯与业务状态灯混为同一输出。

该图日期较早，图内DIP和按键功能说明保留初期安排，例如某些模式和长按操作，不能覆盖后续RTL的业务语义。图内连接器称谓也要与实际主板接口和约束核对；本报告沿用当前工程J2业务命名，不因一张旧图的文字标签直接改线。

### 唱片扩展板

图中MOTOR_EN经100Ω电阻接AO3400A栅极，10k下拉使未驱动时偏向关闭，MOS管作为低侧开关；电机连接在3.3V侧，SS14与电机端并联，承担感性关断电流的续流通路。应沿“电源→电机→MOS→地”理解负载电流，不把GPIO当电机电源。

NEEDLE_SENSE有10k上拉，唱针开关闭合接地，因此低电平表示闭合。八个WS2812串联，首个DIN前有100Ω，电源侧有SS14与总电容、各灯去耦。应能解释数据串联方向与电源并联关系。

这些是图面连接与RTL对应关系的学习说明。本次未测电机启动/堵转电流、MOS温升、WS2812输入门限与实际电源波形，也未重新执行PCB ERC/DRC。因此不能由“图上画了驱动与去耦”推导全部电气可靠性已认证。
