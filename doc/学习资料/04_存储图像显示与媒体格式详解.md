# 存储、图像、显示与媒体格式详解

## 1. 先区分四层格式

| 层级 | 解决的问题 | 项目实例 |
|---|---|---|
| 物理传输 | 怎样把卡上的字节送进FPGA | SPI、SD命令、512字节扇区 |
| 文件定位 | 文件的字节在哪些扇区 | FAT32卷、目录项、簇链 |
| 媒体编码 | 文件字节代表什么 | BMP、裸PCM、RGB565帧序列 |
| 运行时存储 | 怎样适合硬件读取和显示 | 32-bit SDRAM word、FIFO、字节掩码 |

懂其中一层不能自动推出懂其他层。例如支持FAT32簇链不表示所有音频和MV路径都支持碎片；能够把RGB565展开成RGB888也不是压缩视频解码。

## 2. SD SPI：从命令到完整扇区

SPI常见四根线：CS选择设备、SCLK给出串行节拍、MOSI发给卡、MISO从卡读回。SD卡初始化与正式读数采用不同速度和命令流程。

本项目内部控制时钟100MHz。`sd_card_top`默认低速分频参数248、高速参数0，其注释给出的串行时钟公式为：

```text
f_SPI = f_controller / [2 × (DIV + 2)]
低速名义值 = 100MHz / 500 = 200kHz
高速名义值 = 100MHz / 4 = 25MHz
```

这里是该实现的名义分频关系。有效载荷还受命令响应、数据令牌、CRC字节、字节间状态转换、暂停和卡内部等待影响。25MHz单线SPI的原始位速上限折合3.125MB/s，不能直接当作持续文件吞吐实测值。

### CMD17与CMD18

CMD17读单块；CMD18用于多块连续读，停止和收尾也需要协议处理。当前MV走受控CMD18通路，其他请求与它共享底层SPI所有权。一次完整事务的拥有者要维持到结束，不能只切换LBA或数据路由就“抢占”已开始的传输。

学习时重点看：请求何时被接受、数据令牌何时到达、字节索引是否0—511完整、done和error何时有效、超时从何时开始。超时不应把尚未获总线所有权的排队时间误当成已发命令无响应。

规范阅读入口：[SD Association简化规范](https://www.sdcard.org/downloads/pls/)。先读SPI模式、块读取与命令响应，再对照本项目实现，不需要先通读全部高速总线扩展。

## 3. FAT32：文件名如何变成LBA

### 3.1 四个核心概念

- 扇区：本项目使用512字节读写单位。
- 簇：连续若干扇区组成的分配单位。
- 目录项：记录短文件名、属性、首簇、字节长度等。
- FAT表：记录一个簇之后应接哪个簇，直到文件结束。

不要把“第3首歌”与“第3个扇区”混为一谈。曲目编号属于业务；LBA属于物理块位置；簇号属于文件系统。

### 3.2 地址换算

```text
fat_start = partition_start + reserved_sectors
data_start = partition_start + reserved_sectors + fat_count × fat_size
cluster_lba = data_start + (cluster - 2) × sectors_per_cluster
```

例：data_start=4096、每簇8扇区、文件首簇10，则第一扇区LBA为4160。若下一簇为30，跨簇后应跳至4320，而不是简单继续加到下一连续簇。

本项目`fat32_volume_scanner`识别直接引导卷或MBR分区，再解析BPB和根目录。`fat32_file_streamer`处理文件流与簇链；媒体加载器和索引解析器在其上工作。

### 3.3 当前实现边界

根目录只扫描首扇区的16个目录项，不能照教程中的“首簇”泛化成扫描128项。长文件名记录也会占目录项。文件放在卡里、PC能打开，并不保证落在FPGA可见的目录范围内。

封面等文件流路径能够使用FAT链；生产PCM和MV为简化硬件服务，要求物理连续。正式校验器拒绝碎片PCM；`--allow-fragmented-audio`属于离线实验选项，不能作为正式交付支持。

## 4. INDEX.BIN：曲目描述而非整个播放器数据库

`INDEX.BIN`固定512字节，包括64字节头和64字节曲目条目，当前上限4首。记录魔数、版本、条目大小、曲目数量、条目CRC32，以及媒体位置、长度和能力位。MV描述还包含起始LBA、帧数、fps与编码类型。

硬件会校验索引自身CRC32与关键范围。封面和音频文件级CRC/SHA由PC工具验证与追溯，不能说成FPGA在播放时对全部媒体实时计算SHA-256。

索引中的ASCII标题字段并非当前中文界面的动态文字来源。显示标题、歌词与字形主要来自编译期ROM。卡上歌词能力位或文件存在，不等于可以运行时解析任意新LRC。

## 5. BMP：从文件头到像素

常见24-bit BMP包含文件头、DIB信息头与像素数据。需要理解：

1. “BM”魔数只是必要条件之一。
2. 宽、高、位深、压缩方式、像素偏移与文件长度共同限定合法输入。
3. 常见BMP像素按B、G、R字节排列，不是直接RGB顺序。
4. 行可能按4字节对齐，正高度常表示从底行开始；不能忽略方向和步幅。

对于当前640像素宽的24-bit图：

```text
每行 = 640 × 3 = 1920 B，已经是4字节倍数
像素总量 = 640 × 480 = 307200
像素载荷 = 921600 B
典型54字节头文件 = 921654 B
```

生产路径`fat32_media_loader`检查固定几何和像素偏移恰为54。旧`bmp_read`中某些更宽松检查不能替代生产路径的限制。把带扩展头、负高度或不同宽高的图片直接复制进卡，需要先确认转换与校验，不应声称任意BMP兼容。

### 从24-bit文件到32-bit word

图形通路通常把RGB888放在word高24位，低8位保留给音频共享。单个封面地址跨度307200 word，即1228800字节。文件载荷921600字节与SDRAM地址跨度1228800字节不同，是内部格式与布局造成的，不是多读了三分之一文件。

## 6. 为什么需要多bank和完整帧发布

HDMI读取当前可见图时，加载器还可能写下一张图。若二者访问同一份正在改写的像素，屏幕会混出不同时间的内容。多bank让读取与准备分离。

完整提交应考虑：文件有效、像素数量足够、写FIFO已排空、SDRAM写入完成、消费者收到稳定的bank信息。只有“SD读完”远远不够。

四个封面bank、三个MV bank和背景缓存有不同用途，不能都简称“双缓冲”。学习时问每块缓存是谁写、谁读、何时可被复用，而不只是数有几块。

## 7. 当前艺术背景缓存改动是很好的答辩案例

原实现两张静态艺术图复用同一个全帧槽，切换会重新读1200扇区，并在未就绪时回退灰色。最新源码修改把两张RGB565图放在同一word的不同16-bit半字，独立维护ready，提前预热。

```text
word[31:16] = 艺术一RGB565
word[15:0]  = 艺术二RGB565
写艺术一：mask=0011，保护低半字
写艺术二：mask=1100，保护高半字
```

颜色展开只是把原5/6-bit通道按位复制到8-bit，不增加新的颜色精度，也没有再次降低原图精度。预热完成后切换可只改变帧边界选择，无须重新读整图；首次预热仍需时间。

这是当前工作区后续修改的机制分析。其最终构建和实板状态需看15与17的快照，不能套用旧候选的实板结论。

## 8. 光栅与HDMI输出

当前有效区640×480，总时序800×525，像素时钟25MHz：

```text
行频 = 25,000,000 / 800 = 31,250 Hz
帧频 = 25,000,000 / (800 × 525) ≈ 59.5238 Hz
帧周期 ≈ 16.8 ms
```

因此适合说“约60Hz”，若给精确计算应使用59.52Hz，不能把25MHz说成标准25.175MHz。DE标识有效像素，HS/VS提供行帧节拍；消隐期仍属于视频时序的一部分。

HDMI视频数据送入厂家发送核和PHY。125MHz的5倍像素时钟配合双边沿相关串行化实现每像素10-bit符号传输；不要把125MHz内部时钟、250Mb/s每通道符号位速、25MHz像素率混为一个频率。

视频流水线每加一拍，RGB对应的DE、坐标和同步控制也要匹配延迟。错一拍可能表现为边缘错色、行首异常或文字错位，算法公式本身仍可能正确。

## 9. 图层与歌词怎样合成

每个像素时刻按坐标判断哪些图层命中，再按优先级选择颜色或混合。当前页面组织背景、封面/MV窗口、曲目信息、进度、歌词、波形和参数OSD。

同步ROM通常先送字形地址，下一拍得到点阵行。字形位、像素坐标、颜色和DE需要一起对齐。`playback_page`与共享ASCII字体通路的时分使用，也是节约BRAM与控制资源的具体办法。

歌词按媒体时间选择当前句，五行窗口缓存附近文本，逐句高亮并按帧步进上滚。KEY6切换五行和当前句专注。不是从TF任意文本直接逐字渲染，也不是逐字卡拉OK进度染色。

## 10. 转场：公式与真实主链路

概念上的两帧混合公式可写为：`C = αA + (1-α)B`。但当前主链路主要采用单路图像，淡出到黑后切换再淡入；方向擦入是按横坐标揭示新图，未显示区域为黑。

这样降低了同时读取两帧的带宽和控制成本。代价是效果与完整交叉溶解不同。`frame_blend.v`存在不能证明主链路用了双图交叉混合。

模式、方向与系数需要在帧边界按一致状态更新，否则一帧上半部与下半部可能使用不同转场参数。当前顶层实例把`FADE_FRAMES`配置为8；总切换时间还包括对齐、加载与提交等待，不能只用8帧换算承诺全部响应时间。

## 11. 缩放：会理论也要讲实际

最近邻按目标坐标映射一个源像素，成本低，边缘易锯齿。双线性使用邻近四个像素及小数权重，质量通常更平滑，但要有邻域数据、行缓存、乘加与边界处理。

当前封面固定2:1缩小采用行列取样组织，支持640×480到320×240播放窗口。`bilinear_8q8.v`属于未接入主顶层的参考/仿真模块。赛题扩展3强调不同源分辨率适配，当前不能据此认定完整完成。

被问如何扩展时，可答：先扩展BMP尺寸与行步幅处理，再明确等比留边或裁切策略，建立坐标映射，加入缓存与插值，最后评估SDRAM带宽、资源和时序。仅把宽高参数改成可变不够。

## 12. 亮度与对比度的实际算法

主链路使用五档常量移位加法版本`brightness_contrast_steps`：

```text
b = sat(原通道 × B)
out = sat((b - 128) × C + 128)
B = 1/4、1/2、3/4、1、5/4
C = 1/2、3/4、1、5/4、3/2
```

先做亮度并饱和到0—255，再做有符号对比度，最后再饱和。当前不是连续浮点调参。乘以3/4、5/4等可以用移位与加法完成，便于资源和时序控制。

例：原通道200，B=1、C=1/2，输出为164；原通道100，B=1/2、C=1，输出50。高亮饱和会丢失细节，所以画面很亮不等于算法质量更高。
