# VinylFPGA 项目学习与线下比赛答辩总报告

分析日期：2026-10-29（北京时间）。面向已经基本完成开发、现在需要理解项目并参加线下比赛的参赛者。

## 1. 先明确你要学会什么

你的作品是 **VinylFPGA——唱片主题互动音视频播放器**。核心平台目标为安路 EG4S20BG256，工程入口为 `prj/VinylFPGA.al`，顶层模块为 `top`。媒体来自 TF 卡，FPGA 组织文件读取、缓存、播放控制、画面合成与 HDMI 音视频输出；两类扩展板和红外遥控提供实体交互。

最值得讲清的工程问题是：**读卡服务会波动，而屏幕扫描和音频供数需要连续进行，多个通路还必须对同一首歌、同一播放位置达成一致。** 缓存、仲裁、跨域握手、播放会话和帧边界提交是解决这些问题的主线。

比赛前的目标不是逐行背完所有源码，而是达到下面五个标准：

1. 不看资料，用两分钟画出“TF 卡到屏幕和扬声器”的数据流。
2. 能解释一次选曲、暂停、Seek、调参和参数保存分别经过哪些模块。
3. 能计算音频速率、单帧大小、缓存储备和显示刷新率。
4. 每说一项亮点，能给出真实操作、关键代码或测试证据。
5. 面对不会的问题，能说清当前实现范围和验证方法，不靠夸大补漏洞。

## 3. 不同基础的阅读顺序

### 完全初学者

先读 00 → 01 → 02 → 03。接着亲手演示一次浏览、播放、暂停、Seek、调参、保存。再按 04 → 05 → 06 补原理。每读一节就关闭文档，用自己的话讲一分钟。

如果连“寄存器、时钟沿、组合逻辑、状态机”都不熟悉，先在 03 中完成小例子，不要直接从三千行顶层的第一行读到最后一行。

### 已会基本 Verilog，但读大型工程困难

先读 02 和 03 的五条源码追踪路线，然后读 04、05。每次只追一个动作，写清输入、状态、输出、时钟域、完成条件。把 08 中的课程当概念补充，当前项目实现以源码为准。

### 能开发，但上台容易说乱

先读 01、09、15、16。用 10—12 的题库录音，每题先说结论、再说机制、最后说证据或边界。技术细节按评委追问逐层展开。

## 4. 对项目的总体判断

从当前可读源码看，项目已经具有完整产品形态：预置曲库、图片浏览、音频与 MV、歌词、参数 OSD、Flash 保存、实体控制和反馈已经组织到同一工程。其价值集中在系统集成与时序协作，适合围绕完整播放体验进行比赛展示。

需要特别注意版本：本地记录中已有字库优化候选经用户报告实板通过；同时当前工作区又包含双艺术背景缓存等后续修改。旧版本的人工验收与时序结果不能自动证明后续修改版本也已通过。报告将它们分别列出，不把“新代码存在”写成“新固件已经现场验收”。

本次工作是资料分析与学习文档编写，没有修改 RTL、工程配置、媒体，也没有重新烧录或替你做实板验收。已有仿真通过数属于读取本地记录所得，详细来源见 17。

## 5. 比赛表达的三条主线

**面向用户：** 这是一台离线、可预置内容、具有唱片式实体交互的播放器，适合桌面听音与固定主题展示。

**面向技术：** FPGA 内的状态机、缓存、仲裁和握手让多个不同速率、不同时间域的模块合作。实际消费音频样本构成统一播放时间，相关显示在帧边界提交。

**面向证据：** 用真实交互展示结果，用源码解释原因，用明确绑定版本的报告说明资源和时序。把仿真、实现报告、人工实板记录分开说清楚。
