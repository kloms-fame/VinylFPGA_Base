# 音频、统一时基、MV 与跨时钟域详解

## 1. 声音样本到底是什么

PCM是一系列按固定时间间隔记录的振幅数值。48kHz表示每秒48000个样本，16-bit有符号表示每个样本可表达-32768至32767，单声道表示每个时间点只有一路样本。

当前卡上的音频是小端裸PCM，每两个字节组成一个样本，低字节在前。文件名或模块名出现WAV，不代表FPGA解析任意RIFF/WAV头，更不代表MP3、AAC解码。

```text
字节34 12 → 样本0x1234 = 4660
字节00 80 → 样本0x8000 = -32768
数据率 = 48000 × 16 / 8 = 96000 B/s
1个512B扇区 = 256样本 = 5.333...ms
```

单声道复制到左右输出使两个扬声器都发声，但不产生原本没有的立体声空间信息。16-bit左移8位送入24-bit接口，适配的是数字格式，也不会增加源音频精度。

## 2. 为什么不能边读卡边直接发声

音频消费每约20.833μs就需要一个新样本。读卡可能快速返回一整批数据，也可能数百毫秒甚至更长时间不返回。平均读速够快，不表示每个消费时刻都有样本。

本项目采用分层缓存：

```text
SD扇区 → staging → SDRAM音频环 → staging读回 → PCM双时钟FIFO
       → 25MHz域实际消费 → 音量/淡入淡出/静音 → HDMI PCM
```

staging解决一次扇区传输与DMA接口，SDRAM环吸收较长服务波动，近端PCM FIFO负责消费端连续性和跨域。每层解决的问题不同。

## 3. 必须会算的缓存预算

| 对象 | 有效数据容量 | 按96kB/s换算 |
|---|---:|---:|
| SDRAM环1024扇区 | 524288B，即512KiB | 约5.461s |
| 预填/低水位960扇区 | 491520B | 5.12s |
| 高水位1008扇区 | 516096B | 5.376s |
| 名义PCM FIFO4096样本 | 8192B | 85.333ms |
| PCM高水位3072样本 | 6144B | 64ms |
| PCM低水位2048样本 | 4096B | 42.667ms |

4096是名义物理存储规模；实际环形指针与满空区分策略、扇区提交和安全水位会影响可用容量。不要说一定能把4096格全写满再读。

**预填5.12秒内容，不等于固定等待5.12秒才开始。** 等待时间取决于填充这491520字节所需的实际服务时间与其他准备条件。

若接下来完全没有新数据，5.12秒储备理论上可支持等量音频消费，但真实可容忍窗口还受在途服务、边界、近端FIFO和错误恢复影响。不能仅凭容量证明任意5.12秒停顿都无感。

## 4. 完整扇区才允许提交

`audio_prefetch_sdram`检查字节数量、索引和错误；只有完整512字节收齐、没有错误并且DMA写入成功，才推进写指针并发布占用量。

假如只收到300字节就发布，消费者会把后212字节旧数据当新声音。这种错误可能表现为偶发噪声，不能依靠“通常读卡没问题”规避。

还有一个常见边界：最后字节valid与done可能同拍，判断逻辑必须把这一拍也算进去。不能只检查上一拍计数已经等于512。

## 5. 两种仲裁必须分清

### SD服务仲裁

决定哪个请求获得下一段卡服务。当前顶层把音频优先条件明确接入，在音频低储备时限制MV和背景获得新的服务。MV使用CMD18突发，还需要底层总线拥有权、暂停/结束与恢复；已经开始的物理事务不能随意中途改属主。

“音频优先”描述的是当前可允许的仲裁边界和准入策略，不等于硬件可以瞬间抢断正在返回的任何一个字节。

### SDRAM仲裁

决定图形、音频DMA、读写尾部如何共享内存控制器。当前仲裁器不仅选择地址和数据，还需要保持byte mask直到排队写尾完成，读之前恢复适当掩码。

厂家加密控制器的特定接口行为使掩码保持成为必要条件。解释这个已观察到的接口契约，比泛泛说“用了仲裁器”更有工程深度。

## 6. 48kHz节拍与实际消费不是一回事

25MHz/48kHz=520.833...，不能用固定整数521分频精确得到48kHz。分数累加节拍通过混合520与521周期的间隔得到正确长期平均采样率。

`sample_tick`表示该尝试供样的节拍；`sample_consumed`表示本次真正从有效PCM缓冲读出了数据。暂停、尚未准备好或欠载时，两者可以不同。

顶层`timebase_48k`实际接的是`wav_sample_consumed`。每48个被消费样本增加1ms，从而让歌词、进度和MV围绕媒体真实推进，而不是各自按壁钟猜测。

这能减少多个独立计时器造成的逻辑位置分离，但不是扬声器实际声波与显示器光输出之间的纳秒级同步证明。外设处理延迟和MV10fps量化仍然存在。

## 7. 暂停、欠载、静音的区别

| 状态 | 媒体位置 | 输出样本节拍 | 声音 |
|---|---|---|---|
| 正常播放 | 随有效消费推进 | 持续 | 对应媒体 |
| 普通暂停 | 冻结 | 可继续用零样本维持HDMI链 | 静音 |
| 一键静音 | 通常继续推进 | 持续 | 输出受静音门控 |
| 欠载 | 不能假装消费了不存在的数据 | 仍可补零 | 数据不足，可能听到中断 |

本项目读侧欠载有脉冲诊断。补零避免输出非法旧数据并维持接口节奏，不代表听感完全无损，也不等于问题已经恢复。稳定性应该同时看欠载计数、最低储备和真实听音。

## 8. Seek必须同时改变数据与时间

假设目标样本号为S：

```text
扇区偏移 = floor(S / 256)
扇区内跳过样本 = S mod 256
目标LBA = audio_start_lba + 扇区偏移
媒体毫秒 = floor(S / 48)
MV目标帧 = floor(媒体毫秒 / 100)，再按总帧数钳位
```

例：123.456秒对应5925888个样本，扇区偏移23148、扇区内偏移0，MV帧目标1234。若S=1000，则目标位于第3个偏移扇区内，丢弃该扇区前232个样本。

EC1一步对应2秒，即96000样本；红外进度步进5秒，即240000样本。先扩位有符号加法，再把目标钳位到`[0,total_samples-1]`；空音频不能产生负上界。

连续旋转时，要在“最新目标”上累加待处理意图，而不是每次读取一个尚未更新的旧播放位置。否则高速操作会丢步、反跳或重复落在同一点。

## 9. 为什么Seek不能直接清空所有寄存器

发出去的SD/SDRAM命令已经属于外部事务，局部状态机清零不能使物理返回消失。旧数据晚到后，可能污染新曲或被错误当成图形读取结果。

`stream_session`先撤销使能，等待存储、视频事务与读端空闲，再等待元数据稳定后启动新会话。音频DMA保留必要的返回所有权和排空过程；只有协调复位才能处理某些底层永不返回的边界。

答辩可用生活比喻开头：“取消订单不能让已经在路上的包裹消失”，随后立即回到信号：撤销请求、等待busy/ACK、隔离晚返回、重新发布会话。

## 10. 串行除法是合理取舍

`timebase_48k`在Seek装载后把样本号除48转换为毫秒，采用32拍逐位除法。25MHz下32拍约1.28μs，远小于一个48kHz采样周期约20.833μs。

使用多拍计算可避免昂贵的宽组合除法路径，代价是结果有短暂准备窗口。实现同时记录转换窗口中的实际消费样本，并处理load比restart更高的优先级，防止Seek被误清零。

重要理解：运算的“拍数多”不必然用户体验慢，要比较真实时间与所需截止时间。

## 11. MV不是MP4解码器

当前MV输入为预制320×240、RGB565LE、10fps、连续存放的帧序列：

```text
每帧 = 320 × 240 × 2 = 153600B
每帧 = 300扇区
10fps载荷 = 1536000B/s
加单声道音频 = 1632000B/s，尚未计协议与其他媒体开销
第F帧起点 = mv_start_lba + F × 300
```

这里有帧读取、像素展开、缓存和调度，没有H.264/MP4压缩解码。原始文件可以由PC离线转换，但应把转换过程单列说明。

## 12. 当前MV三bank调度

当前`mv_frame_scheduler`维护显示bank、已完成待显示bank和可写bank。显示bank只在`frame_start`改变，未完成帧不能被显示。

按音频时间决定应该显示哪一帧。若旧帧晚到，可以跳过过时帧、追上时间，而不是把所有历史帧慢慢播放造成持续落后。暂停时可保持当前帧，首次帧准备与重启又有专门处理。

README曾记载六帧缓存候选，但当前顶层地址与scheduler明确是三个MV bank。不要把10月23日候选的六帧表现、100.8ms仿真换帧间隔搬来当当前版本实测。

## 13. CDC四种常用方法

| 跨域对象 | 方法 | 必须记住的限制 |
|---|---|---|
| 慢变化单比特电平 | 两级同步 | 降低亚稳态传播概率，不能绝对消除 |
| 稀疏事件 | toggle后同步并异或检测 | 源事件太快、两次翻转未被采到仍可能丢失 |
| 多位状态快照 | 保持数据稳定+req/ack握手 | 数据必须保持足够久，不能逐位独立同步后假设原子性 |
| 连续数据流 | 双时钟FIFO、Gray指针同步 | 指针、水位、复位与物理约束仍需认真设计 |

`cdc_bundle_latest`在忙时合并为最新值，适合参数状态，不适合要求每一个中间值都必须交付的事件。EC1事件桥使用计数差重放并插入源时钟间隔，正是为了不把toggle当无限速队列。

SDC中的异步时钟组只是告诉时序分析如何处理关系，不会自动制造同步电路。Gray码每次逻辑加一只改变一位，但实际布线偏差和采样约束仍要评估。

## 14. HDMI ACR与媒体同步的分工

ACR通过N/CTS描述音频采样率与TMDS时钟的比例，帮助接收端恢复音频节奏；媒体时间负责歌词、进度、MV的内容位置。两者解决不同层面的问题。

典型关系为：`128 × Fs = F_TMDS_clock × N / CTS`。当前`audio_arc_calculate`默认N=6144，并测量一组音频valid之间的像素时钟周期形成CTS。在25MHz、48kHz条件下，名义CTS约25000。

本项目中ACR参数计算在可读RTL，实际音频包/视频编码发送依赖厂家HDMI核，不能把全部工作都归给自己或全部归给黑盒。[AMD ACR接口文档](https://docs.amd.com/r/en-US/pg235-v-hdmi-tx-ss/Audio-Clock-Regeneration-Interface)可辅助理解N/CTS接口概念；具体行为仍以安路接口和当前RTL为准。

## 15. 你应能讲出的三个故障故事

1. 读卡短时慢：分层缓存+音频优先，观察水位与欠载，不能只看平均吞吐。
2. Seek后歌词/MV归零或错帧：检查目标装载、restart优先级与定位结果稳定过程。
3. 切歌后颜色或声音串扰：检查晚到事务、内存读返回所有权、字节掩码与读格式锁存。
