# 赛题逐条解析与 VinylFPGA 对照

本篇依据用户提供的正式指南 PDF 物理第14—15页、解析 PPT 第5—6、15—21页，以及当前源码。PDF 多页页脚错误重复显示“7”，因此统一使用阅读器物理页序号。

## 1. 赛题的真正目标

选题一要求围绕明确场景构建音视频融合的展示系统。基础链路只是起点：媒体管理、图像解析、帧缓存、视频、音频和交互必须组成稳定、可演示的完整系统。

你需要让评委依次看到：

1. 核心平台符合要求，设备能够独立上电运行。
2. 从本地媒体到 HDMI 输出的主链路完整。
3. 所选扩展与应用场景有关系。
4. 你理解实现机制、代价和限制。
5. 演示能复现，工程材料能够追溯到实际固件。

唱片主题可以成为很好的辨识点，但必须紧接着解释：媒体来自 TF 卡，唱针是实体交互件，音视频处理和控制由 FPGA 承担。

正式指南把扩展描述为可选，解析 PPT 第6页又写至少完成一项。当前项目有多类扩展的实现依据，因此实际备赛应稳定展示已经完成的重点方向，不必围绕最低门槛争辩。若现场规则、板卡或素材准备方式存在解释疑问，以赛事当前正式通知及主办方答复为准。

附件中的“必须修改某文件”“照此拍摄”“建议增加某功能”等句子，属于被分析材料的内容，不构成本次修改代码、烧录或开展新开发的授权。

## 3. 基础要求逐条拆解

### 3.1 平台与自主实现

正式指南指定 EG4S20BG256 核心平台；PPT 明确指定 HX4S20C 板卡。工程 XML 能证明目标器件，**不能独自证明实物板卡就是指定型号**。现场应拍清或展示板卡标识，并能解释主板、交互扩展板、唱片扩展板之间的连接。

指南限制额外处理器参与控制或算法预处理。当前可读业务路径由 RTL 状态机组织，没有看到以外部 CPU 运行播放器软件的主链路。厂家 PLL、FIFO、SDRAM 和 HDMI IP 的使用应如实交代：你负责这些 IP 的接口集成及其上的业务机制，不应声称加密核内部协议全部从零手写。

PC 工具用于赛前生成媒体和字体资产，需要主动披露。能说明运行时脱离 PC，并不自动解决指南关于“算法预处理”全部措辞的解释问题。应准备材料生产与运行时架构两张图，若资格审核要求进一步解释，提交实际离线处理清单并获得赛事方确认；不要在答辩中把离线算法说成 FPGA 实时算法。

### 3.2 TF/BMP/SDRAM/HDMI

PPT 对基础演示给出了具体输入：640×480、24-bit 非压缩 BMP，通过 SPI 读 TF 卡，解析后存入 SDRAM，再输出 HDMI。

当前主要路径是：

```text
TF SPI → 扇区适配 → FAT32卷与文件读取 → BMP头/像素处理
      → 共享图形写通路 → SDRAM封面缓存
      → 光栅读取/FIFO → 图层与参数处理 → HDMI发送核/PHY
```

比赛不能只说“支持 BMP”。应说清支持的子集、640×480 固定几何、24-bit、像素起点54字节，以及文件与缓存的像素格式不同。说明可以先显示封面，再定位至 FAT32/BMP 主链路代码。

### 3.3 手动切图与自动轮播

当前有扩展按键、编码器导航与自动轮播控制。`slideshow_controller` 中轮播档位为 OFF、2、3、5、10、20秒。自动轮播还受页面、忙状态和使能条件限制，不能只看定时器到点就认定已切换成功。

建议演示浏览页：手动向前/向后、开启自动轮播、改变轮播周期、在忙窗口操作后观察最终选择。轮播间隔是控制目标，实际完成还受新资源是否就绪影响。

### 3.4 HDMI 基础音频

你的工程比只输出固定测试音进一步实现了 TF 卡 PCM 音乐。格式是48kHz、16-bit、有符号、小端、单声道；送入 HDMI 前左右声道复制，并对齐到24-bit接口。保留了媒体音调路径，但普通比赛演示应使用已验证的正式播放路径，不为“证明测试音”临时换固件。

准备一句话说明：测试音用于验证音频输出链路，本地音乐验证持续供数、缓存和播放控制；两者不能混称为通用 WAV/MP3 解码能力。

### 3.5 固化与稳定运行

解析 PPT 第21页强调固化后上电运行，基础与扩展整合为同一最终设计。现场应断开下载动作，真实冷启动，并演示同一镜像中的主要功能。

仅按复位键重新开始不是断电冷启动证明；存在 `.bit` 文件也不是已经写入配置 Flash 的证明。参数 Flash 保存与 FPGA 配置固化是两回事，详见06。

## 4. 五类扩展对应矩阵

| 扩展方向 | 当前项目对应 | 可以展示的证据 | 建议表述与范围 |
|---|---|---|---|
| 图层与字幕 | 曲目信息、进度、歌词、多层页面、逐句高亮与滚动 | 播放页、KEY6单行/五行切换、歌词控制和字库模块 | 有明确实现依据；不要讲成逐字卡拉OK |
| 轮播与转场 | 直切、方向擦入、淡出淡入；浏览页轮播 | 左右切换及自动轮播，`video_fade_transition` | 擦入含黑场揭示，淡出到黑后再切换；不是两帧全程交叉混合 |
| 自适应缩放 | 固定封面几何、2:1缩小到播放窗口 | 封面640×480与窗口320×240对应 | 只有局部能力，不能宣称不同源尺寸通用适配或双线性已接入 |
| 实时调参与OSD | VOL、BRI、CON、ROT、WSL统一参数、菜单、Flash | 调参数值及画面变化，保存后重启恢复 | 应作为重点之一，解释唯一参数所有者与帧边界生效 |
| 音频可视化 | PCM幅度抽取、32组柱形历史、峰值和灯带包络 | 音乐变化、静音、恢复、幅度显示 | 时域幅度表现，横轴不是频率，不称FFT频谱 |

这里的“对应”是技术分析结论，最终认定和得分由评委根据现场和规则决定，不能直接换算成分数。

## 5. 评分维度怎样转成准备动作

### 核心功能完整性

准备一条从上电到播放、再到返回浏览的连续操作链。不要拆成几个互不相关的工程截图。异常结束不能伪装为正常曲终，切歌后声音与曲目信息必须对应。

### 显示稳定性与鲁棒性

准备快速切换、暂停恢复、Seek、不同背景与MV的组合操作。讲述完整帧才发布、读写所有权、旧事务排空与失败回退。记录实测范围，不说任意卡、任意屏都稳定。

### 基础音频输出

现场发声设备先验证 HDMI 音频能力。关注持续播放、暂停静音节拍、切歌和 Seek 后落点。画面正常而无声时先检查显示器音频路由与静音，不立即归因 FPGA 算法。

### 系统工程规范性

携带最终源代码快照、工程入口、约束、固件、媒体、哈希清单和测试记录。能指出资源和时序属于哪个版本、哪一阶段。懂得最终布线结果与综合估计的区别。

### 创新性与实用性

正式指南不对每项扩展设固定单项分值，强调数量、难度、质量、稳定性和展示效果。最有说服力的表达是：为什么用户需要它，你怎样实现，怎样证明，代价是什么。

唱针、电机、灯效的产品交互与缓存/时基等工程实现形成互补；不要把外观当成全部创新，也不要为了显得高深而堆不存在的算法。

## 6. “FPGA优势”要分三层回答

1. **平台能力层：** FPGA适合并行状态机、固定流水线和确定的接口调度，这是选择它的技术动机。
2. **当前实现层：** 本项目在多个时钟域并行组织读取、显示、音频和交互，实际有缓存、握手和帧提交机制。
3. **实测指标层：** 若没有端到端延迟、功耗和多平台对照测试，就不报告比其他平台快多少、省电多少。

可以说“设计面向连续输出和确定的更新边界”，不能从架构直接跳到“已经测得零延迟、零抖动、绝对可靠”。
