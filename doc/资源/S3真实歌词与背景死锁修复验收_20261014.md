# S3 真实歌词与背景缓存验收教程

本阶段在 S2（`3510eed`）上增加四首真实歌词，并修复背景图缓存读取 SD 扇区时与共享 SDRAM 写事务互相等待的问题。S3 尚未提交；请先完成人工板级验收，确认通过后再提交。

## 交付内容

- 四首歌曲的标题、歌手及时间轴歌词来自 `doc/资源/sd卡/歌曲素材/歌曲1..4/*.srt`。每首歌词独立对应歌曲，LYR2 v2 文件含 UTF-8 文本和 CRC32。源字幕实际 cue 数依次为 50、68、19、63；按现有 16 字符显示窗口排版后的显示行数为 128、76、23、63。
- FPGA 显示端使用从同一组 LYR2 行数据生成的双字库 ROM；歌曲 1/2 和 3/4 各占一个字库 bank，字符地址为 13 位。封面标题区域最多显示 16 个字符，因此歌曲 1 屏幕标题显示为 `Never Gonna Give`，LYR2 文件保留完整标题 `Never Gonna Give You Up`。
- 为适配 EG4S20 的 BRAM 容量，固件行表把显示时间压为 18 位毫秒值（上限 262144 ms）；本阶段四首最长歌词时间不超过 205700 ms，均在范围内。行表拆分成 5 个同步 BRAM ROM，避免宽常量表消耗逻辑 LUT。
- S3 镜像从已验收 S2 镜像复制生成，保留四首音频、四首全长 MV、封面及 ART1/ART2 背景，并新增 `LYRICS.BIN`。INDEX 的四条曲目均置 LRC 标志。
- **LYR2 运行方式说明：**本阶段把 LYR2 放入 SD 卡并与固件 ROM 内容保持一致；当前 RTL 还没有从 SD 动态读取 `LYRICS.BIN` 的运行时通路。板上歌词由固件 ROM 显示。因此这阶段验收的是四首真实歌词与歌曲同步显示、LYR2 镜像格式及元数据的一致性，不代表固件在运行时读取了 LYR2 文件。后续若要求换卡即可动态替换歌词，需要单独实现和验证 SD LYR2 文件加载流程。
- 背景缓存事务改为先取得扇区仲裁许可，再申请 SDRAM writer；收到 writer 确认后才真正发起 SD 扇区读，避免等待 SD 仲裁时一直占住 writer。失败后取消 writer 并重试同一 LBA。

## 操作步骤

1. 先确认 S2 板级验收结论，并使用健康 SD 卡。若卡在系统中无法稳定识别，换卡或先处理卡/读卡器问题；不要在不确定目标盘时继续写入。
2. 在 PowerShell 中核对镜像哈希：

   ```powershell
   Get-FileHash -Algorithm SHA256 'D:\Data_Backup\VinylFPGA_Workspace_Base\VinylFPGA_backups\S3_lyrics_20261014_r5\card_STAGE3.img'
   ```

   输出须与上方 S3 镜像 SHA256 完全相同。

3. 运行 `doc\资源\sd卡\write_card_s3.bat`（管理员权限）。先选择只读诊断；核对磁盘号、型号、序列号和容量确为目标 SD 卡。按提示逐项输入写入确认。该操作会覆盖所选磁盘整盘数据。
4. 等待整盘写入、flush 与完整 SHA256 回读完成。只有工具报告回读通过且读回 SHA 与镜像 SHA 相同，才安全弹出卡。耗时取决于卡、读卡器和接口；记录写入与读回各自耗时，不要中途拔卡。
5. 使用上方完整路径的 S3 `VinylFPGA.bit` 烧录 FPGA。烧录前在 PowerShell 执行 `Get-FileHash -Algorithm SHA256 '<bit 完整路径>'`，结果须为 `62ac5aac5e46d9be509310fb73df68972862bf8bc6c73ad1314a3b5e8a9628ee`；不要误烧旧的 S1/S2 bit。
6. 插入 S3 SD 卡冷启动，等待 SD 初始化和封面索引完成，再按曲目逐项测试。
