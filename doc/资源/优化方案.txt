#### 1. 模块级资源热点与瓶颈分布（基于历史 native 与当前 gate 审查）

安路 EG4S20BG256 芯片硬件上限为 **19,600 LUT4**、**9,800 Slices**（4,900 PLB）和 **64 块 9Kb BRAM**：

* **总体水位**：当前 LUT 约占 79.5%~81%（约 15,600~15,900），Slice 约占 87%（约 8,530），BRAM9K 已固化占用 **47 块**（73.4%），DSP 占用 **10 个**。


* **PLB 密度极限敏感**：历史数据显示 PLB 占用曾达到 2,422/2,450（98.86%）。这意味着芯片逻辑单元虽未全满，但局部拥塞严重，布局布线器走线自由度极低。


* **最紧迫时序路径（WNS 瓶颈）**：
1. **SD 域（100 MHz）**：`fat32_volume_scanner` 到 `fat32_file_streamer` 的 `max_cluster` 扇出网络（逻辑级数达 7 级，布线延迟占比高达 67%，WNS 仅 +0.188 ns）。


2. **内存域（125 MHz）**：`background_raster_address` 中的跨边界连续突发跨度计算（`screen_span` 与 `contiguous_words`），存在 10-bit 减法与比较级联。


3. **视频域（25 MHz）**：`playback_page` 内部的多级字模像素合成 MUX 树与消隐控制逻辑。

### 三、 收尾期“零功能受损”资源与时序优化开发方案

在系统功能已完全实现且通过验收的收尾阶段，严禁对模块接口、协议握手与视觉坐标做颠覆性改动。优化策略聚焦于“死代码剥离、算术常数折叠、高扇出网络打拍、逻辑共享降维”四大核心方向：

```
                    【四大无损优化维度与预期收益】
┌──────────────────────────────────────┬──────────────────────────────────────┐
│ 1. 静态死代码与诊断冗余剔除          │ 2. 编译期常数折叠与无乘法化          │
│  - 清理未接入模块与未连接引脚        │  - 将固定 640×480 像素积硬编码化     │
│  - 剥离 DIAG_SDRAM_PATTERN 生成逻辑  │  - 消除动态 16×16 乘法器             │
│  [预计释放: 80~120 LUT4, 40+ REG]    │  [预计释放: 1~2 DSP / 60~90 LUT4]    │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ 3. 静态跨时钟域信号打拍（切断关键路径）│ 4. 复合光栅跨度运算扁平化            │
│  - 对 max_cluster 等准静态信号插入寄存器│  - 将三元运算级联拆分到流水线预计算  │
│  - 分解 35+ 扇出网络                 │  - 优化 125MHz 突发地址计算链路      │
│  [预计提升: Setup WNS 提高 0.15~0.3ns] │  [预计释放: 30~50 LUT4, 改善布局收敛] │
└──────────────────────────────────────┴──────────────────────────────────────┘

```

#### 优化项 1：顶层未用诊断与死逻辑彻底剔除

1. **清理 `DIAG_SDRAM_PATTERN` 逻辑块**：
`top_tf_hdmi_audio.v` 中定义了完整的彩条模式测试状态机（`pat_wr_req`, `pat_x`, `pat_y`, `pat_state`, `pat_err_cnt` 等约 80 行代码）。虽然 `pat_mode` 为 0，但部分综合器仍会生成不可见的未约束逻辑网络，直接增加全局装箱压力。通过 Verilog `generate` 或直接宏隔离该段逻辑。


2. **剔除冗余实例 `seg_decoder_m0**`：
顶层第 544 行例化了 `seg_decoder seg_decoder_m0` 输出 `seg_data_0`。而在后续数码管显示中，`seg_business_mux` 与 `seg_scan` 完全接管了 `seg_biz_0~7`，`seg_data_0` 属于完全开路的废弃逻辑，直接删除此例化。


3. **清理已弃用的内部连线与接口**：
解除 `song_text_rom` 上的 `ui_ascii_code` 与空挂引脚 `ui_glyph`，删除顶层历史占位信号。



#### 优化项 2：`fat32_media_loader` 编译期常数折叠与乘法器消除

* **代码现状**：
```verilog
expected_pixel_count_q <= {16'd0, bmp_width} * {16'd0, bmp_height};
required_pixel_bytes_q <= (({16'd0, bmp_width} * {16'd0, bmp_height}) << 1) + 
                           ({16'd0, bmp_width} * {16'd0, bmp_height});

```


* **优化动作**：
`bmp_width` 与 `bmp_height` 在顶层固定传入 `16'd640` 与 `16'd480`。在硬件中计算这组动态乘法纯属资源浪费：



$$\text{expected\_pixel\_count} = 640 \times 480 = 307200 = 32\text{'h}0004\text{\_}B000$$


$$\text{required\_pixel\_bytes} = 307200 \times 3 = 921600 = 32\text{'h}000E\text{\_}1000$$



直接替换为 32 位常量赋值。**此项改造可在 100 MHz 关键路径上直接剔除 1 组宽位乘法/移位加法网络，释放 50~80 个 LUT4 并大幅降低 MSlice 拥塞**。



#### 优化项 3：准静态长关键路径流水打拍（主攻 Setup WNS）

* **代码现状**：
在 `fat32_volume_scanner.v` 中，`max_cluster` 在解析完 BPB 后即保持不变，但它直连到 `fat32_file_streamer.v` 的比较器中，形成 7 级逻辑级数和扇出 35 的全工程最差时序路径（网络延时占 67%）。


* **优化动作**：
在 `fat32_file_streamer.v` 输入端将 `max_cluster`、`fat_start_lba`、`data_start_lba` 打 1 拍寄存器（`max_cluster_q`），仅在启动状态（`ST_IDLE`）装载。这一改动**将原本跨越整个层次的长线网络完全阻断，直接为 100 MHz 域斩获 +0.20 ns 以上的 Setup 裕量**。



#### 优化项 4：`background_raster_address` 突发跨度逻辑扁平化

* **代码现状**：
在 `video/background_raster_address.v` 中：
```verilog
wire [9:0] screen_span = (media_row && x < 10'd16) ? 10'd16 - x :
                        (media_row && x < 10'd336) ? 10'd336 - x : 10'd640 - x;

```


此三元操作在 125 MHz 内存时钟下级联了 3 个 10-bit 减法器和比较器。


* **优化动作**：
将减法操作前移至时钟沿打拍计算：利用计数器 `x` 的预判位，分别在 `x < 16`、`x < 336` 区间输出对应的常数减法结果，避免在组合逻辑级联中消耗级联进位链，削减约 20 个 LUT4 并稳固 125 MHz SDRAM 访问时序。
