### 一、 故障深度溯源：为什么选歌时长乱码、播放界面数字无法显示？

经过对当前工程代码树（`top_tf_hdmi_audio.v`、`song_text_rom.v`、`playback_progress.v` 及 `playback_page.v`）的交叉比对，时长乱码和数字不显示的根本原因在于以下四处底层硬件断层：

```
                    【时间总线与字符渲染链路断层排查】
[SD/媒体域: 100MHz]                                      [视频像素域: 25MHz]
audio_size_bytes ──(32位总线无CDC跨域: 严重数据撕裂!)──► u_playback_progress (解算时长)
                                                                 │
                                                   输出: playback_time_ascii[103:0]
                                                                 │
                          ┌──────────────────────────────────────┴──────────────────────────────────────┐
                          ▼                                                                             ▼
               【致命断层 1: 字库路由完全跑偏】                              【致命断层 2: BCD与ASCII基准脱节】
         playback_page 尝试将 ASCII 字符送入 song_font_rom             解算得到的数值(0~9)未加上 8'h30 偏置，
         song_font_rom 仅包含歌曲文本中提取的 178 个汉字!               输出的是 0x00~0x09 (不可见控制字符)，
         数字 0x30(48) 被强行当作“第48号汉字”读出，导致全屏随机汉字乱码!  或总线高低位截取端序颠倒，数字全变空白或乱码!

```

#### 1. 致命断层 1：字符内码与 ASCII 混淆，把数字送进了中文字库

* **代码事实**：工程中的 `song_font_rom`（约 4113 行）是由 `tools/gen_lrc_assets.py` 离线去重生成的，**内部仅收录了 4 首歌曲歌名、歌手和歌词中出现过的 178 个专用汉字字模**。


* **致错机理**：在第 1 阶段重构中，为了避免新增 BRAM 字库，代码试图通过 `song_text_rom` 的 `ui_ascii_code` 接口将时间字符转交给 `song_font_rom` 渲染。但 `song_font_rom` 中根本没有 ASCII 字符索引；当输入字符 `'0'`（ASCII `0x30`，十进制 48）时，字库直接将其当成“第 48 号汉字”取出点阵！这就是**歌名汉字显示完全正常，而时长却变成一串奇怪汉字乱码**的直接原因。


* **修正方案**：工程中原本就包含 `src/display/ascii_font_rom.v`（86 行的轻量级标准 ASCII 点阵）。数字、冒号、负号必须直接走专用 ASCII 字符渲染流，与中文歌曲字库彻底解耦。



#### 2. 致命断层 2：BCD 码未加 `0x30` 偏置或字符总线端序错位

* **代码事实**：`playback_progress.v` 计算分秒后，在二进制转 BCD 阶段拆解出的分秒是 `4'd0 ~ 4'd9` 的裸数值。


* **致错机理**：若未加上 `8'h30` 偏移（`'0'` 的 ASCII 码），输出的总线字符码为 `8'h00 ~ 8'h09`，属于 ASCII 控制字符（NUL、SOH 等），导致字模输出全部为空白；此外，104 位宽总线如果截取端序高低位接反，也会导致冒号与数字拼错半边字节，完全无法显示数字。



#### 3. 致命断层 3：`total_samples` 跨时钟域撕裂（CDC 隐患）

* **代码事实**：`audio_size_bytes` 是在 `sd_card_clk`（100 MHz）下根据 FAT32 解析出的，顶层直接将 `play_total_samples` 跨域接到了 25 MHz 视频域的 `playback_progress`。


* **致错机理**：选歌切换时，32 位总线由于走线偏斜（Clock Skew），在 25 MHz 域采到中间过渡态非法值（如瞬间跳变），导致除法状态机算出的时间溢出，选歌界面时长瞬间崩溃。

### 四、 核心代码重构方案：彻底根治时长与数字显示

#### 1. `playback_progress.v` 重构：场消隐安全解算与三组分立 ASCII 输出

彻底废除原工程中易发生截取端序错误的 104 位宽总线，拆分成三组语义清晰的独立总线，并在内部完成带 `8'h30` 偏移的 ASCII 编码：

```verilog
module playback_progress (
    input  wire        clk,                 // video_clk (25MHz)
    input  wire        rst_n,
    input  wire        vs,
    input  wire [31:0] elapsed_samples,     // 来自 timebase_48k
    input  wire [31:0] total_samples,       // 已经过 frame_start 同步的样本总数
    output reg  [8:0]  progress_fill,       // 0 ~ 320 填充像素
    output reg  [39:0] elapsed_time_ascii,  // " 0:27" 或 "00:27", 5 字符
    output reg  [39:0] remaining_time_ascii,// "-2:30" 或 "-02:30", 5 字符 (带负号!)
    output reg  [39:0] total_time_ascii,    // " 3:48" 或 "03:48", 5 字符 (用于选歌界面)
    output reg         time_known
);

```

##### 场消隐 32 拍轻量状态机算法（0 DSP、零扫描期除法）

在垂直消隐开始时（`vs` 下降沿），基于 48kHz 时基执行秒数换算：


$$\text{elapsed\_sec} = \text{elapsed\_samples} / 48000, \quad \text{total\_sec} = \text{total\_samples} / 48000$$

$$\text{rem\_sec} = (\text{total\_sec} > \text{elapsed\_sec}) \ ? \ (\text{total\_sec} - \text{elapsed\_sec}) : 0$$

$$\text{progress\_fill} = \frac{\text{elapsed\_samples} \times 320}{\text{total\_samples}} = \frac{(\text{elapsed\_samples} \ll 8) + (\text{elapsed\_samples} \ll 6)}{\text{total\_samples}}$$


换算完成后，统一进行 BCD 拆解并显式赋予标准 ASCII 编码：

```verilog
function [7:0] to_ascii;
    input [3:0] bcd_digit;
    begin
        to_ascii = 8'h30 + {4'd0, bcd_digit}; // 必须加上 0x30，彻底杜绝乱码！
    end
endfunction

// 赋值输出端（注意高字节在前，与屏幕光栅从左向右严格一致）：
elapsed_time_ascii <= {
    (cur_min_tens == 0) ? 8'h20 : to_ascii(cur_min_tens), // 高位为0显示空格更精致
    to_ascii(cur_min_units),
    8'h3A, // ':'
    to_ascii(cur_sec_tens),
    to_ascii(cur_sec_units)
};

remaining_time_ascii <= {
    8'h2D, // '-' 负号字符（严格对标参考图！）
    (rem_min_tens == 0) ? 8'h20 : to_ascii(rem_min_tens),
    to_ascii(rem_min_units),
    8'h3A, // ':'
    to_ascii(rem_sec_tens),
    to_ascii(rem_sec_units)
};

total_time_ascii <= {
    (tot_min_tens == 0) ? 8'h20 : to_ascii(tot_min_tens),
    to_ascii(tot_min_units),
    8'h3A, // ':'
    to_ascii(tot_sec_tens),
    to_ascii(tot_sec_units)
};

```

#### 2. `playback_page.v` 重构：字库通道分离与独立 ASCII 像素流水线

在页面渲染器内部，严格分离**中文字模通道**与 **ASCII 数字/符号通道**：

* **歌名/歌手/歌词**：继续访问 `song_font_rom`（16×16，字模 ID 从 1 开始）。


* **时长数字/负号/冒号/曲号**：内部集成或直接连接 `ascii_font_rom`（8×16 等宽点阵）。



##### 相对坐标提取与像素着色逻辑（杜绝复杂比较器）

```verilog
// 1. 已播时间 (X ∈ [16, 55], Y ∈ [350, 365]):
wire in_elap_y = (pixel_y >= 10'd350) && (pixel_y <= 10'd365);
wire [8:0] elap_x_rel = pixel_x[9:0] - 10'd16;
wire in_elap_box = in_elap_y && (elap_x_rel < 9'd40); // 5 个字符，每个宽 8 像素

// 提取当前列对应的字符 (从左到右 0 ~ 4):
reg [7:0] elap_char_code;
always @(*) begin
    case (elap_x_rel[5:3])
        3'd0: elap_char_code = elapsed_time_ascii[39:32];
        3'd1: elap_char_code = elapsed_time_ascii[31:24];
        3'd2: elap_char_code = elapsed_time_ascii[23:16];
        3'd3: elap_char_code = elapsed_time_ascii[15:8];
        3'd4: elap_char_code = elapsed_time_ascii[7:0];
        default: elap_char_code = 8'h20;
    endcase
end

// 2. 剩余时长 (X ∈ [296, 335], Y ∈ [350, 365], 严格右对齐):
wire [8:0] rem_x_rel = pixel_x[9:0] - 10'd296;
wire in_rem_box = in_elap_y && (rem_x_rel < 9'd40);

reg [7:0] rem_char_code;
always @(*) begin
    case (rem_x_rel[5:3])
        3'd0: rem_char_code = remaining_time_ascii[39:32]; // '-' 负号
        3'd1: rem_char_code = remaining_time_ascii[31:24];
        3'd2: rem_char_code = remaining_time_ascii[23:16];
        3'd3: rem_char_code = remaining_time_ascii[15:8];
        3'd4: rem_char_code = remaining_time_ascii[7:0];
        default: rem_char_code = 8'h20;
    endcase
end

// 3. 320px 纯白流线进度条 (X ∈ [16, 335], Y ∈ [342, 345]):
wire in_bar_y = (pixel_y >= 10'd342) && (pixel_y <= 10'd345);
wire [8:0] bar_x_rel = pixel_x[9:0] - 10'd16;
wire in_bar_range = in_bar_y && (bar_x_rel < 9'd320);
wire is_bar_filled = in_bar_range && (bar_x_rel < progress_fill);

```

#### 3. 顶层 `top_tf_hdmi_audio.v` 跨时钟域防撕裂补丁

在顶层将 `play_total_samples` 安全同步到 `video_clk` 域，并在 `frame_start`（消隐开始沿）锁存：

```verilog
reg [31:0] total_samples_v1, total_samples_v2, total_samples_frame;

always @(posedge video_clk or negedge video_rst_n) begin
    if (!video_rst_n) begin
        total_samples_v1    <= 32'd0;
        total_samples_v2    <= 32'd0;
        total_samples_frame <= 32'd0;
    end else begin
        total_samples_v1 <= play_total_samples;
        total_samples_v2 <= total_samples_v1;
        if (frame_start) begin
            total_samples_frame <= total_samples_v2; // 场消隐期间原子锁存，杜绝数据撕裂
        end
    end
end

```
