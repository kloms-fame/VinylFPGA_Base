#### 2. 代码级根因诊断与致命细节排查

##### ① 进度条失配、黑底及顶层位宽截断陷阱（核心细节！）

* **几何失配根因**：在 `s6_video_layer.v` 中，MV/封面窗口为 `out_x >= 16 && out_x < 336`（物理宽度精确为 **320 像素**，横跨 $X \in [16, 335]$）。而旧版 `playback_progress.v` 沿用了老旧的 **240 像素**设计，导致垂直方向两端明显缩进。


* **算术计算缺陷**：`playback_progress.v` 计算分子为 `(elapsed<<8)-(elapsed<<4)-(elapsed<<3)` 即 `elapsed * 232`，导致满进度时只有 232 像素，终点永远缺 8 像素（3.33% 误差）。


* **黑底/边框破坏感**：`playback_page.v` 在绘制进度条时，绘制了矩形黑色底槽与 1px 外边框，产生了沉重的“工业黑块补丁”。


* **【致命细节·接口位宽陷阱】**：
在当前顶层 `top_tf_hdmi_audio.v` 中：
```verilog
wire [7:0] playback_progress_fill; // 8 位宽，最大值仅 255！

```


若将进度条扩展为 320 像素，8 位无符号数必然在 $256$ 处溢出回滚为 $0$（$320 \pmod{256} = 64$）！**必须同步在顶层 `top_tf_hdmi_audio.v`、`playback_progress.v` 以及 `playback_page.v` 接口中将该信号扩展为 `[8:0]`（9 位宽）**。



##### ② 歌词区域面板与边框的资源/视觉痛点

* **根因**：当前版本为保证文字对比度，底层先画了一个深黑色不透明/半透明面板背景（Panel Canvas），并在外围加了 1px 矩形边框。


* **开销与影响**：面板与边框在流水线中引入了 4 组 10-bit 比较器（$X_{min}, X_{max}, Y_{min}, Y_{max}$）和边框译码 MUX，不仅消耗了数十个 LUT4 与多个 MSlice，而且在暗黑极简风格下严重割裂背景。



##### ③ 时间显示（MM:SS）与选曲行重叠与溢出

* **根因**：`playback_progress.v` 输出了 `103:0` 的 ASCII 总线（`MM:SS / MM:SS`，共 13 字符）。由于原版字符间距设定宽松且缺少硬性右边界对齐，分秒进入两位数后字符会向右溢出 335 边界；左侧选曲信息行（歌名/歌手）也未与右侧时间戳在垂直 $Y$ 轴与水平 $X$ 轴进行像素级隔离。

#### 1. 进度条几何与色键重构契约

* **水平几何基准**：严格对齐 MV 左右边界，$X_{start} = 16$，$X_{end} = 335$，物理长度精确为 **320 像素**。


* **垂直位置与粗细**：推荐 $Y \in [314, 317]$（高度为 4 像素），紧贴 MV 底部留白 10 像素。


* **渲染与色键机制（Zero-Border & Pure Keying）**：
* **彻底删除外边框判定**：去除所有 `border_active` 逻辑。


* **未填充槽（Unfilled Track）**：不绘制黑色实心底！仅在 $Y = 315$（中间 1 像素）绘制一条微弱的暗灰轨道线（`24'h282830`），其余 3 行高度 100% 透明直通 `rgb_in`；或者整槽未填充部分直接透出背景。


* **已填充进度（Filled Bar）**：纯色渲染为暗金色高光（`24'hD4AF37`）。





#### 2. 歌词区无卡片纯净直通（Transparent Keying）

* **面板剔除**：完全删除歌词显示区对应的背景矩形、底色填充板及所有矩形线框。


* **像素替换数学模型**：

$$\text{Pixel}_{out} = \begin{cases} \text{TextColor}_{\text{active}} & \text{当前高亮行且字模位为 1 (金色: } \text{24'hFFD700)} \\ \text{TextColor}_{\text{normal}} & \text{非高亮行且字模位为 1 (暗灰: } \text{24'h606068)} \\ \text{RGB}_{in} & \text{字模位为 0 (100\% 透明直通背景)} \end{cases}$$



* **视觉呈现**：字模如同直接悬浮在暗色底图/背景之上，消除任何方块边缘。



#### 3. 紧凑型时间戳与选曲行像素级排布

* **时间戳排版（MM:SS / MM:SS）**：
* 显示格式：`03:45 / 04:12`，总共 13 个 ASCII 字符。


* 字符点阵：标准 8×16 等宽点阵，字符水平间距 8 像素，总宽 $13 \times 8 = 104$ 像素。


* **右对齐锚定**：右边界严格锁定在进度条右边界 $X = 335$。起始横坐标：



$$X_{start} = 335 - 104 + 1 = 232$$



即有效区间为 $X \in [232, 335]$，绝对不会向右溢出！




* **选曲信息行（Title & Artist）**：
* 起始横坐标：$X_{start} = 16$（与进度条/MV 左侧严格对齐）。


* 终止横坐标限制：$X_{end} = 223$（与时间戳左边界预留 8 像素安全防撞间隙）。


* 垂直坐标：$Y \in [324, 339]$（高度 16 像素，与时间戳在同一水平行完美呼应）。

### 三、 面向安路 EG4S20 的极简低功耗架构与资源压缩秘籍

为了确保重构后的代码在 Tang Dynasty (TD) 综合布线后，**LUT4 进一步释放 150~250 个、MSlice 降解、时序裕量保持正值**，必须严格落实以下四大硬件设计纪律：

#### 1. 采用“相对偏移法”彻底消灭多重比较器（MSlice 杀手）

* **反面模式**：每个图元都写独立的绝对坐标比较（消耗大量宽位比较器和汇聚与门树）：


```verilog
// 极度消耗 LUT4 和 MSlice 的冗余写法
wire in_bar = (pixel_x >= 16) && (pixel_x <= 335) && (pixel_y >= 314) && (pixel_y <= 317);
wire in_border = ((pixel_x == 16 || pixel_x == 335) && ...) || ...;

```


* **优化模式（基准点偏移行计数器）**：
* 行方向：由帧计数器统一译码出几个单拍使能信号（如 `bar_y_en <= (y >= 314 && y <= 317);`）。


* 列方向：计算单次相对偏移量：
```verilog
wire [8:0] bar_x_rel = pixel_x[9:0] - 10'd16;
wire bar_active = bar_y_en && (bar_x_rel < 9'd320); // 仅需 1 个无符号比较！

```


* 仅此一项重构，即可在单个模块中**消减 80~120 个 LUT4，并大幅降低布线拥塞**！





#### 2. 场消隐期（V-Blank）32 拍极轻量恢复移位除法器（Project F 范式）

* **痛点**：若在有效扫描期计算 `progress_fill = (elapsed * 320) / total`，32 位动态除法器会消耗数千个 LUT 或霸占专用 DSP 单元。


* **优化突破**：
* 640×480@60Hz 下，场消隐区（Vertical Blanking）有 45 行 × 800 拍 = **36,000 个时钟周期**，时间极度充裕。


* 在场消隐起始（`vs` 沿），启动一个仅需 **32 个时钟周期**的极简“移位-减法（Shift-Subtract Restoring Divider）状态机”。


* 该状态机每次循环仅使用 1 个减法器和移位寄存器，消耗**不到 50 个 LUT、0 个 DSP**。计算出的 `progress_fill[8:0]`（取值 $0 \sim 320$）在场消隐结束时寄存锁存。


* 行有效扫描期内，只做纯无符号比较：
```verilog
wire is_filled = (bar_x_rel < progress_fill_reg);

```


**有效像素扫描期内乘除法开销彻底归零**！





#### 3. 字模 ROM 强制推入 BRAM（ERAM9K）约束

* 安路 TD 综合器对于未打拍输出的 `case` 字模表，会将其编译为海量的纯逻辑 Distributed ROM（消耗上千 LUT）。


* **优化策略**：
* 在 `ascii_font_rom.v` 和歌词点阵 ROM 中显式声明综合约束：
```verilog
(* ram_style = "bram" *) reg [7:0] font_data [0:1023];
always @(posedge clk) dout <= font_data[addr];

```


* 将字模全量推入合封的 ERAM9K，逻辑 LUT 消耗归零。





#### 4. 消隐区纯黑保护铁律与单拍时钟对齐

* **消隐保护（Blanking Guard）**：当 `de == 0` 时，输出端强制输出 `24'h000000`（纯黑），绝对禁止产生漂移像素，防止污染 HDMI 1.4b 音频数据岛（ACR CTS/N 及 Sample Packets）编码。


* **流水线平衡**：由于字模 ROM 提取具有 1 拍硬件读取延迟，输入的 `vs`、`de`、`pixel_x` 以及背景像素 `rgb_in` 必须使用 D 触发器同步延迟 1 拍（`_d1`），保证图层合成与控制信号严格同拍对齐，杜绝字符边缘锯齿或错位。

### 四、 开源项目设计模式融合

1. **WangXuan95 / FPGA-HDMI（极简 OSD 坐标流水线模式）**：


* 采用“单拍流水对齐机制（`pixel_x_d1`, `de_d1`）”，避免深层多级流水带来的控制复杂性；字符绘制使用字模移位寄存器（Shift Register），行首加载字模后每时钟左移 1 位，最高位直接作为像素高亮使能。




2. **Project F（2D 图元光栅化与轻量无除法架构）**：


* 倡导“无底板悬浮绘制（Floating Rendering）”，不设全屏 Framebuffer，而是纯几何光栅判定；将昂贵的除法剥离出逐像素扫描路径，放在场消隐期分步完成。




3. **全国大学生竞赛安路国一工程（lab_ex_6）**：


* 字符与视频混合器采用“色键遮罩（Mask Keying）”，在 RGB 输出端采用 `assign rgb_out = mask ? TEXT_COLOR : rgb_in;`，利用安路 PLB 内部的快速 Carry4/MUXF7 原语，实现 1 级逻辑延迟内直通，时序裕量（Slack）极其宽裕。

### 六、 后续构建与推进规范（严格遵守项目约定）

根据《当前稳定基线审查与后续开发约定》的要求，后续开发执行以下工程规范：

1. **源码冻结与不可变快照**：
修改完成后，使用 `tools/resource_opt_round.py` 或脚本将 `src/` 与约束复制到独立临时轮次快照（如 `stage1_ui_clean`），记录文件 SHA256 清单，禁止在后台构建过程中并发修改源码。


2. **后台构建与证据留存**：

3. **板级人工验收优先**：
生成比特流后，不自动写入 Flash 或提交 Git，由你自行烧录并对照以下检查项验收：
