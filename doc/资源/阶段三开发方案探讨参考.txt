针对播放态背景开发，**最优方案是“PC 端离线高阶高斯预模糊 + 显存空闲区缓存”与“纯硬件极简磨砂漫反射着色器”相结合的混合双轨方案（进阶版方案二）**；方案一（FPGA 纯硬件实时放大模糊）在安路 EG4S20BG256 芯片物理特性下存在刚性物理绝壁，必须予以否决。

#### 1. 方案一的物理死结测算

* **BRAM 物理墙**：参考图中的彩色流体漫反射虚化半径通常超过 40~60 像素。在 640×480 分辨率下，即使仅采用最精简的 $31 \times 31$ 高斯/盒状滤波核，也必须开辟 31 行连续行缓存。每行占用 $640 \times 24\text{ bit} = 15,360\text{ bit}$，31 行共需 **$476,160\text{ bit}$ 的高速缓存**。EG4S20BG256 的 BRAM 总量仅 576 Kbit（64 块 9K），当前工程已固化占用 47 块（约 423 Kbit），**剩余不足 153 Kbit，根本无法开辟卷积行缓冲**。


* **SDRAM 读口仲裁死锁**：SDRAM 单物理端口必须在 25 MHz 节拍下不间断为 HDMI 读 FIFO 供数（每秒消耗 307,200 个 32-bit Word）。若再开辟读通道去并发遍历封面做缩放模糊，读仲裁会频繁将 HDMI FIFO 抽空，导致消隐期或有效扫描期严重撕裂下溢。



#### 2. 最优方案（进阶双轨方案）的破局点

* **空间复用**：当前工程中，4 封面占用 `[0, 1228800)` Words，MV 3 帧环形缓冲占用 `[1228800, 1459200)` Words。而芯片合封的 SDRAM 拥有 2,097,152 Words（8 MB）容量，**尾部尚有 637,952 Words（约 2.55 MB）完全闲置**！一幅 640×480 画面仅需 307,200 Words，这片空间**恰好可以完整存放两张全屏高清艺术背景图（`BG0` 和 `BG1`）**。


* **算术漫反射着色器补位**：设计一个**纯组合逻辑 2D 渐晕漫反射数学模型**（无乘法器，仅耗 18 个 LUT），实时生成与图 2 一致的哑光磨砂深空灰微渐变底色，实现 0 BRAM、0 SDRAM 带宽开销。

#### 1. Mode 0（磨砂深空灰漫反射）纯硬件着色器数学模型

对标图 2 的流媒体暗色模式，底色从画面视窗中心（$X_0=176, Y_0=160$）向全屏四周柔和衰减，呈现出雅致的哑光磨砂质感：


$$\Delta X = \vert{}X - 176\vert{}, \quad \Delta Y = \vert{}Y - 160\vert{}$$

$$\text{Vignette} = (\Delta X \gg 4) + (\Delta Y \gg 3) \quad (\text{纯移位加法，消耗 0 乘法器})$$

$$R = (8\text{'h}28 > \text{Vignette}) \ ? \ (8\text{'h}28 - \text{Vignette}) : 8\text{'h}10$$

$$G = (8\text{'h}2\text{A} > \text{Vignette}) \ ? \ (8\text{'h}2\text{A} - \text{Vignette}) : 8\text{'h}12$$

$$B = (8\text{'h}32 > \text{Vignette}) \ ? \ (8\text{'h}32 - \text{Vignette}) : 8\text{'h}16$$


输出像素在全屏范围内平滑过渡，为右侧歌词和左侧封面提供稳定的阅读对比度。

#### 2. Mode 1 / Mode 2（PC 离线高阶高斯预模糊流体底图）

* **PC 打包脚本流水线**：在 `tools/vinyl_packer.py` 中引入自动生成逻辑。对于每首歌曲封面，自动导出对应的 `BG_SONGx.BMP`（640×480、24 位未压缩），处理流程为：
1. 裁切/填充至 640×480；
2. 执行大核高斯模糊（$\sigma = 60$，消除任何噪点，形成流体渐变）；


3. 增加 15% 饱和度提权，并整体压暗 20%（防止浅色背景导致纯白歌词不可见）；


4. 顺序写入 SD 卡根目录或连续扇区。




* **SDRAM 地址划分与瞬切**：
* `BG_ADDR0 = 21'd1459200`（第 1 艺术底图槽）；
* `BG_ADDR1 = 21'd1766400`（第 2 艺术底图槽）；
* 整个播放期间背景已常驻显存，按键切换只需在帧消隐沿变更显示读地址指针，**切换耗时严格为 0 毫秒，且绝对不会引起音频卡顿**。

### 三、 KEY11（`exp_key_n[10]`, J12）按键重映射与状态机设计

#### 1. 业务冲突彻底解绑

在原工程中，KEY11 在播放态下连接到 `brw_ev_home_tgl`（退出播放返回选歌界面）。

* **修改动作**：在 `ui_event_bridge.v` 和顶层中，**将返回选歌的唯一入口收归为 KEY7（`exp_key_n[6]`）**。


* **新逻辑接入**：KEY11 经硬件消抖（20ms）产生的单拍脉冲，在播放态（`play_active_v2 == 1`）下被识别为 `key11_bg_cycle_pulse`，驱动 2-bit 循环状态机：



```verilog
// 播放态背景模式寄存器 (2-bit, 循环切 4 态)
reg [1:0] bg_mode_reg; // 00: 磨砂灰漫反射, 01: 流体彩色背景A, 10: 艺术背景B, 11: 纯黑演播室

always @(posedge video_clk or negedge video_rst_n) begin
    if (!video_rst_n) begin
        bg_mode_reg <= 2'd0; // 默认采用优雅磨砂灰漫反射
    end else if (frame_start && key11_bg_cycle_pulse_video) begin
        bg_mode_reg <= bg_mode_reg + 2'd1;
    end
end

```

切换动作严格约束在垂直消隐起点（`frame_start`）生效，杜绝一帧之内上下半屏背景撕裂错位。
