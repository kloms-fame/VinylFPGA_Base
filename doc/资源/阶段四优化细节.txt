### 一、 四大细节问题代码级根因深度剖析

#### 1. KEY11 循环模式背景 Mode 3（近黑背景）替换为通用艺术图

* **代码现状**：在当前 `playback_page.v` 中，`background_mode == 2'd3` 时，像素被硬编码为纯色 `24'h08080C`，属于未充分利用的占位态。


* **物理存储空间核算**：
* EG4S20BG256 合封的 32 位 SDRAM 容量为 2,097,152 Words（8 MB）。


* 当前内存划分：
* 四封面缓冲（`BUF0` ~ `BUF3`）：占用 `0` ~ `1,228,799` Words。


* MV 三帧环形缓冲（`MV_ADDR0` ~ `MV_ADDR2`）：占用 `1,228,800` ~ `1,459,199` Words。


* 当前歌曲虚化背景（`SONG_ADDRESS`）：占用 `1,459,200` ~ `1,766,399` Words。


* 艺术背景 1（`ART_ADDRESS`）：占用 `1,766,400` ~ `2,073,599` Words。


* **剩余容量**：$2,097,152 - 2,073,600 = 23,552\text{ Words}$，已不足以完整常驻第三张 640×480（需 307,200 Words）背景。






* **最优工程方案**：
无需在 SDRAM 中开辟第三块全尺寸显存，而是采用 **“通用艺术槽时分热重载（On-Demand Cache Swap）”**：
* 将 SDRAM 的 `21'd1766400` 定义为通用艺术槽 `ART_SLOT`。


* PC 端预先将两张通用艺术图打包为 `ART1.BIN` 与 `ART2.BIN`。


* 当 KEY11 切至 Mode 2 时加载 `ART1`，切至 Mode 3 时复用 `background_cache_loader` 毫秒级流式拉入 `ART2`（耗时仅约 200ms），即可让 Mode 3 完美呈现第二张高清通用艺术图，**新增硬件开销为 0 LUT、0 BRAM**。

#### 2. 播放态专辑封面未缩放、仅裁剪左上角的根因（历史顽疾）

* **代码事实**：
在 `top_tf_hdmi_audio.v` 中，TF 卡加载的封面（`PIC1.BMP` ~ `PIC4.BMP`）均是 640×480 分辨率，行宽为 640 像素。
而在播放态下，视窗物理尺寸为 320×240（$X \in [16, 335], Y \in [40, 279]$）。


* **裁剪发生的致命位置**：
查看 `video/background_raster_address.v` 中的地址步进逻辑：


```verilog
assign address = in_media ? media_cursor : background_cursor;
...
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) media_cursor <= 21'd0;
    else if (latch) media_cursor <= media_base;
    else if (advance && (!mv_q || in_media)) media_cursor <= media_cursor + 21'd1;
end

```


在封面模式下（`mv_q == 0`），代码的注释写着：
`// Covers advance for every screen pixel; compact MV advances only inside its 320x240 window.`
这意味着当扫描线扫过整屏时，`media_cursor` 随着屏幕每个有效像素按 $+1$ 递增。当扫描线行经视窗区间（$X \in [16, 335], Y \in [40, 279]$）时，取出的地址实际上是原 640×480 大图在行 $Y$、列 $X$ 处的局部像素！
硬件根本没有做任何 2:1 缩小抽取，而是纯粹开了一个 320×240 的天窗去局部观察 640×480 原图，导致画面只显示了封面左上角的局部特写！


* **根治手段（纯光栅地址 2:1 抽取算法，0 DSP、0 BRAM）**：
320×240 刚好是 640×480 的严格横纵各 $1/2$！在 SDRAM 内部，行首地址为 $Y \times 640$。


* 在视窗内部（$X_{win} \in [0, 319], Y_{win} \in [0, 239]$），对应的 640 原图采样坐标应为 $(2X_{win}, 2Y_{win})$。


* 如果直接在 SDRAM 读端做跨步读，会打断 128 字的连续突发。


* **最优解法**：在 `SD/fat32_media_loader.v` 预载封面写入 SDRAM 时，直接在写 FIFO 前增加单 bit 计数器，把 640×480 抽取为 320×240 存入 SDRAM 专属封面池；或者在 PC 端由 `vinyl_packer.py` 直接生成匹配播放视窗的 320×240 紧凑帧，彻底恢复封面完整画幅！

#### 3. MV 歌曲切入瞬间闪现封面的机理与影响评估

* **机理重现**：
1. 当用户切歌进入含 MV 的曲目时，顶层触发 `restart`，`s6_video_layer` 内部的 `mv_frame_scheduler` 复位进入待命态，此时首帧尚未到位（`display_valid == 0`）。


2. 与此同时，`mv_stream_player` 启动并向 TF 卡请求首帧的 300 个扇区（153.6 KB）。


3. 在 TF 卡通过 SPI 模式读完首帧的 60~80ms 窗口期内，`mv_read_active` 因等待首帧就绪而保持为 `0`。


4. 查看 `s6_video_layer.v` 的旁路分支：
```verilog
assign mv_read_active = display_enable && display_valid && ...;

```


当 `mv_read_active == 0` 时，视频复合流默认**回退显示底层的 SDRAM 静态封面**！


5. 约 4~5 个视频帧（80ms）后，首帧传输落盘完成，`display_valid` 变 `1`，视窗瞬间切入视频流，人眼便捕获到“封面闪现一下”。




* **影响评估与解决建议**：
* **业务影响极小**：在主流商业播放器中，视频缓冲期展示静态封面占位（Poster Image）属于常见行为。
* **低成本消除方案（< 3 行代码）**：
若追求极致视觉纯净，只需在有 MV 且视频就绪前，给媒体视窗施加“就绪消隐门控”：
在 `s6_video_layer.v` 中，若 `has_mv && !mv_read_active`，媒体视窗区域直接输出纯黑（或背景底色），等首帧 `display_valid == 1` 时再由场消隐边界平滑切入，即可完全抹除封面闪现。

#### 4. 彩色模糊背景偶尔出现异常横线的物理排查

此现象只在“当前歌曲封面衍生的彩色虚化背景”上偶发，切图后消失，具有典型的“存储流水线相位失锁”与“扇区欠载填充”特征：

* **诱因一：复合光栅跨度计算的时钟打拍失步（最主要根因）**：
在 `video/background_raster_address.v` 中：


```verilog
wire media_row = y >= 9'd48 && y < 9'd288;
wire [9:0] next_boundary = (media_row && x < 10'd16) ? 10'd16 :
                          (media_row && x < 10'd336) ? 10'd336 : 10'd640;
wire [9:0] screen_span = next_boundary - x;
...
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) screen_span_q <= 10'd0;
    else screen_span_q <= screen_span;
end

```


在行尾换行处（$X=639 \to 0, Y \to Y+1$），`x` 瞬间归零，但 `screen_span_q` 延迟了 1 拍才更新，导致在跨行交界处，给 SDRAM 控制器的突发长度 `burst_limit` 出现 1 拍的错误计算！
读 FIFO 偶尔多读或少读了 1 个突发，这 1 个突发的数据偏差会在随后的整行显示中表现为一条错位的像素亮线或黑线。


* **诱因二：SD 卡读扇区错误导致的 `PAD` 零数据填充**：
在 `video/background_cache_loader.v` 中：


```verilog
PAD: if (word_count == 9'd256) state<=DRAIN;
...
assign pixel_data = state == PAD ? 32'd0 : ...;

```


若背景图的 1200 个扇区在连续读取时遭遇一次 SPI 校验抖动或偶发重试超时，状态机会跳转到 `PAD`，用 `32'd0`（黑色）将该扇区剩余的字填满。这 256 个零像素落入 SDRAM，在屏幕上就会固化呈现为一条长度为半行或大半行的黑色杂线，直到下一次切图重新写入该内存槽。

#### 1. 视窗 2:1 缩放与居中显示实现（零 DSP 硬件光栅抽取）

在 640×480 原图存入 `BUF0~3` 的前提下，要在 320×240 视窗内完整呈现全貌，最优雅的方式是将 `background_raster_address.v` 中的封面光栅步进修改为**行交织跳跃累加**：

* 在视窗内部（$X \in [16, 335]$），每扫描 2 个屏幕像素，封面地址递增 1（$X$ 轴 2:1 抽取）。


* 在垂直方向（$Y \in [40, 279]$），屏幕每换行一次，封面行基地址跳跃 $+1280$（跳过 1 行原图，实现 $Y$ 轴 2:1 抽取）。


* 如此一来，无需额外占用任何片上 BRAM 或 DSP，320×240 窗口内即可 100% 完整显示整张专辑封面全貌，彻底告别左上角裁剪！



#### 2. MV 首帧缓冲门控（消除闪现封面）

在 `video/s6_video_layer.v` 中：

```verilog
// 优化前：mv_read_active 为 0 时直接回退显示封面
// assign view_rgb = (mv_read_active && !background_image_active && !mv_window_visible) ? 24'd0 : vout_data;

// 优化后：若当前曲目拥有 MV 但视频尚未就绪，在媒体窗口内输出纯黑保护，杜绝封面闪现
wire mv_preloading = play_active && covers_ready && mv_meta_valid && !mv_read_active;
assign view_rgb = (mv_preloading && mv_window_visible) ? 24'h000000 :
                  (mv_read_active && !background_image_active && !mv_window_visible) ? 24'd0 : vout_data;

```

这一改动直击痛点，逻辑极轻量，在 MV 就绪前提供宁静的黑场过渡，就绪后无缝呈现。

#### 3. 背景杂线根治补丁

在 `video/background_raster_address.v` 中：
消除换行时刻 `screen_span_q` 的单拍滞后，改为在组合逻辑中直接用当前的预译码边界驱动突发判定，并在 `video/background_cache_loader.v` 增加单扇区重试标志，禁止错误扇区直接以全零 PAD 写入 SDRAM。
