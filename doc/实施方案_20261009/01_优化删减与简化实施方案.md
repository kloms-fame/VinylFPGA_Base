# VinylFPGA 优化删减与简化 Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:executing-plans` 逐阶段执行，遵守[总览门禁](00_执行总览与阶段门禁.md)。每项需要人工验收，未通过不得进入下一项。所有任务为未来实施步骤。

**Goal:** 在不损失赛题能力及已验收媒体稳定性的前提下，减少非必要逻辑与显示负担，形成可继续开发的精简稳定版本。

**Architecture:** 优先删除独立的WS进度计算，缩小蜂鸣器状态与计数；黑胶、启动图通过独立变体测量决定。保持TF/FAT32、音频、SDRAM仲裁、超时恢复和既有缩放链，避免主链重写。

**Tech Stack:** Verilog-2005、Python/Icarus、Anlogic TD、SynthPilot只读报告及隔离构建。

## Chunk 1: 范围、收益和构建基础

### 1. 删减决策表

| 功能 | 优化阶段决策 | 明确边界 |
|---|---|---|
| WS充能/进度模式 | 优先删除 | KEY10改为关闭↔VU；保留DIP总开关与串行协议 |
| 蜂鸣器多音色/长模式 | 优先简化 | 单频短确认音，旋转不连鸣；不删所有操作反馈 |
| 动态黑胶 | 独立测量后优先简化 | 保留封面/MV入口；不关闭整个S6模块 |
| 启动画面 | 测量后压缩或缩小 | 保留启动等待、跳过、媒体ready门控及Flash启动 |
| 2×2缩略图 | 本阶段保留 | 支撑已验收选图与FPGA缩放；D13替代能力通过后再讨论 |
| BRI/CON模块 | 保留接口 | 当前常量被优化，不等于动态调节已完成；后续开发补齐 |
| 波形、转场、歌词 | 保留 | 用户要求五项扩展全通，不能以删赛题能力减负 |
| FAT32受限目录/簇链 | 保留 | 不改固定LBA主链；大面积候选不等于低风险候选 |
| Seek、暂停、重播、EOF策略、插拔恢复 | 保留 | 已验收链；重写会扩大验证范围 |
| IR、EC1、必要数码管/健康监控 | 保留 | 健康监控规模很小，不是重点收益来源 |
| 未例化源码/旧仿真 | 分类整理，暂不物理删除 | 不释放网表资源；保留历史参考用例和课程来源 |
| 通用UIRES、多背景、FFT、倍速、Flash参数保存 | 不纳入 | 后续用户另行提出才立项 |

参考层级 `lut/ripple`：WS progress 205/9、WS effects 202/30、蜂鸣198/29、黑胶45/28及2DSP、Boot110/40及10BRAM/3DSP。这里是层级逻辑参考，**不是final LUT收益保证**。Boot BRAM不能全部算可释放：需要确认具体Logo与图层占用。FAT父模块与scanner/index子模块不能相加。

推荐方案是“保主链、删独立额外项、减视觉计算”。全面固定镜像重构有较大潜在收益，但会重做媒体合同和恢复；恢复历史优化分支较快，却重新引入资源和验证风险，均不作为本轮默认路线。

### 2. SynthPilot MCP执行方式

上轮已按用户要求取得[官方用法入口](https://www.synthpilot.dev/llms.txt)，并使用TD/MCP形成两组构建证据。本轮只写计划，没有再进行MCP综合或改动工程。

后续用途：

1. 用 `td_connection_info` / `td_test_connection` 确认EDA主机、TD路径和进程状态；不要让MCP与原生构建共用正在写入的目录。
2. 独立快照构建后，用 `td_report_param` 核验实际map_mode、seed和阶段；MCP single-run的AUTO默认值必须核对。不能认为.al写area_prior就实际生效。
3. 用 `td_report_area`、`td_report_qor`、`td_report_timing_summary`、`td_check_timing`、`td_report_analysis` 输出本轮独立文件。
4. 对关键路径用 `td_report_timing_path`、`td_report_hfn`、`td_report_clock_summary`、`td_report_clock_intersection`、`td_report_timing_exception/ignored` 辅助分析；工具只支持既有run或合法已建流程，不虚构import接口。
5. MCP不能提供同策略显式build时，统一资源门禁仍用现有原生脚本；MCP作为交叉分析，不拿AUTO结果混算收益。
6. 写入/构建发生连接超时后先查已生成产物和流程状态，不能盲目重试同名轮次。不同候选一律新目录。

### 3. 候选生成与发布

每项使用O0命令模板创建快照、完整build、收集指标；不能在不同源码上复用旧gate.db。通过后可运行现有：

```powershell
python tools/release_verified_round.py opt_o6_lean_accept_r1
```

该命令生成候选bit，不带 `--program-sram` 不下载。实际SRAM/Flash动作仅在执行阶段按用户当时授权和硬件检查进行；本计划不执行。

当前release脚本校验源/约束/project及主要timing结构，不代替人工阅读路由overflow、CDC、外部接口约束、素材绑定和验收结论。

### 4. 不应越界的“优化”

- 不删对比度或缩放以换取界面资源。
- 不把歌词截成四字来掩盖宽度/存储问题。
- 不关闭超时、恢复、音频低水位保护来缩小FSM。
- 不用降低视频/音频时钟或增加false-path换取通过。
- 不把PC转换后的固定640×480素材当作FPGA多分辨率功能。
- 不整套cherry-pick过去U3/U4；只按当前accepted重新实现最小必要模块。

O6封版后才执行开发方案D0；即使某删减仅半天完成，也必须保留独立构建和人工停点。
