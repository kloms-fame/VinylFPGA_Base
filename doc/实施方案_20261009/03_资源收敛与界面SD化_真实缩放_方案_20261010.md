# 03 资源收敛 + 界面/SD 化 + 真实缩放 总体方案（2026-10-10）

> 承接 01 优化线、02 功能线（D1–D12 已落地）。本方案是在**资源到顶、route 时序不过**的现实下，按"**先减后加、每步过布线门禁**"推进的新一轮计划。
> 器件 EG4S20BG256；唯一签核口径＝TD native `area_prior + seed5 + fix_hold + final`。SynthPilot opt_gate 仅作快速反馈，**不能当签核**。

---

## 0. 现实约束（2026-10-10 本机 route 实测）

| 指标 | 实测 | 判定 |
|---|---|---|
| Slice | 9730/9800 = **99.29%** | 到顶 |
| PLB | **2449/2450（剩 1）** | 最硬的墙 |
| MSlice | 4867/4900 = 99.3% | 到顶 |
| BRAM9K | 49/64（剩 15） | 略有余量 |
| DSP | 11/29 | 宽裕 |
| Setup | ext_mem_clk 125MHz **WNS −2.078ns / TNS −25.3ns / 25 端点** | 不过 |
| Hold | −4ps / 2 端点 | fix_hold 处理 |

- 最差路径：`frame_fifo_write.v` `write_len_latch → App_wr_en`，**5 级加法链（4 ADDER）**，数据 9.798ns/预算 8ns，**布线延迟占 67%**。gate 仅 −0.31ns、place/route 恶化到 −2.1~−2.6ns → 主因是**塞到 99% 的布线拥塞**，必须"删逻辑减压 + 关键链打拍"双管齐下。
- SD 接口为 **1 位 SPI**；SDRAM 映射：4 封面占字 0~1,228,799，3 个 MV 帧占 1,228,800~1,459,199，**空闲约 637,952 字≈2.55MB**。
- 已具备可复用件：通用 `fat32_file_streamer.v`（按 FAT 链吐字节流）、封面四 bank 全屏读路径、`ui_param_csr`、1ms 节拍与 CDC、EC2 浮窗、帧边界提交机制。

## 1. 已锁定决策（两轮 detail）

1. **歌词/文字走 SD**：每首歌由 PC 工具抽取"本曲用字子集"随卡下发，选歌时载入**可写双口字形 RAM**；换歌不刷固件。运行时不做 Unicode/字库管理，**字符解析全部在 PC 端**，FPGA 只按本地字形号取点阵（最省 LUT）。
2. **播放页背景**：RTL 程序生成（封面压暗 / 渐变 / 黑胶纹理 / 星场），**不占 SDRAM**；**KEY12（exp_key_n[11]，拓展2）循环切换**，选择记入参数 CSR。
3. **选歌界面**：**彻底删除缩略图 2×2 模式**，统一回到默认"中央大图选歌页"（复用现有全屏封面读路径，不做新缩放器）；**KEY7（exp_key_n[6]，切歌模式）与 KEY11（exp_key_n[10]，返回主界面）效果统一**，都回到该界面；仅新增底部"序号 歌名 歌手"一行与时长。
4. **四个整首 MV**：四首全部整首；**PC 端保证 MV 与音频严格等长对齐，音频为基准**，FPGA 不做循环/定格兜底，音频 EOF 即停 MV。
5. **文字度量**：英文/数字变宽字（advance 7~9px）、中文/全角固定 16px、空格 5px；时间 `MM:SS` 紧凑；**进度条宽＝封面 320（x[16,336)），末帧正好满格到底**。
6. **歌词区不画边框、进度条不画框和黑底**。
7. D13 真实缩放仍要做，但**排在资源腾出之后**，余量不达标不立项。

## 2. 总体策略与门禁

**先减（R 阶段，不加新功能）→ 后加（F 阶段，按成本排序）**。每个阶段必须：
- 定向 testbench 通过 + 全量回归通过；
- native `area_prior/seed5/fix_hold` **完整 route**，记录 LUT/Slice/**PLB**/BRAM/DSP/**WNS/TNS/违例端**；
- gate 与 final 两套数分栏记录，不得混用；
- 未过门禁不进入下一阶段、不出 bit。

**红线（route 后）**：Slice ≥ **90%（8820）停止叠加功能**，R 阶段目标回落到 ≤85% 给 D13 留余量；PLB 需从 2449 回落到 ≤~2400；BRAM ≤52；**setup WNS≥0（争取 +200ps）、hold≥0**。

## 3. R 阶段：资源收敛与时序修复

### R0　整首 MV 持续带宽/碎片探针（最高优先，决定 F5 可行性）
- 实测 1 位 SPI 下 **音频 96KB/s + MV 1.54MB/s ≈ 1.63MB/s 持续 4 分钟**不欠载；覆盖跨簇、FAT 碎片、刷新避让；记录安全帧率上限与最差簇布局。
- 结论分支：达标→F5 按 10fps/RGB565；不达标→按数据降 MV 帧率（10→8）或位深/量化，**用实测数据定，不拍脑袋**。
- 产出：带宽预算表与长时抓包结论（可先放 30s→3min→4min 阶梯）。

### R1　固化在途重构（补仿真后提交）
- 对象：`song_index_db.v`（case 显式写 + 小端按字节落位）、`lrc_window_controller.v`（六具名行寄存器、无符号边界）、`lrc_five_osd.v`（相位几何译码）、`lrc_scroll_controller.v`、`playback_page.v`、`top_tf_hdmi_audio.v`。
- 补齐 D10–D12 一直缺失的定向仿真：tb_lrc_window / tb_lrc_five_osd / tb_lrc_scroll / tb_playback_page / tb_song_index_db；跑全回归。
- native 完整 route 后**单独提交**，记录相对 HEAD 的 LUT/PLB/WNS 变化。

### R2　修 ext_mem 写 FIFO 时序（消 −2.078ns）
- 文件：`src/SD/frame_fifo_write.v`。把 `write_len_latch → 地址加法链 → App_wr_en` 的 5 级（4 ADDER）组合链拆分：基地址/翻转偏移**预计算并打拍**，长度比较提前一拍，`App_wr_en` 用寄存后的合格信号；保证突发内 128 拍连续语义不变。
- 验证：tb_frame_fifo_write（写满/翻转/背压/突发边界）+ 现有 SDRAM 仲裁/缩略图（R3 前）/MV 回归；route 后 ext_mem_clk WNS≥0。
- 回退合同：若打拍引入可见像素错位，回退本文件并改用"降 ext_mem 时钟 + 带宽核算"备选。

### R3　删除缩略图模式，统一中央大图选歌（最大回收块）
- **删除**：`io/thumbnail_controller.v`、`display/thumbnail_view_reader.v`、`display/thumbnail_layout.v`，以及顶层 `thumb_*` 接线、该路 SDRAM 读口/`rfifo` 例化、读仲裁客户、`view_rgb` 的 thumb 分支、`view_mode_req/enable` 相关逻辑与 .al 清单项。
- KEY7 与 KEY11 统一进入默认选歌（中央大图）态；删除 `brw_thumb_mode` 状态分支。
- 选歌页＝现有全屏封面读路径（**不新增缩放/读口/FIFO**）＋底部一行 OSD"序号 歌名 歌手"＋时长（时长字段在 F2 前先用序号占位，F2 后接真实元数据；时长由 PCM 大小现算）。
- 验证：上电/选曲/切歌/转场/播放进入与退出/拔卡重插回归；确认 SDRAM 仲裁少一个客户后 MV、封面、音频正常；route 前后对比 LUT/PLB/BRAM/WNS（预期四项齐降）。

### R4　去面板框/黑底 + D14 波形极值
- 播放页：歌词区不画外框；进度条区不画框、不铺黑底（与 F1 几何一起落地）。
- D14（`promax_audio_waveform.v`）：先扩 17 位有符号取绝对值（−32768→32768 不溢出），**采集时**饱和并线性归一化到 0..95 存入 bank，像素期只比较，杜绝 8→7 位截断；峰值同理；真静音显零柱。
- 向量：−32768/−32767/−256/−1/0/+1/+256/+32767、静音、暂停、Seek 重启；正负满幅均顶格 95。

> **R 阶段出口门禁**：完整 route 后 Slice≤~85%、PLB 明显回落、ext_mem WNS≥0、全回归通过。达不到则继续在既有链路上做减法，不进入 F。

## 4. F 阶段：功能扩展（每步独立 route 验余量）

### F1　播放页几何与紧凑英文字（近零成本，先做）
- `playback_layout.vh`/`playback_page.v`/`playback_progress.v`：进度条改 **x[16,336) 宽 320**，`fill=floor(320·elapsed/total)`，校正 off-by-one 使**末帧满格、起始 0**；时间 `MM:SS` 紧凑并置于条上。
- 字库渲染加**变宽字度量表**（Latin/数字 7~9px、全角 16、空格 5）；中文不受影响。
- 去歌词框、进度条框与黑底（R4 同批）。
- 验收：开始/中段/结束三点进度与时间；长歌名省略号；英文间距实拍。

### F2　SD 每曲字形子集 + 文字加载（核心，复用 file_streamer）
**PC 工具侧（改造 `tools/gen_lrc_assets.py`，产物从"单片 ROM"改为"每曲 SD 文件"）**
- 输入仍为 `songs_manifest.json` + `trackN.lrc`；对每首歌独立去重，产出：
  - `TRACKn.FNT`：本曲字形表（本地字形号→16×16 点阵）＋行记录（时间戳 ms＋每行本地字形号序列）＋标题/歌手字形序列；**运行时不碰 Unicode**。
  - 工具校验每曲字形数 ≤ `MAX_GLYPHS_PER_SONG`（默认 192，可按实测调）、每行 ≤16 字、时间非递减。
- INDEX 升级 **v3（可选文本记录，向后兼容）**：增 `text_cluster/text_size`；v1/v2 卡无该字段时回退 `TRACK NN / ARTIST -- / NO LYRICS`。

**FPGA 侧（新增轻量加载器 + 可写字形 RAM，复用 `fat32_file_streamer`）**
- 一片**真双口可写字形 RAM**（SD 写口 / 显示读口），容量按单曲上限（192 字形≈6~7 块 BRAM9K）＋小型行/元数据 RAM（~1~2 块）；**替换**现有约 8 块烧录字库 → BRAM 基本持平。
- 保留一片**极小内置 ASCII/符号 ROM**（VOL/BRI/CON/ROT/WSL/NO LYRICS/TRACK/ARTIST/数字/冒号），保证无卡/未载入前 UI 正常。
- 载入时机：**焦点停留 ~300~500ms 或按确认进入播放时**载入该曲子集（旋钮快速转动只保留最后一次，代次管理沿用 cover_navigation 模式）；**播放/MV 开始前全部驻留**，播放期不再为字形访问 SD → 不与 MV 抢带宽。
- 载入期间文字显占位，载入完成帧边界原子刷新；切曲/拔卡/重插/复位行为与封面一致。
- 时长：由 PCM 文件大小按 48k/16bit/单声道现算，不占文本。
- 验收：不刷固件换卡换词；焦点快速转动不串字、不爆音；缺文件回退；四曲逐首标题/歌手/五行歌词/滚动/Seek 正确；route 后 BRAM≤52、WNS≥0。

### F3　程序生成背景 + 封面压暗（KEY12 循环）
- 在视频合成层（现播放页深色底处，`top`/`s6_video_layer`）以**像素坐标纯组合/少量时序**生成：①当前封面压暗（复用已在 SDRAM 的封面做降亮度，无需新图）②渐变 ③黑胶纹理 ④星场；**不新增 SDRAM 区、不读图**。
- KEY12 在播放态循环选择，写入 `ui_param_csr`（新增 BGD 项，复用 1ms/CDC）；与 BRI/CON 级联但放在其前/后明确定义，保证 Boot/消隐/音频链优先级不变。
- 验收：四种背景切换无撕裂、帧边界生效；封面压暗仍可辨；与亮度/对比度/MV/歌词叠加正常；KEY12 不与既有键冲突。

### F4　D13 真实分辨率缩放（余量达标才开工，最难）
- 新增 `bmp_header_parser.v`：解析完整 u32 宽、**有符号高**、像素偏移、DIB、planes、bpp、compression、stride；合法集＝**320×240 或 640×480 × 24bit BI_RGB × 正/负 height**，其余明确拒绝且不写坏 bank。
- 新增 `bmp_scale_normalizer.v`：**装载期**把 320×240 用 2× 最近邻（横复制 2、纵重复 2）规范成 640×480 写入既有 bank，640×480 直通；双行缓冲（约 ≥2 BRAM9K）；按 top-down/up 正确垂直映射，取代写死 `WRITE_V_FLIP`；**下一扇区准入**保证 512B 突发可吞、音频补水优先；全部落 SDRAM 才置 ready。
- 预算 +600 LUT/+300 Slice/+3 BRAM；开工条件＝R/F1/F2 后 route 仍有该余量且 WNS≥+200ps。
- 验收：同卡放原始 320×240 与 640×480（PC 不预缩放）均满屏正确、四角对齐、加载期音频无欠载；坏尺寸干净拒绝。

### F5　四独立曲/词/封面/四整首 MV + 终验（D15）
- 素材（PC 侧，用户提供原始素材、工具打包）：4 个**独立** PCM、4 封面、4 份歌词/歌名/歌手、**4 个与音频严格等长的整首 MV**（音频为基准）；写卡生成 INDEX v3 与各 `TRACKn.FNT`。
- 基于 R0 带宽结论确定 MV 帧率/位深；做 4 首×全曲的音频+MV 并发长稳、跨簇碎片、Seek/暂停/切曲、EOF 停止、回退封面。
- D15：证据矩阵、4h 老化、Flash 烧录冷启动、断电恢复、最终 native 签核与 bit SHA-256。

## 6. 资源预算与停止条件（每阶段 route 后填）

| 阶段 | 动作 | ΔSlice/PLB 预期 | ΔBRAM | WNS 目标 |
|---|---|---|---|---|
| R1 | 重构固化 | 略降 | 0 | 改善 |
| R2 | FIFO 打拍 | ≈0 | 0 | ext_mem ≥0 |
| R3 | 删缩略图 | **明显下降** | −1~−2 | 拥塞下降 |
| R4 | 去框+D14 | ≈0 | 0 | ≥0 |
| F1 | 几何/字距 | 很小 | 0 | ≥0 |
| F2 | SD 文字 | 新增加载器，但替换烧录字库 | **净≈0（≤50）** | ≥0 |
| F3 | 程序背景 | 小增 | 0 | ≥0 |
| F4 | D13 缩放 | +300 Slice | +3 | ≥+200ps |
| F5 | 素材/终验 | 0 | 0 | 签核 |

**停止条件**：任一阶段 route 后 Slice≥90%、PLB 无余量、或 WNS<0 且本阶段无法修复，则暂停后续叠加，回到最省方案（F4 可降级为只支持 640×480，F3 只保留封面压暗，F2 降低单曲字形上限）。

## 7. 风险登记

1. **SPI 持续带宽不足**（四整首 MV）→ R0 先行，退路降帧率/位深。
2. **PLB 到顶**：R3 是主要回收来源；若回收不足，F4 推迟或砍。
3. **SD 文字载入延迟/抖动**：焦点停驻判据 + 代次取消 + 播放前驻留，避免旋钮快速转动串字与播放期抢带宽。
4. **单曲字形超上限**：工具硬性校验并报错；必要时调 `MAX_GLYPHS_PER_SONG`（受 BRAM 上限约束）。
5. **FAT 碎片影响实时读**：写卡工具尽量连续簇排布；R0/F5 实测碎片场景。
6. **F2 加载器跨时钟域**：沿用 cdc_bundle/帧边界提交，禁止新裸跨域总线。

## 8. 用户需准备的素材清单（F5 前）
- 4 个独立音频 PCM（或可由工具从常见格式转出）；
- 4 张封面 BMP（24bit；F4 后允许 320×240 或 640×480）；
- 4 份歌词文本 + 歌名 + 歌手（UTF-8，每行 ≤16 字）；
- 4 个整首 MV，**时长与对应音频严格一致**（320×240/RGB565/约定帧率）；
- 一张容量足够的 TF 卡（四 MV 约 1.4~1.5GB 量级，以 R0 实测帧率为准）。
