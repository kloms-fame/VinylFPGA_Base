> **需要你实测确认的一个细节（RTL 与手册的小出入）**：按当前 RTL，进度满幅算的是 elapsed×232/total（=×256−×16−×8），所以 EOF 时填充约 **232/240，右端可能留约 8px 空隙**，而手册写的是"满 240"。
> - 若你能接受右端留 8px：无需改动。
> - 若要求**严格满 240**：把 `playback_progress.v` 里进度 numerator 的 `− (elapsed<<3)` 这一项去掉（×256−×16=×240）即可，只动一个常量。请验收后告诉我选哪种。

## 4. 接入真实标题 / 歌手 / 歌词（D9 完整流程，可选）

### 4.1 素材规则
- 每曲**最多 128 行**歌词，每行**最多 16 个 Unicode 字形**；长句由素材侧按真实时间拆行。
- 同一时间戳重复时，取文件中**最后一条**。
- 不要用 `demo.lrc` 代替正式歌词。

### 4.2 生成步骤
1. 取得确认无误的 UTF-8 标题、歌手、LRC。
2. 编辑 `doc/资源/lyrics/songs_manifest.json`：四项 `song_id` 必须为 0/1/2/3，每项 `lrc` 为相对 manifest 的路径。
3. PowerShell 执行：
   ```powershell
   Set-Location 'D:\Data_Backup\VinylFPGA_Workspace_Base\VinylFPGA'
   python tools/gen_lrc_assets.py --songs-manifest doc/资源/lyrics/songs_manifest.json
   ```
4. 重新综合、出 bit、烧录。

### 4.3 生成阶段应报错（不会静默截断）
| 检查项 | 预期 |
|---|---|
| 超 128 行 / 超 16 字每行 | 生成脚本报错 |
| 非法秒字段、u32 毫秒溢出 | 生成脚本报错 |

### 4.4 真实素材上板现象
| # | 操作 | 预期现象 | 结果 |
|---|---|---|---|
| 4.4.1 | 逐曲播放 | 显示**各自真实标题/歌手/歌词** | □ |
| 4.4.2 | 首句时间之前 | 歌词行**留空**（不显示 NO LYRICS，也不提前显句） | □ |
| 4.4.3 | Seek 到某句时间 | 该句出现；越过多句后，显示**时间不晚于当前音频时刻的最后一句** | □ |
