# 第三部分：填充真实歌名/歌手/歌词（"填字"）

## 关键概念（先弄清）
- **歌名、歌手、歌词不是运行时从 SD 卡读的**，而是**编译时**由生成器转成字库 ROM、**编译进 bit**。所以改文字 = 改清单 → 跑生成器 → **重新综合出 bit**。
- SD 卡仍放：INDEX、PCM 音频、MV、封面图片。封面进媒体窗口；文字是叠加层，两者分开。
- 对应关系：**SD 卡里第 N 首（INDEX 顺序，从 0 开始）= song_id N**。填字顺序要和 SD 曲目顺序一致。

## 已为你准备好的可照抄示例
| 文件 | 内容 |
|---|---|
| `doc/资源/lyrics/songs_manifest.filled_example.json` | 四曲标题/歌手/歌词路径（已验证可生成） |
| `doc/资源/lyrics/tracks/track1.lrc` | 曲目1 歌词（山湖） |
| `doc/资源/lyrics/tracks/track2.lrc` | 曲目2 歌词（森林） |
| `doc/资源/lyrics/tracks/track3.lrc` | 曲目3 歌词（玫瑰） |
| `doc/资源/lyrics/tracks/track4.lrc` | 曲目4 歌词（黑胶） |

示例填的是：
- song0《山湖之间》/ 演示歌手 A；song1《森林漫步》/ 演示歌手 B；
- song2《玫瑰心语》/ 演示歌手 C；song3《黑胶时光》/ 演示歌手 D。

## 操作步骤
1. 按你的真实内容，**编辑** `songs_manifest.filled_example.json` 和 `tracks/track1~4.lrc`（或新建文件）。
2. 确认无误后，把它**复制覆盖**正式清单：
   ```powershell
   Set-Location 'D:\Data_Backup\VinylFPGA_Workspace_Base\VinylFPGA'
   Copy-Item 'doc/资源/lyrics/songs_manifest.filled_example.json' 'doc/资源/lyrics/songs_manifest.json' -Force
   ```
3. 运行生成器（注意：要用**装了 Pillow 的 Python 3.11**，即 `py -3.11`）：
   ```powershell
   py -3.11 tools/gen_lrc_assets.py --songs-manifest 'doc/资源/lyrics/songs_manifest.json'
   ```
   成功会打印 `SONGS_OK 曲目 4，歌词行数 …，去重字形 …`，并更新：
   `src/display/song_text_rom.v`、`src/display/song_font_rom.v`、`src/include/song_text_geom.vh`。
4. TD 重新综合 → 布线（确认 WNS 正）→ 出 bit → 烧录。

## 素材限制（超限会在生成阶段直接报错，不静默截断）
- 标题、歌手各不超过 **16 个字形**；
- 每曲歌词不超过 **128 行**，每行不超过 **16 个字形**（长句按真实时间自行拆行）；
- LRC 时间格式 `[mm:ss.xxx]`，秒必须 <60；同一时间重复行取**最后一条**；
- 文件必须 UTF-8；不要把 demo.lrc 的说明文字当正式歌词。

## 资源代价（省资源提醒）
- 空素材时字库 512×16（约 1 个 BRAM9K）；填入上面的中文示例后去重 **98 个字形**，字库变为约 2048×16，**约多占 3 个 BRAM9K**（总量约 42→45，仍在 64 内）。
- **字形越省，BRAM 越省**：字库只收录你真正用到的字符。想更省就精简用词、四曲复用相同字眼；LUT/DSP 基本不因此增加。
