# D11/D12 五行歌词 + 帧同步滚动 — 板级详细验收走查（实测素材版）

> 提交：`1398a1a 实现五行歌词与帧同步滚动`。
> 本轮已把**真实标题/歌手/歌词**生成进 ROM（`doc/资源/lyrics/songs_manifest.json` → `gen_lrc_assets.py`）。
> 器件 EG4S20BG256；HDMI 640×480@60；四曲共用同一 AUDIO.PCM（约 4 分 05 秒），曲目0带 30 秒 MV。

---

## 0. 三个必须先弄清的概念

1. **歌词/歌名/歌手是"编译进 bit"，不是放 SD 卡！**
   - 它们由生成器转成 `song_font_rom.v / song_text_rom.v`，**综合进固件**。改文字 = 改 manifest/LRC → 跑生成器 → **重新综合出 bit**。
   - **SD 卡只放**：INDEX、PCM 音频、封面、MV。写 SD **不会**带上歌词。
2. **专辑名（album）当前不支持。** 左侧面板只有"歌名(title)、歌手(artist)"两行，没有专辑字段。
   - 若要加专辑名，需要改生成器+播放页+布局（属新增开发），你确认后我再做。
3. **必须用真实歌词重新综合评估资源。** 空歌词时综合会裁掉 D11/D12 数据通路（报 LUT 15,921、BRAM 42）；本轮已填入 48 行/178 字形，字库变大，**以你本机重新综合/布线结果为准**。

### 1.2 资源代价（省资源提醒）
| 项 | 空素材 | 本轮真实素材 |
|---|---|---|
| 字库规模 | 512×16（约1 BRAM9K） | **4096×16（约8 BRAM9K）** |
| 字形/行数 | 0 | 178 字形 / 48 行 |
- 预计 BRAM 约 **42 → 49**（仍在 64 内，留约 15）。**字形越省 BRAM 越省**：精简用词、四曲复用相同字眼可降低。
- LUT/DSP 主要取决于窗口/滚动逻辑，不随字数线性增长；接入后请以综合报告为准。

### 1.3 TD 出 bit
打开 `prj/VinylFPGA.al` → 综合 → 布局布线 → bit。**完整布线 setup WNS 为正、TNS=0、无 hold 违例**再烧；记录 bit SHA-256。

### 1.4 写 SD（音频/封面/MV）
- 读卡器盘符须为 **E**（不是就去"磁盘管理"改）。
- 双击 `doc/资源/sd卡/write_card.bat` → 输 `6`（card_S6）→ 见 `WRITE_OK`。
- 拔卡插板。注意：歌词不在这张卡里，在 bit 里。

## 2. 五行窗口布局（右侧面板）

右信息面板 **x[352,632)、y[120,360)**。静止时六槽行顶坐标（`224−96 + slot×48`）：

| 槽 | 行顶 y | 相对当前 | 颜色 |
|---|---|---|---|
| slot0 | 128 | −2 行 | 暗灰 `#738397` |
| slot1 | 176 | −1 行 | 浅灰 `#B8C5D1` |
| **slot2** | **224** | **当前行** | **白 `#FFFFFF`** |
| slot3 | 272 | +1 行 | 浅灰 `#B8C5D1` |
| slot4 | 320 | +2 行 | 暗灰 `#738397` |
| slot5 | 368（面板外） | 滚入的新行 | 滚动时进入视野 |

- 每行高 16px；行间距 48px（行间留白）。
- 本轮歌词每 **3 秒**一行（0,3,6,…,33s，共12行）。

## 4. 换成你自己的真实歌词
1. 准备 UTF-8 的标题、歌手、LRC（每曲 ≤128 行、每行 ≤16 字形、行≤16 字的标题/歌手）。
2. 改 `songs_manifest.json`（song_id 0..3，lrc 相对该 manifest 的路径）与对应 LRC。
3. 跑 `py -3.11 tools/gen_lrc_assets.py --songs-manifest doc/资源/lyrics/songs_manifest.json`。
4. 重新综合、布线、出 bit。
- 时间戳格式 `[mm:ss.xxx]`，秒<60；同时间重复行取最后一条；超长/超字会在生成阶段报错。
- 本轮时间戳为"每3秒"的演示节奏，**并非真实歌曲节拍**；要真同步请按歌曲改时间。
