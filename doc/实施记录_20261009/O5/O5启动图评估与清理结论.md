# O5 启动图评估与清理结论

日期：2026-10-10（Asia/Shanghai）  
范围：O5a 启动图无损查表候选评估、O5b 生产源/参考源分类。保持启动图像素、呼吸亮度、守卫与时序不变；不生成 bit。

## 执行结论

- **O5a：组合查表候选不纳入主线。** 候选通过仿真并成功完成 TD `read_design → optimize_rtl → optimize_gate`，导出本轮 `gate.db`。但与当前 O4a 基线相比仅少 2 个 DSP，同时多 306 个 LUT，未达到预先确定的“至少省 3 DSP 且 LUT/BRAM 不增加”门槛。因此停止在 gate 评估，不做 place/route；当前主线 RTL、ROM 与生成器已恢复至 O5 开始前版本。
- **O5b：不删除工程源或磁盘文件。** 完整分类证据见《生产源与参考源分类》。报告显示一些实例与最终 hierarchy 有证据缺口；只有少数 legacy/未引用文件是后续可单独复核的候选，不足以支持本阶段删除。
- 启动图 ROM 原图、几何参数与可见画面没有变更。用户后续可直接按当前工程继续自行生成 bit。

## O5a 方法与结果

采用已批准的无损候选：保留原 16 色调色板、同步 ROM 索引寄存器和三角波增益，把默认 `BREATH_FLOOR=192` 的 16×64 颜色/增益组合实现为组合 case 查表。同步 ROM 后没有添加流水级，其他 `BREATH_FLOOR` 参数仍走原乘法逻辑。

验证项目：

| 检查 | 结果 |
|---|---|
| 16 个 palette index × 64 档 gain，与原 RGB 乘法逐项比较 | 通过，1,024 项 |
| 无效 ROM 数据输出黑色 | 通过 |
| 19,966 个有效 ROM 地址的同步读、palette/RGB 对应关系与同周期亮度结果 | 通过；另检查地址 19,966 越界输出无效/黑色 |
| `tb_boot_s2` 启动画面显示及交接回归 | 通过；`nonblack=43236`、`maxlum=592`、`mid_bright=5932`、`lower=7676`，首图交接与帧边界 skip 检查通过 |
| TD gate 综合 | 通过；`gate.db`、`rtl.area`、`gate.area`、`gate.timing`、`flow.status` 均生成，日志含 `O5_GATE_COMPLETE`，无 place/route/bitgen |

综合资源对比使用同一器件 EG4S20BG256、`area_prior` 映射和同一主工程入口：

| Gate 指标 | O4a 当前基线 | O5a 查表候选 | 变化 |
|---|---:|---:|---:|
| LUT | 13,152 | 13,458 | +306 |
| 寄存器 | 9,319 | 9,319 | 0 |
| BRAM | 42 | 42 | 0 |
| DSP | 13 | 11 | -2 |
| Gate setup WNS | -945 ps | -236 ps | +709 ps |
| Gate setup TNS / violation endpoints | -4,564 ps / 44 | -7,564 ps / 75 | TNS -3,000 ps；+31 endpoints |
| Gate hold WNS | 471 ps | 471 ps | 0 ps |

候选改善了 gate setup WNS，但 setup TNS 和违例端点数增加。因为资源门槛未达到，没有启动布局布线；这些数字是综合 gate 级摘要，不代表最终 route 时序。该候选可作为“DSP 与 LUT 换取”的量化评估，不作为当前发布 RTL。
