# O5b 生产源与参考源分类

日期：2026-10-10（Asia/Shanghai）
范围：只读审查当前 `main` 工作树中的工程输入、top 递归 include、以及 O4a 的最终 hierarchy 报告。本文只作分类，不删除/改写 RTL、`.al`、约束或综合报告，也没有执行构建。

## 结论摘要

- `prj/VinylFPGA.al` 中共解析到 **62 条 `<File>`**；62 条的 `UsedInSyn` 都是 `true`，其中 60 条 RTL / IP 输入、2 条约束输入。`src/io/debounce_filter.v` 是唯一带 `AutoExcluded=true` 的 RTL 条目。`.al` 的 `UsedInSyn=true` 表示工程配置将其列为综合输入，不代表该模块一定出现在最终网表。
- 从 `src/top_tf_hdmi_audio.v` 递归跟踪 `` `include `` 得到 **43 个唯一文件**（含顶层自身，缺失目标为0）。主 top 的显式 include 文件和其包含的头文件是生产编译单元依赖；其中有一部分同时在 `.al` 列出，文件内的包含保护用于避免重复定义。
- O4a 最终报告确认 `top` 的层级网表中有 `u_boot_layer` / `u_boot_logo_rom`、SD/FAT32、HDMI、音频、缩略图、显示与 S1 输入控制等大量实例。报告资源总计 LUT 13,604、寄存器 9,408、BRAM9K 42、DSP 13。启动子树为 `u_boot_layer`：152 LE / 109 LUT / 40 ripple / 61 seq / 10 BRAM / 3 DSP；其 `u_boot_logo_rom` 子树是 27 LE / 27 LUT / 8 seq / 10 BRAM / 0 DSP。子项是父项的一部分，不能将二者直接相加。
- 发现少数**需要保留而不能据本报告判为可清理**的证据缺口：例如 `audio_source_mux`、`hdmi_pcm_source_bridge`、`thumbnail_controller`、`seg_decoder` 在当前 top 源码中有实例化点，但 O4a 的最终层级表没有同名层级；其中部分也没有 `.al` 独立条目或 top include。原因可能是综合优化、编译单元/工程快照差异或报告层级省略，单凭本次材料不能判定。先保留这些输入，不能按“层级没列出”删除。
- `src/display/vinyl_renderer.v` 在当前顶层递归 include、`.al` 文件条目和 O4a 最终层级表中均未发现；这与 O4a 已移除唱片 renderer 的实现吻合，可归为纯参考/legacy 候选，但本阶段仍不删除磁盘文件。
