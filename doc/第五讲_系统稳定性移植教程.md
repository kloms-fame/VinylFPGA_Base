5 项必做优化：

| 序号 | 优化项 | 教程章节 | 主要落点 |

| 1 | BMP 严格校验 | 2.1 | `bmp_read.v` |

## 二、教程 5 项必做优化的落地细节

### 2.1 BMP 严格校验（必做）

`bmp_read.v` 新增字段寄存器与校验条件，`header_match` 由原来的“签名 + 宽高”扩展为 11 项联合校验：

```verilog
assign header_match = (header_0 == "B") &&
                      (header_1 == "M") &&
                      (dib_size >= 32'd40) &&
                      (width[15:0]  == bmp_width) &&
                      (height[15:0] == bmp_height) &&
                      (planes == 16'd1) &&
                      (bit_count    == 16'd24) &&
                      (compression  == 32'd0) &&
                      (pixel_offset >= 32'd54) &&
                      (pixel_offset < file_len) &&
                      (file_len >= (pixel_offset + required_pixel_bytes));
```

解析 `DIB size`（偏移 14~17）与 `planes`（偏移 26~27），补齐 `compression` 的 32 位解析。

### 2.2 错误码上报与恢复（必做）

`bmp_read.v` 新增两个输出：

```verilog
output reg [2:0] bmp_error,   // 0=无 1=头错 2=超时 3=截断
output reg       load_error   // 单周期错误脉冲
```

错误码定义与教程一致：

```verilog
localparam ERR_NONE      = 3'd0;
localparam ERR_HEADER    = 3'd1;
localparam ERR_TIMEOUT   = 3'd2;
localparam ERR_TRUNCATED = 3'd3;
```

`sd_card_bmp.v` 侧实现教程的“重试 1 次 → 失败跳过 → 保留上一帧”策略，并在此基础上改善首图失败处理：首图连续失败时按候选图顺序尝试下一张，避免上电时一直卡在同一张坏图。

恢复逻辑（第 6 段，放在普通调度之后覆盖写）：

```verilog
if (load_error && !load_error_seen) begin
    if (!scan_done && !scan_abort) begin
        // 扫描阶段错误：重试一次，仍失败则强制结束扫描，避免永久 scan_done=0
        if (retry_count < MAX_RETRIES) begin
            retry_count      <= retry_count + 2'd1;
            img_found_count  <= 3'd0;
            scan_start_pulse <= 1'b1;
            scan_abort       <= 1'b0;
            boot_failed      <= 1'b0;
            boot_idx         <= 2'd0;
            load_error_seen  <= 1'b0;
        end else begin
            scan_abort       <= 1'b1;
            load_busy        <= 1'b0;
            source_done_seen <= 1'b0;
            retry_count      <= 2'd0;
            load_error_seen  <= 1'b1;
            if (img_found_count == 3'd0)
                boot_failed <= 1'b1;
        end
    end else begin
        // 加载阶段错误：重试一次
        if (retry_count < MAX_RETRIES) begin
            retry_count      <= retry_count + 2'd1;
            load_start_pulse <= 1'b1;
            load_busy        <= 1'b1;
            source_done_seen <= 1'b0;
            load_error_seen  <= 1'b0;
        end else begin
            // 重试仍失败：保留上一帧，跳过坏图
            load_busy        <= 1'b0;
            source_done_seen <= 1'b0;
            next_req_pending <= 1'b0;
            prev_req_pending <= 1'b0;
            auto_cnt         <= 32'd0;
            retry_count      <= 2'd0;
            load_error_seen  <= 1'b1;
            if (!display_valid) begin
                // 首图失败：按顺序尝试下一张候选图
                if (has_more_boot_r) begin
                    boot_idx         <= boot_idx + 2'd1;
                    load_idx         <= boot_idx + 2'd1;
                    load_sector      <= boot_sector_next;
                    pending_buf_idx  <= 2'd0;
                    write_buf_idx    <= 2'd0;
                    load_start_pulse <= 1'b1;
                    load_busy        <= 1'b1;
                    load_error_seen  <= 1'b0;
                    retry_count      <= 2'd0;
                end else begin
                    boot_failed <= 1'b1;
                end
            end
        end
    end
end
```

同时 `source_done_seen` 与双缓冲提交都加上了 `!load_error` 门控，保证错误周期不会把半帧数据提交到显示缓冲。

### 2.3 坏图快速跳过（必做）

`ST_SCAN` 不匹配分支改为：签名是 `BM` 但头校验失败时，按文件长度跳过整个文件；否则只跳 1 个扇区。

```verilog
if ((header_0 == "B") && (header_1 == "M")) begin
    if ((next_scan_sector_if_match > scan_max_sector) ||
        (next_scan_sector_if_match <= scan_sector)) begin
        scan_done <= 1'b1;
        state     <= ST_IDLE;
    end else begin
        sd_sec_read_addr <= next_scan_sector_if_match;
        scan_sector      <= next_scan_sector_if_match;
    end
end else if (scan_sector >= scan_max_sector) begin
    scan_done <= 1'b1;
    state     <= ST_IDLE;
end else begin
    sd_sec_read_addr <= next_scan_sector_if_miss;
    scan_sector      <= next_scan_sector_if_miss;
end
```

这里额外加了 `next_scan_sector_if_match <= scan_sector` 的保护条件，防止 `file_len` 异常导致的回绕死循环。

### 2.4 加载超时（必做）

教程要求保护 `ST_SCAN` 与 `ST_LOAD_DATA`；本工程额外把 `ST_LOAD_HDR` 也纳入保护，因为头部读取同样可能被 SD 卡卡住。

```verilog
localparam [31:0] TIMEOUT_CYCLES = (CLK_FREQ_HZ / 1000) * SD_READ_TIMEOUT_MS;

always @(posedge clk or posedge rst) begin
    if (rst) begin
        sd_timeout_cnt <= 32'd0;
    end else if ((state == ST_SCAN) || (state == ST_LOAD_HDR) || (state == ST_LOAD_DATA)) begin
        sd_timeout_cnt <= sd_timeout_cnt + 32'd1;
    end else begin
        sd_timeout_cnt <= 32'd0;
    end
end
```

三个状态内超时均输出 `ERR_TIMEOUT + load_error` 并回 `ST_IDLE`。

### 2.5 像素完整性校验（必做）

新增 `pixel_count`，每输出一个完整 24bit 像素计一次；加载完成时比较期望像素数，不足则报 `ERR_TRUNCATED`。

```verilog
assign expected_pixel_count = {16'd0, bmp_width} * {16'd0, bmp_height};
assign required_pixel_bytes = expected_pixel_count * 32'd3;

always @(posedge clk or posedge rst) begin
    if (rst) begin
        pixel_count <= 32'd0;
    end else if (state == ST_LOAD_DATA) begin
        if (bmp_data_valid && (bmp_byte_idx == 2'd2))
            pixel_count <= pixel_count + 32'd1;
    end else begin
        pixel_count <= 32'd0;
    end
end

// ST_LOAD_DATA 完成分支
if (bmp_len_cnt >= file_len) begin
    if (pixel_count < expected_pixel_count) begin
        bmp_error  <= ERR_TRUNCATED;
        load_error <= 1'b1;
    end
    state <= ST_IDLE;
end
```

## 三、架构决策：为什么不做整体模块替换

教程第 6 节明确区分了三种演进阶段：

1. **最小改动**：官方例程 + 5 项必做优化（约 115 行）
2. **模块拆分**：把校验、恢复、快速启动抽成独立模块（`bmp24_decoder.v`、`media_recovery_fsm.v`、`fast_boot_gate.v` 等）
3. **完整架构**：再加 Flash 持久化、UART 上报、OSD 等

并给出结论：“基础完赛做第一步就够了，能应对比赛中 90% 的稳定性问题。”

本工程当前处于第三/四讲成果之上，`bmp_read.v` 与 `sd_card_bmp.v` 已经包含了扫描、按扇区加载、按键调度、双缓冲提交等耦合逻辑。若直接换成完赛分层模块，会连带替换扫描/加载接口、显示提交时序，存在破坏第三、四讲功能的风险，也超出教程“基础完赛”的范围。

因此本讲采用最小改动路线：

- 只扩展 `bmp_read.v` 的字段解析、校验、超时、像素计数与错误输出
- 只在 `sd_card_bmp.v` 增加错误恢复状态与首图候选切换
- 保持 KEY1/KEY2/自动轮播调度顺序不变，仅把 `scan_done` 换成 `scan_done | scan_abort` 的有效信号
- 不动音频、SDRAM、HDMI PHY 与视频时序

### 5.3 时序修复：`boot_sector_next` / `has_more_boot_r`

加入错误恢复后，第一次构建出现新的 `sd_card_clk` 时序违例，最差路径为：

```text
起点：sd_card_bmp_m0/bmp_read_m0/load_error_reg_syn_5.clk
终点：sd_card_bmp_m0/load_sector_reg[14]_syn_4.c[1]
Data Path Delay：10.511ns
Logic Level：9
```

根因：错误恢复分支里 `sector_lut(boot_idx + 2'd1)` 是 32 位 4 选 1 查表，再叠加 3 位加法比较，与 `load_error` 的条件链串成 9 级组合逻辑。

修复方式：把“下一张候选首图”的扇区与存在性提前一拍寄存，错误恢复直接消费寄存器值。

```verilog
// 稳定性时序优化：预计算"下一张候选首图"的扇区与存在性，
// 避免 load_error 直接驱动 32 位 sector_lut 形成长组合路径。
reg [31:0]  boot_sector_next;
reg         has_more_boot_r;

// 时序块内每拍更新
boot_sector_next <= sector_lut(boot_idx + 2'd1);
has_more_boot_r  <= (({1'b0, boot_idx} + 3'd1) < img_found_count);

// 错误恢复分支改为消费预计算值
if (has_more_boot_r) begin
    boot_idx         <= boot_idx + 2'd1;
    load_idx         <= boot_idx + 2'd1;
    load_sector      <= boot_sector_next;
    ...
end
```

这样可以保证：`boot_idx` 与 `img_found_count` 在错误发生时已稳定（错误只可能发生在加载或扫描结束后），因此预计算值与实时计算严格等价；而 `load_error → load_sector` 路径上的 32 位查表与加法被整体移出。

### 7.4 TD 6.2.1 全流程与时序

`sd_card_clk` 时序修复过程：

| 阶段 | SWNS | STNS | 说明 |
|---|---|---|---|
| 第一次构建（仅 5 项必做） | -0.953ns | 负 | `file_len → file_sector_count → next_scan_sector → 上限比较 → 状态机` |
| 加入 `file_sector_count_r` 打拍 | -0.791ns | -2.081ns | 最差路径转为 `load_error → load_sector[14]`，9 级逻辑 |
| 加入 `boot_sector_next` / `has_more_boot_r` | **+0.127ns** | **0.000ns** | `sd_card_clk` 收敛 |

`ext_mem_clk` 仍为 `SWNS = -6.565ns`，该数值在本讲改动前的 `6dfe4b0` 报告里同样是 `-6.565ns`，属于既有 SDRAM 链路问题，本讲未使其恶化，也未改动 SDRAM/加密核。
