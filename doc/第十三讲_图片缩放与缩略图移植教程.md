# 第十三讲 图片缩放与缩略图移植教程

## 一、本讲目标

本讲对应完赛系列：

```text
第十三讲：图片缩放与缩略图
（教程源文件标题：第12课_图片缩放与缩略图.md）
```

移植目标：

```text
1. 用 thumbnail_layout 完成 640x480 -> 2x2 缩略图布局；
2. 每个缩略图 160x120，最近邻 4:1 缩小；
3. focus_index 对应的缩略图显示 2 像素黄色焦点边框；
4. KEY1 短按仍为“下一张”，KEY1 长按 1s 切换“缩略图 / 全屏”；
5. 全屏模式和原有轮播、转场、OSD、WAV、音频波形、HDMI 输出全部保持不变。
```

本讲保留的既有功能：

```text
KEY1 短按下一张
KEY2 短按自动轮播开关
KEY2 长按上一张
自动轮播 / 图片转场 / OSD 状态字幕
WAV 播放 / 音频波形可视化 / HDMI 音频
FAT32 扫描与四 bank 图片加载
Flash 上电自启接口
```

## 三、教程链路与本工程的对应关系

教程给出的数据流：

```text
video_timing -> thumbnail_layout -> media_frame_reader -> 像素 -> OSD/转场
```

本工程的实际映射：

| 教程模块 | 本工程实现 | 说明 |
|---|---|---|
| `thumbnail_layout` | `src/display/thumbnail_layout.v` | 教程源码原样移植，仅补注释，语义零修改 |
| `media_frame_reader` | `src/display/thumbnail_view_reader.v` | 教程参考工程的 reader 是整帧顺序流；本工程 `frame_fifo_read` 已承担该职责，本模块按第八讲 reader 的职责边界补“按坐标取一个像素” |
| 缩略图/全屏切换 | `key_press_hold.v` + 顶层 toggle/同步/帧边界提交 | 教程要求帧边界切换，本设计在 `frame_start` 处提交 |
| `bmp24_decoder` | 沿用本工程既有 `bmp_read` + FAT32 四 bank 加载 | 不重复造轮子，不替换已验证的加载链路 |
| `bilinear_8q8` | `src/display/bilinear_8q8.v`（选做，未加入工程） | 教程标注“选做，完赛未实现”；源码与 TB 保留，不参与综合 |

为什么需要 `thumbnail_view_reader`：

本工程原有的 `frame_fifo_read` 只提供“整帧顺序流式读出”，而
`thumbnail_layout` 输出的恰恰是“当前屏幕像素对应源图哪一个像素”的坐标，
两者职责不同。教程的做法是让 `thumbnail_layout` 只做坐标映射、由 reader
按坐标取像；本工程沿用了这个职责划分，没有改动 `frame_read_write` /
`frame_fifo_read` / SDRAM 控制器内部。

## 五、关键设计决策

### 5.1 三个 thumbnail_layout 实例

`thumbnail_view_reader` 内部实例化三次同一个教程模块：

```text
u_layout_display  ：当前显示行、当前像素的坐标映射
u_layout_prefetch ：下一显示行的坐标映射（地址提前一整行写入）
u_layout_next_px  ：当前行 x+1 的坐标映射（标准 FIFO 提前一拍弹出）
```

三次实例化都是教程模块本身，没有改写 `thumbnail_layout` 的语义。

### 5.2 地址流提前一行

显示第 `n` 行时，地址 FIFO 推送的是“下一显示行 `n+1`”的缩略图像素地址。
视频时钟 25MHz、存储器时钟 125MHz，行内有 5 倍余量，提前一整行足以覆盖
SDRAM 单字读延迟。

### 5.3 两个 FIFO 都选标准模式

实测 show-ahead 的 `wfifo_32_32_512` 在本工程上下文中会被 TD 报
`SYN-5042` 无法推断 BRAM，从而展开成巨量寄存器。因此地址侧与像素侧统一
使用工程既有的 `rfifo_32_32_512` 标准模式，两者都被 TD 成功推断为 BRAM。

标准 FIFO 的 `valid` 比 `re` 晚一拍，因此像素侧采用“提前一拍弹出”：

```text
行内：弹出条件 = 下一显示像素仍是缩略图像素；
行首：行末消隐期弹出下一行首像素，保存在 row_first 寄存器跨消隐。
```

### 5.4 欠载自愈

行内一旦出现取像数据未就绪，就在行末复位两个 FIFO 重对齐，并把紧随其后的
一行整行按黑色处理（该行不消费 FIFO）。这样地址流与像素流不会越对越偏，
坏行只持续一行，后续行自动恢复。

### 5.5 SDRAM 读口换手

SDRAM 控制器只有一路 `App_rd_en/App_rd_addr` 只读口。`sdram_rd_arbiter`
的边界是：

```text
全屏模式（mode_active=0）：app_rd_en/app_rd_addr/frw_rd_valid 纯组合直通，零额外延迟；
缩略图模式：读口交给 thumbnail_view_reader；
换手条件：当前占用方连续静默 QUIET_CYCLES=64 个 mem 时钟。
```

64 拍远大于控制器单次读延迟，保证在途数据全部回到原归属，不会跨模式串像素。

### 5.6 按键入口

教程需要一个“进入缩略图”的入口。本工程复用 KEY1：

```text
KEY1 短按（松开时）：press_pulse -> 原有“下一张”转场；
KEY1 长按 1s     ：hold_pulse -> 切换缩略图/全屏，松开时不再触发下一张；
KEY2            ：仍用原 key_press_debounce，行为完全不变。
```

视图切换用 toggle 电平跨到视频域，经三级同步后在 `frame_start` 处整帧提交，
避免半帧切换撕裂。

## 八、已知边界与风险

1. `thumbnail_layout.v` 中 TD 会报 `HDL-5369 latch inferred for window_x[31]`。
   该警告来自教程源码固有写法，本工程按“教程原样移植”原则未改其语义。
2. 本讲仍只支持 640x480 BMP。教程的“任意分辨率适配 / 保持宽高比”属于
   扩展升级，不在完赛主线内。
3. `image_complete` 直接使用 `sd_card_bmp` 的 bank 就绪标记，依赖“bank 索引
   == 图片序号”的既有约定；若后续改动四 bank 加载顺序，需要同步检查。
4. `bilinear_8q8.v` 为教程选做件，未加入工程，不影响资源与时序。
