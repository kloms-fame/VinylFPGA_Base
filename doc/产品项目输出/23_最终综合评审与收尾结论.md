## 1. 项目最终定位

**VinylFPGA 是基于安路 EG4S20BG256 的唱片主题 FPGA 本地音乐画屏与多媒体系统工程。** 它把 TF 卡资源、固定规格 PCM、封面与 MV、歌词/播放页面、HDMI 音视频、实体输入、灯效和用户参数保存组合为可操作的播放终端。

用户已确认完成赛题一相关开发并完赛。本报告接受这一事实。对于某个固件版本经过哪些测试、是否有对应的现场长时记录，按具体工程档案说明；不能由仓库某次验收未包含板测，推断竞赛阶段没有展示或用户没有完赛。

当前最有说服力的技术叙事是：**以真实 PCM 消费推进媒体时间，用块级缓存、共享存储事务和帧边界提交，把不确定延迟的介质访问转换为有节奏的音视频输出。**

## 3. 系统架构的最终解释

~~~mermaid
flowchart TB
  UI[实体输入] --> BUS[同步解码 / 事件总线 / 命令路由]
  BUS --> CTRL[浏览 / 播放 / 暂停 / Seek / 会话控制]
  SD[SD SPI 扇区服务] --> FS[FAT32 扫描与文件流]
  FS --> INDEX[INDEX 校验与元数据]
  FS --> COVER[封面 BMP 装载]
  INDEX -.地址与格式.-> AUDIO[音频预取]
  INDEX -.地址与格式.-> MV[MV 与背景读取]
  SD --> AUDIO
  SD --> MV
  COVER --> MEM[SDRAM 图像字与音频字节复用]
  AUDIO --> MEM
  MV --> MEM
  MEM --> PCM[4096×16 PCM 样本缓存]
  PCM --> OUTA[音量 / 淡变 / HDMI PCM]
  PCM --> TIME[实际样本消费 / 媒体时间]
  TIME --> SCHED[MV 目标帧 / 歌词 / 进度]
  SCHED --> MV
  MEM --> PIX[帧读出 / 像素流水]
  ROM[编译期文本与字形 ROM] --> PIX
  PIX --> OUTV[图层 / OSD / HDMI 视频]
  CTRL --> AUDIO
  CTRL --> SCHED
  BUS --> CSR[参数 CSR]
  CSR --> NVM[同域持久化 / 用户 Flash]
  CSR --> CDC[参数快照 CDC / 运行消费者]
~~~

图中虚线表示元数据关系，实线表示数据或控制流。音频、MV 和背景的实际块数据直接使用 SD 扇区服务；不能把文件系统到索引的路径画成所有运行媒体数据必经的字节流。

## 4. 最值得讲清楚的六项工程贡献

### 4.1 块存储与实时采样之间的多级解耦

卡侧以扇区交付数据，PCM 侧以 48 kHz 节奏消费样本。完整扇区暂存、SDRAM 扇区缓存、PCM 双时钟样本缓存和背压共同吸收不同阶段的延迟。

48 kHz × 2B 单声道的理论净数据率为 96,000 B/s；512B 覆盖约 5.33 ms。该换算解释缓存的意义，不是卡速实测或最大可容忍停顿的保证。有效容量、触发水位、竞争负载和恢复行为需要同时考虑。

### 4.2 RGB888 与音频字节共享 SDRAM 字

音频缓存没有简单地另划一块完全独立的连续物理空间。当前 DMA 将音频字节放在图像 32-bit 字的低 8 位，图像使用高 24 位。1024×512 个音频字节分布在前 524,288 个字地址的低字节。

~~~text
SDRAM 32-bit word
31                        8 7                0
+--------------------------+------------------+
| 图像 RGB888               | 音频 byte        |
+--------------------------+------------------+
  图像写 mask = 0001          音频写 mask = 1110
~~~

依据：[audio_sdram_dma](../../src/audio/audio_sdram_dma.v)、[audio_sdram_arbiter](../../src/audio/audio_sdram_arbiter.v) 和顶层 PRESERVE_LOW_BYTE 配置。它是明确的资源复用设计，同时增加了字节掩码保持、写尾排空和读返回管理的复杂度。

### 4.3 不可立即撤销的事务生命周期

切歌、Seek 或超时只改变上层意图，已发往 SD/SDRAM 的事务仍可能返回。stream_session 与 DMA 的 drain/guard/recovery 结构保护旧会话、暂存区和新请求之间的边界。维护时不能仅为了缩短等待时间而提前释放仍有在途返回的 ownership。

### 4.4 两层资源仲裁

SD 以完整扇区事务保持 owner；音频紧急时先补数。音频缓存健康且 MV 满足准入时，视频最多连续获得 15 次服务，再让等待中的音频请求获服务。背景是较低优先级并受水位准入控制。

SDRAM 又有独立的音频/图像访问锁、数据返回归属和写掩码尾部排空。两层仲裁解决不同瓶颈，不宜合称为所有客户端平等轮转。

### 4.5 媒体时间与完整帧提交

顶层生成计划采样节拍；播放器真正消费缓存样本后，timebase_48k 推进有效媒体时间。MV 调度跟随该时间，在完整帧写入完成后，通过帧起点提交 bank。SD 最后字节、SDRAM 写完成、显示 bank 生效是三个不同事件。

三缓冲保护正在显示、已完成待显示和正在写入的帧。它与四张封面缓冲、最多四首曲目是三个不同维度的设计，不应混淆。

### 4.6 产品控制与工程追溯

统一事件路由、参数 CSR、按域的 CDC、用户 Flash 双槽/CRC/提交，与显示和主题反馈形成完整控制面。工程又保留输入哈希、回归记录和固定产物，便于回答“哪一个版本支持哪一个结论”。

## 7. 赛题、产品价值与表述边界

项目与安路赛道一 FPGA HDMI 多媒体播放方向高度相关：TF/BMP、SDRAM/FIFO、HDMI 音视频、交互，以及字幕/图层、转场、亮度对比度、波形等实现构成直接技术对应。

“四个扩展方向可对应”是实现层面的计数，不是官方成绩、80% 得分或评委认定。图像缩放没有进入当前活动链；波形符合相关可视化方向，但不能宣传为 FFT。PDF 与 PPT 对扩展要求的不同表述继续按 [08 原文口径](./08_赛题原文要求与材料口径分析.md) 和 [09 实现矩阵](./09_赛题要求与项目实现矩阵.md) 分层解释。

项目的产品价值主要来自完整的本地音乐可视体验、实体控制和工程可解释性；教学价值来自从外设实验到系统集成的跨度。现有材料没有支持音质优于软件播放器、低功耗领先、商业规模部署或行业首创的比较数据。
