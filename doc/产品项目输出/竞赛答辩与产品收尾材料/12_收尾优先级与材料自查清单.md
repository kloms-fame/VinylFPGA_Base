# 12｜收尾优先级与材料自查清单

> 用户已完成赛题一开发并完赛，当前重点为成果沉淀、学习、文档写作、产品表达和后续答辩准备。“争取国一”用于确定准备工作的投入优先级，不作为对赛果、官方评分或名次的预测。本文不新增工程验证结果。

## 1. 当前最值得投入的五件事

1. **版本身份明确。** 展示固件、媒体、ROM、报告、原片关联到同一个版本。当前固定验收bit与Runs同名副本身份不同，必须按实际使用文件说明。
2. **演示结果可见。** 设备原声、真实选曲、转场、MV/歌词、参数前后变化、保存完成与恢复均有明确因果关系。关键原片不靠后期替换结果。
3. **核心机制讲得透。** 能从一段用户动作讲到实际样本时基、SD/SDRAM仲裁、共享字节lane、事务排空、帧边界提交。
4. **贡献边界说得准。** 原创工作、厂商IP、参考模块、离线工具、素材和AI辅助分别有真实来源和责任说明。
5. **结论有对应证据。** 产品效果、实现时序、仿真、现场记录各自引用；未知指标留空，扩展计数不换算官方分数。

这些工作能提升材料质量和答辩准备程度；评审结果还取决于正式规则、现场表现和其他作品，现有材料不支持奖项保证。

## 3. 为什么现在不把“大功能数量”放第一位

固定归档实现已使用BRAM9K64/64、LUT约90.9%、Slice约94.7%，setup WNS +0.121ns、hold WNS +0.030ns。它说明该次实现的余量有限。新功能即使看起来只增加一个界面，也可能改变存储布局、像素流水、CDC、布线和时序；现有报告不会自动适用到修改后的固件。

目前项目已经具备与题目直接相关的音视频、图层字幕、转场、参数OSD和波形可视化路径，最值得先消除的是证据身份混淆、讲解不清、旧控件文档错误与未测效果夸大。素材摆放、操作标签、构图、说明文字和证据索引可以在不改RTL的情况下提高理解效率。

将任意分辨率缩放、FFT、通用编解码、任意LRC导入、无限曲库等放到后续版本清单，注明当前未支持；不因为希望更高奖项就把它们加进现版本功能表。

## 6. 一个结论从主稿进入正式材料的流程

~~~text
想表达的结论
  → 查源码活动路径和当前规格
  → 找同版本工程/仿真/实物记录
  → 确认记录能支持的范围
  → 填EV编号和原始路径
  → 写清条件与局限
  → 同步产品页、报告、PPT、视频字幕
~~~

例：“参数断电后恢复”需要非默认五项值、保存完成、真实失电复电和恢复后数值核对。只有CRC代码与bit文件时，可以讲保存设计；只有软重启录像时，可以讲复位恢复；只有上电Logo时，可以讲本次启动画面。把证据补齐后再扩大结论，不靠文案美化越过缺口。

- [ ] README说明包内容、实际版本、阅读顺序、作者与日期。

## 8. 学习与文档写作的复用方式

写架构时，从 [旧23最终综合评审](../23_最终综合评审与收尾结论.md) 与 [旧24关键接口索引](../24_源码依赖与关键接口索引.md) 找活动路径；写产品时把用户动作和实际结果放在一起；写测试时按 [10证据台账](./10_成果证据台账与待补材料模板.md) 的方法、版本、原始数据填写；准备现场时按 [11演示手册](./11_现场答辩演示与应急执行手册.md) 选择标准或缩短流程。

学习复述可以每次只练一个问题：“为什么SD扇区读取的不确定延迟不会直接决定音频采样节奏？”先自己画链路，再打开代码定位缓存、水位、仲裁和样本消费；最后用自己的话说明哪部分是架构设计，哪部分有实测数据。能说清设计的取舍、限制与证据，比记住模块名称更有用。

本轮只新增收尾材料，未改RTL/约束/媒体/固件，未启动仿真、构建、烧录或实物测量。
