# 11｜现场答辩演示与应急执行手册

> 面向已完成开发并完赛的 VinylFPGA，用于成果展示、后续答辩和展台演示准备。以下时长是团队自用演练方案，不替代赛方安排。目标是让关键能力容易被看见、工程机制容易被理解。未在本轮操作实物。

## 1. 现场主线只记这一句

**“选一张唱片，听到音乐、看到歌词和MV，调好自己的参数，保存后重启仍然记得。”**

它能自然关联赛题的TF图片、HDMI音视频、手动/自动切换、字幕图层、转场、画质调节和波形；再用缓存、时基和存储事务解释背后的工程难点。现场不需要把所有等价按键逐一按完。

产品开场可直接说：

> VinylFPGA是一台基于安路EG4S20的唱片主题本地音乐画屏。我们把TF卡媒体读取、SDRAM缓存、HDMI音视频、歌词与MV、实体控制和参数保存集成到同一个FPGA设计中。下面通过一次完整听歌流程展示它。

器件型号由工程可核对；商品板卡型号以实际丝印、硬件资料补充。运行逻辑与离线素材工具分开说明，避免把PC准备素材误说为运行时需要PC处理。

## 2. 开场前一页状态卡

| 类别 | 进入展示前确认 | 异常处理入口 |
|---|---|---|
| 版本 | 实际固件FW、媒体MD、ROM、板卡HW关联到同一REL | 先解决身份对应，不临时换未知bit |
| 画面 | HDMI输入正确，浏览页稳定可操作 | 第7节 |
| 音频 | 显示/音频设备输出正确，未静音，VOL适中 | 第7节 |
| 曲目 | 第一段有清楚歌词/MV/节奏，曲目ID与ROM相符 | 换同包已核实曲目 |
| 控件 | 认清扩展KEY和母板KEY；遥控按实际码贴标签 | 第3节 |
| DIP | DIP1/3/4/5/6依展示需求启用；DIP2先关闭 | 自动轮播只在浏览段开 |
| 保存 | SW3自动保存策略明确，母板LED无故障 | 保存前后看真实指示 |
| 机械 | 唱针抬起/落下状态明确；外部电机驱动与供电正常 | 抬针不等于暂停歌曲 |
| 备用资料 | 本地打开原片/成片、关键图、报告、版本卡 | 明确标为录像/归档证据 |
| 时间 | 确认当前允许时长、是否允许断电、是否允许播放视频 | 按现场规则缩减 |

无需为了本手册重做已完成工作；从已有正常展示状态开始。若现场规则不允许某动作，保留讲解和证据入口，不擅自操作。

## 3. 真实控件速查：防止照旧文档操作

详细定义以 [视频05控件核对表](../视频拍摄方案/05_全部功能覆盖与真实控件核对表.md) 为准。本轮直接核对了 [ui_command_router](../../../src/io/ui_command_router.v)、[ui_param_persistence](../../../src/io/ui_param_persistence.v)、[ui_param_csr](../../../src/io/ui_param_csr.v)、[vinyl_playback_effects](../../../src/io/vinyl_playback_effects.v)。

| 现场意图 | 当前入口 | 必须等到的结果 |
|---|---|---|
| 选封面/选曲 | EC1旋转；确认按EC1 | 封面选择稳定；确认后有播放结果 |
| 暂停/恢复 | EC1按压或扩展KEY2 | 音频、进度和转盘状态真实变化 |
| 播放态前/后曲 | 扩展KEY3/KEY1 | 曲号/标题及实际内容改变 |
| 播放态音量 | 扩展KEY4加/KEY5减；IR EA加/F8减 | VOL变化；不是切曲 |
| Seek | EC1每步±2秒；IR BB后退5秒/BF前进5秒 | 定位完成后时间/歌词/MV恢复对应 |
| MV/封面 | 扩展KEY8切换 | 看实际画面；该键是翻转不是强制MV |
| 转场 | 浏览态KEY9选模式，再切图 | 播放态不能用它证明浏览转场 |
| 背景 | 播放态KEY11 | 每次等有效背景出现，灰底回退不作成功证据 |
| 参数 | EC2：按进SELECT→转选项→按进ADJUST→转改值→按回SELECT | 面板数值与结果一致 |
| 手动保存 | IR E619FF00或母板KEY3 | 母板LED3忙结束、LED2已保存 |
| 软重启 | IR E916FF00立即触发，无二次确认 | 真实初始化后浏览可用 |
| 恢复默认 | 母板KEY2或IR F20DFF00 | 会触发默认值及默认记录，不作为无副作用菜单键 |
| 黑屏/唤醒 | IR F6黑屏；普通扩展KEY2首次唤醒 | 第一次不附带暂停等业务 |
| VU灯开关 | 扩展KEY10 | 只控制J2 VU，不解释成电机总开关 |

EC2无操作约1.8秒隐藏；隐藏后旋转会改音量。展示参数恢复时保持SELECT查看，下次旋转在隐藏前完成；若隐藏，先按压重新进入SELECT。母板LED与扩展LED不是同一套含义，不能混读。

## 4. 约180秒现场标准流程

本表适用于约三分钟**现场讲解**，不含完整60秒自动消隐等待。自动消隐用补充原片或根据实际允许时长单独演示；三分钟录制版另见 [视频02逐秒脚本](../视频拍摄方案/02_三分钟主片逐秒拍摄脚本.md)。不得把现场删减版称为全部分支验收。

| 时间预算 | 操作 | 讲解要点 | 评委应看到 |
|---|---|---|---|
| 0–15秒 | 整机、FPGA、TF/HDMI接线亮相 | 开场一句话；同一FPGA设计完整运行 | 产品对象和实际连接 |
| 15–40秒 | EC1手动选图；DIP2轮播一次后关；KEY9选两种转场再切图 | 基础链路与图片交互；转场是扩展效果 | TF封面、手动/自动、转场 |
| 40–65秒 | 确认播放，保留设备原声；暂停再恢复 | 音乐来自设备，歌词/进度/波形跟随播放状态 | 实际声音与页面联动 |
| 65–90秒 | MV/封面切换，EC1一次Seek，必要时切曲 | PCM消费推进媒体时间；帧完成后提交显示 | 动态画面、时间变化 |
| 90–115秒 | EC2调整BRI/CON与WSL；唱针抬落 | 参数反馈、实体体验；唱针只控转盘使能 | 数值、画面和灯/电机变化 |
| 115–130秒 | 记录一组非默认值，E6保存并等完成 | 参数为五项有限集合；保存状态有真实指示 | 保存前值与完成状态 |
| 130秒起 | 按选定路线软重启或真实断电，等待实际T | 区分复位恢复和断电自启 | 启动因果全过程 |
| 启动后约15秒 | SELECT查看五项值，重新播放 | 恢复参数，不是播放位置续播 | 非默认值一致、设备继续可用 |
| 剩余时间 | 总结三项工程贡献，进入追问 | 缓存与仲裁、媒体时基、共享存储与帧提交 | 功能背后的设计理由 |

按前130秒+T+15秒核对+10秒总结计算，约155+T秒。T=20秒只是预算示例，得到175秒；如果实际操作或启动更长，删去背景遍历、重复切曲和唱针演示，不能压缩真实启动或不等保存完成。现场讲解时操作往往更慢，要以实际排练修正。

### 讲解与操作配合

先说观众应该看哪里，再操作，最后解释结果。例如：“请看播放进度和歌词——现在暂停——两者停止推进，恢复后从当前位置继续。”不要在结果尚未出现时宣布已经成功。

原声演示留2–4秒不讲话；解释缓存时可以让设备持续播放，减少无效等待。被问到某个细节后，先回答该问题，再回主线，不为了背完脚本抢按下一步。

## 5. 被压缩时间时怎么展示

### 90秒版：保住基本链路、扩展和一项工程说明

| 时间 | 操作/讲解 |
|---|---|
| 0–10秒 | 作品定位、板卡与接口 |
| 10–25秒 | 手动封面、一次自动轮播/转场，轮播后关闭 |
| 25–45秒 | 播放原声，暂停/恢复，歌词/波形/MV |
| 45–65秒 | 亮度/对比度调节及可读OSD；一次Seek |
| 65–80秒 | 调一项非默认参数、手动保存成功 |
| 80–90秒 | 说清缓存、实际样本时基、帧提交；给出恢复录像入口 |

90秒版不启动未知耗时的重启。若评委专门关注断电自启，则将前半段压成已排练的基础展示，预留实际P+T+核对时间，舍弃等价交互，不在快结束时突然断电。

### 30秒版：一句定位、一次播放、一个难点

> 这是基于安路FPGA的本地音乐画屏。现在直接播放TF卡内容，HDMI输出音乐、歌词、波形与MV。我们用实际PCM样本消费推进媒体时间，并通过缓存仲裁和完整帧提交处理SD访问的不确定延迟。这里可以暂停、定位和调参；完整恢复演示与工程报告在备查材料中。

配合一次播放/暂停或一次Seek，确保原声和结果可辨。30秒不承诺展示全部基础清单，不把预先正在播放当成启动性能证明。

## 6. 重启与断电的现场分支

| 条件 | 推荐路线 | 准确话术 |
|---|---|---|
| 板卡真实自启已确认、现场供电允许、实际耗时合适 | 真实断电→复电→五参核对 | “现在真实断电，重新供电后独立启动，再核对保存值。” |
| 希望简单、允许复位、时间足够 | E9软重启→五参核对 | “这里验证复位后参数恢复，不把它当成断电自启。” |
| 现场时间/供电受限 | 保持运行，打开同版本连续原片备查 | “这段是此前该版本的连续记录，现场设备保持运行。” |

真实断电要看到板卡实际失电，检查下载器、USB等反供路径。只拔HDMI、关闭显示器、按复位都不等于板卡断电。配置Flash负责上电配置，与用户参数Flash的保存/恢复是两种职责。

保存后等忙结束再断电；普通正常恢复演示不能证明“写入中任意断电也绝对安全”。具体拍摄段落和时长公式见 [视频07双版本卡](../视频拍摄方案/07_软重启与断电自启双版本拍摄卡.md)。

## 7. 故障分支：先保留事实，再决定继续展示

下表是现场定位建议，不是确认工程存在这些故障。不要同时改多个变量；任何备用录像均明确标注，不冒充此刻设备实时输出。

| 现象 | 第一检查 | 后续选择 | 可直接使用的话术 |
|---|---|---|---|
| 屏幕无信号 | 显示器输入、HDMI连接、实际供电与启动状态 | 使用同条件已准备线材/显示设备；仍失败转版本和结构说明 | “当前先确认显示连接，我会把实时演示与已有记录分别说明。” |
| 画面纯黑但有音乐 | 是否手动/自动息屏 | 用普通KEY2仅唤醒一次，观察是否恢复 | “这是消隐路径，先用普通键唤醒，再继续业务操作。” |
| 有画面无声音 | 设备音量/静音、HDMI音频去向、是否暂停、VOL值 | 核对后仍不恢复就记录现象，不连续Seek/切曲乱试 | “显示正常，音频链路当前需核对；不会把后加音乐当设备声音。” |
| 找不到曲目 | 卡是否为该版本配套、是否插稳、媒体初始化是否完成 | 使用已核实同包备用卡；不用未知卡现场试格式 | “先恢复已核实的配套媒体，曲目与ROM有版本对应。” |
| MV/艺术背景仍灰底 | 资源是否就绪、视窗状态、是否为支持该资源的曲目 | 等待已排练的真实加载；没有结果就跳过该效果 | “当前该图层未就绪，先展示已出现的播放主链路。” |
| 参数面板突然消失 | 1.8秒超时是否已发生 | 先按EC2进SELECT，再查看，避免隐藏态旋转改VOL | “面板自动隐藏，重新进入选择态即可查看。” |
| 保存LED3一直忙或LED4故障 | 保存是否真正完成、是否发生媒体/Flash错误 | 不断电、不宣布成功；保留现象转源码与归档说明 | “这次保存未形成完成证据，当前不进行断电恢复演示。” |
| 唱针抬起后音乐仍有 | 当前设计本来如此 | 指向电机/唱片灯带停转，保留音频 | “唱针控制转盘使能，音频继续播放，这是该版设计。” |
| 按键方向与稿件相反 | 实物编号/实际固件版本/旧码表 | 停止照旧稿连按，用当前屏幕结果核对 | “先按该设备实际版本确认映射，说明稿同步修正。” |
| 启动超过预算 | 继续显示真实过程；不按键抢跑 | 缩减剩余等价操作；不能转成加速启动后仍称实时 | “保留完整启动，接下来只核对核心参数。” |
| 实体运行确实异常 | 留下时间点、状态、REL/FW/MD | 停止现场调试式操作，转备查材料并明确局限 | “这是本次现场出现的现象，已有记录仅说明其各自条件下的结果。” |

预先定义团队可接受的排查时限，例如一次基础检查后仍无结果就转备查；这是沟通安排，不是设备重试机制。现场不临时编辑RTL、重综合或向评委承诺未验证修复。

## 8. 追问时拿出哪一张资料

| 被问内容 | 第一份资料 | 30秒答法 |
|---|---|---|
| 为什么用FPGA | 架构图+实际播放流程 | 固定节奏输出、并发存取和实体控制在同一硬件设计中；收益与实现复杂度同时说明 |
| 难点是否只是拼模块 | 原创贡献表+共享存储/仲裁/会话图 | 举一个不确定SD延迟与固定采样消费冲突，再指出具体水位/事务/提交机制 |
| 是否真实同步 | 样本时基代码+Seek原片 | 架构共同跟随实际样本消费；实测误差另见数据，未测不报0ms |
| 是否上电无需PC | EV24同版本原片 | 直接看真实失电复电；不能用bit生成报告代替 |
| 四个扩展怎样算 | 赛题矩阵+四组画面 | 字幕图层、转场、实时参数OSD、波形；数量是实现对应，不宣称官方已给分 |
| 为什么没做缩放/FFT | 当前规格表 | 当前固定640×480输入，缩放未集成；波形为已采用可视化方案，后续扩展另需预算 |
| 资源是否还宽裕 | 固定area/qor报告 | BRAM9K已满，优先验证与材料完整，新增功能必须重新估算和验证 |
| 什么是你们自己做的 | 贡献表+变更/设计记录 | 分清厂商IP、参考结构、手写逻辑、离线工具和AI辅助，不把全部源码行数算原创 |
| 稳不稳定/功耗如何 | EV31与仪器表 | 按实际运行时间、条件和观察/计数方式回答，WNS不推导长期可靠性或低功耗 |

## 9. 展示结束后的归档

记录使用版本、显示设备、卡片、顺序、真实耗时和异常时间点；保留成功与失败原片。回填 [10证据台账](./10_成果证据台账与待补材料模板.md)，标注哪一段实际证明哪项结论。现场表现好也不把未测指标补成已测；发生异常也不删除此前不同条件下的有效记录。

本手册以清楚展示和工程诚实为目标，不提供虚构评分或得奖概率。
