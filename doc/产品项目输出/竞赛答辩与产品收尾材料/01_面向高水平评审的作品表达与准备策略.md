# 面向高水平评审的作品表达与准备策略

> 对象：已完成开发和完赛的 VinylFPGA。用途：完善今年竞赛相关成果材料、答辩表达、复盘与后续展示。国一作为用户目标；本材料不预测名次。以下优先级是结合当前工程作出的准备建议，不是官方评分表。

## 1. 先确定整套材料的主张

建议作品全称：**VinylFPGA——基于安路EG4S20的唱片主题音画交互终端**。

建议一句话：**用FPGA把本地音乐、画面、歌词与实体交互组织成一次完整的唱片式播放体验。**

技术主张：**以实际音频样本消费推进媒体时间，通过扇区缓存、共享存储仲裁、会话隔离和完整帧提交，协调块存储访问与连续音视频输出。**

这三句话分别回答作品是什么、用户得到什么、系统如何实现。报告摘要、答辩开场、展板和视频沿用同一组主张，再根据篇幅展开。所有后续亮点都应能回到其中一个具体结果。

## 2. 当前作品可形成的四层说服力

| 层次 | 应呈现的事实 | 推荐证据 | 用户应练会的解释 |
|---|---|---|---|
| 题目对应 | 安路平台、本地资源、HDMI音视频与交互 | 实物、工程器件配置、正常播放录像 | 从TF到屏幕和扬声器的数据经过哪些阶段 |
| 系统深度 | 时基、缓存、仲裁、会话、帧提交、CDC | 顶层接线、关键模块、已有定向记录 | 为什么介质延迟与跨域会影响播放，设计怎样保护边界 |
| 产品体验 | 唱片主题、实体旋钮、MV/歌词、灯效、参数记忆 | 一次完整听歌流程与恢复演示 | 每个功能怎样服务同一使用场景 |
| 工程可信度 | 固定版本、资源与时序记录、材料可追溯 | 固件与输入哈希、归档报告、同版本媒体清单 | 每项数字对应哪个版本、哪些条件下成立 |

准备材料时依次补齐这四层。基础播放负责建立信任，关键机制负责支撑技术深度，主题体验负责形成记忆，版本证据负责使结论可复核。

## 3. 建议反复讲清楚的三个核心点

### 3.1 音乐真正走到哪里，画面就参考哪里的时间

可直接使用的讲解：

> 卡片读取和缓存写入速度不均匀，不能把读了多少数据当成已经播放了多少时间。我们的播放核心在真正消费有效样本时产生事件，统一推进歌词、进度和MV参考时间。暂停和定位也围绕这条媒体时间链协调。

展开顺序：计划48kHz节拍 → 缓存数据与下游ready条件 → sample_consumed → timebase_48k → 歌词/进度/MV调度。实际接线见02的F03–F05。

准备一张图和一次暂停/Seek演示。图说明因果，演示说明用户看到的行为。时间对齐误差若没有仪器或逐帧记录，保持为待测项目；已有机制不能直接换算成毫秒级保证。

### 3.2 在有限资源中组织音视频共享访问

可直接使用的讲解：

> 图像使用SDRAM字的高24位，音频缓存使用部分地址的低8位。不同客户端通过写掩码保护彼此的数据，并通过事务锁和排空阶段协调读返回。卡侧又以完整扇区为单位分配音频、MV和背景访问。

展开顺序：32位字结构 → 图像0001/音频1110写掩码 → 排队写入的尾部 → 读返回归属 → SD侧音频紧急优先与健康状态下的视频配额。

这里能体现工程取舍：复用提高已有存储组织的利用程度，同时使掩码和生命周期管理更复杂。描述该设计时可以说明收益和代价；资源占用数字与理论容量要分别解释。该机制是否构成独创、与参考实现差异多大，依赖原创贡献记录，见06。

### 3.3 从数据读完到画面可见，保留完整的完成链

可直接使用的讲解：

> MV最后一个SD字节到达后，写入的数据仍可能在FIFO和SDRAM控制器中。我们等到整帧写完成，再在显示帧边界提交可见bank。三个bank分别承接显示、已完成待显示和写入，减少并发读写之间的干扰。

展开顺序：300扇区读取 → RGB565解包 → 像素写入 → write_finish → done_toggle → frame_start提交。再回答切歌、Seek和旧请求如何处理。

这项设计适合画一张时序示意图。若放波形截图，标明真实信号名、时间轴、输入版本及观察区间；手绘示意图标为设计示意，便于与仿真记录区分。

## 5. 推荐保留的三种讲解长度

### 30秒：快速介绍

> 我们的作品是VinylFPGA，一台基于安路EG4S20的唱片主题音画交互终端。它将本地音乐、封面、MV和歌词通过HDMI呈现，并支持旋钮、红外、转盘灯效与设置记忆。实现重点是实际样本消费驱动的媒体时间，以及共享存储和完整帧提交，让多条链路在同一FPGA系统中协调工作。

### 90秒：有技术含量的项目概览

按四段准备：15秒定位；25秒用户流程；35秒选两个技术机制；15秒证据与当前边界。每段只保留一个中心意思。可以引用上述30秒稿作为首尾，但不必逐字照读。

90秒稿中的两个机制建议为“消费时基”和“完整帧提交”。若评委更关心资源与接口，则替换为“字节lane共享存储”。系统其他细节留给问答。

### 5分钟：建议彩排版本

使用03的12页/300秒稿。这里的5分钟是自我训练预算；实际现场时长按组织方通知调整。三分钟作品视频继续使用既有视频执行包，不把5分钟答辩稿误用作视频时轴。

| 可能追问 | 建议回答结构 | 随后展示 |
|---|---|---|
| 为什么用FPGA做播放器？ | 先说题目与硬件系统学习目标，再讲并行数据流、显式时序和可观察控制；说明固定格式原型的定位 | 架构图与实体交互 |
| 相比基础例程，你做了什么？ | 按参考资产与本人新增机制列举，并给出对应文件与版本记录 | 06贡献表、历史设计文档 |

| 有几项扩展？ | 依当前源码说明字幕/图层、转场、亮度对比度与波形对应；缩放保持实际边界 | 正式要求矩阵与真实画面 |
| 为什么资源这么高？ | 解释完整系统、缓存、字形、控制与实现约束，再说明现有余量和优化取舍 | 指定版本资源报告 |
| 能直接换任意歌曲吗？ | 解释媒体打包、索引、ROM文本和固件版本关系 | 快速说明书与工具流程 |

建议回答节奏：先给一句结论，再讲机制，最后给证据与适用范围。遇到未知的量化指标，说明所缺测量条件，并指出已经建立的机制与可观察事实。

## 7. 产品表达的取舍

当前适合突出：桌面音乐可视体验、实体操作、离线资源、音画与机械反馈、多媒体系统教学价值。当前可描述为“功能原型/竞赛作品/教学展示终端”。

需要另行论证的商业问题：目标用户访谈、愿付价格、BOM、功耗、外壳装配、音频评价、兼容性、内容授权、批量制造和维护。09提供不依赖这些未知数据的展板文案；这些商业问题可作为产品化路线图，实际数据留空。

比较现有方案时，用可验证的功能、接口、输入格式和交互形态比较。关于价格优势、能耗优势、音质优势和市场规模，采用有来源且条件一致的数据后再写入正式材料。

## 8. 本人掌握程度的完成标准

完成下面六件事后，再把“准备好了”记入个人练习表：

1. 在一张白纸画出TF、SDRAM、PCM、媒体时间、MV、HDMI和输入控制的连接。
2. 能沿顶层实例找到正在工作的模块，说明旧文件、生成资产和活动实现的区别。
3. 对三个核心机制各讲90秒，含一个失败场景和一个设计取舍。
4. 能解释一次切歌/Seek从输入到新音画生效的完整顺序。
5. 能指出报告中每个性能数字的来源、版本和测量或计算条件。
6. 能在现场按真实状态操作设备，并在问题出现时如实解释当前结果。

训练题和参考答案见05，高频问答见04，实际证据填表见10。材料准备质量与本人理解深度共同支撑作品展示，最终奖项仍取决于正式评审。
