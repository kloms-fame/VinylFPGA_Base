## 2. 逐页可用内容和讲稿

### 第1页：作品身份

**页面文字**

- VinylFPGA
- 基于安路EG4S20的唱片主题音画交互终端
- 团队：［填写］；学校：［填写］；指导教师：［填写］

**建议画面**：最终实物全景。显示屏、板卡、转盘与灯效可辨；照片版本与演示版本对应。

**15秒讲稿**：各位老师好，我们的作品是VinylFPGA，一台基于安路EG4S20的唱片主题音画交互终端。它把本地音乐、画面和实体操作连接成一次完整的听歌体验。

**过渡**：先从使用者怎样操作它开始。

### 第2页：产品场景

**页面文字**：选封面 → 播放音乐 → 看歌词/MV → 调整体验 → 保存习惯 → 再次使用。

**建议画面**：同一设备六个步骤的照片/图标，最多一行说明。场景写桌面音乐或教学展示，并标为设计场景；是否经过目标用户验证另填记录。

**20秒讲稿**：用户通过旋钮选择曲目，进入音乐、歌词和MV页面；唱针、转盘与灯带提供实体反馈。音量、画面和灯带亮度可以直接调整并保存。我们围绕这条使用流程组织功能，让每个控制都有明确的观察结果。

**过渡**：这些体验背后，是一个同时处理多种节奏的数据流系统。

### 第3页：系统架构

**页面文字**：媒体数据面、运行控制面、持久化配置三条主线。

**建议画面**：绘制TF扇区服务→索引/封面与运行媒体→SDRAM→PCM/像素→HDMI；输入事件→播放控制→各链路；CSR→用户Flash及运行参数CDC。把离线媒体准备画在FPGA边界外，用虚线表示准备文件的关系。

**30秒讲稿**：TF卡提供本地资源，索引和封面走相应文件读取路径，音频、MV与背景按索引组织连续媒体访问。SDRAM和样本缓存解耦读取与输出。另一条控制链把按键、旋钮和红外转换成统一事件，控制浏览、播放和定位。五项用户参数由独立持久化路径保存。

**追问备份**：说明离线PC工具的资源准备职责，说明运行时FPGA和外围模块的实际分工。

### 第4页：数据链路与规格

**页面文字**

- 图像/显示：640×480；基本资源为24-bit未压缩BMP。
- 音频：48kHz、16-bit、单声道裸PCM。
- MV：320×240、RGB565LE、10fps原始帧。
- 当前曲库：最多4曲；标题和歌词使用编译期ROM。

**建议画面**：同一条数据链上标出扇区、字、样本和像素，避免把它们画成一种单位。

**25秒讲稿**：当前版本选择固定格式，便于明确管理数据率和存储布局。音乐使用48kHz、16位单声道PCM，MV采用10帧每秒原始RGB565帧；显示画布为640×480。资源打包、索引和文本ROM按同一内容版本准备，运行时由FPGA完成播放与交互。

**备注**：MV源帧率与HDMI扫描刷新率分别说明；视频导出1080p也不改变FPGA输出规格。

### 第5页：实际消费时基

**页面文字**：计划采样节拍 + 有效缓存 + 下游可接收 → 实际消费事件 → 媒体时间。

**建议画面**：上行画计划tick，中行画sample_consumed，下行画cur_time_ms和MV目标帧；加入暂停与Seek两个标记。无实测波形时标“设计示意”。

**35秒讲稿**：播放器的数据读取是突发的，而用户听到的声音按采样节奏输出。因此我们没有用卡片读入量表示播放时间。当前顶层把播放核心的sample_consumed接入统一时基，真正取走有效样本后才推进时间。歌词、进度与MV使用这条时间链；暂停冻结运行，Seek加载目标样本位置，再协调新会话和画面。

**源码入口**：top_tf_hdmi_audio.v的u_timebase_48k；wav_stream_player.v的buffer_read/sample_consumed；timebase_48k.v的load和计数。

### 第6页：共享存储与访问边界

**页面文字**：高24位RGB888 / 低8位音频byte；卡侧按扇区分配，存储侧保护在途事务。

**建议画面**：左边32位字结构，右边SD与SDRAM两个仲裁框；标出图像0001、音频1110写掩码及排空阶段。

**35秒讲稿**：我们复用部分SDRAM字的低8位存储音频，高24位存储图像。写掩码保护两类数据，存储仲裁进一步管理写尾和读返回归属。卡侧则在完整扇区之间重新选择客户端：音频紧急时优先，缓存健康且视频准入时使用视频配额，背景保持较低优先级。这个设计同时考虑播放连续性、画面更新和有限资源。

**追问备份**：读掩码相关控制器行为、旧事务不能仅凭超时取消、FIFO水位与音频缓存水位的区别。

### 第7页：完整帧提交

**页面文字**：SD最后字节 → SDRAM整帧写完成 → 帧边界提交，三个事件。

**建议画面**：显示bank、完成待显bank、正在写bank；画一条提交时序。

**30秒讲稿**：读取MV最后一个字节后，像素仍可能在写入流水中。系统等待SDRAM整帧写完成，再通知视频域。调度器维护显示、待显示和写入的bank，并只在frame_start提交可见画面。这样把数据读取完成与显示生效分开管理，切歌和定位也有明确的失效与重建边界。

**源码入口**：mv_stream_player.v、mv_frame_scheduler.v、s6_video_layer.v及顶层接线。

### 第8页：产品控制与反馈

**页面文字**：统一输入事件 / 唱针与转盘 / 双灯带 / 五参数记忆。

**建议画面**：旋钮和显示OSD同框；唱针抬起而音乐继续的画面；五项参数列为VOL、BRI、CON、ROT、WSL。

**25秒讲稿**：第一旋钮负责选曲和播放定位，第二旋钮在选择参数与修改参数两种状态间切换。唱针控制转盘使能，音乐播放由独立状态控制。两路灯带提供对应反馈。音量、亮度、对比度、轮播间隔与灯带亮度可以保存，恢复时可逐项核对。

**备注**：五参数恢复与配置Flash上电自启分别展示。母板与扩展按键名称在图中分开标注。

### 第9页：赛题映射

**页面文字**：基础链路；字幕/图层；转场；亮度/对比度OSD；音频波形。

**建议画面**：每项对应一张实际截图和一个模块组。仅呈现当前活动实现，缩放作为当前规格边界说明。

**20秒讲稿**：作品对应赛题一的本地媒体、HDMI音视频与交互方向。在扩展方面，当前实现可对应字幕与图层、转场、亮度对比度调节及波形可视化四类方向。各项集中在同一个最终设计中，后续展示按实际输入与结果逐项定位。

**备注**：四类对应是工程分析结论，不换算成官方得分。正式指南与解析课件的表述差异见旧08/09。

### 第10页：工程结果与证据

**页面文字**：归档实现：LUT17,810/19,600；BRAM9K64/64；Setup WNS+0.121ns；Hold WNS+0.030ns。

**建议画面**：四张简洁数字卡，脚注写“固定验收归档版本”；角落放实际固件身份摘要。把相关回归数量和更详细约束条件放备份页。

**25秒讲稿**：固定验收归档保留了实现结果、输入清单和固件身份。该版本LUT约90.9%，BRAM9K使用64块，Setup与Hold最差裕量分别为正0.121和0.030纳秒。我们将这些归档结果与现场演示记录分开标识，使资源、仿真和实物行为各有对应证据。

**使用条件**：实际拍摄/现场固件与归档版本对应后再把数字放在当前作品结果页；身份未确认时，标题明确写归档版本，不暗示是当前板上测量。时序结果受约束和模型范围限制。

### 第11页：同版本演示

**页面文字**：真实操作 → 可观察结果 → 已保存设置 → 重启后核对。

**建议画面**：现场可直接展示已稳定运行的设备，或播放同版本证据片段并标注“录像”。25秒版本只选一个已经充分准备的因果动作，不在这25秒内强塞完整启动。

**25秒讲稿**：这里先展示一项原速操作及实际反馈。完整保存、真实重启和五项参数核对，使用单独预留时段或同版本连续原片。本页用来说明演示与证据的关系，不把25秒当成整机冷启动预算。

**现场分支**：若演示尚未准备好或发生问题，按11的故障话术说明所见状态，再回到已经准备好的同版本资料。切换资料时明确标识录像与现场来源。

### 第12页：总结与价值

**页面文字**

1. 本地音画与实体交互的一体化体验。
2. 样本时基、共享存储和完整帧提交的系统实现。
3. 可学习、可维护、可追溯的国产FPGA工程案例。

**15秒讲稿**：VinylFPGA将唱片式体验落到完整FPGA系统中。我们的主要工作是协调媒体时间、共享访问和显示提交，并把这些机制与实体交互连接起来。以上是作品介绍，欢迎老师提问。

## 4. 个人彩排方法

第一遍只讲结论和结构；第二遍用手机计时并检查300秒总预算；第三遍随机抽取04的追问，沿代码解释。每次记录一个需要改清楚的句子和一项待补证据。

如果超时，优先删去重复举例和模块名串读。保留第5–7页的关键因果链，再减少备份页口述。作品视频、答辩PPT和书面报告共享事实，分别使用适合各自时长的表达方式。
