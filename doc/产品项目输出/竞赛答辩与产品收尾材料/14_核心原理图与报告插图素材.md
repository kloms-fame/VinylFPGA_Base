# 核心原理图与报告插图素材

> 本文提供可复制的Mermaid与文字示意图。它们根据当前RTL组织，用于学习、报告和PPT制图，均属于设计示意，不是仿真波形、实测时序图或实际硬件接线图。源码入口见02。

## 图1：整体数据面和控制面

~~~mermaid
flowchart LR
    PREP[离线媒体准备] -.生成配套资源.-> TF[TF卡]
    TF --> SEC[SD SPI扇区服务]
    SEC --> FS[FAT32子集与文件流]
    FS --> IDX[INDEX元数据校验]
    FS --> BMP[封面BMP解析]
    IDX -.地址和格式.-> RUN[音频 / MV / 背景客户端]
    SEC --> RUN
    BMP --> MEM[SDRAM共享存储]
    RUN --> MEM
    MEM --> PCM[PCM样本缓存]
    PCM --> AUD[音量淡变与HDMI音频]
    MEM --> PIX[像素读出与合成]
    ROM[编译期文本与字形ROM] --> PIX
    PIX --> VID[HDMI视频]
    INPUT[按键 / 旋钮 / 红外] --> EV[事件解码与业务路由]
    EV --> CTRL[浏览 / 播放 / 暂停 / Seek]
    CTRL --> RUN
    CTRL --> PCM
    EV --> CSR[五参数CSR]
    CSR --> NVM[用户Flash持久化]
    CSR --> SNAP[运行参数快照与CDC]
    SNAP --> AUD
    SNAP --> PIX
~~~

**可直接使用的图注**：系统把文件组织、运行媒体访问、缓存、像素与样本输出分层。实线表示主要数据或控制关系，虚线表示资源准备或元数据关系；离线工具位于运行FPGA边界之外。

**讲解要点**：说明运行音频/MV/背景不是全部经过FAT字节流；说明歌词ROM与卡片资源各自负责什么。该图省略具体仲裁、FIFO和复位，详细机制用后面三张图展开。

## 图2：计划tick与实际媒体时间

~~~mermaid
flowchart LR
    TICK[计划48kHz采样tick] --> CHECK[读条件共同成立]
    READY[下游sample_ready] --> CHECK
    AVAIL[有效缓存与播放条件] --> CHECK
    CHECK --> POP[buffer_read]
    POP --> CONSUMED[sample_consumed]
    POP --> SAMPLE[读取真实PCM样本]
    SAMPLE --> HDMI[音量淡变 / HDMI音频链]
    CONSUMED --> TIME[timebase_48k]
    RUNNING[运行状态] --> TIME
    LOAD[Seek目标样本load] --> TIME
    TIME --> MS[cur_time_ms]
    MS --> LRC[歌词与进度]
    MS --> MV[MV目标帧调度]
~~~

**图注**：顶层将wav_sample_consumed接到timebase_48k的sample_tick输入。正常运行时每48个实际消费样本换算1ms，Seek另有目标位置加载路径。

**适合放在图旁的一句话**：媒体时间跟随有效样本消费，卡片预取进度与媒体播放进度分别管理。

**PPT动画顺序**：先出现计划tick和缓存条件，再出现消费事件，最后出现歌词/MV消费者。这样观众先理解触发条件，再理解输出关系。

**需要本人能解释**：缓存未满足条件时、暂停时、Seek加载期间分别发生什么。对同步误差作量化主张时，另配实测记录；本图只说明机制。

## 图3：SDRAM字节lane复用与两层仲裁

~~~text
一个SDRAM 32bit字：

31                          8 7                0
+----------------------------+------------------+
| 图像RGB888，高24bit          | 音频byte，低8bit  |
+----------------------------+------------------+

图像写：mask=0001，保护低byte
音频写：mask=1110，保护高3个byte
读访问及写尾：按控制器语义管理掩码和ownership
~~~

音频缓存slot×512+offset映射到部分物理字地址的低byte。不要把这个slot写成TF卡LBA，也不要把分布式低byte容量写成一块新的连续32bit地址区。

~~~mermaid
flowchart TB
    A[音频扇区请求与紧急标志] --> S[SD层：完整扇区间分配owner]
    V[MV请求与准入] --> S
    B[背景请求与准入] --> S
    S --> CARD[SD SPI事务]
    CARD --> CLIENT[客户端暂存 / 像素解包]
    CLIENT --> M[SDRAM层：访问锁 / 写掩码 / 返回归属]
    M --> MEM[SDRAM控制器与共享字]
    MEM --> DRAIN[在途返回与写尾排空]
    DRAIN --> NEXT[满足条件后交接下一访问]
~~~

**图注**：SD仲裁和SDRAM仲裁解决不同资源的竞争。SD侧在音频健康状态下给视频配额，在音频紧急状态下优先服务音频；背景受较低优先级和准入条件限制。SDRAM侧进一步保护在途读写与byte lane。

**报告小节建议**：先写空间复用，再写时间仲裁，最后写错误/超时期间ownership的处理。这样可以把容量收益、服务策略和一致性代价解释完整。

## 图4：整帧完成与帧边界可见

~~~mermaid
flowchart LR
    REQ[请求目标MV帧] --> READ[读300个扇区]
    READ --> UNPACK[RGB565LE解包]
    UNPACK --> FIFO[像素FIFO与写入流水]
    FIFO --> WRITE[SDRAM完整帧写入]
    WRITE --> FIN[write_finish标记]
    FIN --> DONE[done_toggle跨域确认]
    DONE --> PEND[完成待显示bank]
    PEND --> COMMIT[满足条件且frame_start]
    COMMIT --> DISPLAY[更新可见bank和帧号]
~~~

~~~text
同一时刻的bank职责示意（编号会随调度轮换）：

Bank A：当前显示，读出保持
Bank B：完整写好，等待显示提交
Bank C：正在写入，尚不可作为成功帧显示

数据事件：最后SD字节 ---- 写入流水完成 ---- done跨域可见 ---- 显示提交
显示边界：                frame_start          frame_start          frame_start

以上只表示先后关系；横向距离不代表实际耗时。
~~~

**图注**：MV读取完成、SDRAM写完成和显示生效分别管理。调度器结合媒体目标时间、完成状态及帧边界选择可见bank；切歌、Seek和失效会影响待显示状态及旧请求处理。

**适合评委追问的解释**：三缓冲使“当前显示、完成待显、正在写入”可以有独立角色；只给出三个bank的数量还不足以保证一致性，关键在何时分配、何时完成以及何时提交。

## 图5：参数保存、恢复和运行消费者

~~~mermaid
flowchart LR
    INPUT[EC2 / 按键 / 红外参数动作] --> CSR[UI域CSR五参数]
    CSR --> SAVE[UI域持久化调度]
    SAVE --> FLASH[用户Flash双槽记录]
    FLASH --> LOAD[启动读取与校验]
    LOAD --> RESTORE[符合优先级条件后恢复]
    RESTORE --> CSR
    CSR --> CDC[运行参数快照CDC]
    CDC --> APPLY[显示 / 音频 / 灯效消费者]
~~~

**图注**：保存与恢复读取同域参数快照；跨域主要发生在运行参数到各消费者的分支。用户Flash参数记录与FPGA配置Flash用途分别说明。

**拍摄对应**：先拍非默认值、保存完成，再拍所选重启方式和恢复值；断电版另保留真正失电与上电自启。只恢复五项用户参数，不画自动续播路径。
