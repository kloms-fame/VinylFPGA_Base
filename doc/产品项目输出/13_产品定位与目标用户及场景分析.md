# 13｜产品定位、目标用户与场景分析

> 分析日期：2026-10-19。此处给出的是基于当前实现的产品设计定位，供竞赛答辩、项目展示和后续产品化讨论使用。它不是用户调研结果、商业验证或已经部署的市场案例。

## 1. 推荐定位

### 一句话定位

> **VinylFPGA 是一套基于安路 FPGA 的唱片主题本地音乐画屏：从 TF 卡读取项目约定格式的媒体，让音频播放、专辑画面、歌词、MV/波形显示和实体交互形成一体化体验。**

### 面向答辩的完整定义

VinylFPGA 将 FPGA 本地媒体处理能力包装成唱片主题的桌面影音体验。用户可浏览和选择本地曲目，通过板上实体输入控制播放；系统把 PCM 音频送入 HDMI 音频链路，同时按播放进度显示封面、歌词、进度、波形或 MV，并以旋钮、灯带和唱片主题反馈强化操作感。项目既是多媒体终端原型，也是展示 FPGA 数据通路、缓存调度、跨时钟域和人机交互集成能力的竞赛作品。

“唱片主题”描述的是视觉和交互风格，不代表设备读取模拟黑胶唱片；“本地音乐画屏”描述内容来源和主要体验，不代表它是通用格式、无限曲库的消费级播放器。

当前是最多四曲、固定媒体规格的竞赛工程原型。标题、艺人和歌词由随固件编译的 ROM 提供；更新媒体卡与更新文字 ROM 的流程不同，详见本文第 8 节。

## 2. 定位方案比较

| 定位方向 | 与现有实现关系 | 主要收益 | 主要风险 | 建议 |
|---|---|---|---|---|
| 通用数字音乐播放器 | 局部相符 | 类别易懂 | 现有格式、曲目数量、媒体导入能力有明确边界，易让人联想到广泛格式兼容 | 不作为唯一定位 |
| 实时信息发布/广告系统 | 偏离当前核心 | 能对应赛题列出的部分应用方向 | 无实时业务数据链路、联网管理及行业环境验证 | 不作为当前产品定位 |
| FPGA 教学实验平台 | 架构匹配 | 工程教学价值突出 | 会弱化唱片主题和用户可见体验 | 作为第二展示价值 |
| 唱片主题本地音乐画屏/桌面影音终端 | 与当前用户流程及代码功能最接近 | 音乐、画面、操作、灯效可形成连贯故事 | 仍是工程原型定位，消费级体验和市场需求未验证 | **推荐主定位** |

## 3. 目标用户分层

| 用户/评审对象 | 想完成的事 | 项目可提供的价值 | 当前证据性质 |
|---|---|---|---|
| 桌面听音或个人展示场景的使用者 | 播放本地曲目，同时看见专辑信息和播放状态 | 选择曲目、播放 PCM、显示歌词/封面/MV或波形，实体交互 | 产品设计假设；需用户测试确认易用性 |
| FPGA 竞赛评委和技术观众 | 快速判断作品是否形成完整系统、技术决策是否可信 | 从 SD 到缓冲、音频/视频输出、交互和物理实现可讲成闭环 | 由 RTL、仿真及实现报告支撑不同层面的结论 |
| 教学演示或科技展项组织者 | 以直观场景展示 FPGA 系统工程 | 可展示音视频时基、存储仲裁、CDC 和输入控制 | 可作为展示用途；需准备演示素材与操作流程 |
| 商业或公共设施运营者 | 稳定管理内容、远程更新或接入实时数据 | 当前资料只能支撑预置本地内容播放这一部分 | 不承诺远程平台、实时业务接入或行业级可靠性 |

主要读者优先为比赛答辩与成果展示；产品用户画像则采用桌面音乐空间中的个人使用者作为场景假设。二者分别回答“向谁讲清项目”和“产品为谁设计”，不能混为市场证明。

## 4. 主场景与辅助场景

### 主场景：桌面/客厅的本地音乐画屏

用户在个人空间选择 TF 卡中的曲目，封面先建立曲目识别；播放过程中，歌词和进度随内容推进，屏幕可显示 MV 或波形，实体控制和灯效提供即时反馈。这个场景无需编造实时数据，也能解释项目的媒体、显示、交互和主题设计。

课程第十六讲的“客厅音乐画屏”及数字相框类场景是可借鉴的场景组织方式。VinylFPGA 的差别在于围绕音乐播放和唱片主题控制构建体验，而不是仅做图片轮播。

### 辅助场景：竞赛/教育技术展示

以一段短演示解释同一片 FPGA 如何完成本地媒体读取、流缓存、HDMI 音视频输出和实体交互。此处的核心对象是技术观众，价值来自“可观察的端到端系统工程”，不是课程课件中的案例自动证明本项目已部署在公共场所。

### 有条件场景：固定内容的商业展陈

若内容均预先放入 TF 卡、交互只使用当前板上控件，可把工程说明为固定素材展项原型。部署端的内容更新、长期运行、亮度环境适应、散热及维护方式仍需单独设计和验证。

## 5. 当前不适合作为主定位的方向

- **应急信息发布、医院叫号、停车场/交通屏：** 依赖外部实时数据、优先级管理和可靠性证明；当前工程资料没有对应业务接口和现场验证。
- **车载辅助显示：** 需要车规环境、振动/温度/电源与安全相关验证；现有作品不能由 HDMI 演示推导出车载可用性。
- **工业看板：** 需要上游工单/产线接口、持续运行、故障恢复和现场可读性验证。
- **通用音视频播放终端：** 当前有项目约定媒体格式和曲目规模限制，不能承诺常见容器、编码格式、任意分辨率都可播放。

若未来希望适配这些领域，应把数据由上游生成后以明确格式导入，并增加相应接口和验证；产品文案不能代替系统能力。

## 6. 场景陈述模板

> 面向【个人桌面听音与展示】的用户，VinylFPGA 将【TF 卡本地曲目】转化为【音频播放、专辑画面和歌词/MV联动】体验；用户通过【旋钮、按键、遥控等现有输入】完成浏览和控制，系统用【屏幕波形/转盘主题灯效】提供可见反馈。该定位目前是依据工程实现形成的产品原型假设，后续以目标用户试用验证交互和内容组织。

此表达包含目标人、内容来源、系统动作、用户操作、可见结果和证据状态，避免只列“支持了多少模块”。

## 8. 当前版本规格与内容更新边界

下表集中定义当前产品文案中的“项目约定格式”。这是当前活动工程的规格，不是赛题对所有作品的统一限制。

| 对象 | 当前规格与数据来源 | 更新或演示边界 |
|---|---|---|
| 曲目数量 | 当前 INDEX 解析及曲目编号链路最多 4 曲；现有歌词数据亦按四曲生成 | 不是插卡后任意数量扫描的无限曲库；增加容量需同步调整索引、控制、显示和资源预算 |
| 歌曲音频 | TF 卡的 48 kHz、16-bit signed、little-endian、单声道原始 PCM；输出左右声道由同一单声道样本映射 | `wav_stream_player` 名称不代表支持 WAV 头解析；不声称 MP3/AAC 等解码或双声道源播放 |
| 封面/基础 BMP | TF 卡的 640×480、24-bit、未压缩 BMP，按当前媒体打包和解析约定准备 | 不同分辨率自适应缩放未接入活动设计；不能只替换任意尺寸图片 |
| MV | TF 连续 LBA 区域中的 320×240、RGB565 little-endian、top-down 原始帧，10 fps；一帧 153,600 bytes/300 扇区 | 这是项目原始视频格式，不是通用视频容器或压缩解码器；MV 源帧率与 HDMI 输出刷新率是两个概念 |
| 标题、艺人、歌词和字形 | 编译进固件的 `song_text_rom` 等 ROM，按曲目 ID 与实际样本消费时间选取、滚动和显示 | 当前显示不从 TF 卡任意 LRC 文件动态解析；TF 卡中的 LRC/LYRICS.BIN 与当前 ROM 必须区分 |
| 持久化参数 | 用户 W25Q64 路径保存音量、亮度、对比度、轮播间隔、WS2812 亮度这五类参数 | 不保存曲目播放位置，不等于断电续播；该用户 Flash 功能也不等于 FPGA 配置 Flash 已固化 |
| 波形与扩展接口 | 从 PCM 幅度产生波形/电平视觉反馈；有外部电机驱动使能接口 | 不称 FFT 频谱；FPGA 引脚不直接驱动电机负载；UART TX 当前恒高、已退役 |

依据：[song_index_db](../../src/SD/song_index_db.v)、[索引约定](../../src/include/song_index_defs.vh)、[顶层接线](../../src/top_tf_hdmi_audio.v)、[song_text_rom](../../src/display/song_text_rom.v)、[音频链路](./03_音频播放链路分析.md)、[视频/媒体链路](./04_视频与媒体存储链路分析.md) 和 [交互与持久化](./05_交互界面与参数持久化分析.md)。

**更新媒体卡：** 保持当前曲目 ID、ROM 文本对应关系和输入规格时，可用现有打包工具准备音频、图像、MV、索引及卡片布局；布局/LBA 改变时同步重新生成索引。不能手工替换文件后继续使用不匹配的旧索引。

**更新文字内容或曲目对应关系：** 新增/修改标题、艺人、歌词、字形或曲目 ID 关联时，需用现有歌词/资源生成工具同步更新 ROM 与资源，再按工程流程构建相应固件。只替换卡上的 LRC/LYRICS.BIN 不会改变当前播放页 ROM 显示内容。2026-10-19 的收尾生成了歌词证据文件，但没有重写物理 SD 卡；生成成功不等于当前卡片已经更新。

**归档同一组内容：** 使用源码/ROM、bit、媒体索引/卡片布局和校准 manifest 的对应版本作为一个交付单元。现有工具包括 [vinyl_packer.py](../../tools/vinyl_packer.py)、[mv_pack.py](../../tools/mv_pack.py)、[pack_backgrounds.py](../../tools/pack_backgrounds.py) 和 [prepare_s3_lyrics.py](../../tools/prepare_s3_lyrics.py)。操作与证据身份见 [交付维护手册](./25_交付维护与证据归档手册.md)。
