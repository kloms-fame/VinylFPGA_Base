# 配音、字幕与后期剪辑执行稿

> 主脚本见 [02](./02_三分钟主片逐秒拍摄脚本.md)。这里提供的是拍摄执行稿，不是已经拍摄成功的结果。只有实际画面出现相应结果，才保留对应解说。
> 参考时轴T=20秒、成片176.5秒。辅助生成器可按实测启动T重排字幕，不会操作FPGA、卡片或工程。

## 1. 配音风格

用清楚、平稳的第一人称介绍，给关键结果留下停顿。标题说产品，操作说结果，技术只补一句原因。不要照读模块名和资源表。

以下为分段主体稿，含少量英文缩写。按本稿时间窗口录制即可，不必追求全片连续讲话。英语、数字的实际发音时长不等于字符数；最终以录音回听对齐为准。

先排练动作，再录分段旁白。每段开头留半秒余量，短句之间自然停顿。旁白一次录两遍，选语义清楚的一遍，不必做广告腔。

## 3. 必须保留的原声窗口

| 位置 | 需要观众听见什么 | 剪辑要求 |
|---|---|---|
| 开始播放26–32秒 | 实际设备音乐，不是素材库配乐 | 无旁白，设备音轨正常音量 |
| 暂停/恢复32–40秒 | 停止与重新发声的对比 | 旁白可在动作前讲，暂停后的1秒尽量安静；与旁白重叠则把本句缩短 |
| 抬针40–44秒 | 转盘停止但音乐继续 | 原声保持，不用静音效果模拟 |
| 静音/恢复71–75秒 | 音乐的消失与恢复 | 不加配乐、不用后期静音制造设备效果 |
| 原速黑屏128.5–130.5秒 | 画面黑但实际音频仍在播放 | 完整原声保留 |
| 重启后重新播放 | 固件启动后实际发出的声音 | 使用本次同一条原片的音轨 |

声音分三轨：A1连续设备/环境原声，A2旁白，A3可选片头/片尾音效。A3默认不加音乐。旁白区可把A1适当压低，真实听音和静音证据窗口恢复原始相对变化。不要用压限、降噪或自动增益把音量调节前后的差异抹平。

## 4. 字幕层级

1. 产品层：开场作品名和结尾三项特点。
2. 功能层：短标签，如“基础：自动轮播”“扩展：亮度与OSD”。
3. 解释层：旁白字幕，最多两行，不覆盖屏幕原生歌词、OSD、LED或手部。
4. 事实提示：等待段4×、原速、归档实现数据等只在相应段出现。

建议1080p画布采用40–46px左右的清晰中文字体，功能标签与旁白分开摆放；这是一组起始设计值，实际按显示器画面和手机回看调整。颜色以白字、深色底条、单一强调色为主，不加频繁跳字。

SRT只携带时间和文字，不携带稳定的位置/字体样式。导入剪辑软件后分别给“旁白”和“功能标签”轨设置样式，不把两个SRT混成同一位置互相覆盖。

## 5. 后期轨道与连续性

~~~text
V1：一条连续主机位原片
    0–112秒原速 / 112–170秒等待前58秒4倍速 / 170秒起原速
V2：同一原片同一时刻的局部放大或全景小窗
V3：功能标签、实际时间换算计时、可选设计说明
V4：旁白字幕
A1：与V1同源的设备原声
A2：后录旁白
~~~

不要新增软件转场来掩盖设备自己的擦入/淡变。切画面细节时可对V1做同时间数字裁切或短距离平移，并保留全景小窗。关键手部操作至少提前半秒进入画面，结果出现后保持一秒。

60秒等待段的经过时间应从原片最后一次有效操作时间计算，成片该段每走1秒对应原片4秒。需要标明计时为后期标注；只有实际等满才写60秒。字幕动画不能替代计时证据。

## 6. 唯一变速段的音频

112–170秒原片压为成片112–126.5秒时，音频不适合用来判断实时音质。可保留经明确变速的音轨，或降低/关闭该段音轨并保留旁白；应注明“变速段不作音质对比”。

原片170秒提前恢复1×，保留触发前2秒；自动息屏后原片172–174秒对应成片128.5–130.5秒。这2秒原声证明黑屏时音乐继续。不能把另一条音乐录音贴到黑屏处冒充当前设备。

## 7. 可以加的一张工程说明卡

若拍摄固件身份能与固定验收报告对应，可短暂叠加：

- 架构：块存储缓存、样本时基、完整帧后提交。

- 明确标注“归档实现结果，2026-10-19”，不是现场测量。

资源数值来源见 [06工程证据](../06_工程实现验证与收尾边界.md)。资源高占用不是低功耗证据。若无法确认本次拍摄固件与该报告对应，只保留不带性能数字的设计说明，最终工程数据在答辩附件引用。

三分钟主片不需要把整张时序/资源报告盖在画面上。保持字幕能被正常速度读完。

## 8. 剪辑执行顺序

1. 导入完整原片，复制备份，不改动源视频文件。
2. 按实际最后操作、自动息屏、E9被接受（或实际复电）和浏览可用时刻打标。
3. 仅将无操作前58秒设为4×，最后2秒与其余全部保留1×；加入公开速度标签。
4. 对齐原声与局部裁切，先确认画面连续，再导入字幕。
5. 按实测T使用辅助生成器输出旁白稿/字幕，再录制分段配音。
6. 校对实际参数值、曲目变化和保存指示；不一致就改文字或重拍，不能替换屏幕结果。
7. 调整语音与设备声层级，检查所有原声证据窗口。
8. 导出后完整回放，确认包括头尾在内小于180秒。

参考导出：1920×1080、16:9、MP4/H.264、SDR，帧率沿用拍摄帧率。[YouTube官方编码建议](https://support.google.com/youtube/answer/1722171?hl=en)可作为兼容性参考，不是本赛项强制规则。具体设置与机位说明见 [04](./04_机位灯光收音与排练执行SOP.md)。

## 9. 附带文件怎么用

- 旁白字幕_T20排练版.srt：文字旁白的参考时轴。
- 功能标签_T20排练版.srt：功能定位、变速/原速与建议参数值。
- 分镜表_T20排练版.csv：原片时间、成片时间、动作、可见结果。
- 配音稿_T20排练版.txt：按窗口录音的干净文字稿。
- 字幕生成器.py：按实测T生成新的SRT/配音稿；标准库脚本，不访问硬件。
- 字幕素材.json：可调整的自有脚本文字和参考时轴。

在本目录下执行，例如实测启动为18.5秒：

~~~powershell
# 默认软重启，分别实测各自T
python ./字幕生成器.py --startup-seconds 18.5
# 可选真实断电版，输出到另一独立目录
python ./字幕生成器.py --startup-seconds 20 --restart-mode power
~~~

输出写入本目录下独立的“字幕输出_soft_T18.5秒”文件夹。脚本不会剪视频、合成真实旁白、推测启动时间或修改项目工程。更改拍摄动作、参数值或首段时长后，仍需按实际录像重新校准，不只修改T。
