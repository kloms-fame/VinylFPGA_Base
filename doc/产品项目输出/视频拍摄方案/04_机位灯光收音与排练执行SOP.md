# 04｜机位、灯光、收音与排练执行 SOP

> 适用方式：一部手机固定横屏、一人操作、后期配音和字幕。本文是待执行的拍摄流程，不是已完成的板级测试或拍摄结果。
> 不修改源码、固件、媒体格式或定时参数来迁就镜头；真实未测的项目保留空白或写“未测”，不得预填“通过”。

## 1. 原片与成片的统一口径

本方案拍一条连续原片，预算200+T秒。用户已确认手机固定机位、一人操作。主片默认软重启，真实断电自启/恢复作为可替换分支。

T默认从E9软重启被接受到浏览页稳定可操作；断电版从实际重新供电到相同终点。分别测量，不混用软重启与冷启动耗时。后续12秒参数核对不计入T。

~~~text
仅无人操作前58秒用4×，最后2秒恢复1×。
原片：200 + T 秒
成片：(200 + T) - 58 + 58/4 = 156.5 + T 秒
T=20秒仅为示例：成片176.5秒
T≤21.5秒：成片≤178秒，留2秒余量
~~~

| 原片时间 | 成片时间 | 速度 | 执行内容 |
|---|---|---:|---|
| 0–112 | 0–112 | 1× | 基础功能、音画交互、五参数与保存 |
| 112–170 | 112–126.5 | 4× | 真实无人操作前58秒，明确标注速度 |
| 170–172 | 126.5–128.5 | 1× | 无操作最后2秒，原速等待自然消隐 |
| 172–174 | 128.5–130.5 | 1× | 黑屏后保留2秒现场音乐 |
| 174–178 | 130.5–134.5 | 1× | 首个普通按键只唤醒 |
| 178–180 | 134.5–136.5 | 1× | 默认准备E9软重启，在180秒触发；断电分支在180秒实际复电 |
| 180–180+T | 136.5–136.5+T | 1× | 对应模式真实启动，直至浏览页稳定可操作 |
| 180+T–192+T | 136.5+T–148.5+T | 1× | SELECT逐项核对五参数，再重新播放 |
| 192+T–200+T | 148.5+T–156.5+T | 1× | 整机持续工作，8秒收尾 |

无操作计时从最后一项被系统接受的操作之后开始。不要把一项操作插在112秒附近却仍从112秒机械计算60秒。排练时定位末次有效输入与实际消隐边沿；若60秒窗口没有覆盖所需结果，应先调整开拍动作节奏和计时边界，再重拍，不减少固件超时值。

成片片头或片尾写明：**“连续实拍；仅无操作等待段4×，其余1×；保留连续原片供核对。”** 等待段持续显示：**“真实无操作前58秒｜本段4×｜原片00:01:52–00:02:50”**。可同时显示对应原片时间码；时间码是后期定位信息，不能替代原片。

不能把成片称为“全程原速一镜到底”。准确表述为“单机位连续实拍，成片仅等待段标明4×”。如果比赛明确要求全程1×或禁止任何变速，应提交200+T秒原片或按实际规则重新设计内容，不能隐藏4×。

> 下文涉及“全断电、灯灭、反供、冷启动”的布置与检查专用于可选断电分支。默认软重启只发E9，不拔电；字幕不得写成断电自启。两条路线均需等保存忙结束后再重启。

## 2. 固定机位与桌面摆位

以下是本项目的拍摄建议，不是器材型号或购买推荐。

1. 手机横屏固定在现有稳固支架/固定物上，先摆设备再确定画面。默认一次拍摄期间不移动、不手持追拍、不切换镜头。
2. 屏幕放画面上方，扩展控件与主板放下方，转盘与灯带放在另一侧；三者尽量在同一景深范围。让观众同时看到“手做了什么”和“屏幕/外设怎样响应”。
3. 两个旋钮、常用按键、遥控接收方向、转盘与唱针、关键指示灯，以及冷启动时操作的电源位置都要可见。线缆从后侧或桌边走，避免横穿显示区。
4. 操作者从画面侧下方伸手，先排练每次按压和旋转。手掌不盖住屏幕、双旋钮、灯带、电机或保存/恢复指示灯；完成动作立即撤手到固定停放位置。
5. 不为说明功能而把手持续指向屏幕；说明交给后期箭头/字幕。后期框选不能遮住操作状态、时间码或故障信息。
6. 先用正常音量、较亮画面和最亮灯带测试构图，再测试息屏与全部板卡断电后的画面。暗场仍应能辨认板卡轮廓和断电动作。

若设备支持且连续录像稳定，可用4K/30fps采集，再输出1080p，使后期有适度裁切余量。4K不是必要条件；现有设备只有1080p时，优先让文字与操作清楚。相同画面裁切只能放大已有像素，不能补回被手挡住或失焦的证据。

裁切放大应平缓、保持当前动作的上下文，不把板卡反应与手部输入拆成互不相见的两段。暂停/静音、唱针与电机、保存指示、断电熄灯等关键片段，优先保留全景。

## 3. 灯光、曝光与颜色

### 3.1 先解决反光，再确定曝光

用现有柔和、稳定的室内光照亮板卡和手，不让灯面或窗户反射在显示屏上。可通过移动现有灯、屏幕角度或机位消除反光，镜头确定后固定全部位置。避免环境灯在画面中直接过曝，也避免把房间完全关黑后让手机只根据屏幕测光。

先显示正常封面/歌词，调整到文字、白色区域和灯带都有细节，再锁定焦点、曝光与白平衡。**展示亮度/对比度时不改手机曝光；屏幕息屏或板卡断电后不补偿曝光。** 否则手机可能主动抬亮画面，使实际亮度变化被抵消，或让黑屏看起来发灰。

手机支持手动/锁定功能时，拍前完成设置；不支持时，先用实录确认自动曝光不会明显抵消变化，并在记录表写出限制。不要把自动测光造成的画面变化描述成 FPGA 显示效果。固定相机位置，禁止在亮度对比演示时重新点按对焦或拖动曝光。

### 3.2 频闪、条纹与屏幕刷新要实录确认

Sony官方说明：在50Hz供电地区，1/50秒或1/100秒快门可作为减轻频闪的起点；支持可变快门的设备可细调，并应检查录制文件中的结果。不同型号功能不同。该建议涉及光源频闪，不能直接保证本项目屏幕刷新与WS2812灯带同时无条纹。[Sony：降低拍摄频闪](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7m3/articles/00122281)

本项目建议分别录10秒“屏幕白字+运动画面”和“最亮/较暗灯带”，再把二者同时拍进画面检查。显示屏刷新、灯带PWM、环境灯和相机读出可能各有影响，不能只看相机预览就宣布解决。手机无法调快门时，从现有可选帧率、灯光、拍摄角度和距离中试出可用组合，最终固定实际通过的设置。

Apple官方说明，支持机型可锁定录像镜头和白平衡；自动FPS可能在暗光下将帧率降至24fps，HDR也有独立开关。菜单与功能随机型而异。[Apple：更改iPhone录像设置](https://support.apple.com/en-gb/guide/iphone/iphc1827d32f/26/ios/26)

对本项目，建议在设备支持时锁镜头/白平衡、关闭自动降帧率，并使用SDR录制或明确的SDR转换流程，以便比较屏幕亮度和颜色。关闭HDR是便于交付和一致性核对的拍摄选择，不是所有手机都必须采用的硬性标准。

## 4. 收音与后期配音

现场只操作，不边操作边长篇讲解。手机持续保留整条原片音轨，扬声器/显示器声音从设备真实输出；手机麦克风不要贴近风扇、手掌或电源噪声源。保持音量清楚而不破音，不在录制中用手机音量键改变录音状态。

先录一段“播放→暂停→继续→静音→恢复”的短排练，听录音文件中各段差别。不要只确认自己现场听到了声音。设备若启用强降噪/自动增益，注意暂停后环境底噪是否被抬高；保留原始文件，并据实标注录音方式。

| 片段 | 原声处理 | 配音/音乐处理 |
|---|---|---|
| 连续播放与歌词推进 | 至少留一段清楚的真实播放声音 | 旁白暂停或降至不影响判断；不另叠同一首歌伪装输出 |
| 暂停、静音及恢复前后 | 保留操作前、操作中、恢复后的原声差别 | 不用配乐跨越填满静音，不用剪掉断续来制造连续 |
| 按键提示/蜂鸣器 | 若展示其功能，保留真实触发与响声 | 不后配拟音代替设备输出 |
| 112–170秒变速等待段 | 原片保留完整原声 | 成片可将变速原声静音并加解说，注明本段4×；不将变速音频用于证明音质或连续播放 |
| 冷启动 | 原片保留电源动作与等待声音 | 可后期配音，但不通过剪音掩盖异常重启或省略等待 |

后期旁白单独录，在画面动作核对后再对齐；字幕解释实际看到的结果。主音轨是否降噪、混入旁白或调整整体响度，应保留可回查的原音轨。不要把原片中的掉音修成“稳定播放证据”。

## 5. 拍前测T与关键动作排练

### 5.1 默认软重启与可选真实冷启动

默认路线：保存完成后用E9软重启，记录到浏览可用的T并核对五参数。以下仅为可选断电路线的补充检查。

冷启动指**切断全部板卡供电，确认指示灯全部熄灭，再重新供电启动**。按复位键、遥控软重启、拔掉一个仍被USB反供的电源口，都不能作为本片的冷启动。

拍前检查主板、扩展板、用户Flash/电机/灯带关联供电以及USB下载器、调试口等可能供电路径。USB若仍给板卡反供，应按实际硬件接线先消除该路径；不能仅拔主电源就口述“完全断电”。保留显示器自身供电不代表板卡仍供电，但须确认实际连接不会造成板卡反供。

使用已有正常供电连接做断电操作，不触碰裸露带电连接。先在排练中验证全断电后固件是否能自行启动；**没有配置Flash自启动能力时，不能通过隐藏重新下载bit来完成“冷启动恢复”镜头。** 如当前硬件不能满足，应把真实限制反馈到总分镜，不用软复位替代。

保存五项参数后，等待实际保存完成指示，再断电。预先记下至少一个非默认值，启动后打开面板逐项核对。不能用“出现开机画面”代替参数恢复证明，也不能把参数恢复说成播放位置续播。

## 6. 一人连续拍摄执行顺序

1. 固定当前固件、卡片和参数基线，记下使用文件身份；预先准备需要对比的非默认值。拍摄工具只负责记录，不改变工程实现。
2. 完成机位、灯光、收音和短样片检查；确认电量、可用空间与整条200+T秒录像能力。开启勿扰，避免来电打断；拍摄中不碰手机。
3. 在画外放一张大字动作卡，标出重要时间点、控件和恢复动作。操作者只需要看动作关键词；后期旁白另录。
4. 每次正式拍摄重新回到主分镜规定的初态；不能沿用上次失败镜头结束时的随机曲目、参数或计时状态。
5. 开始录制，确认录制计时已走，再执行第一步。全程不暂停相机，不换镜头；手部动作小而明确，结果出现后再做下一项。
6. 接近原片112秒时结束最后一次有效输入，手撤到画面内固定位置；保持项目控件60秒无操作。不能因手机提示、读稿或整理线缆误触按键/编码器/遥控。
7. 原片172秒后按主分镜唤醒和完成收尾，保存→等待完成→E9软重启→参数核对的关系保持清楚；若选断电版，再用全断电灯灭与重新上电替换E9动作。
8. 全部结果稳定后再结束录像。立即回放原始文件，查手遮挡、原声、黑屏曝光、真实等待和冷启动端点；未通过就标记本条失败并完整重拍。

原片112秒/172秒是这套预算的定位点。拍摄计时、最后有效输入与项目60秒定时存在偏差时，以真实无操作时长和实际结果为准；本轮不得剪短这60秒或修改字幕伪装准点。需要时修订整条拍摄排练节奏，使时间表与实际录像一致后再正式录制。

## 7. 失败判定与重拍处理

| 问题 | 先做什么 | 主片如何处理 |
|---|---|---|
| MV首帧、切歌、存储保存等比预算慢 | 保留原始响应，记录实际延迟，核对当前状态和媒体；下一轮给真实等待留足时间 | 功能动作段不加速、不插成功片；调整节奏后完整重拍 |
| 屏幕出现摩尔纹或细字彩纹 | 改拍摄距离/角度与构图，适度减少极细纹理放大；重新检查文字可读性 | 先解决样片，不用强锐化或模糊抹掉功能信息 |
| 屏幕或LED条纹、亮暗横带 | 检查实录文件；试合适帧率/快门、灯光和距离，分别及同时检查屏幕与灯带 | 设置固定后完整重拍；不把条纹当成系统灯效 |
| 调亮屏幕时相机反向压暗，或黑屏后画面自动变亮 | 重设曝光/白平衡锁定，检查HDR/自动FPS与镜头切换 | 亮度对照失去可信度的条目重拍，不逐镜头单独拉曝光“修结果” |
| EC2面板约1.8秒无操作超时 | 先熟记隐藏/选择/调节状态；进入面板后及时完成步骤，不在选择中途停下来读稿 | 未完成就按真实逻辑重新进入；不能用假面板叠图替代；正式条节奏被打断则重拍 |
| 手挡住灯、旋钮、电机或保存指示 | 调整伸手路线、线缆与摆位，短录回放 | 证据被挡无法补看，完整重拍相应连续主片 |
| 60秒内误触/误唤醒 | 记录发生时刻，恢复规定初态 | 本条等待证据失败；重新完整拍摄，不能拼接两段无操作时间 |
| 未确认灯灭、仍有USB反供 | 查清全部供电路径，重新做实际全断电排练 | 不能标冷启动通过；不以复位或隐藏拔插代替 |
| 录音中暂停/静音听不出、原声被旁白盖住 | 查原轨和真实输出音量，降低或撤掉该段旁白 | 原轨缺失时重拍，不用后期静音音轨制造“静音已执行” |
| 超过180秒 | 根据实测T核算200+T→156.5+T；移除重复动作/多余旁白并重排 | 除规定等待段外不加速功能过程，不虚填T |

EOF、异常拔卡、错误恢复、故障码或其他异常路径如需展示，**单独补录并明确标为异常/补充演示**，保留对应原片。不要在主片插入异常补录来假装仍为同一次连续操作。主片中意外发生EOF/错误时，保留失败原片、记录原因，恢复初态后重拍；不覆盖原录像。

## 8. 导出与交付

保留相机原始连续文件及原音轨，再导出带字幕/后期配音的三分钟成片。原片文件、成片文件、实际T、4×的原片入出点、总时长和实际固件/媒体身份写入同一条交付记录。

本项目推荐常规横屏16:9、1080p、MP4/H.264、SDR BT.709交付，编码帧率跟随实际录制帧率；4K30采集时可缩为1080p30。不要通过把30fps标签改成24fps来错误改变播放时长；4×等待段在剪辑时间线上明确设速，保持项目输出帧率一致。

YouTube官方上传建议包括MP4/H.264、保留原始录制帧率，以及SDR使用BT.709；1080p标准帧率参考8Mbps、高帧率参考12Mbps。这里25–30fps可参考8Mbps，50–60fps可参考12Mbps。这是平台压缩建议，**不是竞赛文件规范**；最终先满足比赛的格式、大小和时长要求。[YouTube：推荐上传编码设置](https://support.google.com/youtube/answer/1722171?hl=en)
