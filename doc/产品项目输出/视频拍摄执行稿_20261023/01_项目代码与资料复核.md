## 2. 代码揭示的产品主线

`src/top_tf_hdmi_audio.v`的顶层`top`连接TF SPI、SDRAM控制器、HDMI、用户Flash、实体控件、蜂鸣器、两路灯带与唱针/电机控制。`prj/VinylFPGA.al`指定EG4S20BG256，现有工程采用TD 6.2.168116。不要把工程器件字段当作开发板商品型号的照片证据；实拍应补到实际板卡型号标记。

**内容读取：** TF卡扫描与索引发现内容，封面经BMP解析写入SDRAM，音频与MV按索引定位读取。文件流能沿FAT簇链读取，但根目录发现只读首个512字节扇区；这不等于通用文件管理器。当前最多四曲，不能介绍成无限曲库。

**音频播放：** 卡内是48kHz、16bit、单声道裸PCM。扇区预取经过SDRAM缓存，再进入PCM样本缓冲。实际成功消费的样本推进播放进度，歌词与MV用这条时间主线。暂停冻结媒体时间，Seek重新建立会话和缓存。HDMI左右声道由同一单声道内容映射，不介绍成原生双声道解码。

**画面显示：** 输出有效画布640×480，封面为640×480、24bit未压缩BMP；MV为320×240 RGB565LE、10fps原始帧。MV三缓冲分别保护显示、待显示和写入的帧，按帧边界提交。歌词、标题、艺人来自编译进固件的ROM。最终亮度/对比度在所有可见层合成后处理，因此应拍到MV、文字、参数面板一起变化。

**操作与反馈：** 控件先同步、消抖或解码，再变成统一事件。EC1负责浏览、确认、暂停及±2秒Seek；EC2负责五项参数。屏幕、指示灯、数码管、操作音、双灯带和转盘提供不同反馈，必须区分每一路的因果关系。

**参数持久化：** 用户W25Q64保存VOL、BRI、CON、ROT、WSL五项，采用双槽、CRC16、回读和提交逻辑。自动保存以参数停止变化5秒等条件触发；保存成功三音由真正的提交完成事件触发。这里的用户参数Flash与FPGA配置Flash是不同用途。

**内容制作：** 独立Media Studio导入媒体、整理曲序、校准歌词、生成镜像、回读校验和预览。电脑仅在素材准备阶段参与，运行时播放演示应让电脑与板卡的职责清楚可见。

## 5. 当前操作事实与旧资料冲突

| 事项 | 本次采用的口径 | 对拍摄的影响 |
|---|---|---|
| 扩展KEY1/3 | 浏览上一/下一封面；播放上一/下一曲 | 不拍成±2秒Seek，±2秒用EC1 |
| 扩展KEY4/5 | 浏览上一/下一封面；播放音量加/减 | 不拍成歌词手动翻行 |
| EC2 | 按压进入SELECT，旋转选项，再按进入ADJUST，旋转改值 | 避免按一下就声称切到下一个参数 |
| KEY6 | 最新版五行/当前句专注，旧版无业务 | 不称逐字卡拉OK；根据实际固件选择S15稿 |
| KEY9 | 直切→水平擦入→淡出淡入→直切 | 在浏览页实际换图，不能只按模式键 |
| KEY10 | 只切J2灯带全灭/VU | 唱片灯带和电机继续，不拍成整机灯总开关 |
| KEY11 | 播放页灰底/歌曲虚化/艺术图1/艺术图2 | 每一幅等真实资源就绪，不以灰底回退当艺术图 |

| 遥控F8/EA | F807FF00音量减；EA15FF00音量加 | 声音与OSD数值一起核对 |
| 遥控E6/F2 | E619FF00保存；F20DFF00恢复默认 | 旧表“预留”已失效；码中的反码须正确 |

| 保存提示音 | 当前连续三短音，约105ms，不同于普通按键音 | 只把提交完成后的音效称为成功确认 |
| 抬针 | 关闭电机及唱片灯，音频和进度继续 | 保留声音与时间对照；不声称抬针暂停音乐 |

### 48kHz“测试音”需要单独澄清

生产顶层虽然保留`pcm_media_tone`，但启动、浏览、暂停和未就绪状态通过`audio_silent`送静音，正常播放由PCM优先。**不能因为有音调模块，就在脚本里要求浏览页发出测试旋律。** S06可证明真实音乐经48kHz HDMI PCM链输出；采样率依据工程设置，不能只靠耳朵证明。

若最终赛方逐字要求独立测试音，应补一段同一最终固件下播放已知测试PCM的实机证据。需要时在最终同一媒体镜像内预置对应内容，校对索引和ROM对应关系并重新验收；不临时加载测试固件冒充整合设计。本次只规划，不改媒体卡或固件。未补录前不声称已经完成“独立测试音展示”。
