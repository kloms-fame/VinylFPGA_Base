## 3. 第十六讲对产品包装最有用的方法

### 从需求推导功能

课程主张按“具体使用者与场景 → 用户需要 → 系统能力 → 现场演示动作”组织介绍，而不是从 RTL 模块清单开始。它提出四个检验问题：

1. 谁在使用？
2. 删除这项功能会造成什么实际影响？
3. 用户操作控件时，产品场景是否仍然成立？
4. 画面、声音和状态信息能否追溯到板上内容、输入、时钟或 FPGA 自产数据？

这套方法与 VinylFPGA 的唱片主题本地播放场景相合：用户浏览并选择本地曲目，系统让封面、歌词、进度、波形或 MV 随播放状态呈现，实体输入和灯效补足操作反馈。

### 守住系统数据边界

课程强调预置媒体、板上时钟、板上输入和 FPGA 自产内容与外部实时业务数据不同。VinylFPGA 的代码证据能支撑 TF 卡本地媒体和板上交互，不能由文案推导出联网曲库、实时叫号、路况、温度、工单或远程运营平台。

### 扩展项要讲动机

课程建议把扩展能力放在具体使用价值之后，优先讲清少数有清楚体验动机的功能。对 VinylFPGA，建议主讲“播放进度与歌词/MV联动”和“实体唱片主题交互”，再把转场、画质参数及波形作为体验增强。不要为了覆盖课程中每个扩展名目而把未集成的功能算进来。

## 4. 教学工程与当前项目之间的版本差异

| 课程材料常见表述 | 当前 VinylFPGA 的核对结果 | 对外推荐口径 |
|---|---|---|
| OSD 示例是少量状态字符或通用滚动字幕练习 | 当前有歌词、播放状态、进度和参数图层；当前歌词/标题/艺人由随固件编译的 ROM 提供，不是运行时任意 LRC/通知文件解析 | “ROM 歌词与播放状态叠加显示” |
| 旧完赛线只做亮度调节 | 当前工程有离散亮度/对比度调节与参数 OSD | “亮度、对比度分档调节并显示当前参数” |
| 双线性缩放和缩略图交互作为扩展或练习 | bilinear_8q8.v 文件存在但未进入活动顶层链路；不能据文件存在推断任意尺寸缩放已交付 | 在当前功能卖点中暂不列任意分辨率缩放 |
| WAV 流播示例可直接播放文件 | 当前音频路径按项目规定格式读取 16-bit、48 kHz 单声道 PCM，不解析 WAV 容器头 | “支持项目约定格式的本地 PCM 播放” |
| Flash 固化、上电自启 | 项目 W25Q64 用户 Flash 路径保存五项运行参数；它与 FPGA 配置 Flash 写入及断电上电启动不是同一功能 | “部分播放参数可保存/恢复”；不说“断电续播”或“已证明上电自启” |
| 课程示例 UART 字幕/状态输出 | 当前顶层 UART TX 恒高且已退役 | 不作为现行功能，不宣传串口日志或上位机数据回传 |
| 音频可视化示例可做波形或频谱 | 当前项目显示 PCM 幅度波形/电平，不是 FFT 频谱 | 使用“波形/电平可视化”，不使用“频谱分析” |

## 5. 资料指令与用户请求的边界

课程文件中诸如“必须”“建议”“上板验证”“先做本课练习”“把某模块加入工程”等语句，都是课程作者面向学员的教学说明。用户本次请求是分析 VinylFPGA、形成产品定位与多份 Markdown 报告；这些课程语句不会自动转化成本次需要修改 RTL、重新生成工程、跑板卡或覆盖 SDC 的指令。

赛题原文、课程讲义、课程示例代码和当前工程证据各自承担不同角色。判断当前是否实现某功能，以活动 RTL/工程配置和项目自身验证记录为主；判断赛题要求，以赛题原文与赛事最终通知为主；课程中的场景案例仅用于启发产品表达。
