# 02｜系统架构与模块结构

## 1. 顶层概览

工程顶层模块为 top，定义在 src/top_tf_hdmi_audio.v。顶层连接板级时钟/复位、TF 卡 SPI、外部 SDRAM、HDMI、用户 Flash、拓展板输入输出、母板数码管/LED、唱片电机与灯带。模块职责可归为六个逻辑平面：

1. **时钟与复位：** PLL、跨域复位释放、启动脉冲和域内同步。
2. **媒体控制平面：** 扫描/索引、歌曲浏览、播放状态、Seek、错误恢复和会话隔离。
3. **媒体数据平面：** SD 扇区读、PCM 预取、封面/BMP、MV 帧、SDRAM 读写。
4. **音视频输出平面：** PCM 采样、HDMI 音频适配、像素合成、OSD 和 TMDS。
5. **交互与反馈平面：** 消抖、编码器/红外解码、事件路由、数码管/LED/蜂鸣器/WS2812/电机。
6. **配置持久化平面：** 参数 CSR、SPI Flash 事务、双槽记录和启动恢复。

## 3. 工程入口和配置

prj/VinylFPGA.al 标记顶层 top，目标器件 EG4S20BG256，Family EG4，Tang Dynasty 版本 6.2.168116；工程显式登记 57 个 Verilog 文件（总计 59 个工程文件条目，另含 ADC 与 SDC 约束），并绑定 constraints/pin.adc 和 constraints/timing.sdc。top 源文件另以带保护宏的 include 汇入多个新模块，注释说明此机制用于降低工程列表未回写完整时出现黑盒的风险。src 中有 130 个 Verilog 文件、131 个模块声明；这些统计包含独立仿真/实验/历史模块，不能直接等同于活动设计规模。

工程策略可见 area_prior 映射、高 effort packing、place opt_timing=high、route routability；MultiSeed 启用但当前选择 seed 3、单 seed。只有与最终输入哈希及结果相匹配的 run 报告才可作为该版本物理实现证据。

## 5. 关键时钟域与域间通信

当前 PLL IP、顶层连线与 timing.sdc 对应如下。频率来自 PLL 配置，不是实测时钟精度：

| 时钟 | 当前配置 | 主要职责/源码 |
|---|---|---|
| clk | 50 MHz | 板级输入；UI、参数 CSR 与持久化；SDC 主时钟周期 20 ns |
| sd_card_clk | 100 MHz | SD/媒体控制；sys_pll.v 的 C0；不等同于卡引脚 SPI SCLK |
| ext_mem_clk | 125 MHz | SDRAM 接口与 DMA；sys_pll.v 的 C1 |
| ext_mem_clk_sft | 125 MHz，180° | SDRAM 移位采样；sys_pll.v 的 C2 |
| video_clk | 25 MHz | 像素、PCM 消费与媒体时间；video_pll.v 的 C0 |
| hdmi_5x_clk | 125 MHz | HDMI 串行输出；video_pll.v 的 C1 |

SDC 将 clk、SD、存储和视频组按异步关系处理；video_clk 与 hdmi_5x_clk 保留同步分析，SDRAM 移位时钟另有双向 false path。该约束选择不能代替对 CDC 结构的逐条审查。关键域间关系如下：

| 信号类型 | 常用方式 | 用途/注意点 |
|---|---|---|
| 单比特静态状态 | 双触发器同步，如 sync_2ff/sync_bit | 状态允许延迟，不适合单拍脉冲直接跨域 |
| 单拍事件 | toggle + 目标域同步/边沿恢复 | Seek/请求/完成事件；源侧需保持 toggle 到被观察 |
| 多位稳定数据 | cdc_bundle_latest 或 toggle mailbox | 先锁存 payload，再传事件，目标域采样稳定 bundle |
| 连续流数据 | 异步 FIFO、Gray 指针 | 音频样本、像素/SDRAM FIFO，必须约定满空和延迟 |
| 复位 | 异步断言、同步释放 | 各域独立释放，避免恢复时序不确定 |

跨域模块存在不代表 CDC 已由工具全面证明；最终时序例外应与每条同步/握手结构相符。

## 6. 核心责任链

### 6.1 媒体发现与导航

TF SPI → 卷扫描/根目录发现 → 索引与封面加载 → 媒体元数据 → navigation_readiness → browse_fsm/cover_navigation → 用户确认播放。

### 6.2 音频播放

歌曲 LBA/长度 → SD 扇区预取 → SDRAM DMA 缓存 → 读出 client byte 流 → 16-bit PCM 环形缓冲 → 48 kHz 样本消费 → 音量/淡化/源选择 → HDMI 音频输入。

### 6.3 视频播放

INDEX 元数据 → MV 有效性检查 → 按音频进度调度帧/LBA → SD 扇区读取 → RGB565 解包 → 帧写 SDRAM 三缓冲 → frame_start 提交显示 bank → 背景/歌词/OSD 合成 → HDMI 视频。

### 6.4 参数设置与保存

输入事件 → 参数控制器/CSR，然后分两支：运行参数经快照 CDC 进入视频/音频应用，轮播参数另跨至 SD 域；保存参数在同一 50 MHz UI 域直接进入持久化 FSM → W25Q64 新槽写入 → 回读校验 → 提交记录。CDC 不是 Flash 保存路径的串行前置步骤。

### 6.5 SDRAM 字节通道复用

图像与音频并非全部划分为互不重叠的物理地址区。当前 32 位 SDRAM 字的高 24 位存 RGB888，低 8 位可存音频字节；音频缓存的 1024×512＝524,288 字节映射到前 524,288 个 32 位字的低字节。图像帧区地址与音频字节地址可重叠，但更新的字节通道不同：

~~~text
bit 31                       8 7             0
     图像 RGB888 高24位         音频 byte 低8位
图像写掩码 0001：保护低字节；音频写掩码 1110：只更新低字节
~~~

源码依据：top 的 frame_read_write 设置 PRESERVE_LOW_BYTE=1；audio_sdram_dma 的写数据为 {24'd0,stage_dout}、写掩码为 1110，读回取 [7:0]；audio_sdram_arbiter 给图像写入使用 0001。该复用降低独立缓存地址需求，同时使写掩码保持和写尾排空成为关键契约，不能仅凭物理地址相同判断数据冲突。

## 7. 架构上的优点与代价

**优点：** 功能按数据通路和控制通路拆解；顶层集中展示系统连接；不同外设先封装成请求/有效/完成接口；媒体内容索引与运行时数据面分开；关键跨域通信有专用抽象。

**代价：** 顶层较大且承担大量 glue logic；顶层 include 与工程显式文件列表并存，增加维护和版本回写复杂度；SD/FAT32、视频写共享和多级缓存的状态关系需要跨模块理解；厂商 IP/加密模块使完整仿真依赖 stub 或工具环境。

## 8. 活动文件识别注意

判断文件是否参与产品实现应联合检查：

1. prj/VinylFPGA.al 中 UsedInSyn/UsedInP&R 文件条目；
2. top 中的 include 关系和实际模块实例化；
3. 顶层参数开关及 generate 条件；
4. 运行脚本或 compile file list；
5. 仿真 stub 与被综合厂商 IP 的差别。

src 下文件数、仿真 testbench 数和历史结果目录只代表仓库资产，不代表活动网表全部包含它们。sim/legacy 与多轮资源实验尤其需要按当前引用关系区分。

## 9. 主要依赖关系

- SD/SPI 依赖固定板级引脚约束和 TF 卡数据组织。
- FAT32 文件流依赖卷参数与簇链正确性；索引解析再约束 PCM/MV 的格式与 LBA。
- 音频播放依赖转换后的 PCM 格式，不在 FPGA 内完整解析 WAV 容器。
- MV 依赖离线打包出的 RGB565 连续帧和 INDEX 元数据。
- 显示链依赖 PLL、SDRAM IP、行帧时序、字符/歌词 ROM 数据及像素延迟一致性。
- 持久化依赖 W25Q64 指令/擦除粒度、保留扇区布局与 SPI 时序。
- 可复现物理结果依赖源码、约束、TD 工程策略、seed、工具版本和产物哈希一致。
