# 学习自测题与复盘手册

> 用法：先合上源码回答问题，在纸上画图；再用文末提示核对。答案不要求复述文档，而要能指出当前 RTL 的模块、信号或证据来源。

## 1. 闭卷自测题

3. src 目录里有一个模块，是否足以证明它属于当前构建？还应检查哪些资料？

5. 一个模块卡至少应该记录哪些信息？

### B. 输入与控制链

15. SD 扇区缓存、SDRAM 缓存和 PCM BRAM 缓存分别解决什么问题？
16. 音频欠载时，为何保持采样节奏并输出静音可能比停止整个 HDMI 音频时序更合适？
17. 音频时间基准为何应关注实际样本消费，而不只看计划 tick？

### D. 视频与显示

## 2. 答案检查提示

1. 时钟/复位和接口、媒体控制、媒体搬运、音视频输出、交互/显示、持久化/工程证据；它们是学习视角，不是唯一模块划分。
2. 顶层是集成壳，实例多、连接长；先作为地图并从单链路深入更高效。
3. 看 .al 工程文件、顶层实例、宏/参数配置和约束。
4. 控制流是状态/请求/确认；数据流是扇区字节、样本、像素。切歌控制决定新会话，音频数据流负责搬运新歌 PCM。
5. 职责、调用者、时钟/复位、数据单位、握手、状态异常、缓冲背压、验证证据。
6. 同步消抖/编码器解码 → IO Hub → 事件总线 → 命令路由 → 顶层事件桥 → 浏览/播放控制。
7. 总线负责事件接收/缓存仲裁；路由负责策略和业务码；ui_event_bridge 在 50 MHz UI 源域编码逐类 toggle，并对合并后的编码器计数做差值重放；目标模块再同步/检沿，恢复本域事件。
8. 不是。消抖过滤机械抖动；CDC 处理异步时钟采样风险。
9. SD/SDRAM 事务可能已经在途；取消需要排空迟到响应并保护复用缓存。
10. 前者定位卷、目录、文件和索引；后者以起始地址/长度连续稳定供数。
11. 已准备好的单声道、16-bit 有符号、小端、48 kHz PCM；不是完整 WAV 容器解析。
12. 低字节先保存，高字节到达后拼成高字节与低字节组合的 16-bit 值。
13. 48,000 × 16 ÷ 8 = 96,000 字节/秒。
14. 512 ÷ 2 = 256 样本；256 ÷ 48,000 秒约为 5.33 ms。
15. SD 块级突发缓存；SDRAM 大块延迟/容量缓存；BRAM 采样级双时钟消费缓存。
16. 固定时钟/采样节奏更容易维持音频接口连续，欠载时用静音替代有效样本。
17. 实际消费确认了有效样本离开缓存，媒体时间才能对应已输出的内容。
18. 320 × 240 × 2 = 153,600 字节；153,600 ÷ 512 = 300 扇区。
19. 索引提供媒体区起始 LBA、帧数、格式/帧率信息；当前链路校验为格式号 1、10 fps，再按固定每帧 300 扇区寻址。
20. 数据可能仍在写入流水或等待 SDRAM 返回；必须确认存储完成并在安全帧边界切换。
21. 当前显示、已经写完待显示、正在写入。
22. RGB 是像素内容，DE/VS/X/Y 决定该像素在哪一行/帧/显示窗口；延迟错位会导致颜色或叠加图层偏移。
23. 不能。读模块接口、内部状态/像素通路和顶层连接；当前它偏向调度/窗口/银行控制。
24. 单比特可经同步链降低亚稳态传播；多位各自同步可能得到混合旧/新值，需握手、Gray 编码或原子快照等协议。
25. 双槽保留有效旧记录并提供更新槽；CRC 检查内容完整性；读回/提交确认写入结果后再认定新记录有效。具体实现以 RTL 为准。
26. 用户 Flash 保存应用参数，配置 Flash 保存 FPGA 启动配置；本工程五项 UI 参数不等于保存歌曲位置或断电续播。
27. 仿真验证被建模的行为；物理实现说明综合后布局布线/时序资源状态；bitstream 说明生成了配置文件；实体验收需要真实硬件和对应操作证据。
28. 先看 bench 顶层、DUT 端口、编译脚本/宏和检查内容；历史 bench 可能针对旧版本或部分功能。
29. 不能。应说“本轮只读查看了当前工具状态和仓库已有记录，没有重新运行构建”，并引用历史记录的日期/边界。
30. 说明声音样本怎样由 SD 经缓存按 48 kHz 送 HDMI；MV 帧怎样按媒体时间读取、写入、确认并在安全边界显示；再引用实际已有的 RTL/仿真/物理实现证据并明确其覆盖层级。

## 3. 三种复盘练习

### 60 秒口头复述

任选主题，限时一分钟解释。推荐：

- 从旋钮到选曲；
- 从 INDEX 到一帧 MV；
- 从 PCM 字节到 HDMI 样本；
- 一次 Seek 怎样避免旧数据混入；
- 参数怎样保存到用户 Flash。

如果一分钟内只说出模块名，没有说明数据单位、时钟和完成条件，说明还要回源码补链路。

### 一页纸重画

不打开项目文件，重画系统六面图、音频多级缓存、MV 三缓冲生命周期、一条 UI 事件跨域路径。之后对照 [系统架构](./02_系统架构与模块结构.md)、[音频报告](./03_音频播放链路分析.md) 和 [视频报告](./04_视频与媒体存储链路分析.md) 检查遗漏。

### Feynman 简化解释

假设听众只知道“唱片播放器有声音和画面”，用不超过三句话解释一个难点。例如：

- 音频为什么有多个缓存：SD 卡按扇区成块到货，音频却必须按固定采样节奏消耗，所以缓存把两种节奏隔开。
- 帧为什么不能读完立即显示：SD 读完不代表 SDRAM 写完，未完成的画面如果切到显示端会出现混合帧。
- 为什么有 CDC：事件源和消费逻辑由不同的时钟驱动，需用受控协议让状态安全地跨过去。

## 4. 常见误解清单

- 把收到数据当成下游已提交。
- 把所有缓存当成同一层缓存。
- 把文件系统扫描当成每次媒体播放的全部寻址工作。
- 把音乐时间、视频帧率、HDMI 像素时钟和 SD 读取速度当成同一时钟。
- 把 Gray 指针用于任意多位数据总线。
- 把参数持久化描述成断电续播。
- 把 src 全量模块数描述成当前产品的功能清单。
- 把历史 testbench 结果说成本轮刚跑结果。
- 把完成比赛自动等同于仓库里所有板级证据均已归档。

补充自测：CSR 到运行时显示/音频参数与 Flash 保存，是串行还是并行？答案：并行；CDC 负责运行时域间分发，持久化控制器与 CSR 同处 50 MHz UI 域，保存当前参数快照并在启动时恢复。
