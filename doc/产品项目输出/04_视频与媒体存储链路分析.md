# 04｜视频与媒体存储链路分析

## 1. 两类媒体访问路径

项目将文件发现/文件流装载与运行期连续块访问分开：INDEX 和封面使用 FAT32 文件流；音频、MV 和背景依据元数据及资源布局按连续物理 LBA 读取。background_cache_loader 根据 INDEX 提供的背景基址加固定偏移直接发扇区请求，不沿 FAT32 文件流逐块装载背景。这样把文件系统复杂度限制在必要的发现与装载阶段，把运行期数据面简化为连续块流。

## 2. FAT32 与歌曲索引

~~~mermaid
flowchart LR
  CARD[TF卡 SPI] --> CMD[SD命令/扇区读]
  CMD --> SCAN[FAT32卷与根目录扫描]
  SCAN --> STREAM[FAT32文件流/簇链]
  STREAM --> INDEX[INDEX.BIN校验与song_index_db]
  INDEX --> META[封面 音频 MV元数据]
  STREAM --> BMP[BMP头/像素装载]
  BMP --> SDRAM[封面/图像帧区]
  META --> PLAY[播放数据通路]
~~~

fat32_volume_scanner 读取卷引导信息，计算 FAT/数据区起点、簇大小、根目录簇等参数并发现文件。fat32_file_streamer 按簇链读取数据，检查簇号、范围、EOF、自环与遍历上限。fat32_media_loader 把通用字节流接到 INDEX、封面及其他媒体加载过程。

必须明确扫描范围：当前扫描器只读取根目录簇的首个 512 字节扇区，即最多 16 个 32 字节目录项，按 8.3 短名及指定属性匹配 INDEX/PIC/AUDIO。fat32_volume_scanner 的 ST_ROOT_REQ→ST_ROOT_WAIT→ST_DIR_SCAN 只发起一次目录扇区读取，没有递增到后续根目录扇区或遍历其 FAT 簇链。因此文件流支持簇链，并不等同于根目录发现支持完整 FAT32 目录树；制卡工具必须遵守当前目录布局约束。

song_index_db 定义并检查 INDEX.BIN 记录布局、magic、版本、长度、条目数和 CRC32。索引无效时，加载器保留 PIC1~4.BMP 兼容路径。硬件侧校验索引 CRC32；离线 PC 工具负责资源哈希/资源包校验。MV 字段描述 codec、帧率、帧数和起始 LBA。

封面 BMP 装载流程先取得 SDRAM 写区授权，再开始消费文件流；解析文件头与像素偏移，按 BMP 字节顺序组装 RGB 像素后写入帧区。该先后关系避免文件数据先于写缓存准备完成。

## 3. MV 帧格式与读取

当前索引/注释描述 MV 为 320×240 RGB565 little-endian、10 fps、top-down 行序。一帧在卡上为 153,600 bytes，即 300 个 512-byte 扇区。mv_stream_player 将每个 RGB565 像素扩展成 {RGB888,8'd0}，每帧占 76,800 个 32-bit SDRAM word，对应 307,200 字节的物理字跨度；卡上字节数与 SDRAM 字地址单位不能混用。顶层帧 bank 基址为 1,228,800、1,305,600、1,382,400；四个基础图像 buffer 位于字地址 0 到 1,228,799。图像高 24 位与低 8 位音频通道的复用见 [系统架构](./02_系统架构与模块结构.md)。

读取步骤：

1. MV 元数据从 SD 域经 cdc_bundle_latest 等稳定 bundle CDC 到视频域。
2. s6_video_layer 检查 codec、帧率、帧数、LBA 范围与播放状态。
3. mv_frame_scheduler 根据实际音频样本进度选择目标帧；10 fps 对应 100 ms 帧步进，Seek 目标被限制在有效帧范围内。
4. 视频域将 LBA 与 bank 通过 mailbox 请求给 SD 域 mv_stream_player。
5. 播放器获得帧 SDRAM 写令牌后连续读取 300 扇区，将相邻 RGB565 字节转为像素并写入共享像素写入口。
6. 完成信号需等待 SDRAM 写事务真正完成，而不以最后一个 SD 字节到达为准。
7. s6_video_layer 在 frame_start 边界提交显示 bank；MV 尚未有效时继续显示封面，降低首帧等待造成的黑闪。

~~~mermaid
sequenceDiagram
  participant V as 视频域调度器
  participant S as SD读取器
  participant M as SDRAM帧写
  participant D as HDMI显示
  V->>S: 帧LBA与bank请求
  S->>M: 获得写令牌后写入像素
  S->>S: 连续读取300个扇区并解包RGB565
  M-->>S: 帧写完成确认

  Note over D: 新帧提交前仍显示当前bank/封面
~~~

## 4. 三缓冲调度

三块 bank 可同时承担显示中帧、已写完等待其播放时刻的帧和正在写入帧。调度器必须防止写入 bank 与显示 bank 或待显示帧冲突；不可无限预读未来帧；Seek、暂停、恢复、切歌和会话失效时要取消或清理旧请求。三缓冲的有效性在于给 SD/SDRAM 写入延迟留出缓冲空间，同时仍按音频播放时钟提交画面。

## 5. SD 扇区公平仲裁

音频、MV 和背景读取共享单个 SD 扇区服务链。background_sector_mux 在一个 512-byte 扇区事务期间保持 owner，不在事务中途抢占。音频储备临界时不启动新 MV 事务；正常储备时允许视频取得有限连续配额，报告描述 MV 最多连续 15 个扇区后让出一个服务机会。MV 请求在 busy 期间保持，防止因请求与 busy 互锁导致假接受或被音频持续饿死。

背景读取另受音频储备、缓存填充和播放状态约束。SD 读公平性与 SDRAM 音频/图像读写仲裁属于不同层次，应分别观察。

## 6. 背景缓存和像素读链

background_cache_loader 负责按歌曲/艺术装载背景块；epoch/ack 栅栏用于让旧缓存失效并安全切换读者。background_frame_select 锁存帧级来源和基址。background_raster_address 按栅格推进绝对地址，并限制 burst 不跨越行、源区或 SDRAM 列边界。封面显示链由 frame_fifo_read 从 SDRAM 取像素，并和视频时序的有效窗口、地址延迟匹配。

共享写路径包括封面写入、MV 写入和背景写入等客户端，由 media_write_pipeline 做请求整形和下游连接。SDRAM 地址单位和每个客户端的像素宽度/写长度需保持一致。

## 7. 图像合成路径

HDMI 输出像素时序和位置来自 video_timing_data 等模块。当前顶层实际 RGB 顺序为：帧读/来源选择 → video_transition_apply 转场 → brightness_contrast_steps 亮度/对比度 → 媒体错误背景覆盖 → s6_video_layer → playback_page 歌词/标题/进度等 → promax_audio_waveform 波形 → EC2 参数 OSD → 消隐/Boot 最终优先选择 → video_rgb_to_axis_640x480 → HDMI 发射核心。s6_video_layer 当前 rgb_out=rgb_in，主要承担 MV 调度、窗口与 bank 控制，不能仅因名称推断它额外绘制旋转几何图形。像素链的有效信号、坐标、RGB 与控制元数据必须按每级寄存延迟一致前移。

## 8. 主要难点与亮点

- 文件系统簇链流和固定扇区 MV 数据面采用两种不同策略。
- BMP 文件布局、RGB565 字节顺序和 SDRAM 字地址转换均需严格匹配。
- 多时钟域之间传递完整帧 LBA、bank 和完成状态。
- 写完成确认与 SD 读取完成分离，避免读完就显示未落地帧。
- 三缓冲需保护显示中和待显示帧，兼顾暂停/Seek/切歌生命周期。
- SD 带宽仲裁同时保护实时音频并提供视频前进机会。
- 首帧前封面承接和帧边界提交提升画面连续性。
- 共享帧读写、背景缓存与 HDMI 像素流水线让系统在有限片上资源下复用数据路径。

## 10. 后续维护注意

1. 重新打包 MV 或改变分辨率/帧率时，必须同步更新 INDEX 格式、帧扇区数、写长度和 SDRAM 地址规划。
2. 修改 SD 仲裁时同时验证请求保持、busy owner、扇区边界和音频紧急阈值。
3. 修改三缓冲时明确显示帧、待显示帧、写入帧三种身份及释放条件。
4. 修改共享写/FIFO时检查 write_req_ack、数据有效和真实写完成三个阶段。
5. 修改像素流水时同步延迟 RGB、DE、HS/VS、X/Y 和帧选择信号。
6. 任何新的媒体资源需由打包工具生成，并复核索引 CRC、资源边界及实卡播放。
