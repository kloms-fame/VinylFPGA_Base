# 项目学习地图与先修知识

> 适用对象：已经完成 VinylFPGA 开发、希望真正理解架构并能独立讲解、定位和维护工程的项目成员。
> 阅读关系：先读本文建立地图，再按 [19 代码阅读顺序与核心文件导航](./19_代码阅读顺序与核心文件导航.md) 找源码；逐段理解数据流时配合 [20 核心链路逐段学习手册](./20_核心链路逐段学习手册.md)。

## 1. 学习目标：从看过代码到能解释系统

学完这组材料后，目标不是记住模块名称，而是能独立完成以下任务：

1. 用一张图说明系统从 TF 卡、实体交互到 HDMI、音频输出的主要组成。
2. 对任意一个功能，指出命令从哪里来、数据经过哪些模块、最后由谁消费。
3. 说明关键模块工作的时钟域、输入输出单位、握手和复位行为。
4. 解释暂停、切歌、Seek、SD 卡延迟、音频欠载、视频帧未就绪时系统如何处理。
5. 找到支撑一项工程结论的 RTL、仿真记录或物理实现报告，并说明证据覆盖范围。

项目是一个完整的 FPGA 媒体系统，不适合从某个目录开始逐个文件刷完。更有效的方式是先建立系统地图，再一次追一条链路，沿实例关系和信号关系向前后展开。

## 2. 项目地图：六个逻辑面

从理解角度可以把系统分为六个逻辑面。它们是学习用的分层模型，不意味着工程中每层都由一个独立文件夹或单一模块实现。

| 逻辑面 | 要回答的问题 | 典型代码入口 |
|---|---|---|
| 时钟、复位与外设基础 | 系统有哪些时钟？外部存储器、SD、HDMI、按键如何初始化？ | [顶层集成](../../src/top_tf_hdmi_audio.v)、[安路工程](../../prj/VinylFPGA.al)、[时序约束](../../constraints/timing.sdc) |
| 媒体控制 | 现在选中哪首歌？如何播放、暂停、切歌、Seek？ | [播放控制](../../src/audio/play_ctrl.v)、[浏览状态机](../../src/io/browse_fsm.v)、[Seek 控制](../../src/audio/seek_controller.v) |
| 媒体与数据搬运 | 卡上的文件如何定位？扇区如何进入 SDRAM 和片上缓存？ | [FAT32 扫描](../../src/SD/fat32_volume_scanner.v)、[文件流](../../src/SD/fat32_file_streamer.v)、[索引库](../../src/SD/song_index_db.v) |
| 音视频实时输出 | 怎样把 PCM 样本和像素按时送到 HDMI？ | [PCM 播放器](../../src/audio/wav_stream_player.v)、[MV 调度](../../src/video/mv_frame_scheduler.v)、[视频层](../../src/video/s6_video_layer.v) |

| 持久化与工程证据 | 哪些参数保存？如何证明设计有效？ | [参数 CSR](../../src/io/ui_param_csr.v)、[参数持久化](../../src/io/ui_param_persistence.v)、[Flash 存储](../../src/io/w25q64_param_store.v)、[收尾证据分析](./06_工程实现验证与收尾边界.md) |

学习时还要分清两个贯穿所有逻辑面的视角：

- **控制流**：播放状态、事件、请求、确认、取消、完成、异常。通常由状态机、握手和跨时钟域消息构成。
- **数据流**：扇区字节、PCM 样本、像素、歌词时间戳、参数快照。通常由 FIFO、BRAM、SDRAM、总线或流水寄存器承载。

一项功能往往同时有控制流和数据流。例如播放一首歌：控制流决定开始哪个文件、何时暂停；数据流将该文件的 PCM 从 SD 卡搬到 HDMI 音频接口。

### 2.1 当前工程的时钟地图

| 时钟 | 当前频率/相位 | 主要学习对象 |
|---|---|---|
| clk | 板级 50 MHz | 实体交互、事件编码、CSR、参数 Flash 保存/恢复 |
| sd_card_clk | 100 MHz | SD/媒体控制、音频缓存客户端、MV 扇区搬运 |
| ext_mem_clk | 125 MHz | SDRAM 事务与共享资源仲裁 |
| ext_mem_clk_sft | 125 MHz，180°移相 | SDRAM 硬接口采样相关路径；不是另一套媒体时间 |
| video_clk | 25 MHz | 像素/显示、PCM 消费、歌词/媒体时间、MV 调度 |
| hdmi_5x_clk | 125 MHz | HDMI 串行输出相关逻辑 |

频率来自当前 sys_pll/video_pll 配置与顶层连接。SDC 为不同逻辑时钟组声明了异步关系，并保留 video_clk 与 hdmi_5x_clk 同组分析。读约束时还需检查每条跨域路径的同步/握手结构；异步分组本身不是 CDC 安全证明。

## 3. 建议先具备的知识

### 3.1 Verilog 基础

- 组合逻辑与时序逻辑的区别。
- 时钟沿触发过程的含义，非阻塞赋值的时序效果。
- 参数、位宽、数组、拼接、符号扩展和有符号数。
- 有限状态机的状态、转移条件和输出。
- 同步复位与异步复位的差别。

### 3.2 FPGA 系统概念

- 时钟域：由同一时钟驱动的一组时序逻辑。
- CDC：信号跨时钟域时不能假设目标域立即看到稳定值。
- FIFO：生产者与消费者速率不同或时钟不同的缓存。
- BRAM、SDRAM：片上快速小缓存与片外大容量缓存的用途差别。
- 握手：请求、有效、就绪、完成、错误、取消之间的协议。
- 资源和时序：LUT、FF、BRAM、DSP、时钟周期、建立/保持时间。

### 3.3 媒体基础

- 采样率、位深、声道、PCM 有符号数。
- 小端字节序：低字节先到，高字节随后。
- 像素坐标、行场同步、有效显示区。
- RGB565 与 RGB888 的色彩位宽差别。
- FAT32 的分区、引导扇区、目录项、簇和 LBA 扇区。

遇到不熟的概念时，先在当前模块里找到它的作用，不必暂停整个学习去读完整标准。比如读到 Gray 指针，先理解它用于跨域传递 FIFO 读写位置，再回头补 Gray 编码的数学性质。

## 4. 最重要的理解框架

每次读一个模块，都用同一张模块卡片回答八个问题：

1. **职责**：它只解决哪一个问题？它明确不负责什么？
2. **调用关系**：谁实例化它？它又依赖哪些子模块？
3. **时钟与复位**：工作在哪个时钟域？复位有效极性和释放条件是什么？
4. **数据单位**：接口传的是字节、扇区、样本、像素、坐标、毫秒还是参数值？
5. **握手协议**：请求何时有效？下游何时接收？完成信号表示哪个阶段完成？
6. **状态与异常**：暂停、取消、超时、欠载、卡错误时怎样恢复？
7. **缓冲和背压**：缓存在哪里？满或空时谁等待、谁丢弃或降级？
8. **证据**：有没有针对该行为的 testbench、历史结果或物理实现约束？

至少要看接口声明、状态机主干、关键计数器/指针、数据入队和出队、错误恢复，以及调用者如何解释输出。不要把每一行注释都当成当前实现事实；优先以当前工程实际纳入的 RTL 和顶层连接为准。

### 4.1 已填示例：wav_stream_player 模块卡

| 项目 | 当前实现与阅读锚点 |
|---|---|
| 职责 | 通过扇区客户端接口取得 PCM 字节，拼成 16-bit 样本写入双时钟缓存，按读侧节拍提供样本；不解析 WAV 文件头。 |
| 调用者 | 顶层 u_wav_stream_player；扇区客户端连向 u_audio_prefetch_sdram，输出连向音量/混音链。 |
| 时钟/复位 | 写侧 sd_card_clk=100 MHz / sd_media_rst_n；读侧 video_clk=25 MHz / media_video_rst_n，均低有效复位。 |
| 数据单位 | sd_byte 为 8-bit 字节，sd_byte_index 为扇区内字节编号；sample_out 为 16-bit 有符号 PCM；start_lba 为 512B 扇区地址。 |
| PCM 缓存 | 当前 ADDR_WIDTH=12，4096×16-bit；低字节暂存到 lo_byte，高字节到来时写入 {sd_byte,lo_byte}。 |
| 缓存供数门槛 | buffer_available 要求至少一个扇区的样本量，或文件已结束且仍有尾样本；不能将“非空”直接当作所有状态下都允许读。 |
| 实际消费 | buffer_read = rd_rst_n && sample_tick && sample_ready && buffer_available；sample_consumed 直接等于 buffer_read。顶层把它送到 timebase_48k，而非把所有计划采样 tick 都算成媒体时间。 |
| 欠载 | 采样节拍和 ready 到来但无有效缓存数据时输出静音，已启动后可产生 underrun_pulse；没有真实 buffer_read 就不计作有效样本消费。 |
| 写侧水位 | WS_DONE 在 level_wr≥3072（3/4）时进入 WS_WAIT；WS_WAIT 在 level_wr<3072 时恢复请求。2048（1/2）仅用于 buffer_low 标志，不是暂停后的恢复阈值。 |
| CDC | 读写指针经 Gray 编码同步；播放使能、完成/故障等状态也有同步路径。读写两侧观察到的缓存水位带同步延迟。 |
| Seek | skip_samples 丢弃首扇区前若干样本，valid_samples 限定有效长度；sample_base 用于重启后的样本位置。 |
| 证据入口 | sim/audio_cache/tb_wav_startup_ready.v；先核对 DUT 接口、编译输入和检查项，再使用归档结果。 |

读懂这张卡后，再尝试独立为 mv_stream_player 填一张。卡片以模块实例和信号名定位，避免把固定行号当成唯一入口。

## 5. 第一次接触工程：前 30 分钟

### 第 0–5 分钟：确定工程入口

打开 [文档导航](./00_文档集导航.md)、[项目总览](./01_项目总览与价值分析.md) 和 [系统架构](./02_系统架构与模块结构.md)。在 [安路工程文件](../../prj/VinylFPGA.al) 中确认工程顶层、器件和源文件组织。

### 第 5–10 分钟：认出顶层边界

打开 [top_tf_hdmi_audio.v](../../src/top_tf_hdmi_audio.v)。先看模块端口、include、时钟和复位生成、外部 SD/SDRAM/HDMI 接口，以及主要模块实例。此文件是集成壳，不要从第一行连续读到末尾。

### 第 10–20 分钟：在纸上画五个盒子

画出 TF 卡和 FAT32/索引解析、SD 扇区服务与 SDRAM、音频 PCM 缓存与 HDMI 音频、视频帧缓存/图层与 HDMI 像素、按键/旋钮/红外到播放控制和参数保存。暂时不确定的地方标问号，不追细节。

### 第 20–30 分钟：选一条最容易验证的链路

从旋钮事件或 PCM 缓存读出开始。先理解单个模块，再沿实例关系追到上下游。每条链路都记录起点、终点、关键缓存、时钟域和异常行为。

## 6. 学习的主干与支路

推荐主干顺序：

1. 文档和工程入口；
2. 时钟/复位、顶层实例关系；
3. 用户输入事件；
4. FAT32 和歌曲索引；
5. PCM 样本缓存与音频输出；
6. SD 预取、SDRAM DMA 和切歌/Seek 生命周期；
7. 静态封面和显示时序；
8. MV 帧调度、写入完成与三缓冲；
9. 显示合成与 HDMI 输出；
10. 参数跨域与 Flash 持久化；
11. 仿真、实现报告和证据边界。

有两个合理的分支：

- 若你更熟悉媒体文件，先学 SD/FAT32/索引，再回到控制状态机。
- 若你熟悉数字逻辑但不熟文件系统，先学 wav_stream_player 和按键事件，再进 FAT32。

无论从哪条支路开始，都要回到顶层把模块重新接起来，否则容易只学会局部模块，无法解释产品。

## 7. 当前工程学习时必须保留的边界

- src 中的文件数量不能直接等同于当前产品功能数量。通过 .al 工程源文件、顶层实例、宏定义和约束判断当前构建路径。
- 文件名含 WAV 不等于模块会解析 WAV 文件头。本工程音频链路面向已准备好的单声道、16-bit、有符号、小端、48 kHz PCM 流。
- SD 卡读取完成、SDRAM 写完成和视频帧可显示是三个不同事件。
- 仿真通过、综合/布局布线通过、bitstream 生成和实体板长时间运行是不同层级的证据。
- 课程资料和历史设计说明可能对应旧版本；用它们学习原理时，回到当前顶层实例核实映射。

第一遍只需要说清楚六个逻辑面；第二遍按主干顺序打开源码；第三遍完成 [21 阶段学习计划与实践任务](./21_阶段学习计划与实践任务.md) 中的任务；最后使用 [22 学习自测题与复盘手册](./22_学习自测题与复盘手册.md) 做闭卷复述。
