## 1. 技术选型

| 项目 | 当前工程依据 | 选择带来的能力与代价 |
|---|---|---|
| FPGA | 安路 EG4S20BG256，Family EG4 | 适合并行视频/存储控制；BRAM9K 和 Slice 余量有限，需要物理收敛 |
| EDA | Tang Dynasty 6.2.168116 | 完成综合、布局、布线、时序和 bitgen；工程/回标文件会被 GUI 改写 |
| RTL | Verilog HDL，多模块/参数化实现 | 可直接控制硬件时序；层级复杂且需严格处理 CDC 和厂商仿真模型 |
| 媒体卡 | TF 卡 SPI + FAT32 子集 | 易替换媒体；受卡速、碎片化、SD 时序和介质故障影响 |
| 图像/音频缓存 | 外部 SDRAM + FIFO/片上 BRAM | 适配连续视频和 PCM；增加仲裁和时延管理复杂度 |
| 媒体索引 | INDEX.BIN 固定字段及 CRC | 提供硬件端快速访问和连续 MV 地址；需 PC 打包器与 FPGA 格式保持一致 |
| 音频格式 | 48 kHz/16-bit/signed/单声道 PCM | 硬件流简单；素材转换成为交付前置条件 |
| 视频格式 | 320×240 RGB565LE，10 fps 连续帧 | 无需片上通用解码器；需要较高 SD/SDRAM 吞吐与准确 LBA 元数据 |
| 参数存储 | 独立 W25Q64 SPI Flash | 具备非易失配置保存；要求槽位、擦写、校验和掉电策略可靠 |
| 仿真/工具 | Icarus、ModelSim、Python/PowerShell、TD | 多层验证和素材生成；不同仿真器与 PowerShell 版本存在兼容差异 |

## 2. 实现策略

### RTL 分层

外设协议/流接口、业务控制器、缓冲/仲裁、像素/PCM 输出各自拆模块。top 负责 glue logic 和 CDC 接线。部分子模块用 include guard 被 top 包含，同时也以独立文件加入 TD 工程，以适配独立仿真与 GUI 工程列表差异。

### 时序与资源

代码可见的实现方法包括：同步输入与分域复位；多位稳定 payload 搭配 toggle/bundle CDC；DMA 分块让出周期；SD/SDRAM 水位与配额仲裁；帧边界寄存/提交；像素运算用移位加法和饱和裁剪；时间/进度等运算移出像素高频活动路径；共享字体 ROM；RGB888 高 24 位与音频低 8 位复用 SDRAM 字，并以互补写掩码保护数据。

### 物理配置

当前 prj/VinylFPGA.al 显示 area_prior 映射、pack_effort=high、place opt_timing=high、route effort=routability，选择 seed 3。物理结果具有 seed 和布局相关性，必须使用同一源码/约束哈希和最终 run 报告进行比较。

## 5. 风险和未覆盖边界

1. **资源余量：** BRAM9K 64/64，Slice 使用率约 94.7%；新增功能或不同 seed 可能导致布局/布线困难。
2. **I/O 时序模型：** timing.sdc 与收尾记录指出 SD MISO、HDMI 转发时钟/数据等板级延迟模型存在缺口；不应以虚构约束掩盖。
3. **实体媒体差异：** TF 卡容量、品牌、碎片化、文件布局和持续读性能未由有限仿真覆盖。
4. **旧测试维护：** 13 个历史失败需文档化其过时接口/预期，并决定维护、替换或退役；当前不能宣称所有 testbench 全绿。
5. **ROM/SD 卡资源同步：** 该次收尾记录生成并校验了歌词 ROM 新资源，但未据此重写物理 SD 卡/完整镜像；交付镜像应核对实际使用的资源版本和打包结果。
6. **工具链工作区副作用：** 本轮开始时 prj/.lock.f 和 prj/out/back_annotation.adc 已有修改；TD GUI 或脚本可能继续改写项目/回标文件。
7. **厂商 IP 仿真边界：** 部分验证使用 vendor stub；不能由 stub 仿真推导真实 HDMI PHY、SDRAM 控制器全行为。
8. **注释和文档漂移：** 阶段方案中有被后续决定替代的交互规划，以及顶层旧“预留”注释，需要逐项以当前 RTL 复核。
9. **运行目录固件身份：** 当前两份 Runs bit 与固定验收归档哈希不同，来源待核；交付与后续复验以固定归档和实际文件哈希为准。

## 6. 成果归档与后续复验建议顺序

用户的开发和完赛状态已确认。以下顺序用于补齐成果档案及以后版本复验；已有实板材料可直接归档引用，不应仅因该次仓库记录缺项就要求重复所有工作。

1. 固定交付源码快照，记录 Git commit/工作区差异、工具版本、约束和工程哈希。
2. 归档已有冷启动和全功能板测材料，记录板卡、TF 卡、实际固件 SHA、步骤和观察结果；如后续复验，优先使用固定 accepted_artifacts bit。
3. 完整播放每首曲目并覆盖切歌、暂停、反复 Seek、EOF/循环、MV首帧、SD延迟/恢复、歌词快句/末句。
4. 验证用户 Flash 冷启动恢复、保存中复位/掉电、CRC 错误回退和参数范围边界。
5. 检查电机、灯带供电/温升/启动逻辑及蜂鸣器硬件开关条件。
6. 补齐真实 I/O 延迟信息后复核 SDC；将遗留失败 bench 分类维护，确保新用例针对当前接口。
7. 生成最终交付清单：工程、bit/bin、源码快照、SD 素材/镜像、歌词资源、哈希、板测记录、按键表、烧录步骤和故障恢复说明。
