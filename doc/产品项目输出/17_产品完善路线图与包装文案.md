# 17｜产品完善路线图与包装文案

> 分析日期：2026-10-19。本文给出竞赛作品向工程样机/展示产品演进的建议，并提供可直接调整的对外介绍文案。路线图是分析建议，不表示本次已经修改 RTL 或完成未验证功能。

## 1. 产品演进建议

### P0：固化竞赛交付基线

**目标：** 让当前完赛成果容易复核和复现。

- 固定源码、TD工程、生成bit及SHA-256之间的版本关系；既有验收结论对应固定 `accepted_artifacts` 备份，当前 Runs bit 的哈希差异应按 [16 的身份核对](./16_产品效果指标与证据边界.md#21-最终归档与当前-runs-文件的身份核对) 记录，不能按同名文件认定版本相同。
- 归档赛事提交版本、现场演示录像/照片、开发板型号和媒体卡内容。
- 准备一份按实际接线绘制的功能图和真实控件映射。
- 标记“RTL已实现、仿真有覆盖、TD已实现、bit已生成、现场已演示”各自状态。
- 说明13项历史S7失败的基线关系及当前版本覆盖，不把旧记录从归档中删除。

**完成标准：** 外部读者能从一份索引找到当前工程版本、竞赛演示材料和每条结论的证据。

### P1：完善工程样机的媒体体验

**目标：** 减少素材准备和格式错误对演示的影响。

- 将音频输入格式、采样率、位宽、声道、文件长度和索引字段写成正式媒体规范。
- 整合并完善现有 `vinyl_packer.py`、`mv_pack.py`、`pack_backgrounds.py` 和 `prepare_s3_lyrics.py` 等工具，形成统一入口、输入检查和使用说明；明确媒体卡更新与文字 ROM/固件更新的不同步骤。
- 对无卡、索引无效、曲目文件缺失、数据读取失败和曲目切换中断提供明确提示与恢复路径。
- 维护 [当前支持格式/分辨率/四曲上限与 ROM 更新边界清单](./13_产品定位与目标用户及场景分析.md#8-当前版本规格与内容更新边界)，并用它约束演示素材。

**完成标准：** 团队成员可独立制作一张合规TF卡，并判断失败来自素材、卡片还是设备。

### P2：提升现场演示和操作一致性

**目标：** 让观众不依赖开发者口头指导也能完成主要流程。

- 固定开机后的首页、曲目浏览顺序和恢复到主演示状态的方法。
- 给旋钮、按键、遥控和扩展板制作可读标识；更新过时注释和用户说明。
- 为播放、暂停、切歌、Seek、参数调节和异常状态统一视觉反馈。
- 为灯带与外部电机定义供电、驱动、接插件、保护和失效处理方案；明确FPGA只提供使能逻辑。
- 设计桌面支架/外壳和线材整理，并评估散热、搬运和可维护性。

**完成标准：** 首次体验者能按卡片完成播放，不误把主题反馈当作主链路故障。

### P3：扩大媒体能力与产品兼容面

**目标：** 根据目标用户价值决定是否扩展，不为功能数量扩展。

- 若目标是家庭音乐播放，优先评估更多曲目容量、播放列表和更易操作的素材导入流程。
- 若要支持WAV等常见容器，增加容器头解析并建立位宽/采样率/声道转换规则。
- 若素材分辨率变化是刚需，集成缩放链路、定义目标画布与采样质量，并实测资源/时序代价。
- 若需要在线或远程更新，先选定上位机/网口协议、数据校验与失败恢复，不把已退役UART作为现成功能。
- 若需要断电续播，单独设计曲目、进度和播放状态记录，并测试掉电时的原子更新与恢复。

**完成标准：** 每个新增能力都有明确的目标用户、输入规范、资源预算、验证用例和维护责任。

### P4：建立产品级验证

**目标：** 为“长期使用”“兼容”“低功耗”等承诺提供证据。

执行上一份文档提出的上电时间、欠载率、音画误差、输入响应、参数掉电恢复、温升/功耗及用户可用性测量。不同显示器、卡片、素材和供电条件分别记录，避免由一次成功演示推导普遍结论。

**完成标准：** 每个对外产品承诺都能对应到测试方法、阈值、样本范围和结果记录。

## 2. 建议的产品路线优先级

| 优先级 | 事项 | 原因 |
|---|---|---|
| P0-A | 竞赛交付与最终bit证据归档 | 直接提高成果可复核性 |
| P0-B | 媒体格式和控件说明 | 降低现场准备失败和操作歧义 |
| P1-A | 现有媒体打包/生成工具的统一入口、校验与说明完善 | 降低当前素材准备和卡片/ROM/固件版本对应的使用门槛 |
| P1-B | 一键复位演示状态与明确错误反馈 | 提高展示可控性 |
| P2-A | 外壳、接口标识、散热和供电管理 | 从裸板演示走向可拿取的样机 |
| P2-B | 更多格式、曲目和缩放 | 由用户需求与资源预算决定，避免盲目扩大范围 |
| P3 | 实时数据、联网或行业场景适配 | 需要新增接口和额外验证，不能只修改包装文案 |

## 4. 30秒项目介绍

> VinylFPGA 是一套唱片主题的 FPGA 本地音乐画屏原型。用户从 TF 卡浏览项目约定格式的曲目并启动播放，系统把 PCM 音频、专辑画面、歌词和播放状态组织在同一条体验里，并提供波形、实体控制和唱片主题灯效。工程重点是让本地存储、实时音频供数、视频帧调度和交互输入在安路 FPGA 上协同工作。它既是一件可演示的多媒体作品，也是一套完整的 FPGA 系统集成案例。

## 5. 90秒答辩介绍

> 我们的作品叫 VinylFPGA，定位为唱片主题的 FPGA 本地音乐画屏。我们选择桌面音乐展示场景，因为用户真正看到的是一次完整播放：从本地 TF 卡浏览曲目，进入播放后显示专辑画面、歌词和播放位置，同时输出音频，并可呈现 MV 或 PCM 波形。
>
> 工程由媒体读取和索引、音频缓存与输出、视频帧调度、显示叠加、人机交互和参数保存等部分组成。核心难点是让不确定延迟的存储访问服务连续音频与视频消费者，并在不同的时钟域之间安全传递播放状态和控制信息。播放样本时基用于推进相关显示状态，SDRAM帧缓存和资源仲裁负责组织视频数据。
>
> 作品的特色是把唱片主题的实体操作和 FPGA 多媒体链路结合起来。我们会区分源码、仿真、TD物理实现和现场板上展示的证据范围；当前媒体格式和曲目规格也会明确说明。VinylFPGA展示的是一套已经完成竞赛开发的系统工程原型，也为后续的媒体兼容、易用性和样机包装留下扩展方向。

“竞赛开发已完成”来自用户提供的完赛事实；具体比赛名次、商业成熟度或对比性能不包含在这段介绍中。

## 6. 展板/摘要文案建议

**作品简介：**

> VinylFPGA 面向桌面音乐展示体验，基于安路 FPGA 构建本地媒体读取、PCM音频输出、视频显示与实体交互系统。用户可以浏览并播放 TF 卡中的项目规格媒体，查看封面、歌词、播放进度、MV或波形，并通过实体输入控制播放与显示。项目围绕音频连续供数、存储仲裁、视频帧调度和多时钟域协同开展设计，呈现唱片主题与 FPGA 实时多媒体系统工程的结合。

**核心特点：**

- TF 卡本地媒体浏览与播放。
- 播放进度驱动歌词/状态显示。
- HDMI音视频输出与视频帧缓存。
- 唱片主题实体交互、灯效及参数控制。
- 面向 FPGA 多媒体系统集成的完整工程案例。

**技术标签：** 安路 EG4S20、Verilog、FAT32、SPI、SDRAM、PCM、HDMI、CDC、流缓存、时序约束。
