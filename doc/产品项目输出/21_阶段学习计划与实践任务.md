# 阶段学习计划与实践任务

> 计划按阶段而非固定日历安排。每一阶段可拆成 1–3 次专注学习；如果某一步不能脱离资料复述，就先补齐再继续。

## 1. 学习原则

- 每次只攻克一个可解释的功能闭环。
- 先理解端口和单位，再读状态机和内部细节。
- 优先从消费者或顶层实例找到边界，之后沿一个信号向前后展开。
- 每阶段都产出一张图、一页模块卡或一段口头解释。
- 仿真和构建属于验证活动。本学习计划以读取现有 testbench/结果为主；本轮没有重跑构建或测试。

## 2. 七阶段主计划

### 阶段 0：项目定位和先修补齐

**目标：** 搭起心智地图，识别自己需要补的基础知识。

**阅读：**

- [项目总览](./01_项目总览与价值分析.md)
- [系统架构](./02_系统架构与模块结构.md)
- [学习地图](./18_项目学习地图与先修知识.md)
- [工程入口](../../prj/VinylFPGA.al)

**实践任务：**

1. 关掉文档，画六个逻辑面。
2. 写出 PCM、LBA、RGB565、帧 bank 的含义。
3. 列出你暂时不清楚的 HDL 概念，例如 FIFO、CDC、非阻塞赋值。

**完成标志：** 能用 2 分钟说明产品从本地媒体到 HDMI 的大概路径，并知道顶层 RTL 和 TD 工程文件在哪里。

### 阶段 1：工程入口、时钟和顶层地图

**目标：** 能进入源码并正确识别模块、时钟、reset 和当前工程边界。

**阅读：**

- [代码阅读导航](./19_代码阅读顺序与核心文件导航.md)
- [top_tf_hdmi_audio.v](../../src/top_tf_hdmi_audio.v)
- [时序约束 SDC](../../constraints/timing.sdc)
- [引脚约束 ADC](../../constraints/pin.adc)

**实践任务：**

1. 在顶层找 SD 卡、SDRAM、HDMI、音频、视频、输入/参数的实例。
2. 为每个实例记录时钟和复位。
3. 用实例树列出 10 个核心模块及其直接调用者。
4. 在 .al 工程文件中核对这些模块是否属于实际工程输入。

**完成标志：** 能说明“目录里有这个源码”和“当前工程使用这个模块”不是同一件事。

### 阶段 2：控制流与用户交互

**目标：** 能解释一个旋钮步进如何变成选曲、暂停或参数变化。

**阅读：**

- 消抖、正交编码、IR 解码；
- expansion_io_hub、ui_event_bus、ui_command_router、ui_event_bridge；
- browse_fsm、cover_navigation、play_ctrl。

**实践任务：**

1. 选择一个事件，建议编码器步进。
2. 从物理输入追踪至业务状态机。
3. 标出事件载荷、时钟域、每个阶段是否缓存/仲裁。
4. 对照 [tb_browse_fsm.v](../../sim/tb_browse_fsm.v) 或 [tb_debounce_bank.v](../../sim/tb_debounce_bank.v) 阅读一个状态或消抖场景。

**完成标志：** 不看代码能画出输入到播放控制的方框图，并解释事件跨域的做法。

### 阶段 3：媒体定位、FAT32 与最小音频闭环

**目标：** 理解如何从文件系统信息得到媒体地址，以及一个 PCM 样本如何到输出。

**阅读：**

- sd_card_cmd、sd_card_sec_read_write、sd_card_top；
- fat32_volume_scanner、fat32_file_streamer、song_index_db、fat32_media_loader；
- wav_stream_player、timebase_48k。

**实践任务：**

1. 画“扫描/索引装载”和“连续音频播放”两条不同路径。
2. 说明文件簇读取与连续 LBA 流的区别。
3. 从播放器写入侧追踪两个 PCM 字节的拼接，再追踪读侧有效消费。
4. 阅读 [tb_fat32_volume_scanner.v](../../sim/tb_fat32_volume_scanner.v)、[tb_fat32_file_streamer.v](../../sim/tb_fat32_file_streamer.v) 或 [tb_song_index_db.v](../../sim/tb_song_index_db.v) 中的输入条件与检查。
5. 解释 48 kHz、16-bit mono 数据率和 512B 扇区覆盖时长的计算。

**完成标志：** 能区分“PCM 文件格式准备”与“RTL 播放器解析 WAV 容器”的责任边界。

### 阶段 4：音频稳态、缓存、切歌和 Seek

**目标：** 能解释为何使用多级缓存，以及如何保护实时消费免受 SD 延迟影响。

**阅读：**

- [音频预取](../../src/audio/audio_prefetch_sdram.v)
- [音频 DMA](../../src/audio/audio_sdram_dma.v)
- [SDRAM 仲裁](../../src/audio/audio_sdram_arbiter.v)
- play_ctrl、seek_controller、stream_session
- 配套音频报告 [03 音频播放链路](./03_音频播放链路分析.md)

**实践任务：**

1. 分别画出 SD 扇区缓存、SDRAM 音频缓存和 PCM BRAM 缓存。
2. 为每级缓存写出输入速率、输出速率、粒度和时钟域。
3. 写一张切歌时序：旧 SD 请求仍在途时，新会话如何避免复用冲突。
4. 阅读 [tb_audio_prefetch_sdram.v](../../sim/audio_cache/tb_audio_prefetch_sdram.v)、[tb_audio_dma_late_return.v](../../sim/audio_cache/tb_audio_dma_late_return.v) 或 [tb_wav_startup_ready.v](../../sim/audio_cache/tb_wav_startup_ready.v)；先确认 bench 对应当前接口和预期，再解读检查项。

**完成标志：** 能说清楚 SD 完成、SDRAM DMA 完成和 PCM 消费分别代表什么。

### 阶段 5：视频帧、显示合成和媒体时间

**目标：** 从 MV 元数据追到完整帧写入、帧提交、帧读出和 HDMI 像素。

**阅读：**

- mv_frame_scheduler、mv_stream_player、s6_video_layer；
- media_write_pipeline、帧读写/FIFO、视频时序；
- 顶层播放页、歌词、波形、亮度/对比度和 HDMI AXIS 输出部分；
- 配套报告 [04 视频与媒体存储链路](./04_视频与媒体存储链路分析.md)。

**实践任务：**

1. 按 320×240、RGB565、512B 扇区计算单帧字节数和扇区数。
2. 画出“SD 收到最后一个字节”到“帧可显示”之间的确认步骤。
3. 画三缓冲中显示、待显示、写入中的 bank 生命周期。
4. 追踪一个像素：坐标/同步 → 背景或帧数据 → 图层/效果 → HDMI AXIS。
5. 阅读 [tb_mv_frame_scheduler.v](../../sim/tb_mv_frame_scheduler.v)、[tb_mv_stream_player.v](../../sim/tb_mv_stream_player.v) 或 [tb_s6_video_layer.v](../../sim/tb_s6_video_layer.v)。

**完成标志：** 能说明 MV 帧调度如何跟随媒体时间，并区分 SD、SDRAM 和显示边界。

**阅读：**

- ui_param_csr、ui_param_persistence、w25q64_param_store、nvm_spi_transaction；
- [工程验证与收尾边界](./06_工程实现验证与收尾边界.md)

**实践任务：**

1. 列出五项持久化参数，画出 CSR 的并行分支：运行时 CDC 与同一 50 MHz 域内的 Flash 保存/恢复。
2. 画 Flash 双槽记录写入、CRC/读回、提交的事务图。
3. 将一项功能对应到 RTL、仿真、物理实现、bitstream、实物五类证据中的实际层级。

### 两个可以直接照做的只读练习

**练习 A：追一个 PCM 样本。** 打开 wav_stream_player，搜索 lo_byte、lo_pending、buffer_write、buffer_read、sample_consumed，再到顶层搜索 u_timebase_48k。假设正在 WS_FILL、skip_cnt=0、remaining>0，先到 sd_byte=8'h34，下一有效字节为 8'h12：写出两次边沿的寄存器变化，指出写入的样本及其地址。再假设读侧 buffer_available=1、sample_tick=1、sample_ready=1，说明何时读指针和媒体时间推进。最后把 buffer_available 改为 0，解释静音与媒体时间的差别。

验收答案：首字节保存到 lo_byte，第二字节令 buffer_write 成立，写入 16'h1234（有符号值 +4660）并推进 wr_ptr；满足 buffer_read 才读出有效样本并产生 sample_consumed。timebase_48k 还要求 running，48 个有效消费累计 1 ms。欠载输出静音不构成真实消费。注意同步读 RAM 和寄存器的非阻塞赋值，画出取样沿之后的数据更新，不把所有组合/寄存器事件画成同一时刻。

**练习 B：追 EC1 顺时针一步。** 打开 ui_event_bus，搜索 EV_ENC_STEP；再读 ui_command_router 的透传/策略条件及 ui_event_bridge 的 is_enc1_step、enc_target、enc_delivered、emit_encoder、seek_fwd2_tgl。在允许路由、无消隐唤醒吞键、无其他事件竞争的条件下，设 EC1 累计计数从 N 变为 N+1、direction=0，写出事件的 code/arg/aux；追踪它怎样成为源域 toggle，再定位 browse_fsm 和 seek_controller 的接收同步及状态门控。

验收答案：事件码 EV_ENC_STEP，arg 为最新 enc1_count，aux[1]=0 表示 EC1、aux[0]=0 表示顺时针；桥将累计计数作为目标，利用 enc_delta 重放尚未交付的步数，发出之间至少隔开八个源时钟。正向步会翻转 next_tgl 与 seek_fwd2_tgl；是否实际选下一首或执行 +2 s Seek，由目标业务状态决定。不能将“一个步进事件”简单理解为无条件切歌，也不能假设跨域桥自动保证任意速率下事件都不丢失。

这两项练习只需要阅读源码和画时序；如后续要仿真，先核对当前 bench、宏和编译脚本，单独记录新增验证结果。

## 3. 每阶段的学习节奏

建议每个阶段按这四步完成：

1. **预览 10 分钟**：读相关文档目录、模块端口和调用者。
2. **深读 30–60 分钟**：追一个信号/事务，不试图一次读完所有分支。
3. **闭卷复述 10 分钟**：画图并用自己的语言讲解。
4. **隔天回忆 5–10 分钟**：不打开源码，重画链路，再查遗漏。

间隔复习可按首次学习后第 1、3、7、14、30 天进行。每轮只复习核心图、模块卡和自测错题即可。

## 4. 练习题难度阶梯

- **初级**：识别模块端口、时钟、复位、单位。
- **中级**：沿请求/数据/完成信号跟踪调用者和消费者。
- **进阶**：解释 CDC、背压、取消/迟到响应和缓存水位策略。
- **专家**：根据新需求判断影响面、列出验证场景和可能的证据缺口。

可从 [22 学习自测题与复盘手册](./22_学习自测题与复盘手册.md) 自测。先用问题检查自己的解释，再查看提示。

## 5. 防止学习误区

- 不以读过多少文件衡量进度，以能否画出并解释链路衡量。
- 不因为有 testbench 就假定它覆盖了板级和长期运行。
- 不因为本轮没有跑构建，就把历史收尾报告说成刚刚验证。
- 不把历史 bench 的接口直接当成当前产品接口。
- 不在第一轮深挖 SPI 命令或 SDRAM 时序细节；先理解系统为何发起事务、数据流向哪里。
- 遇到未连接的辅助/实验模块，记为储备或历史实现；以当前工程配置判定产品范围。

## 6. 最终毕业任务

独立完成一份单页“VinylFPGA 讲解卡”：

- 产品一句话定义；
- 系统六面架构图；
- 音频样本链路和 MV 帧链路各一条；
- 旋钮或按键控制链路；
- 3 个关键缓存及其职责；
- 3 个工程难点及对应 RTL；
- 2 个本仓库已有证据和 1 个尚需定位或归档的证据；
- 赛题方向与功能实现的对应关系。

可对照 [产品定位](./13_产品定位与目标用户及场景分析.md)、[赛题矩阵](./09_赛题要求与项目实现矩阵.md) 和 [证据边界](./16_产品效果指标与证据边界.md) 完成。若能不靠照读文档讲完并回答追问，说明项目理解已形成结构。
