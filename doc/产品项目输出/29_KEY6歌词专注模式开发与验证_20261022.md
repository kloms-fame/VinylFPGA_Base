# 29｜KEY6 歌词专注模式开发与验证（2026-10-22）

用户在原冻结版本基础上明确批准新增“五行 / 单句专注”切换，并要求原 `prj/VinylFPGA.al` 能够完整生成 bit。旧冻结报告及人工验收结论对应原固件，本次增量另行记录。

## 行为与操作

| 控件 | 端口 / 引脚 | 新行为 |
|---|---|---|
| SW9 / KEY6 | `exp_key_n[5]` / H1 / J2.18 | 播放页面切换“五行歌词 / 当前句专注显示” |

上电默认五行；单句专注隐藏前后句，保留当前句金色高亮和原有换句滚动位置。再次按下恢复五行。模式在下一帧开始时统一生效，避免同一帧内出现两种显示。模式跨暂停、曲目和页面切换保留，系统复位恢复默认；没有增加 Flash 保存字段。

前奏仍显示灰色首句预览；无歌词仍显示 `NO LYRICS`。专注模式不是固定位置单行，也不是逐字卡拉 OK。浏览态持续同步并排空事件；是否接受按键取决于视频域同步消费时是否处于播放页面，与现有背景切换控制的边界语义一致。

## 原因与实现

旧源码的引脚、消抖和按键事件总线已经支持 KEY6，但 `ui_event_bridge` 未译码索引 5，现有按键译码测试明确预期该索引不产生业务动作。旧文档“逐字高亮动效切换”未连入当前显示链，歌词 ROM 也只有逐句时间戳。

本次仅修改四个生产 RTL 文件：

- `src/io/ui_event_bridge.v`：完整匹配 `EV_KEY_DOWN` 和 16 位索引 5，输出独立 toggle；释放和高位别名不触发。
- `src/top_tf_hdmi_audio.v`：将 toggle 连到现有播放页面。
- `src/display/playback_page.v`：两级同步、历史边沿、请求模式和帧模式。快速连续按键先在请求状态累计奇偶，再按帧发布。
- `src/display/lrc_five_osd.v`：专注模式只请求当前逻辑行的字形，静止选槽 2，滚动选槽 3，再通过环形基槽映射字形。前奏显示不依赖高亮有效标志。

新增状态共 6 位：源 toggle 1 位，视频域同步 2 位、历史 1 位、请求模式 1 位、帧模式 1 位。新增寄存器均显式初始化为 0，并用独立时序块实现相同的低有效异步复位。没有新增 primitive、IP、字库、歌词表或帧缓冲；六行缓存和滚动提交握手沿用原实现。没有修改生成资源、音频数据通路、引脚或约束。

## 构建与固件

构建对象为用户原始 `prj/VinylFPGA.al`，通过本机 TD 原生运行管理器执行，与 GUI Run All 的 multi-run 路径一致。器件 EG4S20BG256、顶层 top、TD 6.2.168116；综合 `area_prior / high`、物理 `opt_timing=high / effort=routability`。完整输入已在构建前保存到 `inputs/` 并逐文件计算 SHA-256。

首轮 seed 6 完成综合、布局布线和 bitgen，但最终 setup WNS -1.005 ns、TNS -1.471 ns，不能放行；其 bit 仅为失败候选。最差路径位于既有 100 MHz SD/BMP 链的 `pixel_count` 到 `bmp_data.ce`，其中网线延迟占 78%；新增逻辑所在 25 MHz 视频域的 setup WNS +8.370 ns。失败证据保存在 `failed_seed6/`。随后对同一已综合 gate DB、同一物理策略执行有限的布局种子比较，不放宽时钟或添加 timing exception。

seed 7 完成后的 setup WNS +0.143 ns、hold WNS +0.037 ns，两项 TNS 为 0；seed 8 的 setup WNS -0.043 ns，未放行。seed 7 通过后主动停止已经排队启动的 seed 9/10，取消结果不计为完成的时序失败。随后只将原 `.al` 的两处 seed 字段从 6 改为 7，保持单 seed、单 job 和其他策略，重新通过原生 run manager 执行原工程物理实现与 bitgen，最终结果在下文签核。

已读取用户指定的 SynthPilot [llms.txt](https://www.synthpilot.dev/llms.txt)，并通过当前 `td_connection_info` 确认 TD 安装和版本。运行时结构化接口没有 `launch_runs` / `wait_run` 多运行启动工具，因此构建使用仓库既有 `tools/run_optimized_project.tcl`；不将单运行默认配置当作原 `.al` 策略的等价替代。

SynthPilot 的 `td_open_project` 能分析原工程，但后续 `td_open_run` 导致托管 TD 进程退出并返回 outcome unknown。没有自动重试这一操作，也没有据此宣告时序通过；后续数据库核验使用已验证的 TD 原生只读报告流程。另一次复制工程后复用综合 run 的尝试被 TD 的 up-to-date 检查拦截，未把它当作实际物理运行。种子比较直接调用当前 TD 安装的官方 `MultiSeed.tcl`，使用原 `phy_1` 项目和本轮原始 gate DB。

最终原工程固定 seed 7 的物理实现、显式 hold 修复、bitgen、debugger/BID 收尾完成。`verify_gui_runs` 确认本轮 stage marker 新鲜、没有 error marker、selected-result 副本与 seed 结果逐文件同哈希，且 140 项硬件输入与构建前快照一致；随后对本轮真实 routed DB 独立运行 `update_timing -mode final` 并重报面积、时序和约束。复核结果与第一次 seed 7 候选相同。

## 上板验收

使用本轮新 bit，保持原媒体卡即可。进入有歌词的歌曲，按 KEY6 确认“五行→当前句→五行”；在滚动和暂停时切换，核对当前句连续；随后切曲、Seek、返回浏览再播放，确认模式保留和歌词继续跟随音频；系统复位后恢复五行。

本轮不执行实板下载、Flash 烧录或 SD 卡写入。旧固件已通过的人工验收不能自动覆盖新增行为。
