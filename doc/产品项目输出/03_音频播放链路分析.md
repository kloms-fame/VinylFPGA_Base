# 03｜音频播放链路分析

## 1. 音频格式与外部契约

当前硬件播放路径面向预先准备好的单声道 PCM：16-bit signed little-endian、48 kHz。顶层用 audio_size_bytes / 2 推导样本数，wav_stream_player 不负责解析 WAV 容器头。该选择将文件系统/容器解析压力转移到 PC 侧媒体准备工具，降低 FPGA 逻辑复杂度，但也要求素材生成与 INDEX 元数据严格遵守格式契约。

## 2. 端到端数据链

~~~mermaid
flowchart LR
  LBA[曲目起始LBA/扇区数] --> PREF[SD扇区预取]
  SD[TF卡 SD SPI] --> PREF
  PREF --> STAGE[完整扇区暂存与提交]
  STAGE --> DMA[SDRAM DMA 分块写入]
  DMA --> CACHE[SDRAM 1024槽扇区环形缓存]
  CACHE --> READ[按需扇区读取]
  READ --> BYTES[字节流 client_valid/client_byte]
  BYTES --> WAV[wav_stream_player 拼接PCM]
  WAV --> PCM[4096x16 样本环形缓冲]
  PCM --> TICK[video_clk域 48kHz消费]
  TICK --> GAIN[音量/淡化/音源选择]
  GAIN --> HDMI[HDMI PCM bridge/contract adapter]
~~~

1. **曲目选择：** 媒体扫描/INDEX 提供起始 LBA、总扇区数和音频字节数。
2. **预取：** audio_prefetch_sdram 在 SD 域请求连续扇区，校验字节数和写入索引后才将完整扇区发布给下一阶段。
3. **SDRAM 缓存：** audio_sdram_dma 通过 mailbox 承接跨域请求，将扇区按块写入 SDRAM 环形缓存；DMA 事务需跟踪迟到读返回及取消时的排空。
4. **读出：** 播放器按扇区索引请求缓存数据，以 client_req/client_busy 接收事务，再由 client_valid/client_byte/client_byte_index 返回字节。这里不是每个字节都有 ready 的通用流接口；请求接收、字节有效和扇区完成应分别理解。
5. **PCM 拼接：** wav_stream_player 将相邻低/高字节组成 16-bit little-endian 样本，写入 4096×16-bit 环形缓冲。写侧在 sd_card_clk 域，读侧在 video_clk 域。
6. **实时消费：** 顶层 video_clk 域分数累加器产生 48 kHz 计划取样节拍，暂停状态对播放器消费节拍门控。wav_stream_player 成功从样本缓存读出数据时产生 wav_sample_consumed；timebase_48k 接收该事件并推进媒体样本数/毫秒时间，并不产生采样节拍。欠载时维持输出节奏并送静音，但不把缺失媒体样本算作成功消费；暂停时媒体位置冻结。
7. **输出：** 单声道复制为左右声道，音量和转场淡化后由音源选择器送入 HDMI PCM 桥。16-bit 样本通过接口适配左对齐到 24-bit 输入，低 8 位补零。

## 3. 缓存与背压策略

- audio_prefetch_sdram 的 SDRAM 扇区环形缓存为 1024 个槽位。
- 默认预读目标约 960 扇区，高水位约 1008；低于预读目标后继续补读。
- 低于 384 扇区时产生 prefetch_critical，顶层提高音频 SD 服务紧急度。
- PCM BRAM 环形缓冲有自己的水位管理：完成扇区后若写侧达到约 3/4 水位，暂缓下一扇区；低于同一高水位后恢复。约 1/2 水位另用于 buffer_low 低储备指示，顶层据此提高音频服务优先级，不是写侧恢复阈值。
- 启动门要求先有足够可读内容，或已确认 EOF 且有合法尾部样本，避免短曲因等待满一整扇区而不启动。
- 生产者和消费者使用背压和有效信号解耦，不以连续组合直通方式连接 SD 至 HDMI。

上述水位直接对应 audio_prefetch_sdram 的 PREFILL_SECTORS/HIGH_SECTORS/LOW_SECTORS、prefetch_critical 条件和 wav_stream_player 的 BUFFER_HIGH_WATER/BUFFER_LOW_WATER。改动参数时需重新核对启动等待、实时储备和 MV 服务机会。

## 4. Seek、暂停、切歌和 EOF

### Seek

seek_controller 产生目标样本位置。顶层将目标转换成扇区偏移和首扇区内跳过样本数，再将寄存后的结果交给播放器。每个真正消费的 PCM 样本通过 toggle 通知 SD 域，由影子计数器跟踪样本位置。Seek 过程中丢弃目标位置前的样本，避免 UI/歌词时间与播放内容错位。

### 暂停

暂停后停止有效样本消费计数，使歌曲进度和歌词定位冻结；音频输出则维持 HDMI 侧稳定契约。恢复后继续从当前样本位置前进。

### 切歌与会话隔离

stream_session 在开启新曲前阻断新请求，等待 SD 存储事务、视频写入和 WAV 读取器全部静止，再留出保护拍数后切换 session。这个 drain/guard 阶段避免旧曲目的延迟 SDRAM 返回污染新曲缓存。

### EOF

播放控制有下一首/重播等策略，末扇区有效样本长度会截断，防止扇区填充字节被当作音频内容。默认策略需结合当前 play_ctrl 参数和产品交互说明确认。

## 5. SDRAM 仲裁与系统级协同

audio_sdram_arbiter 把音频和图像侧访问统一到 SDRAM 接口。音频事务进行中阻止图像侧开始新访问；写数据尾部未完成时等待尾部排空，再允许读。该设计针对具体 SDRAM 控制器行为，避免因写掩码/尾部时序影响读出数据。

SD 扇区仲裁和 SDRAM 仲裁是两个不同资源域：前者决定哪一类媒体可以发起下一扇区，后者决定音频/图像如何使用外部存储器访问通道。调试卡顿时要分别查看音频储备、SD 扇区 owner、DMA 状态、SDRAM 读写忙和 PCM FIFO 水位。

音频缓存还复用 SDRAM 图像字的低 8 位：audio_sdram_dma 以 {sector[9:0],offset[8:0]} 定位 1024×512 个字节位置，每个位置使用一个 32 位字的低字节；图像 RGB888 使用高 24 位。音频写 mask=1110、图像写 mask=0001，两者可共享物理字地址。这是地址空间与字节通道复用，不能误解为两块独立、不重叠的常规缓存区。对应源码为 audio_sdram_dma.v 的 mem_wr_data/mem_wr_mask/stage_din，以及顶层 PRESERVE_LOW_BYTE=1 和 audio_sdram_arbiter.v 的图像掩码选择。

## 6. 工程难点与亮点

- **三个时钟域协同：** SD 控制、SDRAM DMA 与视频/音频采样之间需要稳定 payload 与事件配对；采用 toggle mailbox、Gray 指针和异步 FIFO 等结构。
- **事务取消不是立即取消：** 存储控制器可能已经发出请求并迟到返回，必须保留 ownership 并 drain，不能重用旧地址/状态。
- **音频连续性优先：** 音频欠载是直接可感知问题，因此预留缓存水位并在竞争时提升服务等级。
- **启动/Seek 边界：** 短曲、奇数边界、文件尾和 Seek 后跳过样本都需精确控制。
- **播放器与歌词同源时基：** 通过已消费样本推进位置，使显示时间与实际音频进度有一致基础。
- **多级缓存可承受突发延迟：** SD 扇区缓存吸收卡访问抖动，PCM BRAM 缓冲将块级供给转成固定采样节拍。

## 8. 维护时重点保护的契约

1. PCM 字节顺序、样本宽度和采样率。
2. 预取扇区提交只能发生在整扇区有效后。
3. SDRAM DMA 的请求/返回对应关系、迟到返回与 cancel drain。
4. PCM 环形缓冲的跨域指针、空满边界和启动门。
5. 实际消费样本是播放时基；暂停和 Seek 语义必须同步影响歌词与 MV。
6. 音频紧急优先级、常态配额和图像写尾排空不能被局部改动破坏。
7. HDMI bridge 的位宽、左右声道、有效/采样节拍契约。
