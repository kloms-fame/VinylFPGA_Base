# FPGA 竞赛演示视频拍摄规则

## 标准五段式

1. 开场定位：5–10 秒，名称、应用场景、一句话功能定位和实物全景。
2. 基础功能：按正式赛题逐项展示，不能遗漏；每项必须有真实结果画面。
3. 扩展功能：按辨识度和技术价值排序，展示动作与结果，不只写名称。
4. 主题化完整演示：日常状态 → 事件触发 → 处理反馈 → 恢复常态。
5. 结尾总结：最多三个核心亮点、真实资源占用数据、已验证的可靠性指标。

## 推荐三分钟时间表

- 00:00–00:08 开场定位（8 秒）
- 00:08–00:28 基础功能（20 秒）
- 00:28–00:58 扩展功能（30 秒）
- 00:58–02:30 主题化演示（92 秒）
- 02:30–03:00 结尾总结（30 秒）

上述时长来自参考 SOP 正文的时间表。若其开头/备注写的 4–5 分钟与正文冲突，应记录冲突；正式赛事视频要求优先。

## 重要事实限制

参考 SOP 的示例功能包括 TF 卡 BMP 图片读取、HDMI 640×480 输出、手动切换、自动轮播、48 kHz 音频输出，以及转场、OSD、缩略图、资源占用等扩展示例。它们不是所有项目的通用功能清单。只有正式赛题或当前项目证据能够支持时，才加入脚本。

## 资源和可靠性

- LUT、REG、BRAM、DSP 数值必须从对应 FPGA 工具的真实报告读取。
- 启动时间、连续运行、复位、掉电、重复操作等可靠性描述必须来自实际测试。
- 未测数据标为 `[待实测]`，不要生成假数字或“稳定可靠”等无法核验的结论。

## 采集与后期

- 能直接采集 HDMI 时优先使用数字采集，避免手机拍显示器产生反光、摩尔纹和闪烁。
- 对非标准分辨率/自定义 HDMI 时序，采集卡需实测兼容，不能假设所有设备都支持。
- 重要音频应实际录制；不能默认屏幕采集卡会获得作品的独立音频输出。
- 作品功能以实拍/真实采集为证据；AI 生成画面只可用于包装、参考分镜或概念视觉。
- 导出后必须在常规播放器中从头至尾复查。
